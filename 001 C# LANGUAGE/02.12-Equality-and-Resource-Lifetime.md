# 02.12 Equality and Resource Lifetime

## Equals, GetHashCode, and ToString

`Equals` describes equality, `GetHashCode` supports hash-based lookup, and `ToString` supplies a textual representation. They serve different purposes.

```csharp
var first = new ProductId(7);
var second = new ProductId(7);
Console.WriteLine(first.Equals(second)); // True
Console.WriteLine(first.GetHashCode() == second.GetHashCode()); // True
Console.WriteLine(first); // ProductId { Value = 7 }

public readonly record struct ProductId(int Value);
```

Records generate appropriate value-oriented implementations; ordinary classes default to reference-based `Equals` unless customized.

## Reference versus value equality

```csharp
var first = new Person("Deep");
var second = new Person("Deep");
Console.WriteLine(first == second); // True: record value equality.
Console.WriteLine(ReferenceEquals(first, second)); // False: distinct objects.

record Person(string Name);
```

For classes, `ReferenceEquals` checks identity regardless of an overloaded `==`. For value types it can involve boxing, so it is not a value-comparison tool.

## Equality contracts and collections

- Equality should be reflexive, symmetric, and transitive for ordinary equality contracts.
- Equal values must have equal hash codes; unequal values may also collide.
- Never persist a hash code as a stable identifier.
- Do not mutate fields used for equality while an object is a dictionary key or set element.
- A collection's supplied comparer can define equality differently from the object's default behavior.

```csharp
var codes = new HashSet<string>(StringComparer.OrdinalIgnoreCase) { "ABC" };
Console.WriteLine(codes.Add("abc")); // False
```

## Finalizers

A class finalizer uses `~TypeName()`. Its timing is nondeterministic; it is not a scope-exit operation.

Declaration syntax:

```csharp
class FinalizationExample
{
    ~FinalizationExample()
    {
        // Only last-resort native cleanup would belong here.
    }
}
```

Do not add a finalizer merely because a class holds managed objects. Prefer `SafeHandle` for owning native handles; finalizer ordering and process shutdown do not guarantee application-level completion.

## IDisposable and using

`Dispose` expresses deterministic resource cleanup. `using` invokes it when control leaves the scope, including ordinary exception unwinding.

```csharp
using (var reader = new System.IO.StringReader("Hello"))
{
    Console.WriteLine(reader.ReadLine()); // Hello
} // reader.Dispose() is called.
```

A using declaration disposes at the end of its enclosing scope:

```csharp
using var reader = new System.IO.StringReader("Hello");
Console.WriteLine(reader.ReadLine()); // Hello
```

## Ownership versus garbage collection

The garbage collector reclaims unreachable managed memory; it does not know when a file or connection is no longer logically needed. The owner of a disposable resource should arrange disposal; a borrower should not close something still owned by its caller.

Calling `Dispose` does not immediately delete a managed object. Repeated disposal should usually be harmless, while using a disposed resource can throw `ObjectDisposedException`. For asynchronously released resources, the corresponding contract is `IAsyncDisposable` and `await using`.
