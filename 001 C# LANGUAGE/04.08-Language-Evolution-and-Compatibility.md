# 04.08 Language Evolution and Compatibility

## Language version, SDK, and target framework

The SDK supplies the compiler and build tools. The language version controls accepted syntax. The target framework controls the framework API contract and helps select the default language version.

Project settings:

```xml
<PropertyGroup>
  <TargetFramework>net10.0</TargetFramework>
  <LangVersion>14.0</LangVersion>
  <Nullable>enable</Nullable>
</PropertyGroup>
```

Using newer syntax does not automatically make a newer framework API available on an older target. Some language features also depend on runtime or library support.

## Feature availability and diagnostics

Check the selected SDK with `dotnet --version` from the project directory. A repository's `global.json` can affect that selection.

A “feature is not available” diagnostic can require a compatible compiler or language setting. A “type or namespace not found” error may instead indicate a missing reference, namespace import, or unsupported target API.

## Extension members and extension blocks

Traditional extension method:

```csharp
Console.WriteLine("C#".InBrackets()); // [C#]

static class TextExtensions
{
    public static string InBrackets(this string value) => $"[{value}]";
}
```

C# 14 extension block:

```csharp
Console.WriteLine("C#".Bracketed); // [C#]

static class TextExtensions
{
    extension(string value)
    {
        public string Bracketed => $"[{value}]";
    }
}
```

The block declares the receiver once and can expose extension properties as well as methods. It still belongs in an appropriate static extension container and does not grant private-member access.

## Field-backed property syntax

C# 14 lets `field` refer to compiler-generated backing storage inside a property accessor.

```csharp
var item = new Item { Quantity = 3 };
Console.WriteLine(item.Quantity); // 3

class Item
{
    public int Quantity
    {
        get;
        set => field = value >= 0 ? value
            : throw new ArgumentOutOfRangeException(nameof(value));
    }
}
```

Older syntax declares a separate private field and uses it in both accessors. If an existing identifier is named `field`, qualification or `@field` may be needed to disambiguate it inside accessors.

## Stable versus preview features

A preview compiler or `LangVersion=preview` can accept features whose contract is still changing. Avoid `latest` or preview settings when reproducible builds require a fixed supported language baseline.

## Adopting new syntax

Check compiler, target-framework, analyzer, formatter, generator, and CI compatibility together. Build every supported target, exercise runtime behavior, and review public API changes separately from source-only simplifications. A successful build on one developer machine does not establish compatibility for all consumers.
