# 04.01 Lambda Expressions

## Expression and statement lambdas

A lambda is an unnamed function. An expression body produces an expression result; a statement body uses braces and can contain several statements.

```csharp
Func<int, int> square = value => value * value;
Func<int, int> doubled = value =>
{
    int result = value * 2;
    return result;
};
Console.WriteLine(square(4)); // 16
Console.WriteLine(doubled(4)); // 8
```

Use `()` for no parameters and parentheses for multiple parameters: `(left, right) => left + right`.

## Parameter and return-type inference

```csharp
Func<int, int, int> add = (left, right) => left + right;
Func<int, string> describe = (int value) => $"Value: {value}";
Console.WriteLine(add(2, 3)); // 5
Console.WriteLine(describe(7)); // Value: 7
```

The target delegate commonly supplies parameter types. All return paths of a statement lambda must satisfy its result contract. An `Action` lambda returns no value.

## Captures and closures

A closure preserves access to variables used from an enclosing scope. It captures the variable, not a frozen snapshot of its current value.

```csharp
int multiplier = 2;
Func<int, int> scale = value => value * multiplier;
multiplier = 3;
Console.WriteLine(scale(4)); // 12
```

To keep a specific value, copy it into a separate variable and capture that variable.

## Static lambdas

```csharp
Func<int, int> square = static value => value * value;
Console.WriteLine(square(5)); // 25
```

A static lambda cannot capture local variables or `this`. It can use accessible static members. This makes accidental captures a compile-time error.

## Closure lifetime, mutation, and allocation

```csharp
var actions = new List<Action>();
for (int i = 0; i < 3; i++)
{
    int copy = i;
    actions.Add(() => Console.WriteLine(copy));
}
foreach (Action action in actions) action(); // 0, 1, 2
```

Capturing the single `for` variable `i` directly would make these delayed actions observe its final value, 3. Modern `foreach` iteration variables are separate per iteration.

Captured objects can remain alive as long as the delegate retains them. Capturing mutable state does not make it thread-safe. Compiler optimizations can cache or avoid some allocations, so do not assume every lambda either always allocates or never allocates.
