# 03.08 Variance

## Invariance

An invariant type cannot be substituted merely because its type arguments have an inheritance relationship.

```csharp
var dogs = new List<Dog>();
// List<Animal> animals = dogs; // Error: List<T> is invariant.

class Animal { }
class Dog : Animal { }
```

If that conversion were allowed, a caller could insert a non-dog animal into the dog list.

## Covariance with out

Covariance permits a more specific reference-type argument where a more general output type is expected.

```csharp
IEnumerable<string> names = new[] { "Deep" };
IEnumerable<object> values = names;
foreach (object value in values)
    Console.WriteLine(value); // Deep
```

`IEnumerable<out T>` produces `T` values. An `out` type parameter can be used in positions allowed by variance rules; it is not a general writable input slot.

## Contravariance with in

Contravariance permits behavior accepting a broader type to be used where behavior accepting a narrower type is needed.

```csharp
Action<object> printObject = value => Console.WriteLine(value);
Action<string> printString = printObject;
printString("Hello"); // Hello
```

A function able to accept any object can accept a string. The reverse conversion would allow passing objects the string-specific function cannot handle.

## Interface and delegate declarations

```csharp
IProducer<string> strings = new MessageProducer();
IProducer<object> objects = strings;
Console.WriteLine(objects.Get()); // Hello

interface IProducer<out T> { T Get(); }
class MessageProducer : IProducer<string>
{
    public string Get() => "Hello";
}
```

Variance annotations are supported on interfaces and delegates, not ordinary class type parameters. `Func<in T, out TResult>` demonstrates input contravariance and output covariance in one delegate.

## Reference-type restrictions

Generic variance conversions apply to reference-type arguments. `IEnumerable<int>` is not convertible to `IEnumerable<object>` through covariance; converting each integer to object requires boxing.

## Array covariance risks

```csharp
object[] values = new string[1]; // Reference-array covariance.
values[0] = "Hello";
Console.WriteLine(values[0]); // Hello
// values[0] = 42; // ArrayTypeMismatchException at runtime.
```

The array is still a string array at runtime. Prefer accurately typed collections rather than depending on array covariance for writable APIs.
