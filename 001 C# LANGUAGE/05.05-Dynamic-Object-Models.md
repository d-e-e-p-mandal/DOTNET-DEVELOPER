# 05.05 Dynamic Object Models

## Runtime binding

`dynamic` resolves supported member operations at runtime. Use it at a deliberate dynamic boundary rather than throughout an otherwise typed application.

```csharp
dynamic value = "Hello";
Console.WriteLine(value.Length); // 5
// Console.WriteLine(value.Missing); // RuntimeBinderException.
```

Compile-time acceptance does not prove that the runtime object supports the operation.

## ExpandoObject

`ExpandoObject` supports adding and removing named members dynamically and exposes dictionary access to the same data.

```csharp
using System.Dynamic;

dynamic person = new ExpandoObject();
person.Name = "Deep";
person.Age = 20;
Console.WriteLine(person.Name); // Deep

var members = (IDictionary<string, object?>)person;
Console.WriteLine(members.ContainsKey("Age")); // True
members.Remove("Age");
Console.WriteLine(members.ContainsKey("Age")); // False
```

The dictionary view is useful when member names come from data. Missing dynamic members fail at runtime; dictionary `TryGetValue` provides an explicit absence check.

## DynamicObject

Derive from `DynamicObject` to define custom handling of dynamic operations.

```csharp
using System.Dynamic;

dynamic values = new Settings();
Console.WriteLine(values.Theme); // Dark

class Settings : DynamicObject
{
    public override bool TryGetMember(GetMemberBinder binder, out object? result)
    {
        if (binder.Name == "Theme")
        {
            result = "Dark";
            return true;
        }
        result = null;
        return false; // Let the binder report an unsupported member.
    }
}
```

Other hooks include setting members and invoking methods. Returning false does not mean “success with null”; it signals that the operation was not handled.

## Interoperability scenarios

Dynamic objects can be useful for COM automation, scripting bridges, and genuinely schema-changing data. Dynamic member syntax does not automatically turn every JSON value into a dynamic object; the deserializer's chosen representation determines its capabilities.

## Boundaries with typed code

Validate expected member names and value types, then map to a known record or class at the boundary.

```csharp
var input = new Dictionary<string, object?> { ["Name"] = "Deep" };
if (!input.TryGetValue("Name", out object? value) || value is not string name)
    throw new ArgumentException("Name must be text.");

var customer = new Customer(name);
Console.WriteLine(customer.Name); // Deep
record Customer(string Name);
```

Typed internal models restore discoverability and compiler checks. Dynamic binding can add runtime failures, overhead, and restrictions in trimming or AOT scenarios, so verify the deployment model as well as ordinary execution.
