# 02.04 Constructors and Initialization

## Parameterless and parameterized constructors

A constructor initializes an instance. Its name matches the type, and it has no return type.

```csharp
var guest = new User();
var member = new User("Deep");
Console.WriteLine(guest.Name); // Guest
Console.WriteLine(member.Name); // Deep

class User
{
    public string Name { get; }
    public User() : this("Guest") { }
    public User(string name)
    {
        ArgumentException.ThrowIfNullOrWhiteSpace(name);
        Name = name;
    }
}
```

If a class declares no instance constructor, the compiler normally supplies a parameterless one. Adding a parameterized constructor means the implicit parameterless constructor is no longer supplied.

## Constructor overloading and this chaining

Constructors can have different parameter lists. `: this(...)` delegates to another constructor of the same type before the current constructor body runs.

The previous parameterless constructor reuses validation in `User(string name)`. Constructor chains cannot form a cycle.

## base chaining and execution order

```csharp
_ = new Employee("Deep");

class Person
{
    public string Name { get; }
    public Person(string name)
    {
        Name = name;
        Console.WriteLine("Person body");
    }
}
class Employee : Person
{
    public Employee(string name) : base(name)
    {
        Console.WriteLine("Employee body");
    }
}
```

Output: `Person body`, then `Employee body`. Without an explicit initializer, a class constructor normally attempts to call `base()`; an accessible matching base constructor must exist.

## Static constructors

A static constructor initializes type-level state. It has no parameters or access modifier and is not called directly.

```csharp
Console.WriteLine(Settings.Mode); // Static initialization, then Ready.
Console.WriteLine(Settings.Mode); // Ready; initialization is not repeated.

class Settings
{
    public static string Mode { get; }
    static Settings()
    {
        Console.WriteLine("Static initialization");
        Mode = "Ready";
    }
}
```

Avoid blocking or complex external work in static initialization. A failure normally leaves that type unusable through the failed initialization path.

## Field initialization order

For ordinary class construction, fields first have default values. Instance field initializers run before the corresponding constructor body; derived field initialization and base constructor execution make virtual calls during construction particularly risky.

```csharp
_ = new Example();

class Example
{
    private int _first = Log("First field");
    private int _second = Log("Second field");
    public Example() => Console.WriteLine("Constructor body");
    private static int Log(string text)
    {
        Console.WriteLine(text);
        return 1;
    }
}
```

Output: `First field`, `Second field`, `Constructor body`. Initializers in one type run in textual order; do not rely on source-file ordering between parts of a partial type.

## Valid construction

- Validate required values before exposing an instance.
- Do not call overridable methods from constructors; derived state may not yet be established.
- Avoid leaking `this` to events or other objects during incomplete initialization.
- Object initializers run after constructor execution, so ordinary settable properties may still be changed afterward.
- Constructors cannot be `async`; use a separate asynchronous factory when creation requires awaited work.
