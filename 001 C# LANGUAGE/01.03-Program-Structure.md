# 01.03 Program Structure

**Main idea:** traditional C# writes a class and `Main` explicitly. Modern C# can use **top-level statements**, so you can omit those startup wrappers. Other classes remain necessary when your code uses them.

**Practice setup:** use a .NET 10 console project. All complete C# examples below fit inside **Program.cs only**. Replace its contents with one example at a time. No `Student.cs`, `Models` folder, or `GlobalUsings.cs` is needed for this lesson.

```bash
dotnet new console -n StructureDemo -f net10.0
cd StructureDemo
```

Run each example with `dotnet run`, unless another command is shown. Keep the generated `.csproj`; this lesson uses a project-based application.

## 1. Source Files, Namespaces, Types, and Members

### Traditional structure — explicit Program and Main

**Complete Program.cs:**

```csharp
using System;

namespace StructureDemo
{
    internal class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("Hello, Deep!");
        }
    }
}
```

**Output:** `Hello, Deep!`

| Part | Meaning |
|---|---|
| `Program.cs` | Source file containing C# code |
| `using System;` | Allows short names such as `Console` |
| `namespace StructureDemo` | Groups types under a name |
| `class Program` | Type containing the entry-point method |
| `internal` | Makes the type accessible within its assembly |
| `Main` | Method where execution begins |
| `Console.WriteLine(...)` | Statement that prints a line |

A **type** defines data or behavior. A class is one kind of type. A **member** belongs to a type: `Main` is a method member of `Program`. Fields, properties, and constructors are other kinds of members.

### Modern structure — top-level statements

**Complete Program.cs:**

```csharp
Console.WriteLine("Hello, Deep!");
```

**Output:** `Hello, Deep!`

You write the executable statement directly. The compiler generates a containing type and an entry-point method. The application still has an entry point even though you did not write `Main` yourself.

### What can you remove?

| Part | Can you omit it? | Condition |
|---|---|---|
| `using System;` | Yes | `System` is imported globally, or you write `System.Console` |
| Explicit namespace wrapper | Yes | Explicit namespaces are optional; removing one changes its types' full names |
| Explicit `Program` and `Main` wrappers | Yes | Move the startup statements to top level |
| Another class, such as `Student` | Sometimes | Rewrite/remove its uses, or keep its definition elsewhere |
| The name `Program.cs` | Yes, it can be renamed | Startup depends on the entry point, not the file name |

Do not remove only `class Program` and leave a `Main` function at file level expecting it to start automatically. For top-level code, move the statements out of `Main` as shown above. A top-level local function named `Main` is not automatically invoked as the explicit entry point.

Traditional syntax is still supported. “Old” and “new” describe two writing styles.

### Can one file contain several classes?

Yes. `Program.cs` can contain both `Program` and `Student`. A separate source file for every class is a useful convention, not a language requirement.

Namespaces are logical names; folders are physical locations. Moving a file into a folder does not itself change the declared namespace.

## 2. using Directives, Aliases, and Global Usings

### A using directive shortens names

**Complete Program.cs:**

```csharp
using System.Text;

StringBuilder message = new StringBuilder();
message.Append("Hello, Deep!");
Console.WriteLine(message.ToString());
```

**Output:** `Hello, Deep!`

Without the directive, replace the declaration with this fully qualified version:

```csharp
System.Text.StringBuilder message = new System.Text.StringBuilder();
```

A using directive affects name lookup. It does not install a package, copy a class, or execute code. Importing `System` does not also import every nested namespace, such as `System.Text`.

### Type alias

**Complete Program.cs:**

```csharp
using TextBuilder = System.Text.StringBuilder;

TextBuilder message = new TextBuilder();
message.Append("Learning C#");
Console.WriteLine(message.ToString());
```

**Output:** `Learning C#`

`TextBuilder` is an alternative name for the existing type in this file. It does not create a new type.

### Namespace alias and using static

**Complete Program.cs:**

```csharp
using Text = System.Text;
using static System.Math;

Text.StringBuilder message = new Text.StringBuilder();
message.Append("Square root: ");
message.Append(Sqrt(81));
Console.WriteLine(message.ToString());
```

**Output:** `Square root: 9`

`Text` names the namespace. `using static System.Math;` allows `Sqrt` instead of `Math.Sqrt`.

### Global using can stay in Program.cs

**Complete Program.cs:**

```csharp
global using System.Text;

StringBuilder message = new StringBuilder();
message.Append("Ready");
Console.WriteLine(message.ToString());
```

**Output:** `Ready`

The import applies across this project compilation, including any additional source files. A separate `GlobalUsings.cs` is optional. With only one source file, an ordinary using is usually enough.

Put global usings before ordinary usings, executable statements, and namespace/type declarations. An ordinary file-level using applies within that file; a using inside a namespace applies within that namespace body.

### Why Console works without using System

The console template enables implicit imports through this project-file setting:

```xml
<ImplicitUsings>enable</ImplicitUsings>
```

It supplies common global usings, including `System`. This is separate from top-level statements: traditional `Main` can use implicit usings too.

If implicit usings are disabled, add `using System;` or write `System.Console.WriteLine(...)`. Both approaches work with either startup style.

## 3. Main Method and Command-Line Arguments

### Traditional structure

**Complete Program.cs:**

```csharp
using System;

internal class Program
{
    static int Main(string[] args)
    {
        if (args.Length == 0)
        {
            Console.WriteLine("Please provide your name.");
            return 1;
        }

        Console.WriteLine($"Hello, {args[0]}!");
        return 0;
    }
}
```

This traditional example omits a namespace, which is allowed.

### Modern structure — same behavior

**Complete Program.cs:**

```csharp
if (args.Length == 0)
{
    Console.WriteLine("Please provide your name.");
    return 1;
}

Console.WriteLine($"Hello, {args[0]}!");
return 0;
```

Top-level code gets `args` automatically and supports returning an integer exit code.

### Run either version

```bash
dotnet run -- Deep
```

**Output:** `Hello, Deep!`

```bash
dotnet run -- "Deep Mandal"
```

**Output:** `Hello, Deep Mandal!`

| Part | Meaning |
|---|---|
| `--` | Separates application arguments from `dotnet run` options |
| `string[] args` | Array of text arguments supplied at startup |
| `args.Length` | Number of supplied arguments |
| `args[0]` | First argument; indexes begin at zero |
| `"Deep Mandal"` | Quotes keep the two words in one argument |
| `return 0;` | Success by convention |
| `return 1;` | Failure code chosen by this application |

Without quotes, `Deep Mandal` supplies two arguments. The executable name is not included in `args`. With no arguments, its length is zero, so check before accessing `args[0]`.

Run `dotnet run` without a name: both versions print `Please provide your name.` and return `1`. Returning a number does not print it.

Immediately check the exit code with `echo $?` in Bash/Zsh, `$LASTEXITCODE` in PowerShell, or `echo %ERRORLEVEL%` in Windows Command Prompt.

### Main keywords and signatures

`static` means no `Program` object is required to call the method. `void` means no result; `int` permits an exit code. `Main` is case-sensitive and does not need to be public. Its containing class does not have to be named `Program`.

Common forms include `static void Main()`, `static void Main(string[] args)`, and `static int Main(string[] args)`. Asynchronous entry points can return `Task` or `Task<int>`; `async void Main` is not a valid asynchronous entry point.

## 4. Top-Level Statements and Removing Other Classes

### A. Traditional structure with another class

**Complete Program.cs — both classes are in this file:**

```csharp
using System;

internal class Program
{
    static void Main()
    {
        Student student = new Student();
        student.Name = "Deep";
        student.Introduce();
    }
}

class Student
{
    public string Name { get; set; } = "";

    public void Introduce()
    {
        Console.WriteLine($"Hello, {Name}!");
    }
}
```

### B. Modern structure with the same Student class

**Complete Program.cs:**

```csharp
Student student = new Student();
student.Name = "Deep";
student.Introduce();

class Student
{
    public string Name { get; set; } = "";

    public void Introduce()
    {
        Console.WriteLine($"Hello, {Name}!");
    }
}
```

**Output from either version:** `Hello, Deep!`

We omitted the explicit `Program` and `Main` wrappers. We kept `Student` because the code creates and uses a `Student` object.

`Name` is a property member; `Introduce` is a method member. They belong to `Student` and are accessed through `student` here.

### C. Can we also remove Student?

**Yes, if we rewrite this simple program so it no longer needs that type.**

**Complete Program.cs:**

```csharp
string name = "Deep";
Console.WriteLine($"Hello, {name}!");
```

**Output:** `Hello, Deep!`

The greeting is the same, but the design changed: `name` is now a local variable instead of a property on a `Student` object.

Deleting `Student` while leaving `new Student()` fails to compile unless another accessible `Student` type exists. The compiler generates startup infrastructure, not your application classes.

Keep classes when you need objects with related data and behavior. Local variables may be enough for a tiny greeting.

### D. Can we write a function without writing a class?

**Traditional Program.cs — a method in Program:**

```csharp
using System;

class Program
{
    static void Main()
    {
        Greet("Deep");
    }

    static void Greet(string name)
    {
        Console.WriteLine($"Hello, {name}!");
    }
}
```

**Modern Program.cs — a local function in top-level code:**

```csharp
Greet("Deep");

void Greet(string name)
{
    Console.WriteLine($"Hello, {name}!");
}
```

**Output from either version:** `Hello, Deep!`

The top-level `Greet` is a local function inside the generated entry point. It is not automatically a public method callable from other classes. Top-level variables are locals, not automatically fields of `Program`.

### Ordering rules

```text
Global using directives, if any
Ordinary using directives, if any
Top-level statements and local functions
Type declarations or block-scoped namespace declarations
```

- Only one source file per project can contain top-level statements.
- Put all top-level code before type declarations in that file.
- A type can be used before its declaration appears in the source file.
- Top-level statements cannot appear inside an explicit namespace or share a file with a file-scoped namespace.
- If you add an explicit `Main` alongside top-level code, top-level code is the entry point; the compiler warns that the explicit `Main` is ignored as an entry point.

Use one startup style per application. Top-level statements are optional; an explicit `Main` remains valid.

## 5. File-Scoped and Block-Scoped Namespaces

Namespace style is separate from entry-point style. Both examples below use explicit `Main` and require only `Program.cs`.

### Block-scoped namespace — traditional braces

```csharp
using System;

namespace StructureDemo
{
    class Program
    {
        static void Main()
        {
            Console.WriteLine("Inside StructureDemo");
        }
    }
}
```

### File-scoped namespace — less indentation

```csharp
using System;

namespace StructureDemo;

class Program
{
    static void Main()
    {
        Console.WriteLine("Inside StructureDemo");
    }
}
```

**Output from either version:** `Inside StructureDemo`

Both declare `StructureDemo.Program`. File-scoped syntax removes the namespace braces, not the class or method braces.

| Question | Block-scoped | File-scoped |
|---|---|---|
| Syntax | `namespace Name { ... }` | `namespace Name;` |
| Where types belong | Inside the namespace braces | Following the declaration in the file |
| Multiple namespace declarations in one file | Allowed | Not allowed |
| Explicit Main supported | Yes | Yes |

Do not mix these namespace declaration styles in one file. Multiple files can share the same namespace.

**For this lesson's simple top-level programs, omit the namespace declaration.** A block-scoped namespace for helper types can appear after top-level code if needed.

## 6. Statements, Semicolons, Braces, and Formatting

### Statements perform actions

**Complete Program.cs:**

```csharp
int total = 10 + 20;       // Declare and initialize a local variable.
total = total + 5;         // Assign a value.
Console.WriteLine(total); // Call a method. Output: 35.
```

`10 + 20` is an expression that produces a value. `int total = 10 + 20;` is a declaration statement. In traditional code, these lines go inside `Main`.

### Which semicolons and braces can you remove?

| Element | Rule |
|---|---|
| Variable declaration, assignment, method-call statement | Ends with `;` |
| `return` statement | Ends with `;` |
| `using` directive | Ends with `;` |
| File-scoped namespace declaration | Ends with `;` |
| Class or method body | Uses braces; normally no semicolon after the closing brace |
| `if` with a block | No semicolon between the condition and block |

Top-level syntax removes startup wrappers. It does not remove semicolons required by statements or braces needed for other blocks.

**Correct:**

```csharp
int age = 20;

if (age >= 18)
{
    Console.WriteLine("Adult");
}
```

**Deliberately wrong example — accidental empty statement:**

```csharp
int age = 15;

if (age >= 18); // This semicolon is the entire if body.
{
    Console.WriteLine("Adult"); // Separate block: always executes.
}
```

Remove the semicolon after the condition. An `if` with one statement can omit braces, but keeping them makes later edits clearer.

### Braces create local scopes

```csharp
int total = 10;

{
    int extra = 5;
    total = total + extra;
}

Console.WriteLine(total); // Output: 15.
// Console.WriteLine(extra); // Would fail: extra is outside its scope.
```

The inner block can access `total`. Code after that block cannot access its local variable `extra`.

### Formatting

Use four spaces per indentation level, one statement per line, and consistent brace placement. Indentation improves readability; braces determine blocks. Spaces inside strings can affect output.

From the project folder:

```bash
dotnet format
```

This edits formatting according to project rules. It does not correct business logic.
