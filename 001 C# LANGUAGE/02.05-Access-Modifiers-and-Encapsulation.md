# 02.05 Access Modifiers and Encapsulation

## public, private, protected, and internal

Accessibility controls which code may name a type or use a member.

| Modifier | Permitted access |
| --- | --- |
| `public` | Code that can access the containing type |
| `private` | Containing type, including its nested types |
| `protected` | Containing class and derived classes, subject to protected-access rules |
| `internal` | Same assembly and explicitly configured friend assemblies |
| `protected internal` | Same assembly **or** eligible derived-class access |
| `private protected` | Containing class and derived classes in the same assembly |

A project commonly builds one assembly. A namespace is not an assembly and does not grant access by itself.

## Type accessibility versus member accessibility

```csharp
var service = new ReportService();
Console.WriteLine(service.Build()); // Report

internal class ReportService
{
    public string Build() => "Report";
    private string Secret() => "Internal detail";
}
```

A public member of an internal class does not make that class public. A public API also cannot expose a less accessible parameter or return type.

Top-level classes default to `internal`; class members generally default to `private`. Interface member defaults differ. Locals do not take access modifiers.

## Protected access through a derived type

```csharp
var employee = new Employee();
employee.Print(); // 10

class Person
{
    protected int Id = 10;
}
class Employee : Person
{
    public void Print() => Console.WriteLine(Id);
    public int ReadOther(Employee other) => other.Id;
    // public int ReadAny(Person other) => other.Id; // Not valid protected access here.
}
```

Being a derived class does not allow reading a protected instance member through every arbitrary base-class reference.

## Hiding internal state

Encapsulation lets the type control valid changes, instead of allowing callers to write storage directly.

```csharp
var account = new Account();
account.Deposit(100M);
Console.WriteLine(account.Balance); // 100
Console.WriteLine(account.TryWithdraw(30M)); // True
Console.WriteLine(account.Balance); // 70

class Account
{
    public decimal Balance { get; private set; }
    public void Deposit(decimal amount)
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        Balance += amount;
    }
    public bool TryWithdraw(decimal amount)
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        if (amount > Balance) return false;
        Balance -= amount;
        return true;
    }
}
```

## Protecting invariants

An invariant is a rule that must hold for valid state, such as a nonnegative balance.

- Validate before mutation.
- Expose meaningful operations rather than setters for every field.
- Returning a mutable internal list can bypass otherwise private storage. Return a snapshot or an appropriate restricted view when callers must not mutate it.
- `private` is an API boundary, not encryption or a security sandbox.
- Access modifiers do not make multi-step state changes thread-safe.
