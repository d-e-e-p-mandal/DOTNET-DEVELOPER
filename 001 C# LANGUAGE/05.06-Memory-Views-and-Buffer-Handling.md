# 05.06 Memory Views and Buffer Handling

## Span<T> and ReadOnlySpan<T>

A span is a bounded view over contiguous storage. `Span<T>` permits writes through the view; `ReadOnlySpan<T>` does not.

```csharp
int[] numbers = { 1, 2, 3 };
Span<int> middle = numbers.AsSpan(1, 1);
middle[0] = 20;
ReadOnlySpan<int> readOnly = numbers;
Console.WriteLine(readOnly[1]); // 20
```

A span does not own or clone the storage. Bounds are checked for ordinary span indexing, but the backing storage must still have a valid lifetime.

## Memory<T> and ReadOnlyMemory<T>

Memory views can be stored in ordinary objects and retained across asynchronous suspension when their backing storage remains valid.

```csharp
Memory<int> memory = new int[] { 10, 20 };
await Task.Yield();
memory.Span[0] = 99;
Console.WriteLine(memory.Span[0]); // 99
```

Obtain and use the span during a synchronous portion of the operation; do not try to preserve a span across an `await` boundary.

## Slicing without copying

```csharp
ReadOnlySpan<char> text = "name=Deep";
int equals = text.IndexOf('=');
ReadOnlySpan<char> value = text[(equals + 1)..];
Console.WriteLine(value.ToString()); // Deep
```

The slice itself does not copy characters. `ToString()` materializes a string here; zero-copy processing ends when an API requires an owned string.

## Stack, array, and native-backed views

```csharp
Span<int> temporary = stackalloc int[3];
temporary.Clear();
temporary[1] = 7;
Console.WriteLine(temporary[1]); // 7
```

`stackalloc` storage is limited to the current execution lifetime and cannot be returned as a surviving view. Native-backed spans require the native allocation to remain valid; creating a span does not arrange deallocation or extend ownership.

## ArrayPool<T> and ownership

```csharp
using System.Buffers;

byte[] buffer = ArrayPool<byte>.Shared.Rent(4);
try
{
    Span<byte> used = buffer.AsSpan(0, 4); // Rent may return a larger array.
    used.Fill(7);
    Console.WriteLine(used.Length); // 4
    Console.WriteLine(used[0]); // 7
}
finally
{
    ArrayPool<byte>.Shared.Return(buffer, clearArray: true);
}
```

Return a rented array exactly once to the same pool. Do not keep or use a slice after returning its array; another renter may modify it. Rented storage can contain old contents until explicitly initialized.

## Async boundaries and readonly limits

The owner must keep storage valid until all consumers finish, including asynchronous consumers. Returning a buffer before an awaited operation completes is a lifetime bug.

Readonly views prevent mutation through that particular view, not through aliases. `ReadOnlyMemory<T>` over a writable array is not an immutable snapshot.
