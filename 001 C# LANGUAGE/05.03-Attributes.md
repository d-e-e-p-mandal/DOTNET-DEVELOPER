# 05.03 Attributes

## Built-in attributes

Attributes attach metadata to declarations. A compiler, runtime feature, analyzer, framework, or your own code decides how to interpret it.

```csharp
Console.WriteLine(Api.Current()); // Current

static class Api
{
    [Obsolete("Use Current instead.")]
    public static string Old() => "Old";
    public static string Current() => "Current";
}
```

Calling `Old` would produce an obsolete-use diagnostic. Merely creating a custom attribute does not automatically add validation or other behavior.

## Creating a custom attribute

```csharp
using System.Reflection;

var attribute = typeof(Order).GetCustomAttribute<LabelAttribute>();
Console.WriteLine(attribute?.Text); // Sales order

[AttributeUsage(AttributeTargets.Class, AllowMultiple = false, Inherited = false)]
class LabelAttribute : Attribute
{
    public string Text { get; }
    public LabelAttribute(string text) => Text = text;
}
[Label("Sales order")]
class Order { }
```

The `Attribute` suffix can usually be omitted when applying the attribute. Constructor arguments provide positional data; writable public fields or properties can provide named attribute arguments.

## Usage, targets, and inheritance

`AttributeUsage` defines permitted targets, whether repeated applications are allowed, and intended inheritance behavior for attribute lookup.

```csharp
Console.WriteLine(typeof(Data).IsDefined(typeof(SerializableAttribute), false)); // True

[Serializable]
class Data { }
```

Explicit targets such as `[assembly: ...]`, `[return: ...]`, and `[property: ...]` distinguish where metadata belongs. For generated positional-record members, explicit targeting is particularly useful.

Attribute argument values are limited to supported compile-time metadata forms such as constants, `typeof(...)`, enum values, and permitted arrays; arbitrary method calls and arbitrary constructed objects are not valid arguments.

## Reading attributes through reflection

`GetCustomAttribute<T>()` reads a single matching attribute; `GetCustomAttributes<T>()` handles multiple applications. `CustomAttributeData` inspects constructor/named-argument metadata without constructing attribute instances.

Attribute constructors run when an API instantiates those attributes, not simply because an application method containing an attributed declaration runs.

## Metadata versus behavior

An attribute such as `[Required]` only validates when an appropriate validation system processes it. An attribute such as `[Obsolete]` is understood by the compiler. Your custom `[Label]` is descriptive until code reads and acts on it. Keep the consumer and the promised behavior explicit.
