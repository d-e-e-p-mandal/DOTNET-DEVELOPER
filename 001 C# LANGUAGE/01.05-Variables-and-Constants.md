# 01.05 Variables and Constants

A **variable** stores a value that can change. A **constant** names a value fixed at compile time.

## 1. Declaration, Initialization, and Assignment

```csharp
int age;                   // Declaration: introduce a name and type.
age = 20;                  // Assignment: give it a value before reading.
age = 21;                  // Reassignment: replace the previous value.

int marks = 90;            // Declaration with initialization.
Console.WriteLine(age);    // 21
Console.WriteLine(marks);  // 90
```

**Syntax:** `type name;`, `type name = value;`, and `name = value;`.

```csharp
var score = 85; // Compiler infers int from the initializer.
score = 95;    // Valid: still an int.

// var total;       // Invalid: no initializer to infer the type from.
// score = "High";  // Invalid: var does not make the type changeable.

Console.WriteLine(score); // 95
```

## 2. Local Variables, Fields, and Parameters

- **Local:** declared inside a method, block, or top-level code.
- **Field:** declared directly inside a class or struct; stores its state.
- **Parameter:** receives an argument supplied to a method or constructor.

```csharp
Counter counter = new Counter(); // Local variable.
counter.Add(5);                   // 5 is the argument.
Console.WriteLine(counter.Total); // Output: 5.

class Counter
{
    public int Total;             // Instance field; starts at 0.

    public void Add(int amount)   // amount is a parameter.
    {
        int next = Total + amount; // Local variable.
        Total = next;
    }
}
```

Each `Counter` object has its own `Total`. A `static` field belongs to the type instead of an individual object. Public fields here keep the examples small; application code usually exposes state through properties or methods.

## 3. Definite Assignment and Default Values

### Local variables must be assigned before reading

```csharp
int total;
// Console.WriteLine(total); // Compile error: unassigned local variable.

total = 10;
Console.WriteLine(total);    // 10
```

The compiler checks every possible path leading to a read:

```csharp
bool isMember = true;
int discount;

if (isMember)
{
    discount = 10;
}
else
{
    discount = 0;
}

Console.WriteLine(discount); // 10
```

Removing the `else` assignment makes `discount` potentially unassigned.

### Fields and array elements receive default values

- Numeric types: zero; `bool`: `false`; `char`: `'\0'`.
- Reference types: `null`; nullable value types such as `int?`: `null`.
- Enum default: numeric zero, even if no named member represents zero.

```csharp
int[] marks = new int[2];
Console.WriteLine(marks[0]);               // 0
Console.WriteLine(default(bool));          // False
Console.WriteLine(default(string) is null); // True

int total = default; // Explicitly initialize this local to int's default.
Console.WriteLine(total); // 0
```

Non-nullable reference fields still need suitable initialization to avoid nullable-analysis warnings. A non-nullable annotation does not create an object automatically.

## 4. const and Compile-Time Constants

Use `const` when the compiler can determine the value and it should not change.

```csharp
const int MinutesPerHour = 60;
const int HoursPerDay = 24;
const int MinutesPerDay = MinutesPerHour * HoursPerDay;

Console.WriteLine(MinutesPerDay); // 1440

// MinutesPerHour = 30;              // Invalid: cannot reassign a constant.
// const int year = DateTime.Now.Year; // Invalid: requires runtime evaluation.
```

- Initialize a constant at its declaration; use an explicit type, not `var`.
- Constants can be local or type members. A constant member is accessed through the type; do not write `static const`.
- Numeric, Boolean, character, string, and enum constants are supported. Reference-type constants other than strings can only be `null`.
- Arrays and newly created objects cannot be constant values.

**Library rule:** a public `const` value is embedded into compiled callers. Changing it requires rebuilding those callers to use the new value.

## 5. readonly Fields and Initialization Rules

An instance `readonly` field can be assigned in its declaration or in an instance constructor of the declaring type.

```csharp
Student student = new Student("Deep");
Console.WriteLine(student.Name); // Deep

// student.Name = "Asha"; // Invalid outside the allowed initialization code.

class Student
{
    public readonly string Name;

    public Student(string name) // Constructor runs when creating the object.
    {
        Name = name;
    }
}
```

Assignments may occur more than once inside the permitted constructor. `readonly` means assignment is restricted; it does not mean exactly one assignment. An ordinary method cannot assign the field, even when called from the constructor.

**For ordinary local variables, `readonly int total = 10;` is invalid.** The field modifier shown here requires a containing type.

### readonly does not make a referenced object immutable

```csharp
Scores scores = new Scores();
scores.Values[0] = 95;                // Valid: modify the existing array.
Console.WriteLine(scores.Values[0]);  // 95

// scores.Values = new int[2]; // Invalid: replace the readonly field value.

class Scores
{
    public readonly int[] Values = new int[2];
}
```

The array reference cannot be replaced here, but its elements can change.

## 6. const versus readonly versus static readonly

| Feature | const | readonly field | static readonly field |
|---|---|---|---|
| Value determined | Compile time | Can be runtime | Can be runtime |
| Allowed assignments | Declaration only | Declaration or declaring type's instance constructor | Declaration or declaring type's static constructor |
| Belongs to | Local scope or type | Each object | Type |
| Typical access | `Limits.MaxItems` for a member | `settings.UserName` | `Settings.Timeout` |
| Example use | Fixed mathematical/unit value | Value chosen per object | Shared value initialized at runtime |

```csharp
Console.WriteLine(Settings.SecondsPerMinute); // 60
Console.WriteLine(Settings.Timeout.TotalSeconds); // 30

class Settings
{
    public const int SecondsPerMinute = 60;
    public static readonly TimeSpan Timeout;

    static Settings() // Static constructor: no parameters or access modifier.
    {
        Timeout = TimeSpan.FromSeconds(30);
    }
}
```

The static constructor initializes the type once, not once per object. `TimeSpan.FromSeconds(30)` is a runtime method call, so its result cannot be a `const` value. Neither kind of readonly field guarantees that a referenced object is immutable or thread-safe.

## 7. Variable Scope, Lifetime, and Naming Conventions

### Scope — where a name is accessible

```csharp
int total = 10;

if (total > 0)
{
    int bonus = 5;
    total += bonus;
}

Console.WriteLine(total); // 15
// Console.WriteLine(bonus); // Invalid: outside bonus's block.
```

Inner blocks can use accessible outer variables. You cannot redeclare a local with the same name inside its enclosing local scope. A parameter may share a field's name; `this.name` identifies the instance field when needed.

### Lifetime — how long storage is needed

- Ordinary locals are used during a method/block's execution; captured locals can remain alive after the method returns.
- Instance fields live with their object; static fields live with the loaded type.
- Leaving a scope does not immediately destroy referenced objects or force garbage collection.

### Naming conventions

- Locals and parameters: `totalPrice`, `studentName`.
- Private instance fields: `_totalPrice`.
- Public constants and readonly fields: `MaxItems`, `Timeout`.
- Prefer meaningful names; avoid confusing pairs such as `name` and `Name` for two locals.

These are conventions. A project may choose different consistent rules.
