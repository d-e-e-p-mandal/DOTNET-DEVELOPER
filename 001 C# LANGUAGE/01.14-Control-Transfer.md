# 01.14 Control Transfer

## break

`break` exits the nearest enclosing loop or `switch`. Execution continues after that construct.

```csharp
foreach (int value in new[] { 2, 4, 7, 8 })
{
    if (value % 2 != 0)
        break;
    Console.WriteLine(value); // 2, 4
}
Console.WriteLine("Finished");
```

## continue

`continue` skips the rest of the current iteration.

```csharp
for (int i = 1; i <= 4; i++)
{
    if (i == 2)
        continue;
    Console.WriteLine(i); // 1, 3, 4
}
```

- In `for`, control moves to the iterator expression and then the condition.
- In `while`, control moves to the condition.
- In `do–while`, control moves to the final condition.
- In `foreach`, control advances to the next element.

Update state before a possible `continue` when using a manually controlled loop:

```csharp
int i = 0;
while (i < 3)
{
    i++; // Still advances when continue runs.
    if (i == 2) continue;
    Console.WriteLine(i); // 1, 3
}
```

## return

`return` exits the current function. A value-returning function normally uses `return expression;`; a `void` function uses `return;`.

```csharp
Console.WriteLine(FindFirstPositive(new[] { -2, 0, 7, 9 })); // 7

int? FindFirstPositive(int[] values)
{
    foreach (int value in values)
        if (value > 0)
            return value;
    return null; // No matching value.
}
```

Returning from a local function or lambda exits that function, not its caller. A top-level `return;` exits the generated program entry point.

## goto and labels

A label identifies a statement. `goto` transfers control to a valid label in the same function.

```csharp
int[,] cells = { { 1, 2 }, { 3, 9 } };
for (int row = 0; row < 2; row++)
{
    for (int column = 0; column < 2; column++)
    {
        if (cells[row, column] == 9)
            goto Found;
    }
}
Console.WriteLine("Not found");
return;

Found:
Console.WriteLine("Found 9"); // Found 9
```

- A label uses `name:`; a transfer uses `goto name;`.
- You cannot jump into a nested block from outside it or into another function.
- Definite-assignment rules still apply after a jump.
- A small helper function with `return` is often easier to follow than several labels.

## goto case and goto default

These transfers select another section of the same enclosing switch.

```csharp
string command = "save-and-close";
switch (command)
{
    case "save-and-close":
        Console.WriteLine("Saved");
        goto case "close";
    case "close":
        Console.WriteLine("Closed");
        break;
    case "?":
        goto default;
    default:
        Console.WriteLine("Unknown command");
        break;
}
```

Output: `Saved`, then `Closed`. `goto case` targets an appropriate constant case label, not an arbitrary pattern case.

## Nested loops and switches

A `break` inside a switch inside a loop exits only the switch. `continue` still targets the enclosing loop.

```csharp
foreach (int value in new[] { 1, 2, 3 })
{
    switch (value)
    {
        case 1:
            break; // Leave switch, then print 1 below.
        case 2:
            continue; // Skip this loop iteration entirely.
    }
    Console.WriteLine(value); // 1, 3
}
```

To leave several nested loops, return from a helper function, use a carefully controlled flag, or use a clear label.

## Cleanup during control transfer

An executed `finally` block runs when ordinary `return`, `break`, `continue`, or `goto` leaves its associated `try` region.

```csharp
Show();

void Show()
{
    try
    {
        Console.WriteLine("Work");
        return;
    }
    finally
    {
        Console.WriteLine("Cleanup"); // Runs before Show returns.
    }
}
```

This is ordinary control-flow behavior, not a guarantee of cleanup after abrupt process termination.
