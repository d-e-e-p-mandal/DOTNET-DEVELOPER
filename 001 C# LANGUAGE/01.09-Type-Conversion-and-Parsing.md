# 01.09 Type Conversion and Parsing

## 1. Implicit and Explicit Conversions

### Implicit conversion — no cast required

The compiler permits the conversion automatically.

```csharp
byte small = 100;
int count = small;
long large = count;
double measurement = count;
decimal amount = count;

Console.WriteLine(large);                    // 100
Console.WriteLine(measurement.GetType().Name); // Double
Console.WriteLine(amount.GetType().Name);      // Decimal
```

Common examples: `byte → int`, `int → long`, `int → double`, `int → decimal`, and `float → double`.

### Explicit conversion — write a cast

**Syntax:** `(TargetType)expression`

```csharp
long large = 500;
int smaller = (int)large;

double price = 19.95;
int whole = (int)price;

Console.WriteLine(smaller); // 500
Console.WriteLine(whole);   // 19

// int invalid = large; // Compile error without a cast.
```

A cast requests a permitted conversion. It does not guarantee that the value fits or retains its precision.

### Constant conversion versus variable conversion

```csharp
byte first = 200; // Valid: the integer constant fits in byte.

int source = 200;
byte second = checked((byte)source);

Console.WriteLine(second); // 200
// byte invalid = source; // Non-constant int needs an explicit conversion.
```

### Reference conversions

```csharp
string name = "Deep";
object value = name;        // Implicit reference conversion.
string text = (string)value; // Explicit cast; runtime object is a string.

Console.WriteLine(text); // Deep
```

The cast does not create or transform the string object. It checks whether the existing reference can be used as the requested type.

```csharp
object value = 42;

// string wrong = (string)value; // Throws InvalidCastException.
string? text = value as string;  // null when the reference conversion fails.
Console.WriteLine(text is null); // True

if (value is int number)
{
    Console.WriteLine(number); // 42: pattern checks and extracts the value.
}
```

`as` supports reference and nullable value types; it does not parse text or perform numeric conversions.

## 2. Numeric Widening, Narrowing, and Truncation

### Widening does not always preserve every digit

An integer-to-integer widening conversion preserves the number. Conversion to a floating-point type may lose precision even when implicit.

```csharp
long exact = 9_007_199_254_740_993L;
double approximate = exact;

Console.WriteLine((long)approximate);          // 9007199254740992
Console.WriteLine((long)approximate == exact); // False
```

### Narrowing can discard information

```csharp
int source = 300;
byte wrapped = unchecked((byte)source);

Console.WriteLine(wrapped); // 44: only the low 8 bits remain.
```

Unchecked integer narrowing wraps; it does not clamp `300` to `255`. Use a range check or `checked` when overflow should be rejected.

### Fractional values truncate toward zero when cast to integers

```csharp
Console.WriteLine((int)3.9);    // 3
Console.WriteLine((int)(-3.9)); // -3
Console.WriteLine((int)3.9M);   // 3
```

Truncation removes the fractional part. It is different from rounding and from always rounding downward.

```csharp
Console.WriteLine(Math.Truncate(-3.9) == -3.0); // True
Console.WriteLine(Math.Floor(-3.9) == -4.0);    // True
Console.WriteLine(Math.Ceiling(-3.9) == -3.0);  // True
```

### double and decimal require explicit conversion

```csharp
decimal money = 12.5M;
double measurement = (double)money;
decimal restored = (decimal)measurement;

Console.WriteLine(restored == money); // True for this exactly represented value.

// double invalid = money; // No implicit decimal-to-double conversion.
```

This example round-trips exactly; arbitrary decimal values may not. A conversion cannot generally recover digits already lost through earlier arithmetic.

## 3. Cast Expressions and Convert APIs

### Cast versus Convert.ToInt32

```csharp
double value = 2.9;

Console.WriteLine((int)value);          // 2: truncate toward zero.
Console.WriteLine(Convert.ToInt32(value)); // 3: round to nearest integer.
Console.WriteLine(Convert.ToInt32(2.5));   // 2: midpoint rounds to even.
Console.WriteLine(Convert.ToInt32(3.5));   // 4: midpoint rounds to even.
Console.WriteLine(Convert.ToInt32(-2.5));  // -2: midpoint rounds to even.
```

To request a different midpoint rule:

```csharp
double rounded = Math.Round(2.5, MidpointRounding.AwayFromZero);
Console.WriteLine(checked((int)rounded)); // 3
```

### Convert uses the input type's conversion rules

```csharp
Console.WriteLine(Convert.ToInt32("42")); // 42: parse text.
Console.WriteLine(Convert.ToInt32(true)); // 1
Console.WriteLine(Convert.ToBoolean(0));  // False
Console.WriteLine(Convert.ToBoolean(5));  // True

// int invalid = (int)"42"; // Compile error: a cast cannot parse a string.
// int wrong = Convert.ToInt32("2.9"); // FormatException, not numeric rounding.
```

The numeric overload can round `2.9`; the string overload expects integer text. Overload selection matters.

### Null input can become zero

```csharp
string? input = null;
Console.WriteLine(Convert.ToInt32(input)); // 0
```

Do not use this behavior to validate required input: missing input and the number zero would become indistinguishable.

### Boxed number: unboxing versus conversion

```csharp
object boxed = 42; // A boxed int.

// long wrong = (long)boxed; // InvalidCastException: not a boxed long.
long first = (int)boxed;      // Unbox int, then widen to long.
long second = Convert.ToInt64(boxed); // Convert the boxed numeric value.

Console.WriteLine(first == second); // True
```

### Character code versus numeric text

```csharp
Console.WriteLine((int)'7');             // 55: UTF-16 code unit value.
Console.WriteLine(Convert.ToInt32('7')); // 55
Console.WriteLine(int.Parse("7"));      // 7: parse the numeric text.
```

### Parse text written in a specific base

```csharp
Console.WriteLine(Convert.ToInt32("101010", 2)); // 42
Console.WriteLine(Convert.ToInt32("2A", 16));    // 42
```

The base overload accepts bases 2, 8, 10, and 16. Invalid digits or out-of-range input can throw.

## 4. Parse and TryParse

### Parse — return a value or throw

```csharp
int count = int.Parse("42");
int signed = int.Parse("  +42  ");
bool active = bool.Parse("TRUE");

Console.WriteLine(count);  // 42
Console.WriteLine(signed); // 42
Console.WriteLine(active); // True
```

Default integer parsing permits surrounding whitespace and a leading sign. It does not accept a decimal point, group separator, exponent, or C# literal suffix.

```csharp
// int.Parse("abc");        // FormatException.
// int.Parse("3.5");        // FormatException with default integer parsing.
// int.Parse("2147483648"); // OverflowException: outside int's range.
// int.Parse(null);         // ArgumentNullException.
```

### TryParse — check success before using the result

```csharp
string input = "42";

if (int.TryParse(input, out int count))
{
    Console.WriteLine(count); // 42
}
else
{
    Console.WriteLine("Invalid whole number");
}
```

`out int count` declares the result variable and lets the method assign it. The Boolean return value tells you whether parsing succeeded.

```csharp
bool valid = int.TryParse("wrong", out int result);

Console.WriteLine(valid);  // False
Console.WriteLine(result); // 0: failure result, not proof that input was zero.
Console.WriteLine(int.TryParse("0", out _)); // True: zero is valid input.
Console.WriteLine(int.TryParse((string?)null, out _)); // False
Console.WriteLine(int.TryParse("2147483648", out _));  // False
```

`_` discards an output you do not need. Invalid numeric text, null, and integer overflow return `false`; invalid API options can still throw exceptions.

### Source-code literals are not parsing syntax

```csharp
Console.WriteLine(int.TryParse("1_000", out _)); // False
Console.WriteLine(int.TryParse("42U", out _));   // False
Console.WriteLine(int.TryParse("0x2A", out _));  // False
Console.WriteLine(bool.TryParse("1", out _));   // False
```

Underscores and suffixes belong to C# source syntax. Select an appropriate base or parsing style for text from another format.

## 5. Culture-Aware and Invariant Parsing

### Culture determines separators

```csharp
using System.Globalization;

decimal first = decimal.Parse("1,234.56", CultureInfo.GetCultureInfo("en-US"));
decimal second = decimal.Parse("1.234,56", CultureInfo.GetCultureInfo("de-DE"));

Console.WriteLine(first == second);   // True
Console.WriteLine(first == 1234.56M); // True
```

In these formats, `en-US` uses a decimal point; `de-DE` uses a decimal comma. Without a provider, parsing normally uses the current culture.

Use the expected user's culture for user-entered numbers. Use the format specified by a file or protocol for machine data.

### Invariant parsing and formatting

```csharp
using System.Globalization;

decimal amount = decimal.Parse("1234.56", CultureInfo.InvariantCulture);
string text = amount.ToString(CultureInfo.InvariantCulture);

Console.WriteLine(text); // 1234.56, independent of the current culture.
```

Invariant culture gives stable formatting conventions; it does not automatically enforce a strict input grammar.

### NumberStyles selects allowed input features

| Style | Main accepted features |
|---|---|
| `Integer` | Leading/trailing whitespace and a leading sign |
| `Number` | Signs, whitespace, decimal point, and group separators |
| `Float` | Leading sign, whitespace, decimal point, and exponent |
| `HexNumber` | Hexadecimal digits and surrounding whitespace |

```csharp
using System.Globalization;

int grouped = int.Parse("1,234", NumberStyles.AllowThousands,
    CultureInfo.InvariantCulture);
int hex = int.Parse("2A", NumberStyles.HexNumber,
    CultureInfo.InvariantCulture);
double scientific = double.Parse("1.25e2", NumberStyles.Float,
    CultureInfo.InvariantCulture);

Console.WriteLine(grouped); // 1234
Console.WriteLine(hex);     // 42: do not include 0x with HexNumber.
Console.WriteLine(scientific == 125.0); // True
```

### Reject unwanted separators

```csharp
using System.Globalization;

NumberStyles style = NumberStyles.AllowLeadingSign | NumberStyles.AllowDecimalPoint;

Console.WriteLine(decimal.TryParse("12.50", style,
    CultureInfo.InvariantCulture, out _)); // True

Console.WriteLine(decimal.TryParse("12,50", style,
    CultureInfo.InvariantCulture, out _)); // False
```

This style excludes grouping and whitespace. Do not blindly remove commas or dots: a separator may represent a decimal point in the input's culture.

## 6. checked and unchecked

### Checked conversion rejects integer overflow

```csharp
int source = 300;

try
{
    byte value = checked((byte)source);
    Console.WriteLine(value);
}
catch (OverflowException)
{
    Console.WriteLine("Outside byte range");
}
```

**Output:** `Outside byte range`

### Unchecked integer conversion keeps the low bits

```csharp
int source = 300;
byte value = unchecked((byte)source);
Console.WriteLine(value); // 44
```

### Checked arithmetic block

```csharp
int quantity = 50_000;
int price = 50_000;

try
{
    checked
    {
        int total = quantity * price;
        Console.WriteLine(total);
    }
}
catch (OverflowException)
{
    Console.WriteLine("Total exceeds int range");
}
```

**Output:** `Total exceeds int range`

- `checked` affects operations written inside its scope, not automatically operations inside called methods.
- It does not prevent floating-point precision loss or change truncation into rounding.
- Decimal-to-integer overflow throws even inside `unchecked`.
- `Convert.ToInt32` performs its own range checks; `unchecked` does not disable them.
- Out-of-range, NaN, or infinite floating-point values should not be converted using an unchecked integer cast when a dependable result is required.

## 7. Conversion Failures and Safe Input Handling

### Common failures

| Failure | Example | Better handling |
|---|---|---|
| `FormatException` | `int.Parse("abc")` | Use `TryParse` for expected bad input |
| `OverflowException` | `checked((byte)source)` when `source` is 300 | Validate range or catch a specific overflow |
| `InvalidCastException` | Unbox a boxed `int` as `long` | Unbox the actual type, then convert |
| `ArgumentNullException` | `int.Parse` receives null | Check input or use `TryParse` |
| Valid conversion, wrong business value | Quantity `-5` parses successfully | Validate application rules after parsing |

For a constant expression such as `checked((byte)300)` written directly in code, overflow is a compile-time error. With a runtime variable, it throws during execution.

### Floating-point parsing can succeed with infinity or NaN

```csharp
using System.Globalization;

bool parsed = double.TryParse("1e9999", NumberStyles.Float,
    CultureInfo.InvariantCulture, out double value);

Console.WriteLine(parsed);                    // True in modern .NET.
Console.WriteLine(double.IsInfinity(value));  // True
Console.WriteLine(parsed && double.IsFinite(value)); // False
```

When the application requires a finite number, also check `double.IsFinite` or `float.IsFinite`. This rejects both infinity and NaN.

### Validate format, then the allowed range

```csharp
using System.Globalization;

Console.Write("Quantity (1-100): ");
string? input = Console.ReadLine();

if (!int.TryParse(input, NumberStyles.Integer,
    CultureInfo.InvariantCulture, out int quantity))
{
    Console.WriteLine("Enter a valid whole number.");
    return;
}

if (quantity < 1 || quantity > 100)
{
    Console.WriteLine("Quantity must be between 1 and 100.");
    return;
}

Console.WriteLine($"Accepted: {quantity}");
```

- Input `25` → `Accepted: 25`.
- Input `abc`, blank input, or an integer outside `int`'s range → `Enter a valid whole number.`
- Input `0`, `-5`, or `101` → `Quantity must be between 1 and 100.`

Never treat a failed parse as a valid zero just because the output variable contains zero.
