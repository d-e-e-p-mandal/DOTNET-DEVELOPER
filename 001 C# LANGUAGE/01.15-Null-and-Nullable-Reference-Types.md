# 01.15 Null and Nullable Reference Types

## Meaning of null

`null` means a reference does not identify an object. It differs from an empty string, zero, or an empty collection.

```csharp
string? missing = null;
string empty = "";
Console.WriteLine(missing is null); // True
Console.WriteLine(empty.Length);    // 0
```

Dereferencing null throws `NullReferenceException`.

## Nullable contexts and compiler analysis

Enable nullable annotations and warnings in a project:

```xml
<PropertyGroup>
  <Nullable>enable</Nullable>
</PropertyGroup>
```

Or enable them for a source-file region:

```csharp
#nullable enable
string? name = null;
// Console.WriteLine(name.Length); // Nullable dereference warning; unsafe at runtime.
Console.WriteLine(name?.Length); // Blank line: nullable result is null.
```

`#nullable disable` disables the context; `#nullable restore` restores the project setting. Warnings identify possible problems but do not insert runtime null checks.

## string versus string?

- `string`: declares that code expects a non-null reference.
- `string?`: declares that null is an allowed state.
- Both use the same runtime `System.String` type.
- A non-nullable annotation is a compiler contract, not a runtime guarantee against null from unchecked code, reflection, or deserialization.

```csharp
string? optional = GetName();
string required = optional ?? "Guest";
Console.WriteLine(required); // Guest

string? GetName() => null;
```

## Null checks and flow analysis

```csharp
string? name = "Deep";
if (name is not null)
{
    Console.WriteLine(name.Length); // 4: the compiler recognizes the check.
}

if (string.IsNullOrWhiteSpace(name))
    Console.WriteLine("Missing name");
else
    Console.WriteLine(name.Trim()); // Deep
```

`is null` and `is not null` avoid user-defined equality operators. `IsNullOrEmpty` accepts null or `""`; `IsNullOrWhiteSpace` also accepts whitespace-only text.

## Null-conditional access: ?. and ?[]

```csharp
string? name = null;
int? length = name?.Length;
Console.WriteLine(length is null); // True

int[]? values = null;
int? first = values?[0];
Console.WriteLine(first is null); // True
```

- The access is skipped when its receiver is null.
- A value-type result such as `int` becomes nullable, such as `int?`.
- `values?[0]` still throws for a non-null empty array. It checks null, not index validity.
- For multiple nullable receivers, use an appropriate check at each level.
- Parentheses can interrupt a conditional-access chain: `(person?.Address).Street` is not a safe substitute for `person?.Address?.Street`.

## Null-coalescing operators: ?? and ??=

```csharp
string? name = null;
string display = name ?? "Guest"; // Fallback; does not change name.
Console.WriteLine(display); // Guest
Console.WriteLine(name is null); // True

name ??= "Guest"; // Assign only when the variable currently holds null.
Console.WriteLine(name); // Guest
```

The right operand is evaluated only when needed. Empty strings do not activate a null fallback.

## Null-forgiving operator: !

`!` after an expression suppresses a nullable warning for that expression. It does not check, convert, or repair the value.

```csharp
string? value = "known";
Console.WriteLine(value!.Length); // 5

// string? missing = null;
// Console.WriteLine(missing!.Length); // Compiles, but throws at runtime.
```

Prefer a real check when null is possible. Suppression is appropriate only when an external guarantee is genuinely established.

## API null contracts

Reject null at a public boundary when it is not valid input.

```csharp
Console.WriteLine(Normalize("  Deep  ")); // Deep

string Normalize(string value)
{
    ArgumentNullException.ThrowIfNull(value);
    return value.Trim();
}
```

Use annotations to describe validation helpers without forcing callers to use `!`:

```csharp
using System.Diagnostics.CodeAnalysis;

string? name = "Deep";
if (HasText(name))
    Console.WriteLine(name.Length); // 4

bool HasText([NotNullWhen(true)] string? value)
    => !string.IsNullOrWhiteSpace(value);
```

`[NotNullWhen(true)]` describes the contract to the compiler. The implementation must actually honor it.
