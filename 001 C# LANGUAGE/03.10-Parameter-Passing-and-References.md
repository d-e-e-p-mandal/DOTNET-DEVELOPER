# 03.10 Parameter Passing and References

## Pass-by-value for values and object references

Parameters are passed by value unless declared otherwise. For a class argument, the copied value is an object reference.

```csharp
var box = new Box { Value = 1 };
Change(box);
Console.WriteLine(box.Value); // 2: shared object's state changed.

void Change(Box item)
{
    item.Value = 2;
    item = new Box { Value = 99 }; // Reassigns only the parameter copy.
}
class Box { public int Value; }
```

## ref parameters

`ref` aliases the caller's variable. The caller must initialize it before the call, and both declaration and call normally use `ref`.

```csharp
int count = 3;
Double(ref count);
Console.WriteLine(count); // 6

void Double(ref int value) => value *= 2;
```

For a reference-type variable, `ref` also permits replacing which object the caller's variable references.

## out parameters

`out` supplies an output variable. The called method must definitely assign it before returning normally.

```csharp
Split(17, 5, out int quotient, out int remainder);
Console.WriteLine($"{quotient}, {remainder}"); // 3, 2

void Split(int value, int divisor, out int quotient, out int remainder)
{
    quotient = value / divisor;
    remainder = value % divisor;
}
```

An `out` argument need not be initialized beforehand. Use `out _` when intentionally ignoring a result.

## in and ref readonly parameters

`in` provides a readonly reference view. It prevents assigning to the parameter variable; it does not make a referenced object's internal state immutable.

```csharp
var point = new Point(3, 4);
Console.WriteLine(Sum(in point)); // 7
Console.WriteLine(Read(ref point)); // 3

int Sum(in Point value) => value.X + value.Y;
int Read(ref readonly Point value) => value.X;
readonly record struct Point(int X, int Y);
```

`ref readonly` parameters are available from C# 12 and express a stronger preference for a variable passed by reference. `in` arguments can also be omitted at many call sites, allowing compiler-created temporaries. Defensive copies can occur when non-readonly struct members are called through readonly receivers.

## ref locals and returns

```csharp
int[] values = { 10, 20 };
ref int selected = ref Element(values, 1);
selected = 99;
Console.WriteLine(values[1]); // 99

ref int Element(int[] array, int index) => ref array[index];
```

A ref local aliases storage instead of copying its current value. A readonly ref return allows reading through the alias without assignment through it.

## Aliasing and lifetime restrictions

- Two references can identify the same storage, so writes can be visible through both.
- A ref return cannot expose an ordinary local whose storage would no longer be valid.
- Ordinary properties cannot be passed as writable `ref` arguments unless they specifically return by ref.
- Async and iterator methods cannot use ordinary ref, in, or out parameters.
- Reference safety rules prevent escaping aliases beyond their valid lifetime.
- Passing a small struct by reference is not automatically faster; measure actual copy costs and defensive-copy behavior.
