# 02.07 Inheritance

## Base and derived classes

Inheritance creates a type that extends an existing class. A class has at most one direct base class but may implement several interfaces.

```csharp
var employee = new Employee("Deep", "Engineering");
Console.WriteLine(employee.Name); // Deep
Console.WriteLine(employee.Department); // Engineering

class Person
{
    public string Name { get; }
    public Person(string name) => Name = name;
}
class Employee : Person
{
    public string Department { get; }
    public Employee(string name, string department) : base(name)
        => Department = department;
}
```

## Accessible inherited members

Public members can be used through suitable references. Protected members are available to derived implementation code under protected-access rules. Private base state still exists in the object but cannot be accessed directly by derived code.

Constructors are not inherited; derived constructors initialize their own type and select a base constructor.

## this and base

`this` refers to the current object. `base` accesses a base implementation or selects a base constructor.

```csharp
new Child().Print(); // Base, then Child

class Parent
{
    public virtual void Print() => Console.WriteLine("Base");
}
class Child : Parent
{
    public override void Print()
    {
        base.Print(); // Invoke the base implementation explicitly.
        Console.WriteLine("Child");
    }
}
```

`base` is not a separate parent object. The same instance contains base-class and derived-class state.

## Constructor execution across a hierarchy

The base constructor body runs before the derived constructor body. A derived constructor must select an accessible base constructor; implicit `base()` fails when the base has no accessible parameterless constructor.

Avoid virtual calls in base constructors: an override can execute before the derived constructor body establishes its state.

## Upcasting and downcasting

```csharp
Animal animal = new Dog(); // Implicit upcast: same object, broader reference type.
if (animal is Dog dog)
    dog.Fetch(); // Fetching

Animal other = new Animal();
Dog? missing = other as Dog; // Null instead of a failed-cast exception.
Console.WriteLine(missing is null); // True
// Dog wrong = (Dog)other; // InvalidCastException.

class Animal { }
class Dog : Animal
{
    public void Fetch() => Console.WriteLine("Fetching");
}
```

Casting does not transform an `Animal` instance into a `Dog`; a successful downcast reveals an already compatible runtime object.

## Inheritance versus composition

Use inheritance for a stable “is a” relationship with substitutable behavior. Use composition when an object “has a” capability or collaborator.

```csharp
new Car(new Engine()).Start(); // Engine started

class Engine
{
    public void Start() => Console.WriteLine("Engine started");
}
class Car
{
    private readonly Engine _engine;
    public Car(Engine engine) => _engine = engine;
    public void Start() => _engine.Start();
}
```

A car contains an engine; making `Car : Engine` would expose the wrong relationship. Composition also makes independently replaceable capabilities easier to model.
