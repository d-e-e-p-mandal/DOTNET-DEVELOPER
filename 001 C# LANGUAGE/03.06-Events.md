# 03.06 Events

## Publisher and subscriber

An event lets an object publish notifications while controlling who may raise them.

```csharp
var counter = new Counter();
counter.Changed += OnChanged;
counter.Increment(); // Value: 1
counter.Changed -= OnChanged;
counter.Increment(); // No subscriber output.

void OnChanged(object? sender, EventArgs args)
    => Console.WriteLine($"Value: {((Counter)sender!).Value}");

class Counter
{
    public event EventHandler? Changed;
    public int Value { get; private set; }
    public void Increment()
    {
        Value++;
        Changed?.Invoke(this, EventArgs.Empty);
    }
}
```

## event versus a delegate field

External consumers can subscribe with `+=` and unsubscribe with `-=`. They cannot normally replace the entire invocation list or invoke a field-like event directly.

A public delegate field would allow those operations, exposing the publisher's notification machinery to callers.

## EventHandler and typed event data

```csharp
var sensor = new Sensor();
sensor.Measured += (_, args) => Console.WriteLine(args.Value); // 25
sensor.Measure(25);

class MeasurementArgs : EventArgs
{
    public int Value { get; }
    public MeasurementArgs(int value) => Value = value;
}
class Sensor
{
    public event EventHandler<MeasurementArgs>? Measured;
    public void Measure(int value) => Measured?.Invoke(this, new MeasurementArgs(value));
}
```

`sender` identifies the publisher; event data describes the occurrence. Use immutable event data when subscribers should not alter what other subscribers observe.

## Subscribing, unsubscribing, and raising

Keep a named method or stored delegate for later removal. Rewriting an equivalent-looking lambda in `-=` does not reliably remove the originally subscribed handler.

Invoke after state changes are consistent. A handler runs synchronously unless explicitly arranged otherwise, and a thrown exception can prevent subsequent handlers from running.

## Custom event accessors

Custom `add` and `remove` bodies control subscription storage or forwarding. They must implement the intended subscription semantics themselves.

```csharp
var source = new Source();
EventHandler handler = (_, _) => Console.WriteLine("Raised");
source.Changed += handler;
source.Raise(); // Raised
source.Changed -= handler;

class Source
{
    private EventHandler? _handlers;
    public event EventHandler Changed
    {
        add => _handlers += value;
        remove => _handlers -= value;
    }
    public void Raise() => _handlers?.Invoke(this, EventArgs.Empty);
}
```

These simple custom accessors do not add synchronization for concurrent subscription changes.

## Subscriber lifetime

A publisher normally retains delegate references, and delegates retain their instance targets. A long-lived publisher can therefore keep a short-lived subscriber alive. Unsubscribe when the subscription's owner finishes; disposal is a useful boundary. Avoid `async void` event handlers except where the event signature requires them, and handle their exceptions deliberately.
