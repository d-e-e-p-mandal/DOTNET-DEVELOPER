# 01.04 Tokens and Lexical Elements

A **token** is a meaningful piece of source code, such as a keyword, name, literal, or operator.

```csharp
int age = 20;
```

Tokens: `int` → keyword, `age` → identifier, `=` → operator, `20` → literal, `;` → punctuation.

**Try examples separately in Program.cs** in a .NET 10 console project with implicit usings enabled. Run with `dotnet run`. Commented-out incorrect lines are for explanation.

## 1. Keywords and Contextual Keywords

**Keywords** have a predefined language meaning. Examples: `int`, `class`, `if`, `return`, `namespace`.

```csharp
int age = 20;

if (age >= 18)
{
    Console.WriteLine("Adult");
}
```

**Output:** `Adult`

**Contextual keywords** have special meaning only in certain contexts. Examples: `var`, `record`, `async`, `await`, `required`.

```csharp
var score = 90; // var asks the compiler to infer the type: int.
int record = 1; // record is allowed as an identifier here.
Console.WriteLine(score + record);
```

**Output:** `91`

Reserved keywords cannot be ordinary identifiers: `int class = 1;` is invalid. Use `@class` when necessary.

## 2. Identifiers and Naming Rules

An **identifier** is a name you give a variable, type, method, or other program element.

- Start with a letter or `_`; later characters may include digits. C# also supports specific Unicode character categories.
- Do not include spaces or hyphens.
- Names are case-sensitive.
- Escape reserved keywords with `@`, or choose a clearer name.

```csharp
int studentAge = 20;
int marks2 = 85;
int _count = 3;

// int 2marks = 85;       // Invalid: starts with a digit.
// int student age = 20; // Invalid: contains a space.
// int student-age = 20; // Invalid: hyphen is not part of an identifier.

Console.WriteLine(studentAge); // 20
```

**Naming conventions:** `camelCase` for locals and parameters (`studentAge`); `PascalCase` for types, methods, and properties (`Student`, `CalculateTotal`, `Name`). These are conventions, not compiler requirements.

## 3. Literals, Operators, and Punctuation

### Literals — values written directly

```csharp
int count = 42;                  // Decimal integer.
int hex = 0x2A;                  // Hexadecimal: also 42.
int binary = 0b101010;           // Binary: also 42.
long population = 8_000_000_000L; // L means long; _ separates digits.
double price = 12.5;             // double by default.
float ratio = 0.5f;              // f means float.
decimal money = 19.99m;          // m means decimal.
char grade = 'A';                // One char value in single quotes.
string name = "Deep";            // Text in double quotes.
bool active = true;              // true or false.
string? missing = null;          // No string object.
```

`42` is a number, `"42"` is text, and `'4'` is a character. They are different types.

### Operators — perform operations

```csharp
int total = 10 + 5;            // = assigns; + adds.
bool passed = total >= 10;     // >= compares.
bool allowed = passed && true; // && means logical AND.
Console.WriteLine(allowed);
```

**Output:** `True`

Common operators: arithmetic `+ - * / %`, comparison `== != < > <= >=`, logical `&& || !`, assignment `= += -=`.

**Remember:** `=` assigns; `==` compares equality.

### Punctuation — organizes code

```csharp
int[] marks = { 70, 90 };     // []: array; {}: initializer; comma: separator.
Console.WriteLine(marks[0]); // Dot: member access; (): call; []: index.
```

**Output:** `70`

`;` ends a statement. Braces also delimit class, method, and control-flow bodies. Some symbols have different roles depending on context.

## 4. Whitespace and Case Sensitivity

Spaces, tabs, and line breaks usually separate or format code. They can be required to keep tokens separate: `int age` and `intage` are different.

```csharp
int first = 2 + 3;
int second=2+3;
Console.WriteLine(first == second); // True
```

Spaces inside a string are data: `"A B"` differs from `"AB"`.

```csharp
string name = "Deep";
string Name = "Mandal"; // Different identifier; avoid confusing names.
Console.WriteLine(name + " " + Name);
```

**Output:** `Deep Mandal`

`Console.WriteLine` must use the correct capitalization; `console.writeline` is not the same name.

## 5. Escaped Identifiers Using @

Prefix an identifier with `@` to use a reserved keyword as a name.

```csharp
string @class = "C#";
int @score = 90;

Console.WriteLine(@class); // C#
Console.WriteLine(score);  // 90: score and @score are the same name.
```

`@` is not part of the identifier's actual name. Prefer descriptive names such as `className` unless escaping is needed.

**Different use of @ — verbatim strings:**

```csharp
string path = @"C:\Notes\CSharp"; // Backslashes are literal characters.
Console.WriteLine(path);
```

**Output:** `C:\Notes\CSharp`

`@class` escapes a name; `@"..."` changes string-literal syntax. In an ordinary string, use `"C:\\Notes\\CSharp"` for the same path.

## 6. Single-Line, Block, and XML Documentation Comments

### Single-line and block comments

```csharp
// This comment continues to the end of the line.
int total = 10; // A comment can follow code.

/* This comment
   spans multiple lines. */

Console.WriteLine(total); // Output: 10.
```

Comments explain code and do not execute. Block comments cannot be nested. Comment markers inside strings, such as `"// text"`, are ordinary text.

### XML documentation comments

Use `///` immediately before a type or member declaration. Editors can display the documentation when that member is used.

**Complete Program.cs:**

```csharp
Console.WriteLine(Calculator.Square(4)); // Output: 16.

static class Calculator
{
    /// <summary>Returns the square of a number.</summary>
    /// <param name="value">The number to square.</param>
    /// <returns>The number multiplied by itself.</returns>
    public static int Square(int value)
    {
        return value * value;
    }
}
```

The class is included here so the documentation has a method declaration to describe.

To generate an XML documentation file during build:

```bash
dotnet build -p:GenerateDocumentationFile=true
```

## 7. Preprocessor Directives

Directives begin with `#` on their own lines and do not end with semicolons. They control compilation or editor behavior.

### #define and #if — conditional compilation

```csharp
#define DEMO

#if DEMO
Console.WriteLine("Demo build");
#elif DEBUG
Console.WriteLine("Debug build");
#else
Console.WriteLine("Other build");
#endif
```

**Output:** `Demo build`

- `#define DEMO` defines a symbol for this file; place it before source-code tokens such as `using` or statements.
- `#if`, `#elif`, and `#else` select code to compile; `#endif` closes the selection.
- A symbol has no assigned numeric value. `#define LIMIT 10` is invalid C#.
- Ordinary `if` checks a condition during execution; `#if` selects code during compilation.

### #region — editor folding

```csharp
#region Greeting
Console.WriteLine("Hello");
#endregion
```

**Output:** `Hello`

The region groups code for folding in supporting editors. It does not create a variable scope or change execution.

### #nullable — nullable reference analysis

```csharp
#nullable enable

string? name = null; // ? marks a reference that may be null.
Console.WriteLine(name ?? "Guest"); // Use a fallback for null.

// Console.WriteLine(name.Length); // Would warn about dereferencing null.

#nullable restore
```

**Output:** `Guest`

`enable` turns on nullable annotations and warnings; `disable` turns them off; `restore` returns to project settings. The setting applies to following code in the file until changed or the file ends. It does not make null access safe at runtime.
