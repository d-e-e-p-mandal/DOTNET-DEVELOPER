# 01.10 Operators and Expressions

## 1. Arithmetic: +, -, *, /, %

An **operator** performs an operation. Its inputs are **operands**. An **expression** combines values, variables, calls, and operators to perform a computation.

```csharp
int first = 10;
int second = 3;

Console.WriteLine(first + second); // 13: addition.
Console.WriteLine(first - second); // 7: subtraction.
Console.WriteLine(first * second); // 30: multiplication.
Console.WriteLine(first / second); // 3: integer division.
Console.WriteLine(first % second); // 1: remainder.
```

`first + second` produces a value. A `void` method call such as `Console.WriteLine(...)` is also an expression, but does not produce a result value.

### Integer versus fractional division

```csharp
Console.WriteLine(7 / 2);          // 3
Console.WriteLine(-7 / 2);         // -3: truncate toward zero.
Console.WriteLine(7D / 2 == 3.5);  // True
Console.WriteLine(7M / 2 == 3.5M); // True

double wrong = 7 / 2;
Console.WriteLine(wrong == 3.0); // True: int division happened first.
```

The operand types determine the arithmetic. Assigning the result to `double` afterward does not restore a discarded fraction.

### Remainder, not percentage

```csharp
Console.WriteLine(7 % 3);   // 1
Console.WriteLine(-7 % 3);  // -1
Console.WriteLine(7 % -3);  // 1
Console.WriteLine(8 % 2 == 0); // True: even number.
```

A nonzero finite remainder has the sign of the left operand. `%` is not a percentage calculation or a power operator.

```csharp
decimal price = 200M;
decimal discount = price * 15M / 100M;
Console.WriteLine(discount); // 30: fifteen percent.
```

### Unary plus and minus

```csharp
int number = 5;
Console.WriteLine(+number); // 5
Console.WriteLine(-number); // -5
Console.WriteLine(number);  // 5: unary minus did not assign a new value.
```

### Addition versus string concatenation

```csharp
Console.WriteLine(1 + 2 + " items"); // 3 items
Console.WriteLine("Items: " + 1 + 2); // Items: 12
Console.WriteLine("Items: " + (1 + 2)); // Items: 3
```

### Arithmetic failure rules

- Integer and decimal division by zero throw during execution; constant integer division by zero is a compile-time error.
- `float` and `double` can produce infinity or NaN instead.
- Integer addition and multiplication overflow depend on the checked context. Decimal overflow throws.
- Signed integer minimum divided by `-1` can throw overflow even in `unchecked` code.
- Arithmetic on `byte`, `sbyte`, `short`, and `ushort` generally promotes operands to `int`.

## 2. Assignment and Compound Assignment

### Simple assignment

```csharp
int total = 10; // Declare and initialize.
total = 20;     // Replace the stored value.
Console.WriteLine(total); // 20
```

`=` assigns; `==` compares equality. The left side must identify assignable storage, such as a variable, writable property, or array element.

### Arithmetic compound assignments

```csharp
int total = 10;
total += 5; // 15
total -= 3; // 12
total *= 2; // 24
total /= 5; // 4: still integer division.
total %= 3; // 1

Console.WriteLine(total); // 1
```

For built-in numeric variables, `x += y` behaves like adding and assigning back to `x`. Important differences are conversion back to the left-hand type and evaluating the target only once.

### Compound assignment can convert back to the target type

```csharp
byte count = 10;
count += 5;
Console.WriteLine(count); // 15

// count = count + 5; // Compile error: byte + int produces int.

byte large = 250;
unchecked
{
    large += 10;
}
Console.WriteLine(large); // 4: byte overflow wrapped.
```

Compound assignment is not automatically overflow-safe; `checked` would reject the overflowing operation.

### The target expression runs once

```csharp
int[] values = { 10, 20 };
int index = 0;

values[index++] += 5;

Console.WriteLine(values[0]); // 15
Console.WriteLine(index);     // 1
```

Do not rewrite this as `values[index++] = values[index++] + 5`; that evaluates `index++` twice and changes the behavior.

### Other compound forms

Bitwise and shift assignments: `&=`, `|=`, `^=`, `<<=`, `>>=`, `>>>=`.

`??=` assigns only when the current value is null:

```csharp
string? name = null;
name ??= "Guest";
name ??= "Replacement";

Console.WriteLine(name); // Guest
```

Its right side is evaluated only when assignment is needed. An empty string is not null. C# has no `&&=` or `||=` operators; Boolean `&=` and `|=` evaluate the right operand.

### Null-conditional assignment — C# 14

```csharp
int[]? scores = new int[] { 10 };

// Traditional form:
if (scores is not null)
{
    scores[0] += 5;
}

// C# 14 form: another addition of 5.
scores?[0] += 5;
Console.WriteLine(scores?[0]); // 20

scores = null;
scores?[0] = 99; // Skipped when scores is null.
```

With null-conditional assignment, a null receiver skips the assignment and the right-hand expression. Custom types can also define compound-assignment operator overloads in C# 14; the numeric examples above describe built-in behavior.

## 3. Prefix and Postfix Increment / Decrement

`++` adds one; `--` subtracts one. **Prefix** produces the updated value. **Postfix** produces the old value while updating the variable.

```csharp
int number = 5;

Console.WriteLine(++number); // 6: increase, then produce the value.
Console.WriteLine(number++); // 6: produce the old value, then retain 7.
Console.WriteLine(number);   // 7

Console.WriteLine(--number); // 6
Console.WriteLine(number--); // 6: old value; variable becomes 5.
Console.WriteLine(number);   // 5
```

### Assignment with increment

```csharp
int first = 10;
int oldValue = first++;

int second = 10;
int newValue = ++second;

Console.WriteLine($"{first}, {oldValue}"); // 11, 10
Console.WriteLine($"{second}, {newValue}"); // 11, 11
```

- As standalone statements, `number++;` and `++number;` leave the same final value.
- They require an assignable operand: `5++`, `(number + 1)++`, and incrementing a constant are invalid.
- Integer overflow checking also applies to increment/decrement.
- Increment is not inherently atomic for shared variables.
- Avoid assigning the old result back, as in `number = number++`; this defeats the increment's final effect.

## 4. Equality and Relational Operators

```csharp
int first = 10;
int second = 20;

Console.WriteLine(first == second); // False: equal.
Console.WriteLine(first != second); // True: not equal.
Console.WriteLine(first < second);  // True: less than.
Console.WriteLine(first > second);  // False: greater than.
Console.WriteLine(first <= 10);     // True: less than or equal.
Console.WriteLine(second >= 20);    // True: greater than or equal.
```

### Range checks need two comparisons

```csharp
int age = 20;
bool allowed = age >= 18 && age <= 65;
Console.WriteLine(allowed); // True

// bool wrong = 18 <= age <= 65; // Invalid: the first comparison produces bool.
```

### Equality depends on the operand types

```csharp
Console.WriteLine("C#" == "C#"); // True: string content.
Console.WriteLine("C#" == "c#"); // False: different case.

int[] first = { 1 };
int[] second = { 1 };
int[] same = first;

Console.WriteLine(first == second); // False: different arrays.
Console.WriteLine(first == same);   // True: same array.
```

Ordinary classes normally use reference equality with `==`, unless overloaded. Strings and record classes provide value-based equality. User-defined operators can customize behavior.

### Floating-point and nullable comparisons

```csharp
double invalid = double.NaN;
Console.WriteLine(invalid == 0); // False
Console.WriteLine(invalid < 0);  // False
Console.WriteLine(invalid != 0); // True

int? missing = null;
Console.WriteLine(missing == null); // True
Console.WriteLine(missing > 0);     // False
Console.WriteLine(missing <= 0);    // False
```

Use `IsNaN` to detect NaN. A nullable relational comparison with null is false; its opposite comparison is not necessarily true.

## 5. Boolean Logic and Short-Circuit Evaluation

| A | B | `A && B` | `A \|\| B` | `A ^ B` |
|---|---|---|---|---|
| false | false | false | false | false |
| false | true | false | true | true |
| true | false | false | true | true |
| true | true | true | true | false |

- `!A`: NOT; reverses a Boolean value.
- `&&`: AND; evaluates the right side only when the left side is true.
- `||`: OR; evaluates the right side only when the left side is false.
- Boolean `&` and `|`: same AND/OR truth results, but evaluate both sides.
- Boolean `^`: XOR; true when the values differ; evaluates both sides.

### Observe short-circuiting

```csharp
int calls = 0;
bool off = false;
bool on = true;

bool first = off && Probe();
bool second = on || Probe();
Console.WriteLine(calls); // 0: neither call was needed.

bool third = off & Probe();
bool fourth = on | Probe();
Console.WriteLine(calls); // 2: both calls ran.

bool Probe()
{
    calls++;
    return true;
}
```

### Guard an operation

```csharp
int divisor = 0;
bool valid = divisor != 0 && 10 / divisor > 1;
Console.WriteLine(valid); // False: division was skipped.

string? text = null;
bool hasText = text is not null && text.Length > 0;
Console.WriteLine(hasText); // False: Length was not accessed.
```

Replacing `&&` with `&` removes the protection. Do not put an operation that must always execute on the right side of a short-circuit operator.

### Nullable Boolean logic

```csharp
bool? unknown = null;
Console.WriteLine((false & unknown) == false); // True
Console.WriteLine((true | unknown) == true);   // True
Console.WriteLine((true & unknown) is null);   // True
```

`bool?` supports three-state logic with `&` and `|`. `&&` and `||` are not defined for `bool?` operands; decide how null should be handled, for example `unknown ?? false`.

## 6. Bitwise Operators and Bit Shifts

With integer operands, bitwise operators act on individual bits.

```csharp
int first = 0b1100;  // 12
int second = 0b1010; // 10

Console.WriteLine(first & second); // 8:  1000, AND.
Console.WriteLine(first | second); // 14: 1110, OR.
Console.WriteLine(first ^ second); // 6:  0110, XOR.
Console.WriteLine(~first);         // -13: invert all 32 bits of the int.
```

`~` flips every bit in the operand's promoted type, not just the four displayed digits. Integer `^` means XOR, not exponentiation; `Math.Pow(2, 3)` computes 2³.

### Set, test, clear, and toggle flags

```csharp
const int Read = 0b001;
const int Write = 0b010;
const int Execute = 0b100;

int permissions = Read;
permissions |= Write; // Set the Write bit: 011.
Console.WriteLine((permissions & Write) != 0); // True: test it.

permissions &= ~Write;   // Clear Write: 001.
permissions ^= Execute;  // Toggle Execute: 101.
Console.WriteLine(permissions); // 5
```

For a mask with several bits, `(value & mask) != 0` means **any** masked bit is set; `(value & mask) == mask` means **all** masked bits are set.

### Left, arithmetic-right, and logical-right shifts

```csharp
int positive = 8;
Console.WriteLine(positive << 1); // 16: shift left, fill low positions with zero.
Console.WriteLine(positive >> 1); // 4

int negative = -8;
Console.WriteLine(negative >> 1);  // -4: signed shift preserves the sign bit.
Console.WriteLine(negative >>> 1); // 2147483644: fill high positions with zero.

uint unsigned = 8U;
Console.WriteLine(unsigned >> 1); // 4: unsigned right shift fills with zero.
```

`>>>` is the logical right-shift operator. `>>` sign-extends signed operands and zero-fills unsigned operands. Shifted-out bits are discarded.

### Shift counts and numeric promotion

```csharp
Console.WriteLine(1 << 32);   // 1: int uses the low 5 bits of the shift count.
Console.WriteLine(1L << 64);  // 1: long uses the low 6 bits.

byte small = 128;
Console.WriteLine(small << 1); // 256: small integer types promote to int.

Console.WriteLine(-3 >> 1); // -2
Console.WriteLine(-3 / 2);  // -1: division truncates toward zero.
```

For `int`/`uint`, the effective count is `count & 31`; for `long`/`ulong`, it is `count & 63`. Shifts do not throw overflow exceptions in a checked context. They are not a general replacement for multiplication or division when bits are lost or signs matter.

Shift assignments modify the left variable: `value <<= 1`, `value >>= 1`, and `value >>>= 1`.

## 7. Conditional Operator: ?:

**Syntax:** `condition ? valueWhenTrue : valueWhenFalse`

```csharp
int age = 20;
string category = age >= 18 ? "Adult" : "Minor";
Console.WriteLine(category); // Adult
```

The condition must be Boolean. Only the selected branch is evaluated.

```csharp
int divisor = 0;
int result = divisor == 0 ? 0 : 10 / divisor;
Console.WriteLine(result); // 0: division was skipped.
```

### Compatible result types

```csharp
bool found = false;
int? count = found ? 5 : null;
Console.WriteLine(count is null); // True

// var invalid = found ? 5 : null; // No target type to resolve this combination.
```

Branches must have a valid common type or convert to the target type supplied by the surrounding context.

### Nested conditional expressions

```csharp
int score = 75;
string grade = score >= 80 ? "A" : (score >= 60 ? "B" : "C");
Console.WriteLine(grade); // B
```

`?:` associates right-to-left. Keep nested conditions short; use `if`/`else` when branches contain several operations.

`??` is different: it selects a fallback for null, not a branch based on a Boolean condition.

```csharp
string? name = null;
Console.WriteLine(name ?? "Guest"); // Guest
```

## 8. Type Operators: is, as, typeof, sizeof

### is — test compatibility or match a pattern

```csharp
object value = "Deep";

Console.WriteLine(value is string); // True
Console.WriteLine(value is int);    // False

if (value is string name)
{
    Console.WriteLine(name.Length); // 4
}

object? missing = null;
Console.WriteLine(missing is string); // False
Console.WriteLine(missing is null);   // True
```

`is` can also test value patterns:

```csharp
int age = 20;
Console.WriteLine(age is >= 18 and <= 65); // True
```

Pattern `and`, `or`, and `not` are separate syntax from Boolean `&&`, `||`, and `!`. `is` does not perform a numeric conversion: a boxed `int` does not match `is long`.

### as — compatible reference or nullable value, otherwise null

```csharp
object value = 42;
string? text = value as string;
int? number = value as int?;

Console.WriteLine(text is null); // True
Console.WriteLine(number);       // 42

// int invalid = value as int; // Invalid: int cannot represent null.
```

`as` does not parse strings or perform ordinary numeric conversions. An incompatible conversion returns null instead of throwing `InvalidCastException`.

### typeof — get a Type object from a type name

```csharp
Type integerType = typeof(int);
Console.WriteLine(integerType.Name); // Int32
Console.WriteLine(typeof(string).FullName); // System.String

object value = "Deep";
Console.WriteLine(typeof(object).Name); // Object: the named type.
Console.WriteLine(value.GetType().Name); // String: the runtime object's type.
```

Use a type inside `typeof`, not a variable. `GetType()` requires a non-null object reference.

### sizeof — storage size in bytes

```csharp
Console.WriteLine(sizeof(byte));    // 1
Console.WriteLine(sizeof(bool));    // 1
Console.WriteLine(sizeof(char));    // 2
Console.WriteLine(sizeof(int));     // 4
Console.WriteLine(sizeof(long));    // 8
Console.WriteLine(sizeof(double));  // 8
Console.WriteLine(sizeof(decimal)); // 16
```

These built-in types do not require an unsafe context. Other unmanaged types, including native-sized integers, generally require one for `sizeof`; `IntPtr.Size` provides the native pointer size without unsafe code.

`sizeof` does not measure the complete memory occupied by a reference-type object. `sizeof(string)` and `sizeof(object)` are not valid in safe code; in unsafe code their result is the reference size, not the object's heap size.

## 9. nameof and default Expressions

### nameof — compile-time symbol name

```csharp
int quantity = 5;
const string ParameterName = nameof(quantity);

Console.WriteLine(ParameterName);           // quantity
Console.WriteLine(nameof(Console.WriteLine)); // WriteLine
Console.WriteLine(nameof(System.String));     // String
```

`nameof` returns the simple name, not the variable's value or its fully qualified namespace. It is useful in argument validation and messages because symbol renaming can update it automatically.

### default(Type) and the default literal

```csharp
int first = default(int);
int second = default;
bool active = default;
string? name = default;
int? count = default;

Console.WriteLine(first);         // 0
Console.WriteLine(second);        // 0
Console.WriteLine(active);        // False
Console.WriteLine(name is null);  // True
Console.WriteLine(count is null); // True

// var invalid = default; // Invalid: no target type.
var valid = default(int); // Valid: the expression supplies int.
```

### default does not call a struct's constructor

```csharp
Counter first = default;
Counter second = new Counter();

Console.WriteLine(first.Value);  // 0
Console.WriteLine(second.Value); // 10

struct Counter
{
    public int Value;

    public Counter()
    {
        Value = 10;
    }
}
```

A struct's default value gives each field its default value. A reference type's default is null; it does not create an object.

## 10. Precedence, Associativity, and Evaluation Order

### Precedence — how different operators group

```csharp
Console.WriteLine(2 + 3 * 4);   // 14: 2 + (3 * 4).
Console.WriteLine((2 + 3) * 4); // 20
```

Relevant precedence levels, highest first; operators on the same row share a level:

| Level | Operators or expressions |
|---:|---|
| 1 | Member access, calls, indexing, postfix `++`/`--`, `typeof`, `sizeof`, `nameof`, `default` |
| 2 | Unary `+`, `-`, `!`, `~`, prefix `++`/`--`, casts |
| 3 | Range `..` |
| 4 | `switch` and `with` expressions |
| 5 | `*`, `/`, `%` |
| 6 | `+`, `-` |
| 7 | `<<`, `>>`, `>>>` |
| 8 | `<`, `>`, `<=`, `>=`, `is`, `as` |
| 9 | `==`, `!=` |
| 10 | `&` |
| 11 | `^` |
| 12 | `\|` |
| 13 | `&&` |
| 14 | `\|\|` |
| 15 | `??` |
| 16 | `?:` |
| 17 | Assignment and compound assignment; lambda `=>` |

Parentheses explicitly group an expression. For a bit-mask test, write `(flags & mask) != 0`; equality binds more tightly than bitwise AND.

### Boolean grouping can change the result

```csharp
bool admin = true;
bool member = false;
bool paid = false;

Console.WriteLine(admin || member && paid);   // True
Console.WriteLine((admin || member) && paid); // False
```

The first expression groups as `admin || (member && paid)`.

### Associativity — how equal-precedence operators group

```csharp
Console.WriteLine(20 / 5 / 2);   // 2: (20 / 5) / 2.
Console.WriteLine(20 / (5 / 2)); // 10: 5 / 2 is integer division.

int first;
int second;
first = second = 5; // first = (second = 5).
Console.WriteLine(first + second); // 10
```

Arithmetic binary operators normally associate left-to-right. Assignment, `??`, and `?:` associate right-to-left. Associativity describes grouping, not a general reversal of operand evaluation.

### Operand evaluation — left to right

```csharp
int result = Read("A", 2) + Read("B", 3) * Read("C", 4);
Console.WriteLine(result);

int Read(string label, int value)
{
    Console.WriteLine(label);
    return value;
}
```

**Output:**

```text
A
B
C
14
```

Calls run in the order A, B, C. Multiplication then combines B's and C's values before the outer addition. Its higher precedence does not make the B call happen before A.

Short-circuit operators, `?:`, and null-handling operators can skip operands that are not needed. Keep expressions with several mutations or method calls easy to follow; split them into statements when necessary.
