# 05.09 Native Interoperability Foundations

## Managed and native boundaries

Interop lets managed code call native exports or expose callbacks. The signature must match the native ABI: parameter types, widths, ownership, layout, and calling convention.

A C# `long` is always 64-bit, while native C `long` varies by platform. A matching-looking type name is not enough to prove compatibility.

## P/Invoke with DllImport

This declaration calls a Windows API. On other operating systems the example reports that it is platform-specific.

```csharp
using System.Runtime.InteropServices;

if (!OperatingSystem.IsWindows())
{
    Console.WriteLine("Windows API example");
    return;
}
Console.WriteLine(Native.GetCurrentProcessId() > 0); // True on Windows.

static class Native
{
    [DllImport("kernel32.dll", ExactSpelling = true)]
    internal static extern uint GetCurrentProcessId();
}
```

## LibraryImport and source generation

`LibraryImport` generates supported marshalling code at build time. It uses a partial method inside a partial type and requires unsafe code support for generated code.

Project setting:

```xml
<PropertyGroup>
  <AllowUnsafeBlocks>true</AllowUnsafeBlocks>
</PropertyGroup>
```

```csharp
using System.Runtime.InteropServices;

if (!OperatingSystem.IsWindows())
{
    Console.WriteLine("Windows API example");
    return;
}
Console.WriteLine(Native.GetCurrentProcessId() > 0); // True on Windows.

static partial class Native
{
    [LibraryImport("kernel32.dll", EntryPoint = "GetCurrentProcessId")]
    internal static partial uint GetCurrentProcessId();
}
```

The generator runs during a normal SDK build. The declaration alone does not supply the native library on another OS.

## Structure layout and calling conventions

```csharp
using System.Runtime.InteropServices;

Console.WriteLine(Marshal.SizeOf<NativePoint>()); // 8

[StructLayout(LayoutKind.Sequential)]
struct NativePoint
{
    public int X;
    public int Y;
}
```

Sequential layout preserves field order with applicable alignment rules. Use explicit layout or packing only when required by the native definition; guessed packing can silently corrupt data. The platform ABI determines how arguments and return values are passed.

## String and data marshalling

Specify encoding according to the native contract, such as UTF-8 or UTF-16. Clarify whether a pointer references a null-terminated string, a length-delimited buffer, or writable output storage.

Determine who allocates and frees returned memory. Memory allocated by one native allocator generally must be freed through its corresponding release function, not an arbitrary managed or OS allocator.

## Native callbacks and delegate lifetime

When native code retains a delegate-derived callback pointer, keep the delegate alive until native code stops using it. A local `GC.KeepAlive` at the end of one call is insufficient for a callback retained after that call returns.

Prevent managed exceptions from escaping across unsupported native boundaries. Translate failures into the native API's expected error mechanism.

## SafeHandle and resource ownership

A SafeHandle wrapper centralizes native handle release and integrates with disposal and finalization.

```csharp
using System.Runtime.InteropServices;

using var buffer = new NativeBuffer(16);
Console.WriteLine(!buffer.IsInvalid); // True

sealed class NativeBuffer : SafeHandle
{
    public NativeBuffer(int size) : base(IntPtr.Zero, ownsHandle: true)
    {
        if (size <= 0) throw new ArgumentOutOfRangeException(nameof(size));
        SetHandle(Marshal.AllocHGlobal(size));
    }
    public override bool IsInvalid => handle == IntPtr.Zero;
    protected override bool ReleaseHandle()
    {
        Marshal.FreeHGlobal(handle);
        return true;
    }
}
```

This wrapper owns its allocation. Borrowed handles need a different ownership arrangement.

## OS, architecture, and dependencies

Verify the native binary's OS and CPU architecture, export name, dependent libraries, and deployment search paths. Build success validates the managed declaration, not native binary availability or correctness of the native contract. Test the actual supported deployment environments.
