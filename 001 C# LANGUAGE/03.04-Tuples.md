# 03.04 Tuples

## Tuple syntax and names

A tuple groups a small fixed set of values. Named elements improve readability.

```csharp
(string Name, int Age) person = ("Deep", 20);
Console.WriteLine(person.Name); // Deep
Console.WriteLine(person.Item2); // 20
person.Age = 21;
Console.WriteLine(person.Age); // 21
```

Names help source code; they do not define a new nominal type. Compatible tuples can be assigned even when their element names differ.

## ValueTuple versus System.Tuple

Modern tuple syntax normally uses mutable `System.ValueTuple` value types. `System.Tuple` is an older reference-type family with read-only item properties.

```csharp
var modern = (Name: "Deep", Age: 20);
var older = Tuple.Create("Deep", 20);
Console.WriteLine(modern.Name); // Deep
Console.WriteLine(older.Item1); // Deep
```

A tuple containing an object reference copies that reference when the tuple is copied; it does not clone the object.

## Returning multiple values

```csharp
var result = Divide(17, 5);
Console.WriteLine(result.Quotient); // 3
Console.WriteLine(result.Remainder); // 2

(int Quotient, int Remainder) Divide(int value, int divisor)
    => (value / divisor, value % divisor);
```

## Deconstruction and discards

```csharp
var pair = (Name: "Deep", Age: 20);
var (name, age) = pair;
Console.WriteLine($"{name}: {age}"); // Deep: 20
var (_, years) = pair; // Ignore the first component.
Console.WriteLine(years); // 20

int left = 1, right = 2;
(left, right) = (right, left); // Evaluate RHS values, then assign.
Console.WriteLine($"{left}, {right}"); // 2, 1
```

A deconstruction can declare new variables or assign existing variables. A discard represents an intentionally unused component.

## Equality and API tradeoffs

```csharp
Console.WriteLine((X: 1, Y: 2) == (Left: 1, Right: 2)); // True
Console.WriteLine((1, 2) == (2, 1)); // False
```

Tuple equality compares corresponding elements, not their names. Hash-based tuple comparison uses appropriate element equality comparers.

Tuples work well for local grouping and simple multi-result methods. Prefer a named class, struct, or record when a public result needs validation, documentation, behavior, or a stable domain identity. Avoid long positional tuples whose meaning requires memorizing element positions.
