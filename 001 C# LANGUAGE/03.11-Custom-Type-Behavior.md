# 03.11 Custom Type Behavior

## Operator overloading

Operators can give domain types natural syntax when their meaning is clear. Traditional binary operator declarations are public static methods involving the containing type.

```csharp
var total = new Distance(3) + new Distance(4);
Console.WriteLine(total.Metres); // 7

readonly record struct Distance(double Metres)
{
    public static Distance operator +(Distance left, Distance right)
        => new(left.Metres + right.Metres);
}
```

Do not use an operator for an unrelated action such as network access. Operator syntax should preserve understandable mathematical or domain semantics.

## User-defined conversions

`implicit` conversions should be unsurprising and safe for the intended contract. `explicit` requires the caller to acknowledge a conversion that may reject or lose information.

```csharp
Distance distance = 12.5;
double metres = (double)distance;
Console.WriteLine(metres); // 12.5

readonly record struct Distance(double Metres)
{
    public static implicit operator Distance(double metres) => new(metres);
    public static explicit operator double(Distance value) => value.Metres;
}
```

A user-defined conversion must convert to or from the declaring type. `is` and `as` do not invoke user-defined conversion operators.

## IEquatable<T> and IComparable<T>

`IEquatable<T>` supplies typed equality. `IComparable<T>` supplies an ordering result: negative, zero, or positive.

```csharp
var values = new[] { new Rank(3), new Rank(1) };
Array.Sort(values);
Console.WriteLine(values[0].Value); // 1
Console.WriteLine(new Rank(1).Equals(new Rank(1))); // True

readonly record struct Rank(int Value) : IComparable<Rank>
{
    public int CompareTo(Rank other) => Value.CompareTo(other.Value);
}
```

The record struct supplies equality. Compare values with their comparison APIs rather than subtracting integers, which can overflow.

## Equality and ordering comparers

A comparer can define an external policy without changing the domain type.

```csharp
var names = new HashSet<string>(StringComparer.OrdinalIgnoreCase) { "Deep" };
Console.WriteLine(names.Contains("DEEP")); // True

string[] ordered = { "b", "A" };
Array.Sort(ordered, StringComparer.OrdinalIgnoreCase);
Console.WriteLine(string.Join(", ", ordered)); // A, b
```

`IEqualityComparer<T>` provides equality and hashing; `IComparer<T>` provides ordering. They are separate contracts.

## Consistent domain semantics

- Equal values must have equal hash codes.
- When overloading equality, also supply a compatible `Equals` and `GetHashCode` implementation.
- Required paired operator declarations include `==` with `!=` and `<` with `>`.
- Define null, invalid-value, unit, and overflow behavior deliberately.
- Keep key values stable while used in hash collections.
- Do not assume ordering equality and object equality are identical unless the type or comparer contract makes them so.
