# 01.11 Statements, Blocks, and Scope

## 1. Declaration and Expression Statements

A **statement** declares something or tells the program to perform an action. Statements normally execute in order unless control flow changes that order.

### Declaration statements

A local declaration introduces a name inside a method, local function, or other executable block.

```csharp
int quantity;            // Declaration without an initial value.
quantity = 3;            // Assignment after declaration.
decimal price = 25M;     // Declaration with initialization.
var product = "Book";   // Compiler infers string.
const int maxOrder = 10; // Local compile-time constant.

Console.WriteLine($"{product}: {quantity * price}"); // Book: 75
Console.WriteLine(maxOrder); // 10
```

- `int quantity;` creates a local variable declaration; it does not make that local ready to read.
- `decimal price = 25M;` declares and initializes in one statement.
- `var` requires an initializer so the compiler can infer the type.
- A local `const` requires a constant initializer.

### Multiple variables in one declaration

```csharp
int width = 4, height = 3; // Both variables have type int.
Console.WriteLine(width * height); // 12

// var width = 4, height = 3; // Error: var cannot declare multiple variables.
```

Separate declarations are usually easier to read when variables serve different purposes.

### Expression statements

An expression statement evaluates an allowed expression and ends with `;`. Not every expression is allowed as a standalone statement.

```csharp
int count = 1;

count = 5;                // Assignment.
count += 2;               // Compound assignment.
count++;                  // Postfix increment.
--count;                  // Prefix decrement.
Console.WriteLine(count); // Method invocation: 7.

Math.Abs(-10); // Valid method call; its returned value is ignored.

int absolute = Math.Abs(-10); // Keep the returned value.
Console.WriteLine(absolute);  // 10
```

Object creation and awaited operations can also be expression statements:

```csharp
new System.Text.StringBuilder(); // Valid; no variable keeps this object.

await Task.Delay(10); // Wait for the asynchronous operation.
Console.WriteLine("Finished"); // Finished
```

### Expressions that cannot stand alone

```csharp
int number = 5;

// number + 1;  // Error CS0201: arithmetic alone is not a statement.
// number == 5; // Error CS0201: comparison alone is not a statement.
// 42;          // Error CS0201: a literal alone is not a statement.
// number;      // Error CS0201: reading a variable alone is not a statement.

int next = number + 1;           // Store the result.
Console.WriteLine(number == 5);  // True: use the comparison result.
Console.WriteLine(next);         // 6
```

### Local function declarations

A local function is declared inside executable code. Unlike a local variable, it can be called before its declaration appears.

```csharp
Console.WriteLine(Double(4)); // 8

int Double(int value)
{
    return value * 2;
}
```

- A block-bodied local function ends with `}`, without a required semicolon.
- An expression-bodied local function ends with `;`: `int Double(int value) => value * 2;`.

### Declaration versus assignment

```csharp
int score = 10; // Declaration: introduces score.
score = 20;     // Assignment: uses the existing score.

// int score = 30; // Error: score is already declared in this block.

Console.WriteLine(score); // 20
```

### Semicolon rules

```csharp
int total = 2;              // Declaration ends with ;.
total++;                   // Expression statement ends with ;.

if (total > 0)
{
    Console.WriteLine(total); // 3
}                          // No ; required after this block.
```

- Declarations of local variables, expression statements, and statements such as `return`, `break`, and `throw` use semicolons.
- An ordinary block, class body, or block-bodied method does not need a trailing semicolon.
- `do { ... } while (condition);` specifically requires its final semicolon.
- Braces inside an initializer do not replace a declaration's semicolon: `int[] numbers = { 1, 2 };`.

## 2. Empty Statements and Nested Blocks

### Empty statement

An empty statement is a single `;`. It performs no operation.

```csharp
Console.WriteLine("Before");
; // Empty statement.
Console.WriteLine("After");
```

Output:

```text
Before
After
```

### Empty block

A block is zero or more statements enclosed in `{ }`. An empty block has braces but contains no statements.

```csharp
{
    // Empty block: no executable statements.
}

Console.WriteLine("Continued"); // Continued
```

### Accidental semicolon after if

```csharp
bool isAdmin = false;

if (isAdmin); // The if controls only this empty statement.
{
    Console.WriteLine("Access granted"); // Separate block: always runs.
}
```

Output:

```text
Access granted
```

Correct:

```csharp
bool isAdmin = false;

if (isAdmin)
{
    Console.WriteLine("Access granted");
}

Console.WriteLine("Finished"); // Only Finished is printed.
```

### Accidental semicolon after a loop

```csharp
for (int i = 0; i < 3; i++); // Repeats an empty statement three times.
{
    Console.WriteLine("Hello"); // Separate block: runs once.
}
```

Removing the semicolon makes the block the loop body, so `Hello` prints three times.

### Braces versus indentation

Without braces, an `if` controls one following embedded statement. Indentation does not change execution.

```csharp
bool enabled = false;

if (enabled)
    Console.WriteLine("First");
    Console.WriteLine("Second"); // Outside the if, despite indentation.
```

Output:

```text
Second
```

Use braces when multiple statements belong to the same condition or loop.

### A local declaration needs a block under if

```csharp
bool enabled = true;

// if (enabled)
//     int count = 1; // Error CS1023: declaration is not an embedded statement.

if (enabled)
{
    int count = 1;             // Valid declaration inside a block.
    Console.WriteLine(count);  // 1
}
```

The same restriction applies to a declaration used directly as the body of loops such as `while` and `for`.

### Nested blocks

A block can contain another block. The inner block can use variables from an enclosing block.

```csharp
int total = 10;

{
    int bonus = 5;
    total += bonus;

    {
        int extra = 2;
        total += extra;
        Console.WriteLine(total); // 17
    }

    Console.WriteLine(bonus); // 5
    // Console.WriteLine(extra); // Error: extra belongs to the deeper block.
}

Console.WriteLine(total); // 17: the outer variable was changed.
// Console.WriteLine(bonus); // Error: bonus is outside its scope.
```

Braces do not automatically copy an outer variable. Assignment inside the inner block changes that same variable.

## 3. Local Scope and Enclosing Scope

**Scope** is the region of code where a name can be used. An enclosing scope surrounds the current block or function.

### Inner code can use outer variables

```csharp
string customer = "Deep";

if (customer.Length > 0)
{
    string greeting = $"Hello, {customer}";
    Console.WriteLine(greeting); // Hello, Deep
}

Console.WriteLine(customer); // Deep
// Console.WriteLine(greeting); // Error CS0103: name is not available here.
```

### Scope does not allow reading before declaration

For a local declared directly in a block, its scope is that block. Additional rules still prohibit using it before its declaration and reading it before definite assignment.

```csharp
// Console.WriteLine(amount); // Error CS0841: used before declaration.
int amount;
// Console.WriteLine(amount); // Error CS0165: not definitely assigned.

amount = 20;
Console.WriteLine(amount); // 20
```

Local variables do not receive readable default values automatically. Fields and array elements do receive default values.

### Separate sibling blocks can reuse a name

Neither of these blocks encloses the other, so each may declare its own `message`.

```csharp
{
    string message = "First block";
    Console.WriteLine(message);
}

{
    string message = "Second block";
    Console.WriteLine(message);
}
```

Output:

```text
First block
Second block
```

### Variables declared by a for loop

```csharp
for (int index = 0; index < 2; index++)
{
    Console.WriteLine(index); // 0, then 1.
}

// Console.WriteLine(index); // Error: index belongs to the for statement.
```

Declare the variable outside when it is needed afterward:

```csharp
int index;

for (index = 0; index < 2; index++)
{
    Console.WriteLine(index); // 0, then 1.
}

Console.WriteLine(index); // 2
```

An iteration variable declared by `foreach` is also unavailable after that `foreach` statement.

### Variables declared using out

In this example, `number` is in the surrounding block's scope, not only the `if` body.

```csharp
if (int.TryParse("42", out int number))
{
    Console.WriteLine(number); // 42
}

Console.WriteLine(number); // 42
```

`TryParse` assigns its `out` parameter on success and failure. A failed `int.TryParse` assigns zero.

```csharp
bool valid = int.TryParse("hello", out int number);

Console.WriteLine(valid);  // False
Console.WriteLine(number); // 0
```

An `out` declaration inside a method call within an inner block belongs to that inner scope. Its exact scope depends on where the declaration appears.

### Pattern variables: scope and assignment are separate

```csharp
object input = "C#";

if (input is string text)
{
    Console.WriteLine(text.Length); // 2: matching assigned text.
}

// Console.WriteLine(text); // Error CS0165: text may not have been assigned.
```

Here `text` is in scope after the `if`, but it is definitely assigned only on paths where the pattern matched. Being in scope does not guarantee that reading a variable is valid.

### Parameters and different functions

```csharp
PrintDouble(3); // 6
PrintTriple(3); // 9

void PrintDouble(int value)
{
    int result = value * 2;
    Console.WriteLine(result);
}

void PrintTriple(int value)
{
    int result = value * 3; // Independent result and value.
    Console.WriteLine(result);
}
```

- A parameter is available in its function body.
- These two functions can each use the same parameter and local names.
- One function cannot directly use another function's local variables.
- A local function can capture variables from its enclosing function; a `static` local function cannot capture them.

### Top-level variables are not class fields

```csharp
string message = "Hello"; // Local variable in the generated entry point.
Printer.Print(message);   // Pass the value explicitly.

class Printer
{
    public static void Print(string text)
    {
        Console.WriteLine(text); // Hello
        // Console.WriteLine(message); // Error: not a member of Printer.
    }
}
```

Putting a class in the same `Program.cs` file does not give it access to top-level local variables.

## 4. Name Conflicts and Member Qualification

### Duplicate names in the same block

```csharp
int count = 1;
// string count = "Two"; // Error CS0128: duplicate local name.

Console.WriteLine(count); // 1
```

Changing the type does not make the duplicate name valid. C# names are case-sensitive, but using `count` and `Count` for unrelated locals makes code harder to read.

### An inner local cannot reuse an enclosing local's name

Invalid:

```csharp
int count = 1;

{
    int count = 2; // Error CS0136: conflicts with the enclosing local.
}
```

This is still a conflict when the enclosing declaration appears later:

```csharp
{
    int count = 1; // Error CS0136: conflicts with the outer declaration.
}

int count = 2;
```

Use different names or independent sibling blocks. Merely moving the outer declaration does not fix the conflict.

### A method local cannot redeclare its parameter

Invalid:

```csharp
void Print(int value)
{
    int value = 10; // Error CS0136: conflicts with the parameter.
}
```

Assign `value = 10;` to change that parameter variable, or declare a differently named local.

### A parameter can hide a field: use this

`this` means the current object. It distinguishes an instance member from a parameter or local with the same name.

```csharp
var account = new Account("Deep");
account.Print(); // Deep

class Account
{
    private string name;

    public Account(string name)
    {
        this.name = name; // Field on the left, parameter on the right.
    }

    public void Print()
    {
        Console.WriteLine(this.name);
    }
}
```

`name = name;` would assign the parameter to itself; it would not initialize the field with that value. A common alternative is naming the field `_name` and writing `_name = name;`.

### Static members: use the type name

```csharp
Settings.SetLimit(10);
Console.WriteLine(Settings.Limit); // 10

class Settings
{
    public static int Limit = 5;

    public static void SetLimit(int Limit)
    {
        Settings.Limit = Limit; // Static field versus parameter.
        // this.Limit = Limit; // Error: this is unavailable in static code.
    }
}
```

### Base members: use base

`base` selects a member of the base class from an instance member of a derived class.

```csharp
var item = new Child();
item.Print();

class Parent
{
    protected string Name = "Parent";
}

class Child : Parent
{
    private new string Name = "Child"; // Intentionally hides the base field.

    public void Print()
    {
        Console.WriteLine(this.Name); // Child
        Console.WriteLine(base.Name); // Parent
    }
}
```

`base` does not bypass accessibility rules; a private base-class field is still inaccessible to the derived class.

### Namespace qualification and aliases

```csharp
using TextBuilder = System.Text.StringBuilder;

var text = new TextBuilder("Hello");
System.Console.WriteLine(text);         // Hello
global::System.Console.WriteLine(text); // Hello
```

- `System.Console` qualifies the type with its namespace.
- `global::System.Console` starts lookup at the global namespace if another name hides `System`.
- An alias gives a type or namespace another name; it does not create a new type.

## 5. Scope versus Lifetime versus Accessibility

| Term | Question it answers | Example |
| --- | --- | --- |
| Scope | Where can this name be used in code? | A block local cannot be named outside its block. |
| Lifetime | How long does this variable's storage or object exist during execution? | A captured local can survive its function returning. |
| Accessibility | Which code is allowed to access this type or member? | A private field cannot be read directly by an unrelated class. |

### An object can survive the block that created it

```csharp
List<int> saved;

{
    var temporary = new List<int> { 10, 20 };
    saved = temporary; // Both variables refer to the same list.
}

// temporary is no longer in scope.
Console.WriteLine(saved[0]); // 10: the list is still reachable.
```

- The name `temporary` is unavailable outside its block.
- The list remains usable through `saved`.
- Leaving a block does not automatically destroy its objects or immediately run garbage collection.
- A local being in scope does not force its referenced object to stay alive until the closing brace; the runtime can recognize its last use earlier.

### Captured locals can outlive a function call

```csharp
Func<int> next = CreateCounter();

Console.WriteLine(next()); // 1
Console.WriteLine(next()); // 2

Func<int> CreateCounter()
{
    int count = 0;
    return () => ++count; // Returned function retains access to count.
}
```

`CreateCounter` has already returned when `next()` runs. The captured variable still exists, even though calling code cannot refer to it by the name `count`.

### Member accessibility

```csharp
var counter = new Counter();
counter.Increment();
Console.WriteLine(counter.Value); // 1

// Console.WriteLine(counter._value); // Error CS0122: private member.

class Counter
{
    private int _value;
    public int Value => _value;

    public void Increment()
    {
        _value++;
    }
}
```

For class members:

- `public`: accessible wherever the containing type is accessible.
- `private`: access is restricted to the containing type, including its nested types.
- `protected`: available within the containing class and derived classes, subject to protected-access rules.
- `internal`: available within the same assembly; explicitly configured friend assemblies can also access internal members.
- `protected internal`: same assembly **or** derived-class access.
- `private protected`: derived-class access within the same assembly, as well as the containing class itself.

Ordinary local variables cannot use access modifiers such as `public` or `private`. Their visibility is controlled by scope.

### Disposal is separate from scope and garbage collection

```csharp
using (var reader = new System.IO.StringReader("Hello"))
{
    Console.WriteLine(reader.ReadLine()); // Hello
} // Dispose runs when control leaves this using block.

// reader is out of scope here.
```

`using` adds a disposal rule. Ordinary braces alone do not call `Dispose` on local objects.

```csharp
{
    using var reader = new System.IO.StringReader("Hello");
    Console.WriteLine(reader.ReadLine()); // Hello
} // A using declaration disposes at the end of its enclosing scope.
```

Disposal releases resources according to the object's implementation; it does not immediately erase the managed object from memory.

## 6. Reachable and Unreachable Code

**Reachable code** is code the compiler considers possible to execute. **Unreachable code** has no execution path according to the compiler's flow analysis.

### Code after an unconditional return

```csharp
Print();

void Print()
{
    Console.WriteLine("Before");
    return;

    Console.WriteLine("After"); // Warning CS0162: unreachable code.
}
```

Output:

```text
Before
```

Unreachable code usually produces a warning, not a compile-time error. A project configured to treat that warning as an error will reject the build.

### Conditional return does not make everything afterward unreachable

```csharp
PrintStatus(false);
PrintStatus(true);

void PrintStatus(bool ready)
{
    if (!ready)
    {
        Console.WriteLine("Not ready");
        return; // Only this path exits early.
    }

    Console.WriteLine("Ready"); // Reachable when ready is true.
}
```

Output:

```text
Not ready
Ready
```

### Other unconditional transfers

- `throw` exits the current normal execution path by throwing an exception.
- `break` exits its nearest loop or `switch`.
- `continue` moves to the next iteration of its nearest loop.
- `goto` transfers control to a valid target label.

Ordinary statements immediately after such a transfer in the same block are unreachable unless another valid path enters them, such as a jump to a label.

```csharp
for (int i = 0; i < 2; i++)
{
    Console.WriteLine(i); // 0
    break;
    Console.WriteLine("Skipped"); // Warning CS0162.
}

Console.WriteLine("After loop"); // Reachable after break.
```

### Constant conditions versus variable values

```csharp
const bool enabled = false;

if (enabled)
{
    Console.WriteLine("Disabled branch"); // Warning CS0162.
}

Console.WriteLine("Finished"); // Finished
```

The compiler can use the constant value for reachability analysis.

```csharp
bool enabled = false; // A variable, not a constant expression.

if (enabled)
{
    Console.WriteLine("Enabled branch"); // Considered reachable by the compiler.
}

Console.WriteLine("Finished"); // Finished
```

In this execution the branch is skipped, but compiler reachability does not generally track the actual values of ordinary variables. Runtime behavior and compile-time reachability are different questions.

### Unreachable code still must be valid C#

Invalid:

```csharp
if (false)
{
    int number = "hello"; // Error CS0029: invalid conversion, even here.
}
```

Conditional compilation is different:

```csharp
#if false
int number = "hello"; // Excluded from compilation.
#endif

Console.WriteLine("Compiled"); // Compiled
```

`if (false)` keeps the branch in the C# program for checking. `#if false` excludes that section from compilation.

### A value-returning method cannot reach its end without returning

Invalid:

```csharp
int GetDiscount(bool member) // Error CS0161: not all code paths return a value.
{
    if (member)
    {
        return 10;
    }
    // The false path reaches the end without returning an int.
}
```

Correct:

```csharp
Console.WriteLine(GetDiscount(true));  // 10
Console.WriteLine(GetDiscount(false)); // 0

int GetDiscount(bool member)
{
    if (member)
    {
        return 10;
    }

    return 0;
}
```

A path that always throws also cannot reach the method's end, so it does not need a return value:

```csharp
Console.WriteLine(GetFirst(new[] { 7, 9 })); // 7

int GetFirst(int[] values)
{
    if (values.Length == 0)
    {
        throw new ArgumentException("At least one value is required.", nameof(values));
    }

    return values[0];
}
```

### Infinite loops and reachable breaks

```csharp
while (true)
{
    break; // Gives control a path out of the loop.
}

Console.WriteLine("After loop"); // Reachable.
```

A `while (true)` loop with no reachable `break` has no normally reachable endpoint. Code directly after it is unreachable unless another valid control-flow path reaches that code.

### Reachability does not guarantee definite assignment

Invalid:

```csharp
bool valid = DateTime.Now.Second % 2 == 0;
int result;

if (valid)
{
    result = 10;
}

Console.WriteLine(result); // Error CS0165: the false path never assigns result.
```

The final statement is reachable, but reading `result` is invalid. Assign an initial value or assign on every path:

```csharp
bool valid = false;
int result;

if (valid)
{
    result = 10;
}
else
{
    result = 0;
}

Console.WriteLine(result); // 0
```
