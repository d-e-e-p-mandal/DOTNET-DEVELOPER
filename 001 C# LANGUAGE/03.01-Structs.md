# 03.01 Structs

## Declarations, constructors, and members

A struct is a value type. Assignment copies its value rather than creating another reference to the same struct variable.

```csharp
var first = new Point(2, 3);
var second = first;
second.X = 9;
Console.WriteLine(first.X); // 2
Console.WriteLine(second.X); // 9

struct Point
{
    public int X { get; set; }
    public int Y { get; set; }
    public Point(int x, int y) { X = x; Y = y; }
}
```

Structs can have constructors, methods, properties, and interface implementations. They cannot inherit from a user-defined class or struct.

## Default initialization

`default(T)` produces zero/default field values for a struct, even if the struct declares a parameterless constructor.

```csharp
Console.WriteLine(new Score().Value); // 10
Console.WriteLine(default(Score).Value); // 0
Console.WriteLine((new Score[1])[0].Value); // 0: array elements are default-initialized.

struct Score
{
    public int Value;
    public Score() => Value = 10;
}
```

Explicit parameterless struct constructors must be public. Design structs so their default value is meaningful or can be detected safely.

## Copying, mutation, and boxing

A copy of a struct containing references still refers to the same referenced objects. Copying is not a deep clone.

```csharp
var point = new Point { X = 3 };
object boxed = point; // Boxing copies this value into an object.
point.X = 8;
Console.WriteLine(((Point)boxed).X); // 3

struct Point { public int X; }
```

Unboxing requires the compatible boxed value type. Large structs can be expensive to copy; avoid assuming value types always improve performance.

## readonly structs and members

```csharp
var size = new Size(4, 3);
Console.WriteLine(size.Area); // 12

readonly struct Size
{
    public int Width { get; }
    public int Height { get; }
    public int Area => Width * Height;
    public Size(int width, int height) { Width = width; Height = height; }
}
```

A `readonly struct` prevents instance state mutation through its members. A `readonly` instance member on a mutable struct promises not to mutate its receiver. A reference stored inside a readonly struct can still identify a mutable object.

## Class versus struct

Use a class when identity, sharing, inheritance, or large mutable state matters. Consider a struct for small values with value semantics. Storage depends on context: a struct can be embedded in a heap object or array, held in registers, or boxed; it does not necessarily live on the stack.
