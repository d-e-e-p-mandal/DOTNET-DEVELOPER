# 01.08 Literals and Number Representation

## 1. Integer, Real, Boolean, Character, String, and Null Literals

A **literal** is a value written directly in source code.

```csharp
int quantity = 42;       // Integer literal.
double price = 12.5;     // Real literal.
bool active = true;      // Boolean literal: true or false.
char grade = 'A';        // Character literal: single quotes.
string name = "Deep";    // String literal: double quotes.
string? missing = null;  // Null literal: no string object.
```

`42`, `"42"`, and `'4'` are different: an integer, a string, and a character. Likewise, `false` is Boolean, but `"false"` is text.

### Integer, string, and character: different operations

```csharp
Console.WriteLine(10 + 20);     // 30: numeric addition.
Console.WriteLine("10" + "20"); // 1020: string concatenation.
Console.WriteLine('A' == '\u0041'); // True: the same char value.

// char invalid = 'AB'; // Invalid: more than one UTF-16 code unit.
```

### Boolean literals

```csharp
bool enabled = true;
bool finished = false;

Console.WriteLine(enabled && !finished); // True

// bool wrong = True;   // True is not the Boolean literal true.
// bool wrong = 1;      // No implicit integer-to-bool conversion.
// bool wrong = "true"; // A string is not a bool.
```

### Real literals and scientific notation

```csharp
double first = 125.0;
double second = 1.25e2; // 1.25 × 10² = 125.
double small = 1e-3;    // 1 × 10⁻³ = 0.001.

Console.WriteLine(first == second); // True
Console.WriteLine(small == 0.001);  // True
```

`e` and `E` both introduce a decimal exponent. Real literals without a suffix have type `double`.

### The operands determine division

```csharp
double first = 5 / 2;   // int division gives 2, then converts to double.
double second = 5D / 2; // double division gives 2.5.

Console.WriteLine(first == 2.0);  // True
Console.WriteLine(second == 2.5); // True
```

Writing the result into a `double` does not turn earlier integer arithmetic into floating-point arithmetic.

### Character escapes and string forms

```csharp
char newline = '\n';
char backslash = '\\';
char unicodeA = '\u0041';

string regular = "Say \"Hello\".";  // Escape quotes with \".
string path = @"C:\Notes";          // Verbatim: backslashes stay literal.
string raw = """Say "Hello".""";   // Raw: quotes need no escape here.

Console.WriteLine(unicodeA);       // A
Console.WriteLine(regular == raw); // True
```

A character literal represents one UTF-16 code unit. An empty string `""` is valid; an empty character literal `''` is invalid. Verbatim strings write an embedded double quote as `""`.

Common escapes: `\n` newline, `\r` carriage return, `\t` tab, `\\` backslash, `\"` double quote, `\'` single quote, `\0` the zero-valued character.

### Regular versus verbatim strings

```csharp
string regularPath = "C:\\Notes\\CSharp";
string verbatimPath = @"C:\Notes\CSharp";
string quote = @"He said ""Hello"".";

Console.WriteLine(regularPath == verbatimPath); // True
Console.WriteLine(quote); // He said "Hello".
Console.WriteLine("\n".Length);  // 1: a newline character.
Console.WriteLine(@"\n".Length); // 2: backslash and n.
```

### Multiline raw string

```csharp
string json = """
    {
      "name": "Deep",
      "active": true
    }
    """;

Console.WriteLine(json);
```

**Output:**

```json
{
  "name": "Deep",
  "active": true
}
```

The indentation before the closing delimiter is removed from the content. Opening and closing delimiter lines are not included in this string.

### Text containing triple quotes

Use more delimiter quotes than the longest quote sequence inside the raw string:

```csharp
string text = """"Three quotes: """ inside."""";
Console.WriteLine(text); // Three quotes: """ inside.
```

### Interpolated strings

`$` allows expressions inside braces; interpolation is a string expression, not simply literal text.

```csharp
string name = "Deep";
string greeting = $"Hello, {name}!";

Console.WriteLine(greeting);       // Hello, Deep!
Console.WriteLine($"{{{name}}}"); // {Deep}: doubled braces produce literal braces.
```

### null needs a compatible type

```csharp
string? name = null;
int? age = null;

Console.WriteLine(name is null); // True
Console.WriteLine(age is null);  // True

// int count = null; // Invalid: int cannot hold null.
// var value = null; // Invalid: null alone provides no type to infer.
```

`null` is different from zero, `false`, and an empty string.

```csharp
string? missing = null;
string empty = "";
string space = " ";

Console.WriteLine(missing is null); // True
Console.WriteLine(empty is null);   // False
Console.WriteLine(empty.Length);   // 0
Console.WriteLine(space.Length);   // 1
```

## 2. Decimal, Binary, and Hexadecimal Notation

| Notation | Base | Prefix | Digits |
|---|---:|---|---|
| Decimal | 10 | None | `0–9` |
| Binary | 2 | `0b` or `0B` | `0–1` |
| Hexadecimal | 16 | `0x` or `0X` | `0–9`, `A–F` or `a–f` |

```csharp
int decimalValue = 42;
int binaryValue = 0b101010;
int hexValue = 0x2A;

Console.WriteLine(decimalValue == binaryValue); // True
Console.WriteLine(binaryValue == hexValue);     // True
```

Binary `101010` means `32 + 8 + 2 = 42`. Hexadecimal `2A` means `2 × 16 + 10 = 42`.

**Decimal notation** means base 10; it does not mean the C# `decimal` type. `42` is an integer literal; `42M` is a decimal literal. A leading zero does not make a C# number octal: `010` means ten.

### Display the same number in different bases

```csharp
int number = 42;

Console.WriteLine(number);                      // 42
Console.WriteLine(Convert.ToString(number, 2)); // 101010
Console.WriteLine(number.ToString("X"));        // 2A
Console.WriteLine(number.ToString("X4"));       // 002A: at least four hex digits.
Console.WriteLine(Convert.ToString(number, 2).PadLeft(8, '0')); // 00101010
```

Formatting changes the displayed text, not the stored value or its type.

### Hexadecimal does not automatically mean a negative number

```csharp
var bits = 0xFFFF_FFFF;

Console.WriteLine(bits.GetType().Name); // UInt32
Console.WriteLine(bits);               // 4294967295
Console.WriteLine(unchecked((int)bits)); // -1: unchecked conversion to int.
```

The literal is selected as `uint`; the explicit conversion changes how its 32-bit pattern is interpreted.

### Invalid digits

```csharp
// int binary = 0b102; // Invalid: binary has no digit 2.
// int hex = 0xG1;    // Invalid: hexadecimal has no digit G.
// int octal = 0o17;  // Invalid: C# has no 0o octal literal prefix.
```

## 3. Numeric Suffixes: U, L, UL, F, D, M

A suffix helps select the literal's type.

| Suffix | Type-selection rule | Example |
|---|---|---|
| `U` | First fitting type: `uint`, then `ulong` | `42U` |
| `L` | First fitting type: `long`, then `ulong` | `42L` |
| `UL` | `ulong` | `42UL` |
| `F` | `float` | `1.5F` |
| `D` | `double` | `1.5D` |
| `M` | `decimal` | `1.5M` |

```csharp
var count = 42U;
var distance = 42L;
var size = 42UL;
var speed = 1.5F;
var ratio = 1.5D;
var price = 1.5M;

Console.WriteLine(count.GetType().Name); // UInt32
Console.WriteLine(speed.GetType().Name); // Single
Console.WriteLine(price.GetType().Name); // Decimal
```

Suffix letters are case-insensitive. Prefer uppercase `L` because lowercase `l` resembles `1`. `LU` also means `ulong`. There is no dedicated `byte`, `short`, or `nint` literal suffix.

### U and L can select ulong for large literals

```csharp
var first = 5_000_000_000U;              // Too large for uint: ulong.
var second = 10_000_000_000_000_000_000L; // Too large for long: ulong.

Console.WriteLine(first.GetType().Name);  // UInt64
Console.WriteLine(second.GetType().Name); // UInt64
```

`L` does not guarantee `long` for every positive literal; the value must fit.

### A decimal point is not required with F, D, or M

```csharp
Console.WriteLine((42F).GetType().Name); // Single
Console.WriteLine((42D).GetType().Name); // Double
Console.WriteLine((42M).GetType().Name); // Decimal
```

### Hex digits versus suffix letters

```csharp
Console.WriteLine(0x1D);              // 29: D is a hex digit here.
Console.WriteLine(0xFF);              // 255: F is a hex digit here.
Console.WriteLine((0x10UL).GetType().Name); // UInt64: UL is the suffix.
```

For a `float` with the value sixteen, write `16F`; `0x10F` is the integer 271.

## 4. Digit Separators

Use `_` to group digits for readability. Separators do not change the value or selected type.

```csharp
int million = 1_000_000;
int flags = 0b_1111_0000; // Separator may follow the binary prefix.
int mask = 0x_FF_FF;     // Separator may follow the hex prefix.
decimal amount = 1_234.56_78M;

Console.WriteLine(million); // 1000000
Console.WriteLine(flags);   // 240
Console.WriteLine(mask);    // 65535
Console.WriteLine(amount == 1234.5678M); // True
```

Place separators between digits, or after `0b`/`0x`. Do not place them at the end or directly beside a decimal point, exponent marker, exponent sign, or suffix.

```csharp
// int bad = 1000_;   // Invalid trailing separator.
// double bad = 1_.5; // Invalid beside decimal point.
// long bad = 10_L;   // Invalid before suffix.
```

`_1000` is an identifier, not a numeric literal.

### Separators in fractional and exponent digits

```csharp
double fraction = 0.123_456;
double large = 1e1_0; // Exponent digits form 10: 1 × 10¹⁰.

Console.WriteLine(fraction == 0.123456); // True
Console.WriteLine(large == 10_000_000_000D); // True

// double bad = 1e_3;  // Invalid beside the exponent marker.
// double bad = 1e+_3; // Invalid beside the exponent sign.
```

## 5. Literal Type Selection and Constant Expressions

### Unsuffixed integer literals

The compiler selects the first type that can hold the literal: **int → uint → long → ulong**. An integer literal exceeding `ulong`'s range is a compile-time error.

```csharp
var first = 42;                         // int
var second = 3_000_000_000;              // uint
var third = 5_000_000_000;               // long
var fourth = 10_000_000_000_000_000_000; // ulong

Console.WriteLine(second.GetType().Name); // UInt32
Console.WriteLine(third.GetType().Name);  // Int64
Console.WriteLine(fourth.GetType().Name); // UInt64
```

In `-42`, the minus sign is the unary negation operator applied to the literal `42`.

### Literal type versus variable type

```csharp
long large = 42;  // int literal implicitly converted to long.
byte small = 200; // In-range integer constant may convert to byte.
float speed = 1.5F;

// byte invalid = 300; // Outside byte's range.
// float wrong = 1.5;  // double literal needs F or an explicit conversion.

Console.WriteLine(large.GetType().Name); // Int64
Console.WriteLine(small.GetType().Name); // Byte
```

### An in-range constant differs from an ordinary variable

```csharp
const int Limit = 200;
byte first = Limit; // Valid: compiler knows the constant fits.

int limit = 200;
// byte second = limit; // Invalid without an explicit conversion.

Console.WriteLine(first); // 200
```

The compiler does not apply the special constant conversion merely because a non-constant variable currently holds a small number.

The destination type does not automatically change the type of every operand in the expression.

```csharp
// long area = 50_000 * 50_000; // Compile-time int overflow before assignment.
long area = 50_000L * 50_000;   // Multiplication now uses long.
Console.WriteLine(area);        // 2500000000
```

### Constant expressions

A constant expression can be evaluated during compilation. It can combine literals, constants, and permitted operators.

```csharp
const int Width = 8;
const int Height = 4;
const int Area = Width * Height;
const string Language = "C" + "#";

Console.WriteLine(Area);     // 32
Console.WriteLine(Language); // C#

// const int year = DateTime.Now.Year; // Requires runtime evaluation.
// const int size = Math.Abs(-5);     // Ordinary method calls are not constant expressions.
```

`8` is a literal; `Width * Height` is a constant expression. A `readonly` field is not a compile-time constant, even when initialized with a literal.

### Constant strings and interpolation

```csharp
const string Language = "C#";
const string Title = $"Learn {Language}"; // Interpolated part is a constant string.
const string MemberName = nameof(Console.WriteLine);

Console.WriteLine(Title);      // Learn C#
Console.WriteLine(MemberName); // WriteLine

// const string Count = $"Count: {10}"; // Numeric formatting is not constant interpolation.
```

Constant interpolation requires constant string expressions inside the braces. `nameof` also produces a compile-time string constant.

### Constant overflow

```csharp
// const int invalid = int.MaxValue + 1; // Compile-time overflow.
const int wrapped = unchecked(int.MaxValue + 1);
Console.WriteLine(wrapped); // -2147483648
```

Use `unchecked` only when integer wraparound is intentional; otherwise choose a type with enough range.
