# 05.08 Unsafe Code

## unsafe contexts and compiler settings

Unsafe code permits pointer operations that ordinary managed code restricts. Enable it in the project:

```xml
<PropertyGroup>
  <AllowUnsafeBlocks>true</AllowUnsafeBlocks>
</PropertyGroup>
```

The setting permits unsafe code; an `unsafe` context is still required around pointer syntax.

## Pointers, address-of, and dereferencing

```csharp
unsafe
{
    int value = 10;
    int* pointer = &value; // Address of local storage.
    *pointer = 20;        // Write through the pointer.
    Console.WriteLine(value); // 20
}
```

`&` takes an address; unary `*` reads or writes the pointed-to location. A pointer does not automatically track ownership, bounds, or the lifetime of its target.

## Pointer arithmetic and bounds

```csharp
unsafe
{
    int* values = stackalloc int[3];
    values[0] = 10;
    values[1] = 20;
    values[2] = 30;
    Console.WriteLine(*(values + 1)); // 20
}
```

Adding one advances by one element, not necessarily one byte. Pointer indexing does not supply the bounds checks of an array or span.

## fixed and pinning

```csharp
int[] values = { 10, 20 };
unsafe
{
    fixed (int* pointer = values)
    {
        pointer[1] = 99;
    } // Pointer must not be used after the pinning lifetime ends.
}
Console.WriteLine(values[1]); // 99
```

Pinning prevents relocation of the relevant managed object during the fixed region. It does not make out-of-bounds access safe or transfer ownership to native code.

## stackalloc

For bounded temporary buffers, a span-backed allocation can avoid raw pointer operations:

```csharp
Span<byte> buffer = stackalloc byte[16];
buffer.Clear();
Console.WriteLine(buffer.Length); // 16
```

Keep stack allocations small and bounded. Contents should be initialized before reading. Avoid repeated unbounded stack allocation inside loops.

## Managed function pointers

```csharp
unsafe
{
    delegate*<int, int> operation = &Double;
    Console.WriteLine(operation(4)); // 8
}
static int Double(int value) => value * 2;
```

A function pointer identifies callable code rather than a managed delegate object. It does not capture a target object or closure.

## Unmanaged function pointers

```csharp
using System.Runtime.CompilerServices;
using System.Runtime.InteropServices;

unsafe
{
    delegate* unmanaged[Cdecl]<int, int> callback = &Callbacks.Double;
    Console.WriteLine(callback(4)); // 8
}
static class Callbacks
{
    [UnmanagedCallersOnly(CallConvs = new[] { typeof(CallConvCdecl) })]
    public static int Double(int value) => value * 2;
}
```

The signature and calling convention must match the native contract. An `UnmanagedCallersOnly` method is not called as an ordinary managed method.

## Alignment, lifetime, and corruption

Do not dereference freed, uninitialized, misaligned, or out-of-range pointers. The compiler does not prove those native contracts for you. Prefer spans, safe handles, and established interop APIs unless pointer control is needed for a measured or platform-defined reason.
