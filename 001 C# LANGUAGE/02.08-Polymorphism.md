# 02.08 Polymorphism

## Compile-time overload resolution

Overload resolution chooses between methods using compile-time argument information, except when dynamic binding is involved.

```csharp
object value = "hello";
Console.WriteLine(Formatter.Format(value)); // Object overload
Console.WriteLine(Formatter.Format("hello")); // String overload

static class Formatter
{
    public static string Format(object value) => "Object overload";
    public static string Format(string value) => "String overload";
}
```

The actual string inside `value` does not make the compiler choose the string overload when the argument is statically typed `object`.

## Runtime virtual dispatch

For a virtual call, the runtime object determines which override runs.

```csharp
Animal animal = new Dog();
animal.Speak(); // Woof

class Animal
{
    public virtual void Speak() => Console.WriteLine("Animal sound");
}
class Dog : Animal
{
    public override void Speak() => Console.WriteLine("Woof");
}
```

## virtual and override

`virtual` permits replacement in a derived class; `override` supplies the replacement. The inherited member must be virtual, abstract, or already overridden and not sealed.

An override must honor the inherited contract. Use `base.Method()` when deliberately extending the base behavior rather than entirely replacing it.

## Member hiding with new

Hiding introduces another member selected through the reference's declared type; it does not override the base virtual slot.

```csharp
Child child = new Child();
Parent parent = child;
child.Show(); // Child
parent.Show(); // Parent

class Parent
{
    public void Show() => Console.WriteLine("Parent");
}
class Child : Parent
{
    public new void Show() => Console.WriteLine("Child");
}
```

`new` makes intentional hiding explicit. Omitting it in this case normally produces a warning, not runtime overriding.

## sealed classes and sealed overrides

```csharp
Base item = new FinalBehavior();
item.Print(); // Final behavior

class Base
{
    public virtual void Print() => Console.WriteLine("Base");
}
class FinalBehavior : Base
{
    public sealed override void Print() => Console.WriteLine("Final behavior");
}
sealed class Leaf : FinalBehavior { }
```

`sealed override` prevents further overriding of that member. `sealed class` prevents deriving from the class. A sealed override does not by itself seal the containing class.

## Declared type versus runtime type

- Declared type controls which members are available at compile time and influences overload selection.
- Runtime type supplies the implementation selected for a virtual or interface dispatch.
- An upcast changes the reference's available compile-time view, not the object's runtime type.
- Prefer polymorphic calls over repeated type checks when all implementations share a meaningful operation.
