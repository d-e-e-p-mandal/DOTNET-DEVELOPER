## 1. Build Collection Query Pipelines

A **collection query pipeline** processes a collection through multiple LINQ operations.

A typical pipeline contains:

```text
SOURCE
   │
   ▼
FILTER
   │
   ▼
TRANSFORM
   │
   ▼
SORT
   │
   ▼
MATERIALIZE
   │
   ▼
RESULT
```

### Example

```csharp
int[] numbers = { 10, 5, 20, 15, 30 };

int[] result = numbers
    .Where(x => x >= 10)
    .Select(x => x * 2)
    .OrderBy(x => x)
    .ToArray();

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
20, 30, 40, 60
```

### Execution

```text
Input:
10, 5, 20, 15, 30

Filter >= 10:
10, 20, 15, 30

Multiply by 2:
20, 40, 30, 60

Sort:
20, 30, 40, 60
```

### Important principles

- Keep transformations focused.
- Prefer pure predicates and selectors.
- Avoid unnecessary intermediate collections.
- Materialize results when a stable collection is required.

**Key point:** Collection pipelines combine small operations into a complete data-processing workflow.

## 2. Build Search and Filtering Pipelines

Search pipelines retrieve elements matching one or more conditions.

### Example: Product search

```csharp
public record Product(
    int Id,
    string Name,
    decimal Price,
    string Category
);
```

```csharp
Product[] products =
{
    new(1, "Laptop", 50000m, "Electronics"),
    new(2, "Mouse", 500m, "Electronics"),
    new(3, "Keyboard", 1500m, "Electronics"),
    new(4, "Chair", 3000m, "Furniture")
};

string keyword = "key";
decimal maximumPrice = 2000m;

var result = products
    .Where(p => p.Name.Contains(
        keyword,
        StringComparison.OrdinalIgnoreCase))
    .Where(p => p.Price <= maximumPrice);

foreach (var product in result)
{
    Console.WriteLine(product.Name);
}
```

**Output:**

```text
Keyboard
```

### Search pipeline

```text
Products
   │
   ▼
Name Contains "key"
   │
   ▼
Price <= 2000
   │
   ▼
Matching Products
```

For in-memory LINQ, `StringComparison.OrdinalIgnoreCase` provides case-insensitive matching. For database-backed `IQueryable<T>`, string-comparison overload support depends on the query provider.

**Key point:** Search pipelines combine predicates to narrow a collection to matching elements.

## 3. Build Sorting and Pagination Pipelines

Sorting determines result order.

Pagination divides ordered results into smaller pages.

### Example

```csharp
int[] numbers =
{
    50, 10, 40, 20, 30, 60, 70
};

int pageNumber = 2;
int pageSize = 3;

int[] result = numbers
    .OrderBy(x => x)
    .Skip((pageNumber - 1) * pageSize)
    .Take(pageSize)
    .ToArray();

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
40, 50, 60
```

### Execution

```text
Sorted:
10, 20, 30, 40, 50, 60, 70

Page 1:
10, 20, 30

Page 2:
40, 50, 60

Page 3:
70
```

### Reusable pagination function

```csharp
static IEnumerable<T> Paginate<T>(
    IEnumerable<T> source,
    int pageNumber,
    int pageSize)
{
    if (pageNumber < 1)
        throw new ArgumentOutOfRangeException(
            nameof(pageNumber));

    if (pageSize < 1)
        throw new ArgumentOutOfRangeException(
            nameof(pageSize));

    int skip = checked((pageNumber - 1) * pageSize);

    return source
        .Skip(skip)
        .Take(pageSize);
}
```

Usage:

```csharp
var page = Paginate(
    Enumerable.Range(1, 20),
    2,
    5
);

Console.WriteLine(string.Join(", ", page));
```

**Output:**

```text
6, 7, 8, 9, 10
```

For reliable pagination, apply a deterministic ordering before `Skip()` and `Take()`.

**Key point:** Sorting and pagination should be combined to produce predictable pages of data.

## 5. Build Grouped Reports

Grouped reports organize data into categories and calculate information for each category.

### Example

Using the `Sale` record from Point 4:

```csharp
Sale[] sales =
{
    new("Laptop", 2, 50000m),
    new("Mouse", 5, 500m),
    new("Laptop", 1, 50000m),
    new("Mouse", 3, 500m)
};

var report = sales
    .GroupBy(s => s.Product)
    .Select(group => new
    {
        Product = group.Key,
        Quantity = group.Sum(x => x.Quantity),
        Revenue = group.Sum(
            x => x.Quantity * x.UnitPrice)
    })
    .OrderBy(x => x.Product);

foreach (var item in report)
{
    Console.WriteLine(
        $"{item.Product}: {item.Quantity}, {item.Revenue}");
}
```

**Output:**

```text
Laptop: 3, 150000
Mouse: 8, 4000
```

### Grouping structure

```text
SALES
  │
  ▼
GROUP BY PRODUCT
  │
  ├── Laptop
  │      ├── Quantity
  │      └── Revenue
  │
  └── Mouse
         ├── Quantity
         └── Revenue
```

**Key point:** `GroupBy()` organizes related records into groups that can be independently summarized.

## 7. Build Inner Joins

An **inner join** combines elements from two collections when their keys match.

Unmatched elements are excluded.

### Example

```csharp
public record Employee(
    int Id,
    string Name,
    int DepartmentId
);

public record Department(
    int Id,
    string Name
);
```

```csharp
Employee[] employees =
{
    new(1, "Amit", 10),
    new(2, "Rahul", 20),
    new(3, "Priya", 30)
};

Department[] departments =
{
    new(10, "IT"),
    new(20, "HR")
};

var result = employees.Join(
    departments,
    employee => employee.DepartmentId,
    department => department.Id,
    (employee, department) => new
    {
        Employee = employee.Name,
        Department = department.Name
    }
);

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.Employee} - {item.Department}");
}
```

**Output:**

```text
Amit - IT
Rahul - HR
```

Priya is excluded because department `30` does not exist.

### Inner join

```text
EMPLOYEES           DEPARTMENTS

Amit   → 10 ─────── 10 → IT

Rahul  → 20 ─────── 20 → HR

Priya  → 30         No Match
```

**Key point:** `Join()` returns matching combinations from two collections.

## 8. Build Group Joins

A **group join** associates each element in one collection with a group of matching elements from another collection.

### Example

Using the `Employee` and `Department` records from Point 7:

```csharp
var result = departments.GroupJoin(
    employees,
    department => department.Id,
    employee => employee.DepartmentId,
    (department, matchingEmployees) => new
    {
        Department = department.Name,
        Employees = matchingEmployees.ToArray()
    }
);

foreach (var group in result)
{
    Console.WriteLine(group.Department);

    foreach (var employee in group.Employees)
    {
        Console.WriteLine($"  {employee.Name}");
    }
}
```

**Output:**

```text
IT
  Amit
HR
  Rahul
```

### Group join structure

```text
DEPARTMENT
    │
    ▼
MATCHING EMPLOYEE GROUP
    │
    ├── Employee 1
    ├── Employee 2
    └── Employee 3
```

A department with no matching employees still appears, with an empty employee group.

**Key point:** `GroupJoin()` represents one-to-many relationships without flattening the matching elements.

## 9. Build Left Outer Joins

A **left outer join** returns every element from the left collection, including those without a matching element on the right.

### Example

Using the records and collections from Point 7:

```csharp
var result = employees
    .GroupJoin(
        departments,
        employee => employee.DepartmentId,
        department => department.Id,
        (employee, matches) => new
        {
            employee,
            matches
        })
    .SelectMany(
        item => item.matches.DefaultIfEmpty(),
        (item, department) => new
        {
            Employee = item.employee.Name,
            Department = department?.Name ?? "Unknown"
        });

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.Employee} - {item.Department}");
}
```

**Output:**

```text
Amit - IT
Rahul - HR
Priya - Unknown
```

### Comparison

| Join Type | Unmatched Left Elements |
|---|---|
| Inner join | Excluded |
| Group join | Included with empty group |
| Left outer join | Included with missing right value |

**Key point:** A left outer join preserves all left-side records.

## 10. Build Data Reconciliation Queries

**Data reconciliation** compares two datasets to identify matches, missing records, and differences.

### Example

```csharp
int[] sourceA = { 1, 2, 3, 4 };

int[] sourceB = { 3, 4, 5, 6 };

int[] matched = sourceA
    .Intersect(sourceB)
    .OrderBy(x => x)
    .ToArray();

int[] onlyA = sourceA
    .Except(sourceB)
    .OrderBy(x => x)
    .ToArray();

int[] onlyB = sourceB
    .Except(sourceA)
    .OrderBy(x => x)
    .ToArray();

Console.WriteLine(
    $"Matched: {string.Join(", ", matched)}");

Console.WriteLine(
    $"Only A: {string.Join(", ", onlyA)}");

Console.WriteLine(
    $"Only B: {string.Join(", ", onlyB)}");
```

**Output:**

```text
Matched: 3, 4
Only A: 1, 2
Only B: 5, 6
```

### Reconciliation

```text
SOURCE A       SOURCE B
1              3
2              4
3              5
4              6

MATCHED: 3, 4
ONLY A: 1, 2
ONLY B: 5, 6
```

`Intersect()` and `Except()` use set semantics, so duplicates are not preserved in these results.

**Key point:** Reconciliation queries identify shared, missing, and unmatched data.

## 11. Build Duplicate Detection

```csharp
int[] numbers =

    Console.WriteLine(
        $"{item.Value}: {item.Count}");

```

**Output:**


```text
INPUT
  │
  ▼

  │
  ▼

  │
  ▼

  │
  ▼
```

**Key point:** Grouping and counting provide a direct method for detecting duplicates.

## 16. Build Composable Validation Rules

Composable validation combines small validation functions into larger rules.

### Example

```csharp
static bool IsPositive(int number)
{
    return number > 0;
}

static bool IsLessThanHundred(int number)
{
    return number < 100;
}
```

### Compose predicates

```csharp
static Func<T, bool> And<T>(
    Func<T, bool> first,
    Func<T, bool> second)
{
    return value =>
        first(value) && second(value);
}
```

### Usage

```csharp
Func<int, bool> valid =
    And<int>(
        IsPositive,
        IsLessThanHundred
    );

Console.WriteLine(valid(50));
Console.WriteLine(valid(-5));
Console.WriteLine(valid(150));
```

**Output:**

```text
True
False
False
```

### Validation composition

```text
INPUT
  │
  ▼
RULE 1
  │
  ▼
RULE 2
  │
  ▼
VALID / INVALID
```

The `&&` operator short-circuits, so the second rule is evaluated only when the first succeeds.

**Key point:** Composable validation builds complex rules from small reusable predicates.

## 17. Build Pure Pricing Calculations

Pure pricing functions calculate prices using explicit inputs without accessing external state.

### Example

```csharp
static decimal CalculateFinalPrice(
    decimal price,
    decimal discountRate,
    decimal taxRate)
{
    decimal discounted =
        price * (1 - discountRate);

    return discounted * (1 + taxRate);
}
```

Usage:

```csharp
decimal result = CalculateFinalPrice(
    1000m,
    0.10m,
    0.18m
);

Console.WriteLine(result);
```

**Output:**

```text
1062.0000
```

### Calculation

```text
Original Price = 1000

Discount = 10%

Discounted Price = 900

Tax = 18%

Final Price = 1062
```

### Pure-function characteristics

- Same inputs produce the same result.
- No database access.
- No configuration lookup.
- No mutation of external variables.
- Easy to test independently.

The example assumes valid rates and does not apply currency-specific rounding rules.

**Key point:** Pure pricing calculations make business rules deterministic and reusable.

## 20. Reconcile Two Data Sources by Business Key

A **business key** identifies an entity using a meaningful value, such as an employee code or product SKU.

Reconciliation by business key compares corresponding records across datasets.

### Example

```csharp
public record Product(
    string Sku,
    decimal Price
);
```

```csharp
Product[] sourceA =
{
    new("A100", 100m),
    new("B200", 200m),
    new("C300", 300m)
};

Product[] sourceB =
{
    new("A100", 100m),
    new("B200", 250m),
    new("D400", 400m)
};
```

### Compare matching records

```csharp
var differences = sourceA.Join(
    sourceB,
    a => a.Sku,
    b => b.Sku,
    (a, b) => new
    {
        a.Sku,
        PriceA = a.Price,
        PriceB = b.Price
    })
    .Where(x => x.PriceA != x.PriceB);

foreach (var item in differences)
{
    Console.WriteLine(
        $"{item.Sku}: {item.PriceA} vs {item.PriceB}");
}
```

**Output:**

```text
B200: 200 vs 250
```

### Find missing business keys

```csharp
var keysA = sourceA.Select(x => x.Sku);
var keysB = sourceB.Select(x => x.Sku);

Console.WriteLine(
    $"Only A: {string.Join(", ", keysA.Except(keysB))}");

Console.WriteLine(
    $"Only B: {string.Join(", ", keysB.Except(keysA))}");
```

**Output:**

```text
Only A: C300
Only B: D400
```

This example assumes each SKU uniquely identifies one product within each source.

**Key point:** Business-key reconciliation identifies missing records and inconsistent values across datasets.

## 21. Handle Null and Empty Inputs

Queries should define how they handle null references and empty collections.

### Example: Null-safe filtering

```csharp
static IEnumerable<int> GetPositive(
    IEnumerable<int>? numbers)
{
    return (numbers ?? Enumerable.Empty<int>())
        .Where(x => x > 0);
}
```

Usage:

```csharp
var result1 = GetPositive(null);
var result2 = GetPositive(Array.Empty<int>());
var result3 = GetPositive(new[] { -2, 3, 5 });

Console.WriteLine(result1.Count());
Console.WriteLine(result2.Count());
Console.WriteLine(
    string.Join(", ", result3));
```

**Output:**

```text
0
0
3, 5
```

### Important distinction

| Input | Meaning |
|---|---|
| `null` | No sequence reference |
| Empty sequence | Valid sequence containing no elements |
| Nonempty sequence | Sequence containing values |

Treating `null` as empty is a design choice, not a universal requirement.

**Key point:** Null and empty input behavior should be explicit and consistent.

## 22. Handle Duplicate Data

Duplicate data can affect joins, aggregations, and reports.

### Example

```csharp
int[] numbers =
{
    1, 2, 2, 3, 3, 3
};

int[] unique = numbers
    .Distinct()
    .OrderBy(x => x)
    .ToArray();

Console.WriteLine(string.Join(", ", unique));
```

**Output:**

```text
1, 2, 3
```

### Detect duplicates

```csharp
var duplicates = numbers
    .GroupBy(x => x)
    .Where(group => group.Count() > 1)
    .Select(group => group.Key);

Console.WriteLine(
    string.Join(", ", duplicates));
```

**Output:**

```text
2, 3
```

### Duplicate handling strategies

| Strategy | Purpose |
|---|---|
| `Distinct()` | Remove duplicate values |
| `DistinctBy()` | Remove duplicates by selected key |
| `GroupBy()` | Group duplicate records |
| `ToHashSet()` | Build a collection of unique values |
| Validation | Reject duplicates when uniqueness is required |

**Key point:** Duplicate handling depends on whether duplicates are valid, unwanted, or meaningful.

## 23. Handle Missing Relationships

Missing relationships occur when a record references another record that does not exist.

### Example

```csharp
public record Employee(
    string Name,
    int DepartmentId
);

public record Department(
    int Id,
    string Name
);
```

```csharp
Employee[] employees =
{
    new("Amit", 1),
    new("Rahul", 2),
    new("Priya", 3)
};

Department[] departments =
{
    new(1, "IT"),
    new(2, "HR")
};
```

### Detect missing departments

```csharp
var missing = employees
    .GroupJoin(
        departments,
        employee => employee.DepartmentId,
        department => department.Id,
        (employee, matches) => new
        {
            employee,
            HasDepartment = matches.Any()
        })
    .Where(x => !x.HasDepartment)
    .Select(x => x.employee.Name);

Console.WriteLine(
    string.Join(", ", missing));
```

**Output:**

```text
Priya
```

### Missing relationship handling

```text
EMPLOYEE
    │
    ▼
FIND DEPARTMENT
    │
    ├── Found → Continue
    │
    └── Missing → Report / Default / Reject
```

**Key point:** Queries should deliberately handle records whose related entities are missing.

### Repeated enumeration

```csharp
numbers.ToArray();
```

The predicate executes again.

## 26. Measure Allocation Costs

### Allocation sources

| Operation | Possible Allocation |
|---|---|
| `ToArray()` | Array |

## 27. Measure Materialization Costs

Materialization converts a deferred sequence into a concrete collection.

### Example

```csharp
IEnumerable<int> query = Enumerable.Range(1, 100000)
    .Where(x => x % 2 == 0);
```

At this point, the query has not been enumerated.

### Materialization

```csharp
var stopwatch = Stopwatch.StartNew();

int[] result = query.ToArray();

stopwatch.Stop();

Console.WriteLine(result.Length);
```

**Output:**

```text
50000
```

### Materialization comparison

| Deferred Query | Materialized Collection |
|---|---|
| May re-execute | Stores calculated results |
| Can avoid storing all results | Requires memory |
| Useful for streaming | Useful for repeated access |
| Observes source at enumeration time | Captures results when materialized |

**Key point:** Materialize when the benefits of stable results or repeated access justify the cost.

## 28. Diagnose Multiple Enumeration

Multiple enumeration occurs when the same deferred sequence is enumerated repeatedly.

### Example

```csharp
int counter = 0;

var query = Enumerable.Range(1, 3)
    .Select(x =>
    {
        counter++;
        return x * 2;
    });

int count = query.Count();

int sum = query.Sum();

Console.WriteLine(count);
Console.WriteLine(sum);
Console.WriteLine(counter);
```

**Output:**

```text
3
12
6
```

The selector executes twice for each element.

### Solution

```csharp
int[] values = query.ToArray();

int count = values.Length;
int sum = values.Sum();
```

Materialization avoids re-executing the selector on subsequent operations.

**Key point:** Diagnose repeated enumeration when a deferred query is consumed multiple times.

## 29. Diagnose Deferred-Execution Bugs

Deferred execution means a query may execute after the source data has changed.

### Example

```csharp
List<int> numbers = new()
{
    1, 2, 3
};

var query = numbers.Where(x => x > 1);

numbers.Add(4);

Console.WriteLine(
    string.Join(", ", query));
```

**Output:**

```text
2, 3, 4
```

The query observes the updated collection.

### Stable snapshot

```csharp
List<int> numbers = new()
{
    1, 2, 3
};

int[] result = numbers
    .Where(x => x > 1)
    .ToArray();

numbers.Add(4);

Console.WriteLine(
    string.Join(", ", result));
```

**Output:**

```text
2, 3
```

**Key point:** Deferred queries should be materialized when a stable result snapshot is required.

## 30. Diagnose Closure Bugs

A closure captures variables from an enclosing scope.

Capturing mutable variables can produce unexpected results.

### Example

```csharp
List<Func<int>> functions = new();

for (int i = 0; i < 3; i++)
{
    functions.Add(() => i);
}

foreach (var function in functions)
{
    Console.WriteLine(function());
}
```

**Output:**

```text
3
3
3
```

All lambdas capture the same loop variable.

### Solution

```csharp
List<Func<int>> functions = new();

for (int i = 0; i < 3; i++)
{
    int copy = i;

    functions.Add(() => copy);
}

foreach (var function in functions)
{
    Console.WriteLine(function());
}
```

**Output:**

```text
0
1
2
```

### Explanation

```text
INCORRECT:
All lambdas → Same variable

CORRECT:
Each lambda → Separate local variable
```

**Key point:** Be careful when lambdas capture mutable variables.

## 31. Refactor Imperative Loops into LINQ

LINQ can replace loops that primarily filter, transform, or aggregate data.

### Imperative version

```csharp
List<int> result = new();

foreach (int number in numbers)
{
    if (number % 2 == 0)
    {
        result.Add(number * 2);
```

### LINQ version

```csharp
int[] numbers = { 1, 2, 3, 4, 5, 6 };

var result = numbers

    .ToList();

Console.WriteLine(

```

**Output:**

```text
4, 8, 12
```

### Comparison

| Imperative Loop | LINQ |
|---|---|
| Explicit iteration | Declarative operations |
| Manual result accumulation | Built-in operators |
| Useful for complex control flow | Useful for data transformations |
| Direct execution | May use deferred execution |

**Key point:** Refactor loops into LINQ when it improves clarity without hiding important behavior.

## 32. Refactor Overcomplicated LINQ into Loops

LINQ is not always the clearest choice.

Complex stateful operations may be easier to express using loops.

### Example: Running total

```csharp
int[] numbers = { 10, 20, 30 };

List<int> runningTotals = new();

int total = 0;

foreach (int number in numbers)
{
    total += number;

    runningTotals.Add(total);
}

Console.WriteLine(
    string.Join(", ", runningTotals));
```

**Output:**

```text
10, 30, 60
```

A loop makes the evolving accumulator explicit.

### When loops may be preferable

- Complex control flow.
- Early `break` or `continue`.
- Stateful algorithms.
- Performance-sensitive operations.
- Multiple coordinated mutations.

**Key point:** Prefer the implementation that expresses the algorithm most clearly.

## 33. Choose IEnumerable<T> vs IQueryable<T>

`IEnumerable<T>` represents a sequence that can be enumerated.

`IQueryable<T>` represents a query that may be translated by a query provider.

### IEnumerable example

```csharp
IEnumerable<int> numbers =
    Enumerable.Range(1, 10);

var result = numbers.Where(x => x > 5);
```

This uses LINQ-to-Objects.

### IQueryable example

```csharp
IQueryable<Product> query =
    dbContext.Products.Where(p => p.Price > 1000m);
```

In a supported database provider, the expression may be translated into a database query.

The second example assumes an application-defined `DbContext` and `Product` entity.

### Comparison

| IEnumerable<T> | IQueryable<T> |
|---|---|
| Enumerable sequence | Provider-backed query abstraction |
| Uses delegates for LINQ-to-Objects | Uses expression trees for query operators |
| Common for in-memory data | Common for database queries |
| Executes using enumeration | Provider controls execution |
| Supports ordinary C# functions | Translation support varies |

**Key point:** Choose based on where and how the query should execute.

## 34. Choose GroupBy vs ToLookup

Both operations organize elements by key.

### GroupBy

```csharp
var groups = numbers.GroupBy(x => x % 2);
```

`GroupBy()` is deferred in LINQ-to-Objects.

### ToLookup

```csharp
var lookup = numbers.ToLookup(x => x % 2);
```

`ToLookup()` immediately creates a lookup.

### Comparison

| GroupBy | ToLookup |
|---|---|
| Deferred | Immediate |
| Produces groups during enumeration | Builds a reusable lookup |
| Useful for grouped processing | Useful for repeated key-based access |
| Supports query pipelines | Supports indexed access by key |

**Key point:** Use `GroupBy()` for grouped query processing and `ToLookup()` for reusable key-based grouping.

## 35. Choose Dictionary vs Lookup

A dictionary associates a unique key with one value.

A lookup associates a key with multiple values.

### Dictionary

```csharp
Dictionary<int, string> employees = new()
{
    [1] = "Amit",
    [2] = "Rahul"
};

Console.WriteLine(employees[1]);
```

**Output:**

```text
Amit
```

### Lookup

```csharp
var lookup = new[]
{
    (Department: "IT", Name: "Amit"),
    (Department: "IT", Name: "Priya"),
    (Department: "HR", Name: "Rahul")
}
.ToLookup(x => x.Department);

foreach (var employee in lookup["IT"])
{
    Console.WriteLine(employee.Name);
}
```

**Output:**

```text
Amit
Priya
```

### Comparison

| Dictionary | Lookup |
|---|---|
| One value per key | Multiple values per key |
| Mutable by default | `ToLookup()` produces a read-only grouping structure |
| Key must be unique | Repeated keys are expected |
| Direct key-value access | Key-to-group access |

**Key point:** Choose a dictionary for unique-key mappings and a lookup for one-to-many relationships.

## 36. Choose HashSet vs Set Operators

```csharp
HashSet<int> values = new()
```

```csharp
int[] first = { 1, 2, 3 };
```

**Output:**

```text
3
```

### Comparison

| HashSet<T> | LINQ Set Operators |
|---|---|
| Persistent collection | Sequence operations |
| Supports `Add()` and `Remove()` | Produces query results |
| Useful for repeated membership checks | Useful for set comparisons |
| Maintains unique elements | Uses set semantics |

**Key point:** Use `HashSet<T>` when maintaining a set; use LINQ set operators when computing relationships between sequences.

## 37. Choose First vs Single

`Single()` requires exactly one matching element.

### Example

### Single

```csharp
int[] numbers = { 5 };
```

### Comparison

| Operation | Empty | Multiple Matches |
|---|---|---|
| `First()` | Throws | Returns first |

| `Single()` | Throws | Throws |
| `SingleOrDefault()` | Returns default | Throws |

## 38. Choose Any vs Count

`Any()` checks whether at least one element exists or matches a predicate.

`Count()` counts elements.

### Any

```csharp
int[] numbers = { 1, 2, 3 };

bool exists = numbers.Any(x => x > 2);

Console.WriteLine(exists);
```

**Output:**

```text
True
```

### Count

```csharp
int count = numbers.Count(x => x > 2);

Console.WriteLine(count);
```

**Output:**

```text
1
```

### Comparison

| Any | Count |
|---|---|
| Returns `bool` | Returns `int` |
| Checks existence | Counts matches |
| Can stop at first match | Must determine total matches |
| Prefer for existence checks | Prefer when actual count is needed |

**Key point:** Use `Any()` for existence checks and `Count()` when the number of matches matters.

## 39. Choose Select vs SelectMany

`Select()` transforms each input element into one output value.

`SelectMany()` transforms each input into a sequence and flattens the resulting sequences.

### Select

```csharp
int[] numbers = { 1, 2, 3 };

var result = numbers.Select(x => x * 2);

Console.WriteLine(
    string.Join(", ", result));
```

**Output:**

```text
2, 4, 6
```

### SelectMany

```csharp
int[][] numbers =
{
    new[] { 1, 2 },
    new[] { 3, 4 }
};

var result = numbers.SelectMany(x => x);

Console.WriteLine(
    string.Join(", ", result));
```

**Output:**

```text
1, 2, 3, 4
```

### Comparison

```text
Select:

Input → Output

1 → 2
2 → 4
3 → 6
```

```text
SelectMany:

Input → Sequence → Flatten

[1, 2]
[3, 4]

   ↓

1, 2, 3, 4
```

**Key point:** Use `Select()` for projection and `SelectMany()` for flattening nested sequences.

## 40. Choose Join vs GroupJoin

`Join()` produces matching pairs.

`GroupJoin()` produces one outer element associated with a group of matches.

### Join

```csharp
var result = employees.Join(
    departments,
    e => e.DepartmentId,
    d => d.Id,
    (e, d) => new
    {
        e.Name,
        Department = d.Name
    });
```

### GroupJoin

```csharp
var result = departments.GroupJoin(
    employees,
    d => d.Id,
    e => e.DepartmentId,
    (d, matches) => new
    {
        Department = d.Name,
        Employees = matches
    });
```

These snippets assume the `Employee` and `Department` models defined in Point 7.

### Comparison

| Join | GroupJoin |
|---|---|
| Matching pairs | Outer element with matching group |
| Flat output | Hierarchical output |
| Unmatched elements excluded | Outer elements preserved |
| Useful for relational combinations | Useful for one-to-many grouping |

**Key point:** Choose `Join()` for matching pairs and `GroupJoin()` for grouped relationships.

## 41. Choose Deferred vs Materialized Results

Deferred queries execute when enumerated.

Materialized results are stored in concrete collections.

### Deferred

```csharp
IEnumerable<int> query = numbers
    .Where(x => x > 10);
```

### Materialized

```csharp
int[] result = numbers
    .Where(x => x > 10)
    .ToArray();
```

### Comparison

| Deferred | Materialized |
|---|---|
| Delays execution | Executes immediately |
| Can observe later source changes | Stores results at materialization time |
| May repeat work | Can reuse stored results |
| Often uses less intermediate memory | Requires collection storage |

**Key point:** Choose deferred execution for streaming and composability; materialize when stable or repeatedly accessed results are required.

## 42. Choose LINQ vs foreach

LINQ expresses what data should be selected or transformed.

`foreach` expresses explicit iteration.

### LINQ

```csharp
int[] numbers = { 1, 2, 3, 4 };

var result = numbers
    .Where(x => x % 2 == 0)
    .Select(x => x * 2);
```

### foreach

```csharp
List<int> result = new();

foreach (int number in numbers)
{
    if (number % 2 == 0)
    {
        result.Add(number * 2);
    }
}
```

Both produce:

```text
4, 8
```

### Decision guide

| Use LINQ When | Use foreach When |
|---|---|
| Filtering data | Complex control flow |
| Projecting objects | Explicit mutation |
| Grouping records | Early exits |
| Joining collections | Stateful algorithms |
| Aggregating results | Multiple coordinated actions |

**Key point:** LINQ and `foreach` are complementary tools; choose based on readability and behavior.

## 43. Choose LINQ vs a Different Data Structure

Sometimes a different data structure is more appropriate than repeatedly querying a collection.

### Example: Repeated membership checks

Using LINQ:

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

bool exists = numbers.Contains(3);
```

For a single small search, this is reasonable.

For repeated membership checks, a `HashSet<T>` may be more efficient.

### HashSet

```csharp
HashSet<int> numbers = new()
{
    1, 2, 3, 4, 5
};

Console.WriteLine(numbers.Contains(3));
```

**Output:**

```text
True
```

### Example: Repeated key lookup

Instead of repeatedly searching:

```csharp
var employee = employees
    .FirstOrDefault(e => e.Id == employeeId);
```

Build a dictionary when IDs are unique:

```csharp
Dictionary<int, Employee> employeeById =
    employees.ToDictionary(e => e.Id);
```

Then:

```csharp
if (employeeById.TryGetValue(
    employeeId,
    out Employee? employee))
{
    Console.WriteLine(employee.Name);
}
```

### Data structure selection

| Requirement | Suitable Choice |
|---|---|
| Sequential processing | `IEnumerable<T>` |
| Repeated membership checks | `HashSet<T>` |
| Unique-key lookup | `Dictionary<TKey, TValue>` |
| One-to-many key lookup | `ILookup<TKey, TElement>` |
| Ordered indexed collection | `List<T>` or array |
| Immutable collection | Immutable collection types |
| Database query translation | `IQueryable<T>` |

### Complexity considerations

For a collection containing `n` elements:

| Operation | Typical Complexity |
|---|---|
| Linear search in array | O(n) |
| HashSet membership | O(1) average |
| Dictionary key lookup | O(1) average |
| LINQ sorting | O(n log n) |
| Single-pass filtering | O(n) |

Hash-based performance depends on hashing quality and implementation details.

**Key point:** Selecting an appropriate data structure can improve performance more than rewriting a LINQ expression.
