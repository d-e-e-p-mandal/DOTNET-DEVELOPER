# 06.11 — QUERY EXECUTION

**Chapter:** 06 — LINQ Fundamentals  
**Namespace:** `System.Linq`

LINQ query execution determines **when a query runs, how elements are processed, and whether results are calculated again during subsequent enumerations**.

This section follows the 19 topics in your master syllabus, focusing specifically on execution behavior without repeating the detailed operator notes from previous sections.

---

## 1. Query Declaration

Query declaration defines a LINQ query without necessarily executing it.

### Syntax

```csharp
var query = source.Where(condition);
```

### Example 1: Method Syntax

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

var query = numbers.Where(n => n > 2);

// Query declared
// No elements processed yet
```

### Example 2: Query Syntax

```csharp
var query =
    from n in numbers
    where n > 2
    select n;

// Query declared
```

### Example 3: Declaration with Side Effects

```csharp
var query = numbers.Where(n =>
{
    Console.WriteLine($"Checking {n}");
    return n > 2;
});

Console.WriteLine("Query created");
```

**Output:**

```text
Query created
```

The predicate has not executed because the query has not been enumerated.

**Key point:** Declaring a deferred LINQ query constructs its execution instructions, not its final results.

---

## 2. Query Execution

Query execution occurs when LINQ processes the source sequence to produce results.

### Example 1: Executing with foreach

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

var query = numbers.Where(n => n > 2);

foreach (int n in query)
{
    Console.WriteLine(n);
}
```

**Output:**

```text
3
4
5
```

### Example 2: Executing with ToList

```csharp
var query = numbers.Where(n => n > 2);

List<int> result = query.ToList();

// Result: 3, 4, 5
```

### Example 3: Executing with Count

```csharp
var query = numbers.Where(n => n > 2);

int count = query.Count();

Console.WriteLine(count);

// Output: 3
```

**Key point:** Execution can produce a sequence, materialize a collection, or calculate a single value.

---

## 3. Deferred Execution

Deferred execution postpones processing until the query is enumerated.

### Example 1: Query Executes Later

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

var query = numbers.Where(n =>
{
    Console.WriteLine($"Checking {n}");
    return n > 3;
});

Console.WriteLine("Before enumeration");

foreach (int n in query)
{
    Console.WriteLine($"Result: {n}");
}
```

**Output:**

```text
Before enumeration
Checking 1
Checking 2
Checking 3
Checking 4
Result: 4
Checking 5
Result: 5
```

### Example 2: Deferred Projection

```csharp
var query = numbers.Select(n =>
{
    Console.WriteLine($"Processing {n}");
    return n * 10;
});

// No processing yet

var result = query.ToArray();

// Processing occurs here
```

### Example 3: Query Never Enumerated

```csharp
var query = numbers.Where(n =>
{
    Console.WriteLine(n);
    return n > 2;
});

// No enumeration
// No output
```

**Key point:** Deferred execution allows query processing to happen only when results are requested.

---

## 4. Immediate Execution

Immediate execution evaluates a query at the point where a terminal operation is called.

### Example 1: ToList

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

var result = numbers
    .Where(n => n > 2)
    .ToList();

// Query executed immediately
// Result: 3, 4, 5
```

### Example 2: ToArray

```csharp
int[] result = numbers
    .Where(n => n % 2 == 0)
    .ToArray();

// Result: 2, 4
```

### Example 3: Count

```csharp
int count = numbers
    .Where(n => n > 3)
    .Count();

// Output: 2
```

### Example 4: Sum

```csharp
int sum = numbers
    .Where(n => n > 2)
    .Sum();

// Output: 12
```

**Important:** Immediate execution does not always mean creating a collection. Scalar operators execute immediately but return individual values.

---

## 5. Lazy Evaluation

Lazy evaluation processes elements only when they are needed.

### Example 1: Processing Elements One by One

```csharp
int[] numbers = { 1, 2, 3 };

var query = numbers.Select(n =>
{
    Console.WriteLine($"Transforming {n}");
    return n * 10;
});

foreach (int value in query)
{
    Console.WriteLine($"Received {value}");
}
```

**Output:**

```text
Transforming 1
Received 10
Transforming 2
Received 20
Transforming 3
Received 30
```

### Example 2: Only Required Elements

```csharp
var query = numbers.Select(n =>
{
    Console.WriteLine($"Processing {n}");
    return n * 10;
});

int first = query.First();

// Output:
// Processing 1

// first = 10
```

### Example 3: Partial Processing

```csharp
var result = numbers
    .Select(n =>
    {
        Console.WriteLine($"Processing {n}");
        return n * 10;
    })
    .Take(2)
    .ToList();
```

**Output:**

```text
Processing 1
Processing 2
```

**Key point:** Lazy evaluation avoids processing unnecessary elements when the operators support incremental execution.

## 6. Enumeration-Triggered Execution

Enumeration-triggered execution starts when a consumer requests elements from a deferred query.

### Example 1: foreach

```csharp
int[] numbers = { 1, 2, 3 };

var query = numbers.Where(n =>
{
    Console.WriteLine($"Checking {n}");
    return n > 1;
});

foreach (int n in query)
{
    Console.WriteLine(n);
}
```

**Output:**

```text
Checking 1
Checking 2
2
Checking 3
3
```

### Example 2: Manual Enumerator

```csharp
var query = numbers.Select(n =>
{
    Console.WriteLine($"Processing {n}");
    return n * 2;
});

using var enumerator = query.GetEnumerator();

Console.WriteLine("Enumerator created");

enumerator.MoveNext();

Console.WriteLine(enumerator.Current);
```

**Output:**

```text
Enumerator created
Processing 1
2
```

### Example 3: Multiple MoveNext Calls

```csharp
using var enumerator = query.GetEnumerator();

while (enumerator.MoveNext())
{
    Console.WriteLine(enumerator.Current);
}
```

**Key point:** For ordinary deferred iterator queries, `GetEnumerator()` prepares enumeration, while `MoveNext()` requests processing.

## 7. Materialization-Triggered Execution

Materialization evaluates a sequence and stores its elements in a concrete collection.

### Example 1: ToList

```csharp
int[] numbers = { 1, 2, 3, 4 };

var query = numbers.Where(n => n > 2);

List<int> result = query.ToList();

// Result: 3, 4
```

### Example 2: ToArray

```csharp
int[] result = numbers
    .Select(n => n * 10)
    .ToArray();

// Result: 10, 20, 30, 40
```

### Example 3: ToDictionary

```csharp
record Student(int Id, string Name);

Student[] students =
{
    new(1, "Amit"),
    new(2, "Rahul")
};

var result = students.ToDictionary(
    s => s.Id,
    s => s.Name
);

// 1 → Amit
// 2 → Rahul
```

### Example 4: Materialization Snapshot

```csharp
List<int> numbers = new() { 1, 2, 3 };

var query = numbers.Where(n => n > 1);

var result = query.ToList();

numbers.Add(4);

Console.WriteLine(string.Join(", ", result));

// Output: 2, 3
```

The materialized list does not automatically include later additions to the source.

**Note:** Materialization copies the sequence elements into a collection, but reference-type elements are not automatically deep-cloned.

## 8. Scalar Terminal Operators

Scalar terminal operators execute a query and return a single value instead of a sequence.

### Common Operators

| Operator | Result |
|---|---|
| `Count()` | Number of elements |
| `LongCount()` | Number of elements as `long` |
| `Any()` | Boolean |
| `All()` | Boolean |
| `First()` | First matching element |
| `Last()` | Last matching element |
| `Single()` | Exactly one matching element |
| `Sum()` | Total |
| `Average()` | Average |
| `Min()` | Minimum |
| `Max()` | Maximum |
| `Aggregate()` | Accumulated result |

### Example 1: Count

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

int result = numbers
    .Where(n => n > 2)
    .Count();

// Output: 3
```

### Example 2: Any

```csharp
bool result = numbers
    .Where(n => n > 3)
    .Any();

// Output: True
```

### Example 3: First

```csharp
int result = numbers
    .Where(n => n > 2)
    .First();

// Output: 3
```

### Example 4: Sum

```csharp
int result = numbers
    .Where(n => n > 2)
    .Sum();

// Output: 12
```

**Key point:** Scalar terminal operators execute when called, but they do not necessarily enumerate every element. For example, `Any()` can stop after finding one element.

## 9. Streaming Operators

Streaming operators can produce output incrementally without first consuming the entire source.

### Common Streaming Operators

```text
Where
Select
SelectMany
Skip
Take
SkipWhile
TakeWhile
Concat
```

### Example 1: Streaming Filter

```csharp
int[] numbers = { 1, 2, 3, 4 };

var query = numbers.Where(n =>
{
    Console.WriteLine($"Checking {n}");
    return n % 2 == 0;
});

foreach (int n in query)
{
    Console.WriteLine($"Result: {n}");
}
```

**Output:**

```text
Checking 1
Checking 2
Result: 2
Checking 3
Checking 4
Result: 4
```

### Example 2: Streaming Pipeline

```csharp
var query = numbers
    .Where(n => n > 1)
    .Select(n => n * 10);

foreach (int n in query)
{
    Console.WriteLine(n);
}

// Output: 20, 30, 40
```

### Example 3: Streaming with Early Stop

```csharp
var result = numbers
    .Where(n => n > 1)
    .Take(2)
    .ToList();

// Output: 2, 3
```

**Key point:** Streaming operators generally process only the source elements required to produce the next result.

## 10. Buffering Operators

Buffering operators store some or all source elements internally before producing certain results.

### Common Examples

| Operator | Buffering Behavior |
|---|---|
| `OrderBy()` | Buffers the source before producing sorted results |
| `OrderByDescending()` | Buffers the source before producing sorted results |
| `Reverse()` | Buffers a general enumerable source before reversing |
| `GroupBy()` | Builds groups before yielding them |
| `ToLookup()` | Immediately builds a lookup |
| `ToList()` | Materializes the entire sequence |
| `ToArray()` | Materializes the entire sequence |

### Example 1: OrderBy Buffering

```csharp
int[] numbers = { 3, 1, 2 };

var query = numbers
    .Select(n =>
    {
        Console.WriteLine($"Reading {n}");
        return n;
    })
    .OrderBy(n => n);

foreach (int n in query)
{
    Console.WriteLine($"Result: {n}");
}
```

**Output:**

```text
Reading 3
Reading 1
Reading 2
Result: 1
Result: 2
Result: 3
```

### Example 2: Reverse Buffering

```csharp
var query = numbers
    .Select(n =>
    {
        Console.WriteLine($"Reading {n}");
        return n;
    })
    .Reverse();

foreach (int n in query)
{
    Console.WriteLine($"Result: {n}");
}
```

**Output:**

```text
Reading 3
Reading 1
Reading 2
Result: 2
Result: 1
Result: 3
```

### Example 3: Deferred but Buffering

```csharp
var query = numbers.OrderBy(n => n);

// No sorting yet

var result = query.ToList();

// Sorting occurs during enumeration
```

**Important:** Deferred execution and streaming are different concepts. An operator can execute later but still buffer its input when enumeration begins.

## 11. Query Re-execution

A deferred query can execute again when it is enumerated again.

### Example

```csharp
int[] numbers = { 1, 2, 3 };

var query = numbers.Select(n =>
{
    Console.WriteLine($"Processing {n}");
    return n * 2;
});

Console.WriteLine("First execution");

foreach (int n in query)
{
    Console.WriteLine(n);
}

Console.WriteLine("Second execution");

foreach (int n in query)
{
    Console.WriteLine(n);
}
```

**Output:**

```text
First execution
Processing 1
2
Processing 2
4
Processing 3
6

Second execution
Processing 1
2
Processing 2
4
Processing 3
6
```

**Key point:** A normal deferred query does not automatically cache its results.

## 12. Repeated Enumeration

Repeated enumeration means traversing the same sequence multiple times.

### Example 1: Two foreach Loops

```csharp
int[] numbers = { 1, 2, 3, 4 };

var query = numbers.Where(n => n > 2);

foreach (int n in query)
{
    Console.WriteLine(n);
}

foreach (int n in query)
{
    Console.WriteLine(n);
}
```

**Output:**

```text
3
4
3
4
```

### Example 2: Count Followed by foreach

```csharp
var query = numbers.Where(n =>
{
    Console.WriteLine($"Checking {n}");
    return n > 2;
});

int count = query.Count();

foreach (int n in query)
{
    Console.WriteLine(n);
}
```

The predicate executes again during the second enumeration.

### Example 3: Avoid Repeated Enumeration

```csharp
var result = query.ToList();

int count = result.Count;

foreach (int n in result)
{
    Console.WriteLine(n);
}
```

**Key point:** Materialize a deferred query when its results must be reused and repeated execution would be costly.

## 13. Repeated Work

Repeated work occurs when the same query calculations are performed multiple times.

### Example 1: Expensive Calculation

```csharp
int Calculate(int n)
{
    Console.WriteLine($"Calculating {n}");
    return n * n;
}

int[] numbers = { 1, 2, 3 };

var query = numbers.Select(Calculate);

int firstSum = query.Sum();
int secondSum = query.Sum();
```

**Output:**

```text
Calculating 1
Calculating 2
Calculating 3
Calculating 1
Calculating 2
Calculating 3
```

### Example 2: Cache Results

```csharp
var result = numbers
    .Select(Calculate)
    .ToList();

int firstSum = result.Sum();
int secondSum = result.Sum();
```

**Output:**

```text
Calculating 1
Calculating 2
Calculating 3
```

### Example 3: Avoid Duplicate Database Queries

```csharp
// IQueryable<Student> query = db.Students.Where(s => s.Age > 18);

// var count = query.Count();
// var students = query.ToList();
```

For an EF Core database query, these operations normally issue separate database queries.

**Key point:** Repeated enumeration can repeat CPU work, file reads, or database operations depending on the source.

## 14. Source Changes Before Enumeration

Deferred queries can observe changes made to their source before enumeration.

### Example 1: Add Element

```csharp
List<int> numbers = new() { 1, 2, 3 };

var query = numbers.Where(n => n > 1);

numbers.Add(4);

foreach (int n in query)
{
    Console.WriteLine(n);
}
```

**Output:**

```text
2
3
4
```

### Example 2: Remove Element

```csharp
List<int> numbers = new() { 1, 2, 3, 4 };

var query = numbers.Where(n => n > 1);

numbers.Remove(3);

var result = query.ToList();

// Output: 2, 4
```

### Example 3: Array Value Change

```csharp
int[] numbers = { 1, 2, 3 };

var query = numbers.Select(n => n * 10);

numbers[0] = 5;

var result = query.ToList();

// Output: 50, 20, 30
```

### Example 4: Snapshot Before Change

```csharp
List<int> numbers = new() { 1, 2, 3 };

var result = numbers
    .Where(n => n > 1)
    .ToList();

numbers.Add(4);

// Result remains: 2, 3
```

**Important:** Modifying a `List<T>` while it is actively being enumerated generally throws `InvalidOperationException`. Changing it before enumeration begins is different.

## 15. Captured Variables

Deferred queries can use the current value of an external variable when the query executes.

### Example 1: Change Threshold

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

int minimum = 2;

var query = numbers.Where(n => n > minimum);

minimum = 4;

var result = query.ToList();

// Output: 5
```

### Example 2: Execute with Different Values

```csharp
int minimum = 2;

var query = numbers.Where(n => n > minimum);

var first = query.ToList();

minimum = 3;

var second = query.ToList();

// First:  3, 4, 5
// Second: 4, 5
```

### Example 3: Capture a Fixed Value

```csharp
int minimum = 2;
int fixedMinimum = minimum;

var query = numbers.Where(n => n > fixedMinimum);

minimum = 4;

var result = query.ToList();

// Output: 3, 4, 5
```

**Key point:** The detailed closure mechanism belongs to Section 06.04. Here, the important point is that captured values can affect later query execution.

## 16. Side Effects

Side effects are observable actions performed during query execution, such as printing output or modifying external state.

### Example 1: Console Output

```csharp
int[] numbers = { 1, 2, 3 };

var query = numbers.Select(n =>
{
    Console.WriteLine($"Processing {n}");
    return n * 10;
});

var result = query.ToList();
```

**Output:**

```text
Processing 1
Processing 2
Processing 3
```

### Example 2: External Counter

```csharp
int counter = 0;

var query = numbers.Where(n =>
{
    counter++;
    return n > 1;
});

Console.WriteLine(counter);

// Output: 0

var result = query.ToList();

Console.WriteLine(counter);

// Output: 3
```

### Example 3: Repeated Side Effects

```csharp
int counter = 0;

var query = numbers.Select(n =>
{
    counter++;
    return n * 2;
});

query.ToList();
query.ToList();

Console.WriteLine(counter);

// Output: 6
```

### Example 4: Prefer Pure Transformations

```csharp
var query = numbers.Select(n => n * 2);

foreach (int n in query)
{
    Console.WriteLine(n);
}
```

**Key point:** Prefer side-effect-free predicates and selectors because LINQ operators may defer, repeat, skip, or reorder evaluation.

## 17. Deferred Exceptions

Deferred exceptions occur during query enumeration rather than during query declaration.

### Example 1: Division by Zero

```csharp
int[] numbers = { 2, 1, 0 };

var query = numbers.Select(n => 10 / n);

// No exception yet

try
{
    var result = query.ToList();
}
catch (DivideByZeroException)
{
    Console.WriteLine("Division by zero");
}
```

**Output:**

```text
Division by zero
```

### Example 2: Exception During foreach

```csharp
var query = numbers.Select(n => 10 / n);

try
{
    foreach (int value in query)
    {
        Console.WriteLine(value);
    }
}
catch (DivideByZeroException)
{
    Console.WriteLine("Error occurred");
}
```

**Output:**

```text
5
10
Error occurred
```

### Example 3: Invalid Cast During Enumeration

```csharp
object[] values = { 10, "Hello", 20 };

var query = values.Cast<int>();

try
{
    foreach (int n in query)
    {
        Console.WriteLine(n);
    }
}
catch (InvalidCastException)
{
    Console.WriteLine("Invalid cast");
}
```

**Output:**

```text
10
Invalid cast
```

### Example 4: Immediate Argument Validation

```csharp
int[] numbers = { 1, 2, 3 };

try
{
    var query = numbers.Where(null!);
}
catch (ArgumentNullException)
{
    Console.WriteLine("Invalid predicate");
}
```

**Output:**

```text
Invalid predicate
```

**Important:** Not every LINQ exception is deferred. Many operators validate invalid arguments immediately when the method is called.

## 18. Early Termination

Early termination allows an operation to finish without processing the entire source.

### Example 1: Any Stops After First Match

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

bool result = numbers.Any(n =>
{
    Console.WriteLine($"Checking {n}");
    return n > 2;
});
```

**Output:**

```text
Checking 1
Checking 2
Checking 3
```

**Result:**

```text
True
```

### Example 2: First Stops After Match

```csharp
int result = numbers.First(n =>
{
    Console.WriteLine($"Checking {n}");
    return n > 3;
});
```

**Output:**

```text
Checking 1
Checking 2
Checking 3
Checking 4
```

**Result:**

```text
4
```

### Example 3: All Stops on False

```csharp
bool result = numbers.All(n =>
{
    Console.WriteLine($"Checking {n}");
    return n < 3;
});
```

**Output:**

```text
Checking 1
Checking 2
Checking 3
```

**Result:**

```text
False
```

### Example 4: Take Limits Processing

```csharp
var result = numbers
    .Select(n =>
    {
        Console.WriteLine($"Processing {n}");
        return n * 10;
    })
    .Take(2)
    .ToList();
```

**Output:**

```text
Processing 1
Processing 2
```

**Key point:** Early termination improves efficiency when only part of a sequence is needed.

## 19. Infinite-Sequence Risks

Infinite-sequence risks occur when an operation requires a sequence to finish, but the sequence has no end.

### Example 1: Infinite Generator

```csharp
IEnumerable<int> InfiniteNumbers()
{
    int n = 1;

    while (true)
    {
        yield return n++;
    }
}
```

### Example 2: Safe Bounded Execution

```csharp
var result = InfiniteNumbers()
    .Take(5)
    .ToList();

// Output: 1, 2, 3, 4, 5
```

### Example 3: Unsafe Materialization

```csharp
// Do not execute:

var result = InfiniteNumbers().ToList();
```

The sequence never ends, so this operation cannot complete normally and may exhaust memory.

### Example 4: Unsafe Sorting

```csharp
// Do not execute:

var result = InfiniteNumbers()
    .OrderBy(n => n)
    .First();
```

`OrderBy()` must consume the source before producing its first sorted element, so this query cannot complete.

### Example 5: Unsafe Count

```csharp
// Do not execute:

int count = InfiniteNumbers().Count();
```

Counting an unbounded generated sequence cannot finish normally.

### Example 6: Safe Conditional Termination

```csharp
var result = InfiniteNumbers()
    .TakeWhile(n => n <= 5)
    .ToList();

// Output: 1, 2, 3, 4, 5
```

### Example 7: Filtering May Never Produce a Result

```csharp
// Do not execute:

var result = InfiniteNumbers()
    .Where(n => n < 0)
    .First();
```

No generated element satisfies the condition, so the query keeps searching indefinitely.

### Safe vs Unsafe Operations

| Operation | Infinite Sequence | Reason |
|---|---|---|
| `Take(5)` | Usually safe | Limits output |
| `First()` | Usually safe | Needs first element |
| `Any()` | Depends | May stop early |
| `TakeWhile()` | Depends | Condition must eventually become false |
| `Where()` | Depends | May never find a match |
| `ToList()` | Unsafe without a bound | Attempts to consume everything |
| `Count()` | Unsafe without a bound | Requires counting all elements |
| `OrderBy()` | Unsafe without a bound | Requires complete input |
| `Reverse()` | Unsafe without a bound | Requires complete input |

**Key point:** A finite result is not guaranteed merely because a query is deferred. The execution strategy of each operator matters.

## 20. Quick Revision

| Topic | Purpose | Example |
|---|---|---|
| Query Declaration | Defines query instructions | `var q = source.Where(...)` |
| Query Execution | Processes source elements | `foreach (var x in q)` |
| Deferred Execution | Delays processing | `Where()` |
| Immediate Execution | Calculates result immediately | `ToList()` |
| Lazy Evaluation | Processes values when needed | `Select()` |
| Enumeration-Triggered Execution | Starts during iteration | `MoveNext()` |
| Materialization-Triggered Execution | Creates a concrete result collection | `ToArray()` |
| Scalar Terminal Operators | Returns one value | `Count()`, `First()` |
| Streaming Operators | Produces results incrementally | `Where()`, `Select()` |
| Buffering Operators | Stores input before producing results | `OrderBy()` |
| Query Re-execution | Runs again on enumeration | Two `foreach` loops |
| Repeated Enumeration | Traverses query multiple times | `Count()` then `foreach` |
| Repeated Work | Repeats calculations | Two `Sum()` calls |
| Source Changes before Enumeration | Observes later source changes | `list.Add()` before `ToList()` |
| Captured Variables | Uses current captured values | `n => n > minimum` |
| Side Effects | Performs observable actions | `Console.WriteLine()` |
| Deferred Exceptions | Throws during enumeration | `Select(n => 10 / n)` |
| Early Termination | Stops when enough data is found | `Any()`, `First()` |
| Infinite-Sequence Risks | May never finish | `InfiniteNumbers().ToList()` |

## 21. Final Execution Comparison

| Execution Type | When It Runs | Processes Entire Source? | Example |
|---|---|---|---|
| Deferred + Streaming | During enumeration | Not necessarily | `Where()` |
| Deferred + Buffering | During enumeration | Often yes, before yielding | `OrderBy()` |
| Immediate + Scalar | When called | Depends on operator | `Any()` |
| Immediate + Materialization | When called | Yes, for finite sources | `ToList()` |
| Repeated Enumeration | Every traversal | Depends on query | Two `foreach` loops |
| Early Termination | Until result is determined | Often no | `First()` |
