# 09.05 — IMMUTABILITY

**Chapter:** 09 — Functional C#  
**Total Syllabus Points:** 19  
**Language:** C#  
**Namespaces:** `System`, `System.Collections.Generic`, `System.Collections.Immutable`

**Immutability** means that a value or an object's observable state cannot be changed after creation.

Instead of modifying existing data, immutable programming commonly creates new values or objects representing the desired changes.

Immutability is important in functional programming because it makes state changes easier to understand, reduces unintended side effects, and simplifies many concurrent operations.

This section covers all **19 syllabus points in their original order**, with explanations, C# examples, and outputs.

**Example conventions:** The examples use modern C# syntax. Each code block is intended as an independent example unless it explicitly refers to a type defined immediately before it. Top-level statements and local functions can be placed in `Program.cs`; class and record declarations belong at file or namespace scope.

## 1. Immutable Values

An **immutable value** cannot be changed after it has been created.

Operations that appear to modify an immutable value actually produce a different value.

### Example 1: Immutable string

```csharp
string message = "Hello";

string updated = message.ToUpperInvariant();

Console.WriteLine(message);
Console.WriteLine(updated);
```

**Output:**

```text
Hello
HELLO
```

**Explanation:**

`string` is immutable in C#.

Calling `ToUpperInvariant()` does not modify the original string. It returns a string containing the uppercase result.

### Example 2: String concatenation

```csharp
string first = "Hello";

string second = first + " World";

Console.WriteLine(first);
Console.WriteLine(second);
```

**Output:**

```text
Hello
Hello World
```

The original string remains unchanged.

### Example 3: Immutable value transformation

```csharp
int number = 10;

int result = number + 5;

Console.WriteLine(number);
Console.WriteLine(result);
```

**Output:**

```text
10
15
```

The addition produces a new integer value.

Unlike immutable reference objects, an `int` variable can be reassigned. The integer value itself is not modified in place.

### Example 4: Immutable date value

```csharp
DateTime original = new(2026, 1, 10);

DateTime updated = original.AddDays(5);

Console.WriteLine(original.ToString("yyyy-MM-dd"));
Console.WriteLine(updated.ToString("yyyy-MM-dd"));
```

**Output:**

```text
2026-01-10
2026-01-15
```

`DateTime.AddDays()` returns a new value.

### Characteristics

| Characteristic | Description |
|---|---|
| State | Cannot change after creation |
| Modification | Produces a new value |
| Predictability | Existing values remain unchanged |
| Sharing | Can often be shared safely |
| Examples | `string`, `DateTime`, immutable records |

**Key point:** Immutable values preserve their original state; transformations produce new values.

## 2. Mutable Values

A **mutable value or object** can have its state changed after creation.

C# supports mutable objects through writable fields, properties, arrays, and collections.

### Example 1: Mutable variable

```csharp
int number = 10;

number = 20;

Console.WriteLine(number);
```

**Output:**

```text
20
```

The variable is reassigned to another integer value.

### Example 2: Mutable class

```csharp
class Employee
{
    public string Name { get; set; } = "";
    public decimal Salary { get; set; }
}
```

Usage:

```csharp
Employee employee = new()
{
    Name = "Amit",
    Salary = 30000
};

employee.Salary = 40000;

Console.WriteLine(employee.Salary);
```

**Output:**

```text
40000
```

The existing `Employee` object is modified.

### Example 3: Mutable list

```csharp
List<int> numbers = new()
{
    10, 20, 30
};

numbers.Add(40);

Console.WriteLine(string.Join(", ", numbers));
```

**Output:**

```text
10, 20, 30, 40
```

`List<T>.Add()` changes the existing collection.

### Example 4: Mutable array

```csharp
int[] numbers = { 10, 20, 30 };

numbers[0] = 100;

Console.WriteLine(string.Join(", ", numbers));
```

**Output:**

```text
100, 20, 30
```

### Mutable vs immutable

| Mutable | Immutable |
|---|---|
| Existing state can change | Existing state remains unchanged |
| Often updates in place | Often produces a new object |
| Can require synchronization | Reduces shared-mutation concerns |
| Examples: `List<T>`, arrays | Examples: `string`, `ImmutableArray<T>` |

**Key point:** Mutable objects allow in-place changes, while immutable objects preserve their existing state.

## 3. readonly Fields

The `readonly` keyword restricts when a field can be assigned.

A `readonly` instance field can be assigned in its declaration or in an instance constructor of its containing type.

A `static readonly` field can be assigned in its declaration or static constructor.

### Syntax

```csharp
class Example
{
    private readonly int value;

    public Example(int value)
    {
        this.value = value;
    }
}
```

### Example 1: Readonly integer field

```csharp
class Employee
{
    private readonly int id;

    public Employee(int id)
    {
        this.id = id;
    }

    public int GetId()
    {
        return id;
    }
}
```

Usage:

```csharp
Employee employee = new(101);

Console.WriteLine(employee.GetId());
```

**Output:**

```text
101
```

### Example 2: Readonly field initialization

```csharp
class Configuration
{
    public readonly string ApplicationName = "MyApp";
}
```

Usage:

```csharp
Configuration config = new();

Console.WriteLine(config.ApplicationName);
```

**Output:**

```text
MyApp
```

### Example 3: Reassignment is prohibited

```csharp
class Example
{
    private readonly int number = 10;

    public void Change()
    {
        number = 20; // Compilation error
    }
}
```

The field cannot be reassigned from an ordinary instance method.

### Example 4: Readonly reference to a mutable object

```csharp
class NumberStore
{
    private readonly List<int> numbers = new();

    public void Add(int number)
    {
        numbers.Add(number);
    }

    public int Count => numbers.Count;
}
```

Usage:

```csharp
NumberStore store = new();

store.Add(10);
store.Add(20);

Console.WriteLine(store.Count);
```

**Output:**

```text
2
```

The field cannot be reassigned after initialization, but the referenced list can still be modified.

**Key point:** `readonly` prevents reassignment of a field outside its permitted initialization locations. It does not automatically make referenced objects immutable.

## 4. Readonly References

A readonly reference cannot be reassigned after initialization, but the object it references may still be mutable.

This distinction is especially important for reference types.

### Example 1: Readonly reference to a list

```csharp
class Example
{
    private readonly List<int> numbers = new();

    public void AddNumber(int number)
    {
        numbers.Add(number);
    }

    public void Print()
    {
        Console.WriteLine(string.Join(", ", numbers));
    }
}
```

Usage:

```csharp
Example example = new();

example.AddNumber(10);
example.AddNumber(20);

example.Print();
```

**Output:**

```text
10, 20
```

### Example 2: Reference reassignment is prohibited

```csharp
class Example
{
    private readonly List<int> numbers = new();

    public void Replace()
    {
        numbers = new List<int>(); // Compilation error
    }
}
```

### Example 3: Referenced object remains mutable

```csharp
class Employee
{
    public string Name { get; set; } = "";
}

class EmployeeManager
{
    private readonly Employee employee = new()
    {
        Name = "Amit"
    };

    public void Rename()
    {
        employee.Name = "Rahul";
    }

    public string Name => employee.Name;
}
```

Usage:

```csharp
EmployeeManager manager = new();

manager.Rename();

Console.WriteLine(manager.Name);
```

**Output:**

```text
Rahul
```

### Important distinction

```text
Readonly Reference
        │
        ▼
    Object Address ─────────► Mutable Object
       Fixed                  State can change
```

**Key point:** Readonly references protect the reference assignment, not necessarily the object's internal state.

## 5. init-Only Properties

An `init` accessor allows a property to be assigned during object initialization but prevents ordinary reassignment afterward.

It was introduced in C# 9.

### Syntax

```csharp
class Employee
{
    public string Name { get; init; } = "";
}
```

### Example 1: Initialize an object

```csharp
class Employee
{
    public string Name { get; init; } = "";
    public int Age { get; init; }
}
```

Usage:

```csharp
Employee employee = new()
{
    Name = "Amit",
    Age = 25
};

Console.WriteLine(employee.Name);
Console.WriteLine(employee.Age);
```

**Output:**

```text
Amit
25
```

### Example 2: Modification after initialization

```csharp
Employee employee = new()
{
    Name = "Amit"
};

employee.Name = "Rahul"; // Compilation error
```

The `init` property cannot be assigned from ordinary code after initialization.

### Example 3: Constructor initialization

```csharp
class Product
{
    public string Name { get; init; }
    public decimal Price { get; init; }

    public Product(string name, decimal price)
    {
        Name = name;
        Price = price;
    }
}
```

Usage:

```csharp
Product product = new("Laptop", 50000);

Console.WriteLine(product.Name);
Console.WriteLine(product.Price);
```

**Output:**

```text
Laptop
50000
```

### Example 4: Mutable object inside an init-only property

```csharp
class Employee
{
    public List<string> Skills { get; init; } = new();
}
```

Usage:

```csharp
Employee employee = new()
{
    Skills = new List<string> { "C#" }
};

employee.Skills.Add("LINQ");

Console.WriteLine(
    string.Join(", ", employee.Skills)
);
```

**Output:**

```text
C#, LINQ
```

The property reference cannot ordinarily be reassigned after initialization, but the list remains mutable.

### `set` vs `init`

| Accessor | Initialization | Later Assignment |
|---|---|---|
| `set` | Allowed | Allowed |
| `init` | Allowed | Not allowed in ordinary code |
| `get` only | Depends on implementation | Not allowed through the property |

**Key point:** `init` restricts when properties can be assigned, but it does not guarantee deep immutability.

## 6. Records

A **record** is a C# type designed to support data-oriented programming.

Records provide value-based equality and convenient syntax for creating modified copies.

C# supports record classes and record structs.

### Syntax

```csharp
record Employee(string Name, int Age);
```

This declares a record class.

### Example 1: Positional record

```csharp
record Employee(string Name, int Age);
```

Usage:

```csharp
Employee employee = new("Amit", 25);

Console.WriteLine(employee.Name);
Console.WriteLine(employee.Age);
```

**Output:**

```text
Amit
25
```

### Example 2: Value-based equality

```csharp
record Employee(string Name, int Age);
```

Usage:

```csharp
Employee first = new("Amit", 25);
Employee second = new("Amit", 25);

Console.WriteLine(first == second);
Console.WriteLine(ReferenceEquals(first, second));
```

**Output:**

```text
True
False
```

The two record objects contain equal values but are different object instances.

### Example 3: Record with init-only properties

```csharp
record Product
{
    public string Name { get; init; } = "";
    public decimal Price { get; init; }
}
```

Usage:

```csharp
Product product = new()
{
    Name = "Laptop",
    Price = 50000
};

Console.WriteLine(product.Name);
```

**Output:**

```text
Laptop
```

### Example 4: Record with mutable properties

```csharp
record Employee
{
    public string Name { get; set; } = "";
}
```

Usage:

```csharp
Employee employee = new()
{
    Name = "Amit"
};

employee.Name = "Rahul";

Console.WriteLine(employee.Name);
```

**Output:**

```text
Rahul
```

**Important:** Records are not automatically immutable. Their mutability depends on their members.

### Example 5: Record copy

```csharp
record Employee(string Name, int Age);
```

Usage:

```csharp
Employee first = new("Amit", 25);

Employee second = first with
{
    Age = 26
};

Console.WriteLine(first.Age);
Console.WriteLine(second.Age);
```

**Output:**

```text
25
26
```

**Key point:** Records support value-based equality and convenient copy operations, making them useful for immutable data models.

## 7. Record Structs

A `record struct` combines record features with value-type semantics.

Unlike record classes, record structs are value types.

### Syntax

```csharp
record struct Point(int X, int Y);
```

### Example 1: Basic record struct

```csharp
record struct Point(int X, int Y);
```

Usage:

```csharp
Point point = new(10, 20);

Console.WriteLine(point.X);
Console.WriteLine(point.Y);
```

**Output:**

```text
10
20
```

### Example 2: Value-based equality

```csharp
record struct Point(int X, int Y);
```

Usage:

```csharp
Point first = new(10, 20);
Point second = new(10, 20);

Console.WriteLine(first == second);
```

**Output:**

```text
True
```

### Example 3: Mutable record struct

```csharp
record struct Point(int X, int Y);
```

Usage:

```csharp
Point point = new(10, 20);

point.X = 100;

Console.WriteLine(point.X);
```

**Output:**

```text
100
```

A positional `record struct` is mutable by default.

### Example 4: Readonly record struct

```csharp
readonly record struct Point(int X, int Y);
```

Usage:

```csharp
Point point = new(10, 20);

Console.WriteLine(point.X);
Console.WriteLine(point.Y);
```

**Output:**

```text
10
20
```

Attempting to assign `point.X = 100` produces a compilation error.

### Example 5: Copying a record struct

```csharp
readonly record struct Point(int X, int Y);
```

Usage:

```csharp
Point first = new(10, 20);

Point second = first with
{
    X = 100
};

Console.WriteLine(first.X);
Console.WriteLine(second.X);
```

**Output:**

```text
10
100
```

### Record vs record struct

| Feature | `record` | `record struct` |
|---|---|---|
| Type category | Reference type | Value type |
| Equality | Value-based | Value-based |
| Assignment | Copies reference | Copies value |
| Positional properties | Init-only by default | Mutable by default |
| `with` expression | Supported | Supported |
| Readonly declaration | Not applicable in the same form | `readonly record struct` |

**Key point:** Use `readonly record struct` when you need a value-type record whose fields and properties cannot be reassigned after initialization.

## 8. with Expressions

A `with` expression creates a copy of an object or value with selected members changed.

It is commonly used with records.

### Syntax

```csharp
var updated = original with
{
    Property = newValue
};
```

### Example 1: Change one property

```csharp
record Employee(string Name, int Age);
```

Usage:

```csharp
Employee original = new("Amit", 25);

Employee updated = original with
{
    Age = 26
};

Console.WriteLine(original);
Console.WriteLine(updated);
```

**Output:**

```text
Employee { Name = Amit, Age = 25 }
Employee { Name = Amit, Age = 26 }
```

### Example 2: Change multiple properties

```csharp
record Product(string Name, decimal Price, int Stock);
```

Usage:

```csharp
Product original = new("Laptop", 50000, 10);

Product updated = original with
{
    Price = 45000,
    Stock = 15
};

Console.WriteLine(original);
Console.WriteLine(updated);
```

**Output:**

```text
Product { Name = Laptop, Price = 50000, Stock = 10 }
Product { Name = Laptop, Price = 45000, Stock = 15 }
```

### Example 3: Copy without changing properties

```csharp
record Employee(string Name, int Age);
```

Usage:

```csharp
Employee original = new("Amit", 25);

Employee copy = original with { };

Console.WriteLine(original == copy);
Console.WriteLine(ReferenceEquals(original, copy));
```

**Output:**

```text
True
False
```

The copy is a different record-class instance but has equal values.

### Example 4: Record struct with expression

```csharp
readonly record struct Point(int X, int Y);
```

Usage:

```csharp
Point first = new(10, 20);

Point second = first with
{
    Y = 50
};

Console.WriteLine(first);
Console.WriteLine(second);
```

**Output:**

```text
Point { X = 10, Y = 20 }
Point { X = 10, Y = 50 }
```

**Key point:** `with` expressions support copy-and-update operations without modifying the original top-level value.

## 9. Non-Destructive Mutation

**Non-destructive mutation** means creating a modified copy instead of changing the original object.

Despite the word *mutation*, the original data remains unchanged.

### Example 1: Employee salary update

```csharp
record Employee(string Name, decimal Salary);
```

Usage:

```csharp
Employee original = new("Amit", 30000);

Employee updated = original with
{
    Salary = 40000
};

Console.WriteLine(original.Salary);
Console.WriteLine(updated.Salary);
```

**Output:**

```text
30000
40000
```

### Example 2: Update a product

```csharp
record Product(string Name, decimal Price);
```

Usage:

```csharp
Product product = new("Laptop", 50000);

Product discounted = product with
{
    Price = product.Price * 0.90m
};

Console.WriteLine(product.Price);
Console.WriteLine(discounted.Price);
```

**Output:**

```text
50000
45000.00
```

### Example 3: Function returning an updated record

```csharp
record Employee(string Name, decimal Salary);

static Employee IncreaseSalary(
    Employee employee,
    decimal amount
)
{
    return employee with
    {
        Salary = employee.Salary + amount
    };
}
```

Usage:

```csharp
Employee original = new("Amit", 30000);

Employee updated = IncreaseSalary(original, 5000);

Console.WriteLine(original.Salary);
Console.WriteLine(updated.Salary);
```

**Output:**

```text
30000
35000
```

### Example 4: Non-destructive collection update

```csharp
int[] original = { 10, 20, 30 };

int[] updated = original
    .Select(x => x * 2)
    .ToArray();

Console.WriteLine(
    string.Join(", ", original)
);

Console.WriteLine(
    string.Join(", ", updated)
);
```

**Output:**

```text
10, 20, 30
20, 40, 60
```

### Destructive vs non-destructive

| Destructive Mutation | Non-Destructive Mutation |
|---|---|
| Modifies existing state | Produces updated data |
| Original state is overwritten | Original state remains available |
| Often uses setters or collection mutations | Often uses `with` or immutable collections |
| Can affect shared references | Reduces unintended changes to shared data |

**Key point:** Non-destructive mutation preserves the original state while producing an updated version.

## 10. Shallow Immutability

**Shallow immutability** means an object's top-level properties cannot be reassigned, but objects referenced by those properties may still be mutable.

A common example is a record containing a mutable list.

### Example 1: Record with a mutable list

```csharp
record Employee(
    string Name,
    List<string> Skills
);
```

Usage:

```csharp
Employee employee = new(
    "Amit",
    new List<string> { "C#" }
);

employee.Skills.Add("LINQ");

Console.WriteLine(
    string.Join(", ", employee.Skills)
);
```

**Output:**

```text
C#, LINQ
```

Although `Skills` is an init-only property, the list itself is mutable.

### Example 2: Shallow copying with `with`

Using the same `Employee` record:

```csharp
Employee original = new(
    "Amit",
    new List<string> { "C#" }
);

Employee copy = original with
{
    Name = "Rahul"
};

copy.Skills.Add("LINQ");

Console.WriteLine(
    string.Join(", ", original.Skills)
);

Console.WriteLine(
    string.Join(", ", copy.Skills)
);
```

**Output:**

```text
C#, LINQ
C#, LINQ
```

Both records reference the same list.

### Example 3: Reference equality of nested objects

```csharp
record Department(string Name);

record Employee(
    string Name,
    Department Department
);
```

Usage:

```csharp
Department department = new("IT");

Employee first = new("Amit", department);

Employee second = first with
{
    Name = "Rahul"
};

Console.WriteLine(
    ReferenceEquals(
        first.Department,
        second.Department
    )
);
```

**Output:**

```text
True
```

The nested department object is shared.

### Example 4: Shallow immutable properties

```csharp
class Configuration
{
    public List<string> Servers { get; init; } = new();
}
```

Usage:

```csharp
Configuration config = new()
{
    Servers = new List<string>
    {
        "Server1"
    }
};

config.Servers.Add("Server2");

Console.WriteLine(
    string.Join(", ", config.Servers)
);
```

**Output:**

```text
Server1, Server2
```

### Shallow immutability characteristics

| Property | Behavior |
|---|---|
| Top-level property reassignment | Restricted |
| Nested mutable objects | Can change |
| `with` copying | Shallow for record classes |
| Shared nested references | Possible |
| Deep protection | Not guaranteed |

**Key point:** Shallow immutability protects the top-level structure but does not guarantee that nested objects cannot change.

## 11. Deep Immutability

**Deep immutability** means the entire reachable state of an object is immutable, including its nested objects and collections.

A deeply immutable object cannot be changed through any of its nested references.

### Example 1: Immutable nested records

```csharp
record Address(
    string City,
    string State
);

record Employee(
    string Name,
    Address Address
);
```

Usage:

```csharp
Employee employee = new(
    "Amit",
    new Address("Howrah", "West Bengal")
);

Console.WriteLine(employee.Address.City);
```

**Output:**

```text
Howrah
```

Both positional records contain immutable strings and init-only properties.

For these definitions, ordinary application code cannot modify their state after construction.

### Example 2: Updating nested immutable objects

Using the previous records:

```csharp
Employee original = new(
    "Amit",
    new Address("Howrah", "West Bengal")
);

Employee updated = original with
{
    Address = original.Address with
    {
        City = "Kolkata"
    }
};

Console.WriteLine(original.Address.City);
Console.WriteLine(updated.Address.City);
```

**Output:**

```text
Howrah
Kolkata
```

The nested `Address` record is copied and updated.

### Example 3: Immutable collection inside a record

```csharp
using System.Collections.Immutable;

record Employee(
    string Name,
    ImmutableArray<string> Skills
);
```

Usage:

```csharp
Employee original = new(
    "Amit",
    ImmutableArray.Create("C#")
);

Employee updated = original with
{
    Skills = original.Skills.Add("LINQ")
};

Console.WriteLine(
    string.Join(", ", original.Skills)
);

Console.WriteLine(
    string.Join(", ", updated.Skills)
);
```

**Output:**

```text
C#
C#, LINQ
```

The original collection remains unchanged.

### Example 4: Immutable nested structure

```csharp
using System.Collections.Immutable;

record Address(string City);

record Employee(
    string Name,
    Address Address,
    ImmutableArray<string> Skills
);
```

Usage:

```csharp
Employee original = new(
    "Amit",
    new Address("Howrah"),
    ImmutableArray.Create("C#")
);

Employee updated = original with
{
    Address = new Address("Kolkata"),
    Skills = original.Skills.Add("LINQ")
};

Console.WriteLine(original.Address.City);
Console.WriteLine(updated.Address.City);
```

**Output:**

```text
Howrah
Kolkata
```

**Important:** Deep immutability requires every reachable component to be immutable. An immutable collection of mutable objects is not deeply immutable.

### Shallow vs deep immutability

| Shallow Immutability | Deep Immutability |
|---|---|
| Top-level state is protected | Nested state is also protected |
| Nested objects may be mutable | Nested objects must be immutable |
| Mutable collections may remain | Uses immutable collections |
| Shared nested references can change | Shared immutable values remain stable |

**Key point:** Deep immutability requires immutability throughout the complete object graph.

## 12. Immutable Collections

Immutable collections cannot be modified after creation.

Operations such as adding, removing, or replacing elements return new collection values rather than changing the existing collection.

C# provides immutable collection types through:

```csharp
using System.Collections.Immutable;
```

Common types include:

- `ImmutableArray<T>`
- `ImmutableList<T>`
- `ImmutableDictionary<TKey,TValue>`
- `ImmutableHashSet<T>`
- `ImmutableQueue<T>`
- `ImmutableStack<T>`

### Example 1: ImmutableArray

```csharp
using System.Collections.Immutable;

ImmutableArray<int> numbers =
    ImmutableArray.Create(10, 20, 30);

ImmutableArray<int> updated =
    numbers.Add(40);

Console.WriteLine(
    string.Join(", ", numbers)
);

Console.WriteLine(
    string.Join(", ", updated)
);
```

**Output:**

```text
10, 20, 30
10, 20, 30, 40
```

### Example 2: ImmutableList

```csharp
using System.Collections.Immutable;

ImmutableList<int> numbers =
    ImmutableList.Create(1, 2, 3);

ImmutableList<int> updated =
    numbers.Add(4);

Console.WriteLine(
    string.Join(", ", numbers)
);

Console.WriteLine(
    string.Join(", ", updated)
);
```

**Output:**

```text
1, 2, 3
1, 2, 3, 4
```

### Example 3: ImmutableDictionary

```csharp
using System.Collections.Immutable;

ImmutableDictionary<int, string> employees =
    ImmutableDictionary<int, string>.Empty
        .Add(1, "Amit")
        .Add(2, "Rahul");

var updated = employees.Add(3, "Priya");

Console.WriteLine(employees.Count);
Console.WriteLine(updated.Count);
```

**Output:**

```text
2
3
```

### Example 4: ImmutableHashSet

```csharp
using System.Collections.Immutable;

ImmutableHashSet<int> numbers =
    ImmutableHashSet.Create(1, 2, 3);

var updated = numbers.Add(4);

Console.WriteLine(numbers.Contains(4));
Console.WriteLine(updated.Contains(4));
```

**Output:**

```text
False
True
```

### Example 5: ImmutableStack

```csharp
using System.Collections.Immutable;

ImmutableStack<int> stack =
    ImmutableStack<int>.Empty;

stack = stack.Push(10);
stack = stack.Push(20);

ImmutableStack<int> updated = stack.Pop();

Console.WriteLine(stack.Peek());
Console.WriteLine(updated.Peek());
```

**Output:**

```text

10
```

### Example 6: ImmutableQueue

```csharp
using System.Collections.Immutable;

    ImmutableQueue<int>.Empty;

queue = queue.Enqueue(10);
queue = queue.Enqueue(20);

ImmutableQueue<int> updated = queue.Dequeue();

Console.WriteLine(updated.Peek());
```

```text
20
```

### Immutable collection comparison

| Collection | Purpose |
|---|---|
| `ImmutableArray<T>` | Immutable indexed sequence |
| `ImmutableList<T>` | Persistent immutable list |
| `ImmutableDictionary<TKey,TValue>` | Immutable key-value mapping |

| `ImmutableStack<T>` | Immutable last-in-first-out collection |
| `ImmutableQueue<T>` | Immutable first-in-first-out collection |

**Key point:** Immutable collections preserve previous versions when updates produce new collections.

## 13. Read-Only Collection Interfaces

Read-only collection interfaces expose data without providing mutation methods through the interface.

Common interfaces include:

```csharp
IReadOnlyCollection<T>
IReadOnlyList<T>
IReadOnlyDictionary<TKey, TValue>
```

However, a read-only interface does not guarantee that the underlying collection is immutable.

### Example 1: IReadOnlyCollection

```csharp
List<int> numbers = new()
{
    10, 20, 30
};

IReadOnlyCollection<int> readOnly = numbers;

Console.WriteLine(readOnly.Count);
```

**Output:**

```text
3
```

### Example 2: IReadOnlyList

```csharp
List<string> names = new()
{
    "Amit",
    "Rahul"
};

IReadOnlyList<string> readOnly = names;

Console.WriteLine(readOnly[0]);
Console.WriteLine(readOnly[1]);
```

**Output:**

```text
Amit
Rahul
```

### Example 3: Underlying collection remains mutable

```csharp
List<int> numbers = new()
{
    10, 20
};

IReadOnlyList<int> readOnly = numbers;

numbers.Add(30);

Console.WriteLine(readOnly.Count);
```

**Output:**

```text
3
```

The interface prevents mutation through `readOnly`, but another reference can still modify the list.

### Example 4: IReadOnlyDictionary

```csharp
Dictionary<int, string> employees = new()
{
    [1] = "Amit",
    [2] = "Rahul"
};

IReadOnlyDictionary<int, string> readOnly =
    employees;

Console.WriteLine(readOnly[1]);
```

**Output:**

```text
Amit
```

### Example 5: Immutable collection exposed through a read-only interface

```csharp
using System.Collections.Immutable;

IReadOnlyList<int> numbers =
    ImmutableArray.Create(10, 20, 30);

Console.WriteLine(numbers.Count);
Console.WriteLine(numbers[0]);
```

**Output:**

```text
3
10
```

### Comparison

| Read-Only Interface | Immutable Collection |
|---|---|
| Restricts operations through an interface | Prevents in-place collection updates |
| Underlying collection may change | Existing collection value remains unchanged |
| Useful for API contracts | Useful for immutable state |
| Does not guarantee immutability | Provides collection-level immutability |

**Key point:** Read-only interfaces restrict access to mutation operations; immutable collections prevent mutation of the collection itself.

## 14. Immutable Storage

Immutable storage means keeping application data in structures that preserve existing values when updates occur.

Instead of modifying stored data directly, an application replaces its current state with a new immutable value.

### Example 1: ImmutableArray storage

```csharp
using System.Collections.Immutable;

ImmutableArray<int> storage =
    ImmutableArray<int>.Empty;

storage = storage.Add(10);
storage = storage.Add(20);
storage = storage.Add(30);

Console.WriteLine(
    string.Join(", ", storage)
);
```

**Output:**

```text
10, 20, 30
```

The `storage` variable is reassigned, but each immutable array value remains unchanged.

### Example 2: Preserve an earlier version

```csharp
using System.Collections.Immutable;

ImmutableList<int> original =
    ImmutableList.Create(10, 20);

ImmutableList<int> updated =
    original.Add(30);

Console.WriteLine(
    string.Join(", ", original)
);

Console.WriteLine(
    string.Join(", ", updated)
);
```

**Output:**

```text
10, 20
10, 20, 30
```

### Example 3: Immutable dictionary storage

```csharp
using System.Collections.Immutable;

ImmutableDictionary<int, string> storage =
    ImmutableDictionary<int, string>.Empty;

storage = storage.Add(1, "Amit");
storage = storage.Add(2, "Rahul");

Console.WriteLine(storage[1]);
Console.WriteLine(storage[2]);
```

**Output:**

```text
Amit
Rahul
```

### Example 4: Immutable application state

```csharp
using System.Collections.Immutable;

record ApplicationState(
    ImmutableArray<string> Users
);
```

Usage:

```csharp
ApplicationState state = new(
    ImmutableArray<string>.Empty
);

state = state with
{
    Users = state.Users.Add("Amit")
};

state = state with
{
    Users = state.Users.Add("Rahul")
};

Console.WriteLine(
    string.Join(", ", state.Users)
);
```

**Output:**

```text
Amit, Rahul
```

**Key point:** Immutable storage represents updates by replacing the current state reference with a new immutable value.

## 15. Structural Sharing

**Structural sharing** means reusing unchanged parts of an existing data structure when creating a modified version.

This avoids copying the entire structure for every update.

Persistent immutable data structures commonly use structural sharing.

### Example 1: ImmutableList

```csharp
using System.Collections.Immutable;

ImmutableList<int> original =
    ImmutableList.Create(10, 20, 30);

ImmutableList<int> updated =
    original.Add(40);

Console.WriteLine(
    string.Join(", ", original)
);

Console.WriteLine(
    string.Join(", ", updated)
);
```

**Output:**

```text
10, 20, 30
10, 20, 30, 40
```

`ImmutableList<T>` uses a tree-based implementation that can share unchanged internal nodes between versions.

### Example 2: Multiple versions

```csharp
using System.Collections.Immutable;

ImmutableList<int> version1 =
    ImmutableList.Create(10);

ImmutableList<int> version2 =
    version1.Add(20);

ImmutableList<int> version3 =
    version2.Add(30);

Console.WriteLine(
    string.Join(", ", version1)
);

Console.WriteLine(
    string.Join(", ", version2)
);

Console.WriteLine(
    string.Join(", ", version3)
);
```

**Output:**

```text
10
10, 20
10, 20, 30
```

Each version remains usable.

### Example 3: ImmutableDictionary

```csharp
using System.Collections.Immutable;

var version1 =
    ImmutableDictionary<int, string>.Empty
        .Add(1, "Amit");

var version2 =
    version1.Add(2, "Rahul");

Console.WriteLine(version1.Count);
Console.WriteLine(version2.Count);
```

**Output:**

```text
1
2
```

Immutable dictionary implementations can reuse unchanged internal structure between versions.

### Example 4: ImmutableArray comparison

```csharp
using System.Collections.Immutable;

var original =
    ImmutableArray.Create(10, 20, 30);

var updated = original.Add(40);

Console.WriteLine(original.Length);
Console.WriteLine(updated.Length);
```

**Output:**

```text
3
4
```

**Important distinction:** `ImmutableArray<T>` uses array-backed storage. Adding an element generally requires creating new array storage and copying existing elements.

It does not provide the same tree-based structural sharing as `ImmutableList<T>`.

### Structural sharing concept

```text
Original Version
       │
       ▼
    Shared Nodes
       │
       ├───────────────┐
       │               │
       ▼               ▼
   Version 1        Version 2
                       │
                       ▼
                   New Nodes
```

**Key point:** Structural sharing reduces copying by reusing unchanged internal data between immutable collection versions.

## 16. Copying Tradeoffs

Immutable programming frequently creates new values or objects instead of changing existing ones.

This provides safety and predictability but may introduce allocation and copying costs.

### Example 1: Mutable list update

```csharp
List<int> numbers = new()
{
    10, 20, 30
};

numbers.Add(40);

Console.WriteLine(
    string.Join(", ", numbers)
);
```

**Output:**

```text
10, 20, 30, 40
```

The existing list is modified.

### Example 2: ImmutableArray update

```csharp
using System.Collections.Immutable;

ImmutableArray<int> numbers =
    ImmutableArray.Create(10, 20, 30);

ImmutableArray<int> updated =
    numbers.Add(40);

Console.WriteLine(
    string.Join(", ", updated)
);
```

**Output:**

```text
10, 20, 30, 40
```

A new immutable array value is produced.

### Example 3: Repeated immutable updates

```csharp
using System.Collections.Immutable;

ImmutableList<int> numbers =
    ImmutableList<int>.Empty;

for (int i = 1; i <= 5; i++)
{
    numbers = numbers.Add(i);
}

Console.WriteLine(
    string.Join(", ", numbers)
);
```

**Output:**

```text
1, 2, 3, 4, 5
```

This is correct, but repeated updates can involve additional allocations.

### Example 4: Builder for bulk updates

```csharp
using System.Collections.Immutable;

ImmutableArray<int>.Builder builder =
    ImmutableArray.CreateBuilder<int>();

for (int i = 1; i <= 5; i++)
{
    builder.Add(i);
}

ImmutableArray<int> numbers =
    builder.ToImmutable();

Console.WriteLine(
    string.Join(", ", numbers)
);
```

**Output:**

```text
1, 2, 3, 4, 5
```

A builder allows efficient mutable construction before producing an immutable result.

### Example 5: Copying a record

```csharp
record Employee(
    string Name,
    decimal Salary
);
```

Usage:

```csharp
Employee original = new("Amit", 30000);

Employee updated = original with
{
    Salary = 35000
};

Console.WriteLine(original.Salary);
Console.WriteLine(updated.Salary);
```

**Output:**

```text
30000
35000
```

For a record class, the `with` expression creates another object and performs a shallow copy before applying the requested changes.

### Tradeoff comparison

| Approach | Advantages | Tradeoffs |
|---|---|---|
| Mutable collections | Efficient in-place updates | Shared mutation concerns |
| `ImmutableArray<T>` | Compact indexed immutable storage | Updates often copy arrays |
| `ImmutableList<T>` | Structural sharing | Tree navigation and allocations |
| Immutable records | Clear copy-and-update syntax | New object allocation |
| Collection builders | Efficient bulk construction | Builder itself is mutable |

**Key point:** Choose immutable data structures according to update frequency, collection size, memory requirements, and concurrency needs.

```text
0
1
```


Usage:

```csharp
CounterState state = new(0);

state = Increment(state);
state = Increment(state);
state = Increment(state);
```

**Output:**

```text
3
```

### Example 3: Preserve state history

```csharp
record CounterState(int Count);

static CounterState Increment(CounterState state)

        Count = state.Count + 1
    };

```

Usage:

```csharp
CounterState version1 = new(0);

CounterState version3 = Increment(version2);

Console.WriteLine(version2.Count);
Console.WriteLine(version3.Count);
```

**Output:**

```text
0
1

```

### Example 4: Immutable employee state

```csharp
using System.Collections.Immutable;
```

```csharp
EmployeeState original = new(

);
```

**Output:**

```text

```

### Immutable state transition

```text
State 1
   │
   ▼
Transition Function
   │
   ▼
State 2
   │
   ▼
Transition Function
   │
   ▼
State 3
```

Each state version remains unchanged.

**Key point:** Immutable state makes transitions explicit and allows previous state versions to remain available.

## 18. Concurrent Operations

Immutability simplifies concurrent programming because multiple threads can safely read the same immutable data without coordinating writes to that data.

However, immutable data does not automatically make all operations thread-safe.

### Example 1: Concurrent reads

```csharp
using System.Collections.Immutable;

ImmutableArray<int> numbers =
    ImmutableArray.Create(10, 20, 30, 40);

Parallel.For(0, 4, index =>
{
    int value = numbers[index];

    Console.WriteLine(value);
});
```

**Possible output:**

```text
10
20
30
40
```

The order may differ because operations execute concurrently.

The immutable array is not modified.

### Example 2: Concurrent immutable transformations

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

int[] squares = numbers
    .AsParallel()
    .Select(static x => x * x)
    .OrderBy(static x => x)
    .ToArray();

Console.WriteLine(
    string.Join(", ", squares)
);
```

**Output:**

```text
1, 4, 9, 16, 25
```

Each operation calculates a result without modifying shared input state.

### Example 3: Immutable snapshots

```csharp
using System.Collections.Immutable;

ImmutableList<int> original =
    ImmutableList.Create(10, 20, 30);

ImmutableList<int> updated =
    original.Add(40);

Console.WriteLine(original.Count);
Console.WriteLine(updated.Count);
```

**Output:**

```text
3
4
```

Both snapshots can be read independently.

### Example 4: Thread-safe state replacement

```csharp
using System.Collections.Immutable;

ImmutableList<int> state =
    ImmutableList<int>.Empty;

Parallel.For(1, 101, number =>
{
    ImmutableInterlocked.Update(
        ref state,
        current => current.Add(number)
    );
});

Console.WriteLine(state.Count);
```

**Output:**

```text
100
```

`ImmutableInterlocked.Update()` atomically replaces the state reference using a compare-and-swap retry mechanism.

The update function may be invoked more than once during retries, so it should not produce unrelated side effects.

### Example 5: Immutable state with parallel calculations

```csharp
using System.Collections.Immutable;

ImmutableArray<int> numbers =
    ImmutableArray.Create(1, 2, 3, 4, 5);

int sum = numbers
    .AsParallel()
    .Sum();

Console.WriteLine(sum);
```

**Output:**

```text
15
```

### Concurrency comparison

| Mutable State | Immutable State |
|---|---|
| Shared writes may require locks | Concurrent reads need no mutation locks |
| Race conditions can occur during updates | Existing snapshots remain stable |
| Readers may observe intermediate changes | Readers can use complete snapshots |
| Updates may modify shared objects | Updates create new values |
| Synchronization is often necessary | Atomic publication is still necessary for shared state changes |

**Key point:** Immutability simplifies concurrent reads, but coordinating updates to shared state still requires appropriate synchronization.

## 19. Benefits of Immutability

Immutability provides several advantages in application design, functional programming, LINQ, and concurrent systems.

### 19.1 Predictability

Immutable values do not unexpectedly change.

```csharp
record Employee(string Name, int Age);

Employee original = new("Amit", 25);

Employee updated = original with
{
    Age = 26
};

Console.WriteLine(original.Age);
Console.WriteLine(updated.Age);
```

**Output:**

```text
25
26
```

The original state remains predictable.

### 19.2 Reduced Side Effects

Functions can return new values without modifying their inputs.

```csharp
static int[] DoubleNumbers(int[] numbers)
{
    return numbers
        .Select(static x => x * 2)
        .ToArray();
}

int[] original = { 1, 2, 3 };

int[] updated = DoubleNumbers(original);

Console.WriteLine(
    string.Join(", ", original)
);

Console.WriteLine(
    string.Join(", ", updated)
);
```

**Output:**

```text
1, 2, 3
2, 4, 6
```

### 19.3 Easier Testing

Functions that operate on immutable inputs and return new results are easier to test because their behavior does not depend on hidden mutable state.

```csharp
record Employee(string Name, decimal Salary);

static Employee IncreaseSalary(
    Employee employee,
    decimal amount
)
{
    return employee with
    {
        Salary = employee.Salary + amount
    };
}
```

Usage:

```csharp
Employee employee = new("Amit", 30000);

Employee updated = IncreaseSalary(employee, 5000);

Console.WriteLine(updated.Salary == 35000);
Console.WriteLine(employee.Salary == 30000);
```

**Output:**

```text
True
True
```

### 19.4 Safer Sharing

Immutable values can be shared without the risk of another component changing those values in place.

```csharp
using System.Collections.Immutable;

ImmutableArray<int> numbers =
    ImmutableArray.Create(10, 20, 30);

var first = numbers;
var second = numbers;

first = first.Add(40);

Console.WriteLine(
    string.Join(", ", first)
);

Console.WriteLine(
    string.Join(", ", second)
);
```

**Output:**

```text
10, 20, 30, 40
10, 20, 30
```

### 19.5 Easier State History

Previous state versions remain available.

```csharp
record CounterState(int Count);

CounterState version1 = new(0);

CounterState version2 = version1 with
{
    Count = 1
};

CounterState version3 = version2 with
{
    Count = 2
};

Console.WriteLine(version1.Count);
Console.WriteLine(version2.Count);
Console.WriteLine(version3.Count);
```

**Output:**

```text
0
1
2
```

### 19.6 Simpler Concurrent Reads

Immutable values can be read concurrently without worrying about in-place mutation of those values.

```csharp
using System.Collections.Immutable;

ImmutableArray<int> numbers =
    ImmutableArray.Create(1, 2, 3, 4, 5);

int sum = numbers.AsParallel().Sum();

Console.WriteLine(sum);
```

**Output:**

```text
15
```

### 19.7 Clearer Data Flow

Immutable transformations make changes explicit.

```csharp
record Product(string Name, decimal Price);

Product original = new("Laptop", 50000);

Product discounted = original with
{
    Price = original.Price * 0.90m
};

Product final = discounted with
{
    Price = discounted.Price + 1000
};

Console.WriteLine(original.Price);
Console.WriteLine(discounted.Price);
Console.WriteLine(final.Price);
```

**Output:**

```text
50000
45000.00
46000.00
```

Each transformation produces a new version.

### Benefits summary

| Benefit | Explanation |
|---|---|
| Predictability | Existing values remain unchanged |
| Reduced side effects | Functions can avoid modifying inputs |
| Easier testing | Stable inputs simplify assertions |
| Safer sharing | Immutable objects resist unintended modification |
| State history | Previous versions remain available |
| Concurrent reads | Shared immutable values can be read safely |
| Clearer data flow | State transitions are explicit |
| Easier reasoning | Fewer hidden mutations |
| Reusability | Immutable values can be reused across operations |

**Key point:** Immutability improves predictability, maintainability, and safe data sharing, especially when applications contain complex state or concurrent operations.
