# 09.06 — FUNCTION COMPOSITION

**Chapter:** 09 — Functional C#  
**Total Main Syllabus Points:** 16  
**Additional Subtopics:** AND, OR, NOT  
**Language:** C#  
**Namespace:** `System`

**Function composition** is the process of combining two or more functions to create a new function.

Instead of writing one large function containing many operations, we create smaller functions and connect them.

The output of one function becomes the input of another function.

Function composition is an important concept in functional programming because it improves code reuse, modularity, testability, and readability.

This section covers all **16 main syllabus points and their subtopics in the original order**.

---

## 1. Function Composition Concept

Function composition combines functions so that the result of one function is passed to another.

### Mathematical representation

Suppose:

\[
f(x)=x+10
\]

\[
g(x)=x\times2
\]

Their composition is:

\[
(g\circ f)(x)=g(f(x))
\]

For `x = 5`:

```text
Input: 5
   ↓
f(x) = x + 10
   ↓
15
   ↓
g(x) = x * 2
   ↓
30
```

### Example 1: Basic function composition

```csharp
Func<int, int> addTen =
    x => x + 10;

Func<int, int> multiplyByTwo =
    x => x * 2;

Func<int, int> composed =
    x => multiplyByTwo(addTen(x));

Console.WriteLine(composed(5));
```

**Output:**

```text
30
```

### Explanation

The functions execute in this order:

```csharp
addTen(5)             // 15
multiplyByTwo(15)     // 30
```

The composed function behaves like a single function.

### Example 2: Three functions

```csharp
Func<int, int> addFive =
    x => x + 5;

Func<int, int> multiplyByTwo =
    x => x * 2;

Func<int, int> subtractThree =
    x => x - 3;

Func<int, int> composed =
    x => subtractThree(
        multiplyByTwo(
            addFive(x)
        )
    );

Console.WriteLine(composed(10));
```

**Output:**

```text
27
```

### Execution

```text
10
 ↓
Add 5
 ↓
15
 ↓
Multiply by 2
 ↓
30
 ↓
Subtract 3
 ↓
27
```

### Example 3: String composition

```csharp
Func<string, string> trim =
    text => text.Trim();

Func<string, string> upper =
    text => text.ToUpperInvariant();

Func<string, string> composed =
    text => upper(trim(text));

Console.WriteLine(composed("  hello  "));
```

**Output:**

```text
HELLO
```

**Key point:** Function composition creates a new function by connecting smaller functions.

## 2. Output → Input Composition

In function composition, the output type of one function must be compatible with the input type of the next function.

### Basic structure

```text
Function A
Input: T1
Output: T2
      │
      ▼
Function B
Input: T2
Output: T3
```

### Example 1: Integer to integer

```csharp
Func<int, int> square =
    x => x * x;

Func<int, int> addTen =
    x => x + 10;

Func<int, int> composed =
    x => addTen(square(x));

Console.WriteLine(composed(5));
```

**Output:**

```text
35
```

### Example 2: Integer to string

```csharp
Func<int, int> square =
    x => x * x;

Func<int, string> format =
    x => $"Result: {x}";

Func<int, string> composed =
    x => format(square(x));

Console.WriteLine(composed(5));
```

**Output:**

```text
Result: 25
```

### Example 3: String to integer to boolean

```csharp
Func<string, int> getLength =
    text => text.Length;

Func<int, bool> isLong =
    length => length >= 5;

Func<string, bool> composed =
    text => isLong(getLength(text));

Console.WriteLine(composed("Hello"));
Console.WriteLine(composed("Hi"));
```

**Output:**

```text
True
False
```

### Type flow

```text
string
   │
   ▼
Get Length
   │
   ▼
int
   │
   ▼
Check Length
   │
   ▼
bool
```

**Key point:** Function composition requires compatible output and input types.

## 3. Transformation Pipelines

A transformation pipeline processes data through multiple functions.

Each function performs one transformation.

### Example 1: String transformation pipeline

```csharp
Func<string, string> trim =
    text => text.Trim();

Func<string, string> upper =
    text => text.ToUpperInvariant();

Func<string, string> addPrefix =
    text => "USER: " + text;

Func<string, string> pipeline =
    text => addPrefix(upper(trim(text)));

Console.WriteLine(pipeline("  amit  "));
```

**Output:**

```text
USER: AMIT
```

### Pipeline

```text
"  amit  "
     │
     ▼
Trim
     │
     ▼
"amit"
     │
     ▼
Uppercase
     │
     ▼
"AMIT"
     │
     ▼
Add Prefix
     │
     ▼
"USER: AMIT"
```

### Example 2: Numeric transformation pipeline

```csharp
Func<int, int> addTen =
    x => x + 10;

Func<int, int> doubleValue =
    x => x * 2;

Func<int, int> square =
    x => x * x;

Func<int, int> pipeline =
    x => square(doubleValue(addTen(x)));

Console.WriteLine(pipeline(5));
```

**Output:**

```text
900
```

### Example 3: LINQ transformation pipeline

```csharp
int[] numbers =
{
    1, 2, 3, 4, 5, 6
};

var result = numbers
    .Where(x => x % 2 == 0)
    .Select(x => x * 10)
    .Select(x => $"Value: {x}");

foreach (var item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
Value: 20
Value: 40
Value: 60
```

### Explanation

```text
Source
   ↓
Filter Even Numbers
   ↓
Multiply by 10
   ↓
Format as String
   ↓
Result
```

**Key point:** Transformation pipelines separate complex processing into small, understandable steps.

## 4. Chaining Functions

Function chaining means applying functions sequentially.

Each function receives the result produced by the previous function.

### Example 1: Direct chaining

```csharp
static int AddFive(int x)
{
    return x + 5;
}

static int Double(int x)
{
    return x * 2;
}

static int Square(int x)
{
    return x * x;
}

int result = Square(Double(AddFive(5)));

Console.WriteLine(result);
```

**Output:**

```text
400
```

### Example 2: Delegate chaining

```csharp
Func<int, int> addFive =
    x => x + 5;

Func<int, int> doubleValue =
    x => x * 2;

Func<int, int> square =
    x => x * x;

int result = square(doubleValue(addFive(5)));

Console.WriteLine(result);
```

**Output:**

```text
400
```

### Example 3: Chaining string functions

```csharp
static string TrimText(string text)
{
    return text.Trim();
}

static string Uppercase(string text)
{
    return text.ToUpperInvariant();
}

static string AddPrefix(string text)
{
    return "Hello " + text;
}

string result =
    AddPrefix(Uppercase(TrimText("  amit  ")));

Console.WriteLine(result);
```

**Output:**

```text
Hello AMIT
```

### Example 4: Chaining with LINQ

```csharp
string[] names =
{
    "  amit ",
    " rahul ",
    " priya "
};

var result = names
    .Select(name => name.Trim())
    .Select(name => name.ToUpperInvariant())
    .Where(name => name.Length >= 5);

Console.WriteLine(
    string.Join(", ", result)
);
```

**Output:**

```text
RAHUL, PRIYA
```

**Key point:** Function chaining creates a sequence of operations where each step processes the previous result.

## 5. Forward Composition

**Forward composition** applies functions in the same order in which they are supplied.

It is often called **pipe-style composition**.

### Structure

```text
Input
  ↓
First Function
  ↓
Second Function
  ↓
Result
```

### Example 1: Basic forward composition

```csharp
static Func<T, R> Pipe<T, M, R>(
    Func<T, M> first,
    Func<M, R> second
)
{
    return input => second(first(input));
}

Func<int, int> addTen =
    x => x + 10;

Func<int, int> doubleValue =
    x => x * 2;

var pipeline = Pipe(addTen, doubleValue);

Console.WriteLine(pipeline(5));
```

**Output:**

```text
30
```

### Explanation

```text
Pipe(addTen, doubleValue)

5
 ↓
addTen
 ↓
15
 ↓
doubleValue
 ↓
30
```

### Example 2: Different input and output types

```csharp
static Func<T, R> Pipe<T, M, R>(
    Func<T, M> first,
    Func<M, R> second
)
{
    return input => second(first(input));
}

Func<int, int> square =
    x => x * x;

Func<int, string> format =
    x => $"Square: {x}";

var pipeline = Pipe(square, format);

Console.WriteLine(pipeline(5));
```

**Output:**

```text
Square: 25
```

### Example 3: Three-stage forward composition

```csharp
static Func<T, R> Pipe<T, M, R>(
    Func<T, M> first,
    Func<M, R> second
)
{
    return input => second(first(input));
}

Func<string, string> trim =
    text => text.Trim();

Func<string, string> upper =
    text => text.ToUpperInvariant();

Func<string, int> length =
    text => text.Length;

var pipeline = Pipe(
    Pipe(trim, upper),
    length
);

Console.WriteLine(pipeline("  hello  "));
```

**Output:**

```text
5
```

**Key point:** Forward composition emphasizes the order in which data flows through functions.

## 6. Reverse Composition

**Reverse composition** uses the conventional mathematical composition order.

For:

\[
f\circ g
\]

the function `g` executes first, followed by `f`.

### Structure

```text
Compose(f, g)

Input
  ↓
g
  ↓
f
  ↓
Result
```

### Example 1: Basic reverse composition

```csharp
static Func<T, R> Compose<T, M, R>(
    Func<M, R> outer,
    Func<T, M> inner
)
{
    return input => outer(inner(input));
}

Func<int, int> addTen =
    x => x + 10;

Func<int, int> doubleValue =
    x => x * 2;

var composed = Compose(doubleValue, addTen);

Console.WriteLine(composed(5));
```

**Output:**

```text
30
```

### Explanation

```text
Compose(doubleValue, addTen)

5
 ↓
addTen
 ↓
15
 ↓
doubleValue
 ↓
30
```

### Example 2: Reverse composition with strings

```csharp
static Func<T, R> Compose<T, M, R>(
    Func<M, R> outer,
    Func<T, M> inner
)
{
    return input => outer(inner(input));
}

Func<string, string> trim =
    text => text.Trim();

Func<string, string> upper =
    text => text.ToUpperInvariant();

var composed = Compose(upper, trim);

Console.WriteLine(composed("  hello  "));
```

**Output:**

```text
HELLO
```

### Forward vs reverse composition

| Forward Composition | Reverse Composition |
|---|---|
| `Pipe(f, g)` | `Compose(g, f)` |
| Applies `f`, then `g` | Applies `f`, then `g` |
| Data-flow order | Mathematical composition order |
| Left-to-right interpretation | Right-to-left interpretation |

**Key point:** Reverse composition lists the outer function first, but executes the inner function first.

## 7. Predicate Composition

A **predicate** is a function that returns `bool`.

Predicate composition combines multiple conditions into one reusable predicate.

The syllabus includes three operations:

1. AND
2. OR
3. NOT

### 7.1 AND Composition

AND composition returns `true` only when both predicates return `true`.

### Example 1: Combine two predicates

```csharp
Func<int, bool> greaterThanTen =
    x => x > 10;

Func<int, bool> isEven =
    x => x % 2 == 0;

Func<int, bool> combined =
    x => greaterThanTen(x) && isEven(x);

Console.WriteLine(combined(12));
Console.WriteLine(combined(15));
Console.WriteLine(combined(8));
```

**Output:**

```text
True
False
False
```

### Example 2: Generic AND function

```csharp
static Func<T, bool> And<T>(
    Func<T, bool> first,
    Func<T, bool> second
)
{
    return value =>
        first(value) && second(value);
}

Func<int, bool> positive =
    x => x > 0;

Func<int, bool> even =
    x => x % 2 == 0;

var predicate = And(positive, even);

Console.WriteLine(predicate(10));
Console.WriteLine(predicate(-2));
```

**Output:**

```text
True
False
```

The `&&` operator uses short-circuit evaluation.

If the first predicate returns `false`, the second predicate is not evaluated.

---

### 7.2 OR Composition

OR composition returns `true` when at least one predicate returns `true`.

### Example 1: Combine conditions

```csharp
Func<int, bool> lessThanFive =
    x => x < 5;

Func<int, bool> greaterThanTen =
    x => x > 10;

Func<int, bool> combined =
    x => lessThanFive(x) || greaterThanTen(x);

Console.WriteLine(combined(3));
Console.WriteLine(combined(7));
Console.WriteLine(combined(15));
```

**Output:**

```text
True
False
True
```

### Example 2: Generic OR function

```csharp
static Func<T, bool> Or<T>(
    Func<T, bool> first,
    Func<T, bool> second
)
{
    return value =>
        first(value) || second(value);
}

Func<int, bool> negative =
    x => x < 0;

Func<int, bool> greaterThanTen =
    x => x > 10;

var predicate = Or(negative, greaterThanTen);

Console.WriteLine(predicate(-5));
Console.WriteLine(predicate(5));
Console.WriteLine(predicate(15));
```

**Output:**

```text
True
False
True
```

The `||` operator also uses short-circuit evaluation.

---

### 7.3 NOT Composition

NOT composition reverses the result of a predicate.

### Example 1: Negate a predicate

```csharp
Func<int, bool> isEven =
    x => x % 2 == 0;

Func<int, bool> isOdd =
    x => !isEven(x);

Console.WriteLine(isOdd(5));
Console.WriteLine(isOdd(6));
```

**Output:**

```text
True
False
```

### Example 2: Generic NOT function

```csharp
static Func<T, bool> Not<T>(
    Func<T, bool> predicate
)
{
    return value => !predicate(value);
}

Func<int, bool> positive =
    x => x > 0;

var notPositive = Not(positive);

Console.WriteLine(notPositive(-5));
Console.WriteLine(notPositive(10));
```

**Output:**

```text
True
False
```

### Example 3: AND, OR, NOT together

```csharp
static Func<T, bool> And<T>(
    Func<T, bool> first,
    Func<T, bool> second
)
{
    return x => first(x) && second(x);
}

static Func<T, bool> Or<T>(
    Func<T, bool> first,
    Func<T, bool> second
)
{
    return x => first(x) || second(x);
}

static Func<T, bool> Not<T>(
    Func<T, bool> predicate
)
{
    return x => !predicate(x);
}

Func<int, bool> positive =
    x => x > 0;

Func<int, bool> even =
    x => x % 2 == 0;

Func<int, bool> greaterThanTen =
    x => x > 10;

var condition = Or(
    And(positive, even),
    Not(greaterThanTen)
);

Console.WriteLine(condition(12));
Console.WriteLine(condition(5));
Console.WriteLine(condition(15));
```

**Output:**

```text
True
True
False
```

### Predicate composition table

| Operation | Operator | Meaning |
|---|---|---|
| AND | `&&` | Both conditions must be true |
| OR | `\|\|` | At least one condition must be true |
| NOT | `!` | Reverse the condition |

**Key point:** Predicate composition creates reusable complex conditions from smaller predicates.

## 8. Partial Application

**Partial application** means fixing some arguments of a function to produce another function that requires fewer arguments.

### Example 1: Fix one argument

```csharp
Func<int, int, int> multiply =
    (a, b) => a * b;

Func<int, int> multiplyByTen =
    x => multiply(10, x);

Console.WriteLine(multiplyByTen(5));
Console.WriteLine(multiplyByTen(8));
```

**Output:**

```text
50
80
```

The first argument is fixed to `10`.

### Example 2: Addition

```csharp
Func<int, int, int> add =
    (a, b) => a + b;

Func<int, int> addFive =
    x => add(5, x);

Console.WriteLine(addFive(10));
Console.WriteLine(addFive(20));
```

**Output:**

```text
15
25
```

### Example 3: Partial application with three arguments

```csharp
Func<int, int, int, int> calculate =
    (a, b, c) => a + b * c;

Func<int, int, int> fixedA =
    (b, c) => calculate(10, b, c);

Console.WriteLine(fixedA(5, 2));
```

**Output:**

```text
20
```

### Example 4: Fix two arguments

```csharp
Func<int, int, int, int> calculate =
    (a, b, c) => a + b + c;

Func<int, int> fixedArguments =
    c => calculate(10, 20, c);

Console.WriteLine(fixedArguments(5));
```

**Output:**

```text
35
```

### Example 5: Generic partial application

```csharp
static Func<T2, TResult> Apply<T1, T2, TResult>(
    Func<T1, T2, TResult> function,
    T1 fixedValue
)
{
    return second =>
        function(fixedValue, second);
}

Func<int, int, int> multiply =
    (a, b) => a * b;

var multiplyByFive = Apply(multiply, 5);

Console.WriteLine(multiplyByFive(10));
```

**Output:**

```text
50
```

**Key point:** Partial application creates specialized functions by fixing selected arguments.

## 9. Currying Concepts

**Currying** transforms a function that accepts multiple arguments into a sequence of functions, each accepting one argument.

### Original function

```csharp
Func<int, int, int> add =
    (a, b) => a + b;
```

### Curried function

```csharp
Func<int, Func<int, int>> add =
    a => b => a + b;
```

### Mathematical representation

Original:

\[
f(a,b)=a+b
\]

Curried:

\[
f(a)(b)=a+b
\]

### Example 1: Basic currying

```csharp
Func<int, Func<int, int>> add =
    a => b => a + b;

Console.WriteLine(add(10)(20));
```

**Output:**

```text
30
```

### Explanation

```text
add(10)
   │
   ▼
Returns function:
b => 10 + b
   │
   ▼
add(10)(20)
   │
   ▼
30
```

### Example 2: Store an intermediate function

```csharp
Func<int, Func<int, int>> multiply =
    a => b => a * b;

Func<int, int> multiplyByFive =
    multiply(5);

Console.WriteLine(multiplyByFive(10));
Console.WriteLine(multiplyByFive(20));
```

**Output:**

```text
50
100
```

### Example 3: Three-argument currying

```csharp
Func<int, Func<int, Func<int, int>>> add =
    a => b => c => a + b + c;

Console.WriteLine(add(10)(20)(30));
```

**Output:**

```text
60
```

### Partial application vs currying

| Partial Application | Currying |
|---|---|
| Fixes selected arguments | Transforms a multiargument function |
| Produces a function with fewer arguments | Produces nested single-argument functions |
| Can be applied to ordinary delegates | Creates a chain of function calls |
| Example: `multiplyByFive(10)` | Example: `multiply(5)(10)` |

**Key point:** Currying transforms multiple arguments into a sequence of single-argument function applications.

---

## 10. C# Currying Patterns

C# supports currying through nested `Func<>` delegates and lambda expressions.

### Pattern 1: Two-argument currying

```csharp
Func<int, Func<int, int>> add =
    a => b => a + b;

Console.WriteLine(add(5)(10));
```

**Output:**

```text
15
```

### Pattern 2: Three-argument currying

```csharp
Func<int, Func<int, Func<int, int>>> calculate =
    a => b => c => a + b * c;

Console.WriteLine(calculate(10)(5)(2));
```

**Output:**

```text
20
```

### Pattern 3: Generic Curry method

```csharp
static Func<T1, Func<T2, TResult>>
    Curry<T1, T2, TResult>(
        Func<T1, T2, TResult> function
    )
{
    return first =>
        second =>
            function(first, second);
}

Func<int, int, int> multiply =
    (a, b) => a * b;

var curried = Curry(multiply);

Console.WriteLine(curried(5)(10));
```

**Output:**

```text
50
```

### Pattern 4: Uncurrying

Uncurrying converts a curried function into a function accepting multiple arguments.

```csharp
static Func<T1, T2, TResult>
    Uncurry<T1, T2, TResult>(
        Func<T1, Func<T2, TResult>> function
    )
{
    return (first, second) =>
        function(first)(second);
}

Func<int, Func<int, int>> curried =
    a => b => a + b;

var normal = Uncurry(curried);

Console.WriteLine(normal(10, 20));
```

**Output:**

```text
30
```

### Pattern 5: Curried string formatting

```csharp
Func<string, Func<string, string>> greet =
    greeting => name =>
        $"{greeting}, {name}";

var sayHello = greet("Hello");

Console.WriteLine(sayHello("Amit"));
Console.WriteLine(sayHello("Rahul"));
```

**Output:**

```text
Hello, Amit
Hello, Rahul
```

**Key point:** Nested delegates allow C# to express currying even though ordinary C# methods commonly accept multiple parameters.

## 11. Function Factories

A **function factory** creates and returns a configured function.

Function factories often use closures, partial application, or currying.

### Example 1: Multiplier factory

```csharp
static Func<int, int> CreateMultiplier(
    int factor
)
{
    return number => number * factor;
}

var doubleValue = CreateMultiplier(2);
var tripleValue = CreateMultiplier(3);

Console.WriteLine(doubleValue(10));
Console.WriteLine(tripleValue(10));
```

**Output:**

```text
20
30
```

### Example 2: Predicate factory

```csharp
static Func<int, bool> GreaterThan(
    int minimum
)
{
    return value => value > minimum;
}

var greaterThanTen = GreaterThan(10);

Console.WriteLine(greaterThanTen(15));
Console.WriteLine(greaterThanTen(5));
```

**Output:**

```text
True
False
```

### Example 3: String transformation factory

```csharp
static Func<string, string> CreatePrefixer(
    string prefix
)
{
    return text => prefix + text;
}

var addHello = CreatePrefixer("Hello ");
var addWelcome = CreatePrefixer("Welcome ");

Console.WriteLine(addHello("Amit"));
Console.WriteLine(addWelcome("Rahul"));
```

**Output:**

```text
Hello Amit
Welcome Rahul
```

### Example 4: Discount factory

```csharp
static Func<decimal, decimal> CreateDiscount(
    decimal percentage
)
{
    return price =>
        price * (1 - percentage / 100);
}

var discount10 = CreateDiscount(10);
var discount20 = CreateDiscount(20);

Console.WriteLine(discount10(1000));
Console.WriteLine(discount20(1000));
```

**Output:**

```text
900.0
800.0
```

### Example 5: Function factory with composition

```csharp
static Func<int, int> CreatePipeline(
    int addAmount,
    int multiplier
)
{
    Func<int, int> add =
        x => x + addAmount;

    Func<int, int> multiply =
        x => x * multiplier;

    return x => multiply(add(x));
}

var pipeline = CreatePipeline(10, 2);

Console.WriteLine(pipeline(5));
```

**Output:**

```text
30
```

**Key point:** Function factories create specialized functions that can be composed with other functions.

## 12. Composition Order

The order in which functions are composed affects the result.

Function composition is generally **not commutative**.

This means:

\[
f(g(x))\neq g(f(x))
\]

for many functions.

### Example 1: Different composition orders

```csharp
Func<int, int> addTen =
    x => x + 10;

Func<int, int> doubleValue =
    x => x * 2;

Func<int, int> first =
    x => doubleValue(addTen(x));

Func<int, int> second =
    x => addTen(doubleValue(x));

Console.WriteLine(first(5));
Console.WriteLine(second(5));
```

**Output:**

```text
30
20
```

### Explanation

First composition:

```text
5 → Add 10 → 15 → Double → 30
```

Second composition:

```text
5 → Double → 10 → Add 10 → 20
```

### Example 2: String transformation order

```csharp
Func<string, string> trim =
    text => text.Trim();

Func<string, string> addPrefix =
    text => "Hello " + text;

Func<string, string> first =
    text => addPrefix(trim(text));

Func<string, string> second =
    text => trim(addPrefix(text));

Console.WriteLine($"[{first("  Amit  ")}]");
Console.WriteLine($"[{second("  Amit  ")}]");
```

**Output:**

```text
[Hello Amit]
[Hello   Amit]
```

### Example 3: Composition associativity

Function composition is associative when functions are compatible.

\[
h\circ(g\circ f)=(h\circ g)\circ f
\]

```csharp
Func<int, int> f =
    x => x + 1;

Func<int, int> g =
    x => x * 2;

Func<int, int> h =
    x => x * x;

Func<int, int> first =
    x => h(g(f(x)));

Func<int, int> second =
    x => (h(g(f(x))));

Console.WriteLine(first(5));
Console.WriteLine(second(5));
```

**Output:**

```text
144
144
```

Both expressions apply `f`, then `g`, then `h`.

### Example 4: Explicit associativity with Compose

```csharp
static Func<T, R> Compose<T, M, R>(
    Func<M, R> outer,
    Func<T, M> inner
)
{
    return x => outer(inner(x));
}

Func<int, int> f = x => x + 1;
Func<int, int> g = x => x * 2;
Func<int, int> h = x => x * x;

var left = Compose(h, Compose(g, f));
var right = Compose(Compose(h, g), f);

Console.WriteLine(left(5));
Console.WriteLine(right(5));
```

**Output:**

```text
144
144
```

**Key point:** Composition order matters. Function composition is associative, but generally not commutative.

## 13. Type Compatibility

Functions can be composed only when their parameter and return types are compatible.

### Example 1: Compatible types

```csharp
Func<int, string> convert =
    number => number.ToString();

Func<string, int> length =
    text => text.Length;

Func<int, int> composed =
    number => length(convert(number));

Console.WriteLine(composed(12345));
```

**Output:**

```text
5
```

### Type flow

```text
int
 ↓
Convert to string
 ↓
string
 ↓
Get Length
 ↓
int
```

### Example 2: String to integer to boolean

```csharp
Func<string, int> length =
    text => text.Length;

Func<int, bool> valid =
    value => value >= 5;

Func<string, bool> composed =
    text => valid(length(text));

Console.WriteLine(composed("Hello"));
Console.WriteLine(composed("Hi"));
```

**Output:**

```text
True
False
```

### Example 3: Incompatible types

```csharp
Func<int, string> convert =
    number => number.ToString();

Func<double, bool> check =
    value => value > 10;

// Invalid:
// Func<int, bool> composed =
//     number => check(convert(number));
```

The first function returns `string`, while the second expects `double`.

C# does not implicitly convert a string to a double.

### Example 4: Add an explicit conversion function

```csharp
Func<int, string> convert =
    number => number.ToString();

Func<string, double> parse =
    text => double.Parse(
        text,
        System.Globalization.CultureInfo.InvariantCulture
    );

Func<double, bool> check =
    value => value > 10;

Func<int, bool> composed =
    number => check(parse(convert(number)));

Console.WriteLine(composed(15));
```

**Output:**

```text
True
```

### Compatibility table

| First Function Output | Second Function Input | Compatible? |
|---|---|---|
| `int` | `int` | Yes |
| `string` | `string` | Yes |
| `int` | `object` | Yes, through boxing |
| `string` | `object` | Yes |
| `string` | `double` | No implicit conversion |
| `int` | `string` | No implicit conversion |

**Key point:** Composition requires that the first function's output can be passed to the second function's input.

## 14. Generic Composition

Generic composition allows functions with different input, intermediate, and output types to be combined.

### Generic Compose method

```csharp
static Func<TInput, TOutput>
    Compose<TInput, TMiddle, TOutput>(
        Func<TMiddle, TOutput> outer,
        Func<TInput, TMiddle> inner
    )
{
    return input => outer(inner(input));
}
```

### Example 1: Integer composition

```csharp
static Func<TInput, TOutput>
    Compose<TInput, TMiddle, TOutput>(
        Func<TMiddle, TOutput> outer,
        Func<TInput, TMiddle> inner
    )
{
    return input => outer(inner(input));
}

Func<int, int> square =
    x => x * x;

Func<int, string> format =
    x => $"Result: {x}";

var composed = Compose(format, square);

Console.WriteLine(composed(5));
```

**Output:**

```text
Result: 25
```

### Example 2: String composition

```csharp

    Compose<TInput, TMiddle, TOutput>(

    )

}

Func<string, string> trim =
```

### Example 3: Generic forward composition

```csharp
static Func<TInput, TOutput>
    Pipe<TInput, TMiddle, TOutput>(
        Func<TInput, TMiddle> first,
        Func<TMiddle, TOutput> second
    )
{
    return input => second(first(input));
}

Func<string, string> upper =
    text => text.ToUpperInvariant();

    text => text.Length;

var pipeline = Pipe(upper, length);

Console.WriteLine(pipeline("hello"));
```

```text
5
```

### Example 4: Generic composition with different types

```csharp
static Func<TInput, TOutput>
    Pipe<TInput, TMiddle, TOutput>(
        Func<TInput, TMiddle> first,
        Func<TMiddle, TOutput> second
    )
{
    return input => second(first(input));
}

Func<int, string> convert =
    number => $"Number: {number}";

Func<string, bool> isLong =
    text => text.Length > 10;

Console.WriteLine(pipeline(100));
Console.WriteLine(pipeline(100000));
```

**Output:**

```text

True
```

Both formatted strings have more than ten characters.

### Generic composition type flow

```text
TInput
   │
   ▼
First Function
   │
   ▼
TMiddle
   │
   ▼
Second Function
   │
   ▼
TOutput
```

**Key point:** Generic composition combines type-safe functions without restricting them to a single data type.

## 15. Avoiding Excessive Indirection

Function composition improves modularity, but too many layers of functions can make code difficult to follow.

**Indirection** means reaching an operation through intermediate functions rather than calling it directly.

### Example 1: Simple direct operation

```csharp
int number = 10;

int result = number * 2;

Console.WriteLine(result);
```

**Output:**

```text
20
```

This is clear and direct.

### Example 2: Unnecessary abstraction

```csharp
Func<int, int> doubleValue =
    x => x * 2;

Func<int, int> process =
    x => doubleValue(x);

Func<int, int> execute =
    x => process(x);

Console.WriteLine(execute(10));
```

**Output:**

```text
20
```

The extra functions provide no meaningful benefit.

### Example 3: Meaningful composition

```csharp
Func<string, string> normalize =
    text => text.Trim().ToUpperInvariant();

Func<string, bool> isValid =
    text => text.Length >= 5;

Func<string, bool> validate =
    text => isValid(normalize(text));

Console.WriteLine(validate("  hello  "));
Console.WriteLine(validate("  hi  "));
```

**Output:**

```text
True
False
```

Here, composition separates two meaningful operations:

1. Normalization
2. Validation

### Example 4: Prefer readable pipelines

```csharp
int[] numbers =
{
    1, 2, 3, 4, 5, 6
};

var result = numbers
    .Where(x => x % 2 == 0)
    .Select(x => x * 10)
    .ToArray();

Console.WriteLine(
    string.Join(", ", result)
);
```

**Output:**

```text
20, 40, 60
```

The pipeline clearly expresses the processing steps.

### Example 5: Use named functions for complex logic

```csharp
static bool IsEligible(int age)
{
    return age >= 18 && age <= 60;
}

static string FormatAge(int age)
{
    return $"Age: {age}";
}

int[] ages =
{
    15, 20, 35, 70
};

var result = ages
    .Where(IsEligible)
    .Select(FormatAge);

foreach (string item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
Age: 20
Age: 35
```

### Composition readability guidelines

| Practice | Recommendation |
|---|---|
| Small functions | Prefer functions with clear responsibilities |
| Function names | Use descriptive names |
| Deep nesting | Avoid when it reduces readability |
| Generic abstractions | Introduce when they provide meaningful reuse |
| LINQ pipelines | Prefer clear transformation sequences |
| One-off operations | Use direct code when simpler |
| Complex logic | Extract meaningful named functions |
| Composition order | Make execution order understandable |

**Key point:** Compose functions when composition improves clarity or reuse. Avoid abstraction that only adds unnecessary layers.
