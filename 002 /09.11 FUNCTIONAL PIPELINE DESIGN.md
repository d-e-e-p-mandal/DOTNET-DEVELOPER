# 09.11 — FUNCTIONAL PIPELINE DESIGN

**Chapter:** 09 — Functional C#  
**Total Syllabus Points:** 19  
**Language:** C#  
**Level:** Beginner → Advanced

Functional pipeline design is a programming approach in which data passes through a sequence of small, focused functions. Each function performs a specific operation and passes its result to the next stage.

In C#, functional pipelines can be built using methods, delegates, lambda expressions, LINQ operators, and immutable data structures.

This section explains each syllabus point in its original order, with definitions, C# examples, execution flow, and outputs.

---

## 1. Pipeline Inputs

A **pipeline input** is the original data supplied to a sequence of transformations.

The input can be a single value, an object, a collection, or another data structure.

### Example 1: Single-value input

```csharp
static int Double(int number)
{
    return number * 2;
}

int input = 10;

int result = Double(input);

Console.WriteLine(result);
```

**Output:**

```text
20
```

Here:

```text
Pipeline Input = 10
Transformation = Double
Pipeline Output = 20
```

### Example 2: Collection input

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

var result = numbers
    .Where(x => x > 2)
    .Select(x => x * 10);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
30, 40, 50
```

### Execution flow

```text
Input
[1, 2, 3, 4, 5]
        │
        ▼
Filter x > 2
[3, 4, 5]
        │
        ▼
Multiply by 10
[30, 40, 50]
        │
        ▼
Output
```

### Important characteristics

A pipeline input should have a clearly defined type and meaning.

For example:

```csharp
IEnumerable<int> numbers
```

indicates that the pipeline accepts a sequence of integers.

```csharp
string name
```

indicates that the pipeline accepts a string.

**Key point:** Every functional pipeline begins with a clearly defined input.

---

## 2. Pipeline Outputs

A **pipeline output** is the final result produced after all processing stages have completed.

A pipeline may return a scalar value, a transformed collection, or a new object.

### Example 1: Scalar output

```csharp
int[] numbers = { 10, 20, 30, 40 };

int result = numbers
    .Where(x => x > 15)
    .Sum();

Console.WriteLine(result);
```

**Output:**

```text
90
```

Explanation:

```text
Input:
10, 20, 30, 40

Filter:
20, 30, 40

Sum:
90
```

### Example 2: Collection output

```csharp
string[] names =
{
    "Rahul",
    "Amit",
    "Priya"
};

string[] result = names
    .Select(name => name.ToUpperInvariant())
    .ToArray();

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
RAHUL, AMIT, PRIYA
```

### Example 3: Object output

```csharp
public record Summary(
    int Count,
    int Total
);
```

```csharp
int[] numbers = { 10, 20, 30 };

Summary result = new(
    numbers.Length,
    numbers.Sum()
);

Console.WriteLine(result);
```

**Output:**

```text
Summary { Count = 3, Total = 60 }
```

### Output design principles

| Principle | Explanation |
|---|---|
| Clear type | The caller knows what the pipeline returns |
| Predictable result | The output follows the documented rules |
| Minimal information | Return only the information needed |
| Explicit failure behavior | Define how invalid input or failures are represented |

**Key point:** The pipeline output should clearly represent the result of the complete computation.

## 3. Transformation Stages

A **transformation stage** converts data from one form into another.

In functional programming, transformations are commonly represented by functions.

### Example 1: Multiple transformation stages

```csharp
static int Double(int number)
{
    return number * 2;
}

static int AddTen(int number)
{
    return number + 10;
}

static string Format(int number)
{
    return $"Result: {number}";
}
```

Usage:

```csharp
int input = 5;

int first = Double(input);

int second = AddTen(first);

string output = Format(second);

Console.WriteLine(output);
```

**Output:**

```text
Result: 20
```

### Execution flow

```text
5
│
▼
Double
│
▼
10
│
▼
AddTen
│
▼
20
│
▼
Format
│
▼
"Result: 20"
```

### Example 2: LINQ transformation stages

```csharp
int[] numbers = { 1, 2, 3, 4 };

var result = numbers
    .Select(x => x * 2)
    .Select(x => x + 10)
    .Select(x => $"Value: {x}");

foreach (string item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
Value: 12
Value: 14
Value: 16
Value: 18
```

Each `Select()` introduces a transformation stage.

### Transformation types

```text
TInput → TOutput
```

Examples:

```text
int → int
int → string
string → int
Employee → EmployeeDto
```

**Key point:** Transformation stages convert data while allowing each processing step to remain focused.

## 4. Filtering Stages

A **filtering stage** selects elements that satisfy a condition.

In LINQ, filtering is commonly implemented using `Where()`.

### Example 1: Basic filtering

```csharp
int[] numbers =
{
    10, 15, 20, 25, 30
};

var result = numbers
    .Where(x => x >= 20);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
20, 25, 30
```

### Example 2: Multiple filtering stages

```csharp
int[] numbers =
{
    5, 10, 15, 20, 25, 30
};

var result = numbers
    .Where(x => x > 10)
    .Where(x => x % 2 == 0);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
20, 30
```

### Execution flow

```text
Input:
5, 10, 15, 20, 25, 30
            │
            ▼
Filter x > 10
15, 20, 25, 30
            │
            ▼
Filter Even Numbers
20, 30
            │
            ▼
Output
```

### Example 3: Filtering with a named function

```csharp
static bool IsEven(int number)
{
    return number % 2 == 0;
}

int[] numbers = { 1, 2, 3, 4, 5, 6 };

var result = numbers.Where(IsEven);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
2, 4, 6
```

### Filtering vs transformation

| Filtering | Transformation |
|---|---|
| Selects elements | Converts elements |
| Commonly uses `Where()` | Commonly uses `Select()` |
| Can reduce element count | Usually preserves element count |
| Uses a predicate | Uses a selector |

**Key point:** Filtering stages control which elements continue through a pipeline.

## 5. Validation Stages

A **validation stage** checks whether input data satisfies required rules before further processing.

Validation can reject invalid input, return a validation result, or prevent later stages from executing.

### Example 1: Validation using a function

```csharp
static bool IsValidAge(int age)
{
    return age >= 0 && age <= 120;
}

Console.WriteLine(IsValidAge(25));
Console.WriteLine(IsValidAge(-5));
```

**Output:**

```text
True
False
```

### Example 2: Validation before transformation

```csharp
static string FormatAge(int age)
{
    if (age < 0 || age > 120)
        throw new ArgumentOutOfRangeException(
            nameof(age)
        );

    return $"Age: {age}";
}

Console.WriteLine(FormatAge(25));
```

**Output:**

```text
Age: 25
```

### Example 3: Validate a collection

```csharp
int[] ages =
{
    20, -5, 35, 150, 40
};

var validAges = ages
    .Where(age => age >= 0 && age <= 120);

Console.WriteLine(string.Join(", ", validAges));
```

**Output:**

```text
20, 35, 40
```

**Important distinction:** Filtering invalid elements is appropriate only when discarding them is acceptable. If invalid input must cause an error, validation should report the failure rather than silently remove data.

### Example 4: Validation result

```csharp
public record ValidationResult(
    bool IsValid,
    string? Error
);
```

```csharp
static ValidationResult ValidateAge(int age)
{
    if (age < 0)
        return new(false, "Age cannot be negative.");

    if (age > 120)
        return new(false, "Age exceeds the allowed range.");

    return new(true, null);
}
```

Usage:

```csharp
ValidationResult result = ValidateAge(-5);

Console.WriteLine(result.IsValid);
Console.WriteLine(result.Error);
```

**Output:**

```text
False
Age cannot be negative.
```

**Key point:** Validation stages ensure that later processing receives acceptable data or a clearly reported failure.

## 6. Aggregation Stages

An **aggregation stage** combines multiple values into a summary result.

Common LINQ aggregation methods include:

- `Sum()`
- `Count()`
- `Average()`
- `Min()`
- `Max()`
- `Aggregate()`

### Example 1: Sum

```csharp
int[] numbers = { 10, 20, 30 };

int total = numbers.Sum();

Console.WriteLine(total);
```

**Output:**

```text
60
```

### Example 2: Count

```csharp
int[] numbers = { 5, 10, 15, 20 };

int count = numbers
    .Where(x => x > 10)
    .Count();

Console.WriteLine(count);
```

**Output:**

```text
2
```

### Example 3: Average

```csharp
int[] marks = { 70, 80, 90 };

double average = marks.Average();

Console.WriteLine(average);
```

**Output:**

```text
80
```

### Example 4: Complete aggregation pipeline

```csharp
int[] numbers =
{
    5, 10, 15, 20, 25
};

int result = numbers
    .Where(x => x > 10)
    .Select(x => x * 2)
    .Sum();

Console.WriteLine(result);
```

**Output:**

```text
120
```

### Execution

```text
Input:
5, 10, 15, 20, 25
          │
          ▼
Filter > 10
15, 20, 25
          │
          ▼
Multiply by 2
30, 40, 50
          │
          ▼
Sum
120
```

**Key point:** Aggregation stages reduce a collection into a calculated summary.

## 7. Composition

**Function composition** means connecting functions so that the output of one function becomes the input of another.

### Example 1: Manual composition

```csharp
static int Double(int number)
{
    return number * 2;
}

static int AddFive(int number)
{
    return number + 5;
}
```

Usage:

```csharp
int result = AddFive(Double(10));

Console.WriteLine(result);
```

**Output:**

```text
25
```

### Example 2: Composition with delegates

```csharp
Func<int, int> doubleValue = x => x * 2;

Func<int, int> addFive = x => x + 5;

Func<int, int> composed =
    x => addFive(doubleValue(x));

Console.WriteLine(composed(10));
```

**Output:**

```text
25
```

### Example 3: Generic composition

```csharp
static Func<TInput, TOutput> Compose<TInput, TMiddle, TOutput>(
    Func<TInput, TMiddle> first,
    Func<TMiddle, TOutput> second)
{
    return input => second(first(input));
}
```

Usage:

```csharp
Func<int, int> multiply = x => x * 3;

Func<int, string> format = x => $"Value: {x}";

Func<int, string> pipeline =
    Compose(multiply, format);

Console.WriteLine(pipeline(5));
```

**Output:**

```text
Value: 15
```

### Composition flow

```text
TInput
   │
   ▼
Function A
   │
   ▼
TMiddle
   │
   ▼
Function B
   │
   ▼
TOutput
```

**Key point:** Composition creates larger operations by combining smaller functions.

## 8. Small Functions

A **small function** performs one clearly defined operation.

Small functions are easier to understand, test, reuse, and combine.

### Example 1: Multiple responsibilities in one function

```csharp
static string ProcessName(string name)
{
    string trimmed = name.Trim();

    string upper = trimmed.ToUpperInvariant();

    return $"Hello, {upper}";
}
```

This function performs three operations.

### Example 2: Separate small functions

```csharp
static string TrimName(string name)
{
    return name.Trim();
}

static string UppercaseName(string name)
{
    return name.ToUpperInvariant();
}

static string AddGreeting(string name)
{
    return $"Hello, {name}";
}
```

Usage:

```csharp
string input = "  Rahul  ";

string result = AddGreeting(
    UppercaseName(
        TrimName(input)
    )
);

Console.WriteLine(result);
```

**Output:**

```text
Hello, RAHUL
```

### Benefits

| Benefit | Explanation |
|---|---|
| Readability | Each function has a clear purpose |
| Testing | Each operation can be tested separately |
| Reusability | Functions can be used in other pipelines |
| Composition | Functions can be connected easily |
| Maintenance | Changes are isolated to focused operations |

### Important consideration

Small functions should represent meaningful operations.

Creating a separate function for every trivial expression can make code harder to follow.

**Key point:** Prefer focused functions with clear responsibilities rather than unnecessary fragmentation.

## 9. Pure Functions

A **pure function** produces its result entirely from its explicit inputs and does not produce observable side effects.

For the same inputs, it produces the same result.

### Example 1: Pure function

```csharp
static int Square(int number)
{
    return number * number;
}

Console.WriteLine(Square(5));
Console.WriteLine(Square(5));
```

**Output:**

```text
25
25
```

### Example 2: Impure function

```csharp
static int counter = 0;

static int Increment()
{
    counter++;

    return counter;
}
```

This function depends on and modifies external state.

### Example 3: Convert to a pure function

```csharp
static int Increment(int counter)
{
    return counter + 1;
}
```

Usage:

```csharp
int initial = 10;

int updated = Increment(initial);

Console.WriteLine(initial);
Console.WriteLine(updated);
```

**Output:**

```text
10
11
```

### Pure vs impure functions

| Pure Function | Impure Function |
|---|---|
| Depends on explicit inputs | May depend on external state |
| No observable side effects | May modify external state |
| Predictable results | Results may depend on environment |
| Easier to test | Often requires additional setup |
| Easier to compose | May introduce hidden dependencies |

**Key point:** Pure functions make functional pipelines more predictable and easier to reason about.

## 10. Reusable Functions

A **reusable function** performs an operation that can be applied in multiple contexts.

### Example 1: Reusable predicate

```csharp
static bool IsPositive(int number)
{
    return number > 0;
}
```

Usage:

```csharp
int[] numbers =
{
    -10, 5, -3, 8, 0
};

var positives = numbers.Where(IsPositive);

Console.WriteLine(string.Join(", ", positives));
```

**Output:**

```text
5, 8
```

### Example 2: Reuse in another pipeline

```csharp
int[] values =
{
    -20, 10, 30, -5
};

int total = values
    .Where(IsPositive)
    .Sum();

Console.WriteLine(total);
```

**Output:**

```text
40
```

The same `IsPositive()` function works in different pipelines.

### Example 3: Generic reusable transformation

```csharp
static IEnumerable<TResult> Transform<TSource, TResult>(
    IEnumerable<TSource> source,
    Func<TSource, TResult> selector)
{
    return source.Select(selector);
}
```

Usage:

```csharp
int[] numbers = { 1, 2, 3 };

var result = Transform(
    numbers,
    x => $"Number: {x}"
);

foreach (string item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
Number: 1
Number: 2
Number: 3
```

This example illustrates generic reuse; in ordinary code, calling `Select()` directly would usually be simpler.

**Key point:** Reusable functions reduce duplication and allow consistent behavior across pipelines.

## 11. Explicit Dependencies

An **explicit dependency** is a value or service supplied directly to a function rather than accessed through hidden global state.

### Example 1: Hidden dependency

```csharp
static decimal taxRate = 0.10m;

static decimal CalculateTotal(decimal amount)
{
    return amount + amount * taxRate;
}
```

The function depends on an external variable.

Changing `taxRate` changes its behavior without changing its arguments.

### Example 2: Explicit dependency

```csharp
static decimal CalculateTotal(
    decimal amount,
    decimal taxRate)
{
    return amount + amount * taxRate;
}
```

Usage:

```csharp
Console.WriteLine(CalculateTotal(1000m, 0.10m));
Console.WriteLine(CalculateTotal(1000m, 0.20m));
```

**Output:**

```text
1100.00
1200.00
```

### Example 3: Dependency through a delegate

```csharp
static decimal Calculate(
    decimal amount,
    Func<decimal, decimal> adjustment)
{
    return adjustment(amount);
}
```

Usage:

```csharp
Func<decimal, decimal> addTax =
    amount => amount * 1.10m;

Console.WriteLine(Calculate(1000m, addTax));
```

**Output:**

```text
1100.00
```

### Comparison

```text
Hidden Dependency

Function
   │
   ▼
Global Variable
```

```text
Explicit Dependency

Input + Dependency
        │
        ▼
      Function
        │
        ▼
      Output
```

**Key point:** Explicit dependencies make a function's behavior easier to understand and test.

## 12. Immutable Intermediate Results

An **immutable intermediate result** is a value produced by one stage that subsequent stages do not modify in place.

### Example 1: Immutable numeric values

```csharp
int original = 10;

int doubled = original * 2;

int increased = doubled + 5;

Console.WriteLine(original);
Console.WriteLine(doubled);
Console.WriteLine(increased);
```

**Output:**

```text
10
20
25
```

Each stage produces a new value.

### Example 2: Immutable records

```csharp
public sealed record Product(
    string Name,
    decimal Price
);
```

Usage:

```csharp
Product original = new("Laptop", 50000m);

Product discounted = original with
{
    Price = original.Price * 0.90m
};

Console.WriteLine(original.Price);
Console.WriteLine(discounted.Price);
```

**Output:**

```text
50000
45000.00
```

### Example 3: Immutable collection results

```csharp
using System.Collections.Immutable;

ImmutableArray<int> original =
    ImmutableArray.Create(1, 2, 3);

ImmutableArray<int> updated =
    original.Add(4);

Console.WriteLine(string.Join(", ", original));
Console.WriteLine(string.Join(", ", updated));
```

**Output:**

```text
1, 2, 3
1, 2, 3, 4
```

`ImmutableArray<T>` is provided by the `System.Collections.Immutable` library.

### Benefits

- Earlier results remain available.
- Stages cannot accidentally change immutable values.
- Data flow is easier to trace.
- Sharing immutable values is generally safer.

**Key point:** Immutable intermediate results help prevent unintended interactions between pipeline stages.

## 13. Error Propagation

**Error propagation** means passing information about a failure through the pipeline so that later stages can respond appropriately.

A failure may be represented by an exception or an explicit result value.

### Example 1: Exception propagation

```csharp
static int Divide(int a, int b)
{
    if (b == 0)
        throw new DivideByZeroException();

    return a / b;
}
```

Usage:

```csharp
try
{
    Console.WriteLine(Divide(10, 0));
}
catch (DivideByZeroException)
{
    Console.WriteLine("Division failed.");
}
```

**Output:**

```text
Division failed.
```

### Example 2: Explicit result type

```csharp
public sealed record Result<T>(
    bool IsSuccess,
    T? Value,
    string? Error
);
```

```csharp
static Result<int> Divide(int a, int b)
{
    if (b == 0)
    {
        return new(
            false,
            default,
            "Cannot divide by zero."
        );
    }

    return new(
        true,
        a / b,
        null
    );
}
```

Usage:

```csharp
Result<int> result = Divide(10, 0);

if (result.IsSuccess)
{
    Console.WriteLine(result.Value);
}
else
{
    Console.WriteLine(result.Error);
}
```

**Output:**

```text
Cannot divide by zero.
```

### Error propagation flow

```text
Input
  │
  ▼
Stage 1
  │
  ▼
Stage 2
  │
  ├── Success ──► Stage 3
  │
  └── Failure ──► Error Result
```

### Important consideration

A result type should clearly distinguish success and failure. The simple example above is educational; a more robust design can prevent invalid combinations such as `IsSuccess = true` with an error message.

**Key point:** Error propagation preserves failure information so the caller can handle it appropriately.

## 14. Short-Circuiting

**Short-circuiting** means stopping further processing once a condition has been satisfied or a failure has occurred.

### Example 1: Boolean short-circuiting

```csharp
static bool IsPositive(int number)
{
    Console.WriteLine("Checking positive");

    return number > 0;
}

static bool IsEven(int number)
{
    Console.WriteLine("Checking even");

    return number % 2 == 0;
}
```

Usage:

```csharp
int number = -4;

bool result =
    IsPositive(number) &&
    IsEven(number);

Console.WriteLine(result);
```

**Output:**

```text
Checking positive
False
```

`IsEven()` is not called because the first condition is false.

### Example 2: LINQ short-circuiting

```csharp
int[] numbers = { 2, 4, 6, 7, 8 };

bool result = numbers.Any(x => x % 2 != 0);

Console.WriteLine(result);
```

**Output:**

```text
True
```

`Any()` can stop as soon as it finds `7`.

### Example 3: Stop after validation failure

```csharp
static string ProcessAge(int age)
{
    if (age < 0)
        return "Invalid age";

    if (age > 120)
        return "Age exceeds limit";

    return $"Accepted age: {age}";
}

Console.WriteLine(ProcessAge(-5));
```

**Output:**

```text
Invalid age
```

### Short-circuiting operators

| Operator | Short-Circuit Behavior |
|---|---|
| `&&` | Stops when the left operand is false |
| `\|\|` | Stops when the left operand is true |
| `Any()` | Stops after finding a matching element |
| `All()` | Stops after finding a nonmatching element |
| `First()` | Stops after retrieving the first matching element |
| `Take(n)` | Can stop after producing the requested number of elements |

**Key point:** Short-circuiting avoids unnecessary work when further processing cannot change the result.

## 15. Pipeline Readability

**Pipeline readability** means organizing stages so that the flow of data and the purpose of each operation are easy to understand.

### Example 1: Difficult-to-read pipeline

```csharp
var result = numbers.Where(x => x > 0).Select(x => x * 2).Where(x => x > 10).OrderBy(x => x).ToList();
```

This code is valid but harder to scan.

### Example 2: Readable formatting

```csharp
var result = numbers
    .Where(x => x > 0)
    .Select(x => x * 2)
    .Where(x => x > 10)
    .OrderBy(x => x)
    .ToList();
```

Each stage appears on a separate line.

### Example 3: Meaningful named functions

```csharp
static bool IsPositive(int number)
{
    return number > 0;
}

static int Double(int number)
{
    return number * 2;
}

static bool IsGreaterThanTen(int number)
{
    return number > 10;
}
```

Usage:

```csharp
int[] numbers =
{
    -5, 2, 4, 6, 8
};

var result = numbers
    .Where(IsPositive)
    .Select(Double)
    .Where(IsGreaterThanTen)
    .OrderBy(x => x)
    .ToList();

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
12, 16
```

### Readability principles

| Principle | Explanation |
|---|---|
| Clear stage names | Communicate the purpose of each operation |
| Consistent formatting | Make data flow easy to follow |
| Focused functions | Avoid overly complicated lambdas |
| Meaningful ordering | Organize stages logically |
| Limited nesting | Avoid deeply nested expressions when possible |
| Appropriate abstraction | Extract complexity only when it improves clarity |

**Key point:** A good functional pipeline should be readable from input to output.

## 16. Pipeline Debugging

**Pipeline debugging** means identifying which processing stage produces an unexpected value or behavior.

### Example 1: Inspect intermediate results

```csharp
int[] numbers =
{
    1, 2, 3, 4, 5
};

var filtered = numbers
    .Where(x => x > 2)
    .ToArray();

var doubled = filtered
    .Select(x => x * 2)
    .ToArray();

int total = doubled.Sum();

Console.WriteLine(
    $"Filtered: {string.Join(", ", filtered)}"
);

Console.WriteLine(
    $"Doubled: {string.Join(", ", doubled)}"
);

Console.WriteLine($"Total: {total}");
```

**Output:**

```text
Filtered: 3, 4, 5
Doubled: 6, 8, 10
Total: 24
```

### Example 2: Debug individual functions

```csharp
static int Double(int number)
{
    return number * 2;
}
```

Because the function is separate, it can be tested directly:

```csharp
Console.WriteLine(Double(5));
Console.WriteLine(Double(10));
```

**Output:**

```text
10
20
```

### Important consideration

Materializing intermediate LINQ results with `ToArray()` or `ToList()` changes execution behavior and consumes memory.

For debugging, this can be useful because it establishes clear boundaries between stages.

For performance-sensitive production code, unnecessary materialization should generally be avoided.

**Key point:** Debug pipelines by inspecting stage boundaries and testing individual transformations.

## 17. Pipeline Testing

**Pipeline testing** verifies that individual stages and the complete pipeline produce expected results.

### Example 1: Test a transformation

```csharp
static int Double(int number)
{
    return number * 2;
}
```

```csharp
Console.WriteLine(Double(5) == 10);
Console.WriteLine(Double(0) == 0);
```

## 18. Pipeline Performance

**Pipeline performance** concerns the execution time, memory usage, and repeated work introduced by processing stages.

### Example 1: Early filtering

```csharp
int[] numbers =
{
    1, 2, 3, 4, 5, 6
};

var result = numbers
    .Where(x => x > 3)
    .Select(x => x * 100);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
400, 500, 600
```

Filtering before an expensive transformation can reduce the number of transformations performed.

### Example 2: Avoid unnecessary materialization

Less efficient when intermediate collections are not needed:

```csharp
var filtered = numbers
    .Where(x => x > 3)
    .ToList();

var doubled = filtered
    .Select(x => x * 2)
    .ToList();

int total = doubled.Sum();
```

More direct:

```csharp
int total = numbers
    .Where(x => x > 3)
    .Select(x => x * 2)
    .Sum();
```

### Example 3: Avoid repeated enumeration

```csharp
var query = numbers.Where(x => x > 3);

int count = query.Count();

int sum = query.Sum();
```

Depending on the source, this may enumerate the query twice.

If repeated reuse is necessary:

```csharp
int[] values = numbers
    .Where(x => x > 3)
    .ToArray();

int count = values.Length;

int sum = values.Sum();
```

This performs filtering once and stores the results.

### Performance considerations

| Concern | Explanation |
|---|---|
| Repeated enumeration | May repeat expensive processing |
| Unnecessary materialization | Allocates additional memory |
| Sorting | Requires comparison work and buffering |
| Expensive selectors | Can dominate execution time |
| Early filtering | Can reduce downstream processing |
| Deferred execution | Delays work until enumeration |
| Large inputs | Can increase memory and processing costs |

**Key point:** Optimize pipelines based on actual costs while preserving clarity and correctness.

## 19. Building Complete Functional Pipelines

A **complete functional pipeline** combines input handling, validation, filtering, transformation, aggregation, and output generation.

### Example: Student marks processing

First, define the data models:

```csharp
public sealed record Student(
    string Name,
    int Marks
);

public sealed record StudentResult(
    string Name,
    int Marks,
    string Grade
);
```

### Step 1: Define validation

```csharp
static bool HasValidMarks(Student student)
{
    return student.Marks >= 0
        && student.Marks <= 100;
}
```

### Step 2: Define filtering

```csharp
static bool HasPassed(Student student)
{
    return student.Marks >= 40;
}
```

### Step 3: Define transformation

```csharp
static string CalculateGrade(int marks)
{
    if (marks >= 90)
        return "A";

    if (marks >= 75)
        return "B";

    if (marks >= 60)
        return "C";

    return "D";
}
```

### Step 4: Define projection

```csharp
static StudentResult ToResult(Student student)
{
    return new StudentResult(
        student.Name,
        student.Marks,
        CalculateGrade(student.Marks)
    );
}
```

### Step 5: Build the pipeline

```csharp
Student[] students =
{
    new("Rahul", 95),
    new("Amit", 65),
    new("Priya", 85),
    new("Ravi", 30),
    new("Neha", 110)
};

StudentResult[] results = students
    .Where(HasValidMarks)
    .Where(HasPassed)
    .Select(ToResult)
    .OrderByDescending(student => student.Marks)
    .ToArray();
```

### Step 6: Display the output

```csharp
foreach (StudentResult student in results)
{
    Console.WriteLine(
        $"{student.Name} - {student.Marks} - {student.Grade}"
    );
}
```

**Output:**

```text
Rahul - 95 - A
Priya - 85 - B
Amit - 65 - C
```

In this example, invalid marks and failing students are deliberately excluded. In an application where invalid records must be reported, validation should return errors instead of silently filtering them.

### Complete pipeline architecture

```text
STUDENT DATA
     │
     ▼
VALIDATION
Marks between 0 and 100
     │
     ▼
FILTERING
Marks >= 40
     │
     ▼
TRANSFORMATION
Calculate Grade
     │
     ▼
PROJECTION
Create StudentResult
     │
     ▼
SORTING
Highest Marks First
     │
     ▼
MATERIALIZATION
ToArray()
     │
     ▼
FINAL OUTPUT
```

### Example: Aggregation after processing

```csharp
double average = results.Average(
    student => student.Marks
);

Console.WriteLine($"Average: {average:F2}");
```

**Output:**

```text
Average: 81.67
```

### Characteristics of the completed pipeline

- Input data is clearly defined.
- Validation and filtering are separate operations.
- Transformations use small named functions.
- Original student objects are not modified.
- Processing stages are easy to inspect.
- The output type is explicit.
- The result is materialized once.

**Key point:** Complete functional pipelines combine small, predictable stages into a clear data-processing workflow.
