# 06.01 Introduction to LINQ

## Language Integrated Query

Use LINQ to filter, transform, group, and combine data.

```csharp
using System.Linq;

int[] numbers = { 1, 2, 3, 4 };
var result = numbers.Where(n => n % 2 == 0).Select(n => n * 10);
Console.WriteLine(string.Join(", ", result)); // 20, 40
```

`Where` keeps matching elements; `Select` transforms each retained element. The original array is unchanged.

### Reading the query from left to right

- For the source `1, 2, 3, 4`, the filter keeps `2, 4`; the projection changes them to `20, 40`.
- The query's element type is `int` throughout this example.

```csharp
int[] numbers = { 1, 2, 3, 4 };
IEnumerable<int> even = numbers.Where(n => n % 2 == 0);
IEnumerable<string> labels = even.Select(n => $"Number {n}");
Console.WriteLine(string.Join("; ", labels)); // Number 2; Number 4
```

- `n` is the lambda parameter.
- `n => n % 2 == 0` is a function that receives one integer and returns a Boolean.
- `n => $"Number {n}"` receives an integer and returns a string, so the result becomes `IEnumerable<string>`.

### Query syntax for the same work

```csharp
int[] numbers = { 1, 2, 3, 4 };
var query = from number in numbers
            where number % 2 == 0
            select number * 10;
Console.WriteLine(string.Join(", ", query)); // 20, 40
```

- Both forms describe the same operations here.
- `from`, `where`, and `select` are C# query-expression syntax; `Where` and `Select` are method calls.

## Collections and standard operators

- Arrays, lists, sets, and many other sources implement `IEnumerable<T>`.
- Standard sequence operators are commonly extension methods in `System.Linq`.

```csharp
var names = new List<string> { "Mira", "Deep", "Sam" };
string[] ordered = names.OrderBy(name => name, StringComparer.Ordinal).ToArray();
Console.WriteLine(string.Join(", ", ordered)); // Deep, Mira, Sam
```

LINQ usually returns a new sequence or result; it does not sort or remove items in the source collection in place.

## Imperative versus declarative code

```csharp
int[] source = { 1, 2, 3, 4 };
var byLoop = new List<int>();
foreach (int value in source)
    if (value > 2) byLoop.Add(value * 2);

var byQuery = source.Where(value => value > 2).Select(value => value * 2).ToList();
Console.WriteLine(byLoop.SequenceEqual(byQuery)); // True
```

- The loop states how to accumulate results; the query states which transformation is wanted.
- A loop remains appropriate for complex control flow or deliberate side effects.

### A single result versus a sequence

```csharp
int[] values = { 2, 4, 6 };
IEnumerable<int> filtered = values.Where(n => n > 2);
int count = filtered.Count();
bool exists = filtered.Any();
Console.WriteLine(count); // 2
Console.WriteLine(exists); // True
```

- `Where` returns a sequence.
- `Count` produces one integer; `Any` produces one Boolean.
- Read an operator's result type before deciding whether to enumerate it, store it, or use it in a condition.

## LINQ to Objects versus providers

- LINQ to Objects executes .NET delegates over local enumerable sources.
- A query provider, often exposed through `IQueryable<T>`, can inspect expression trees and translate supported operations into another form such as SQL.

- Similar-looking syntax does not guarantee identical execution location, translation support, null semantics, or ordering.
- An in-memory example is not proof that a database provider can translate the same method call.

## Sources, transformations, and results

```csharp
int[] source = { 3, 1, 2 };               // Source.
IEnumerable<int> query = source.Where(n => n > 1).OrderBy(n => n); // Query.
int[] result = query.ToArray();           // Execute and retain results.
Console.WriteLine(string.Join(", ", result)); // 2, 3
```

- A query variable commonly represents pending work.
- Enumeration or a terminal operation triggers that work; naming a query does not automatically cache its results.

### When the source changes

```csharp
var source = new List<int> { 1, 2 };
var query = source.Where(n => n > 1);
source.Add(3);
Console.WriteLine(string.Join(", ", query)); // 2, 3
```

- The query did not save the original results.
- It reads the source when enumerated.
- Creating `query.ToArray()` before `Add` would retain the original matching membership instead.

### Null is not an empty sequence

```csharp
IEnumerable<int>? missing = null;
IEnumerable<int> safe = missing ?? Enumerable.Empty<int>();
Console.WriteLine(safe.Count()); // 0
```

- Only apply this fallback when missing data should mean no results.
- Otherwise, reject null so an application bug does not silently become an empty report.

## Querying dictionaries

`Dictionary<TKey,TValue>` is queried as key-value pairs.

```csharp
var scores = new Dictionary<string, int>
{
    ["Mira"] = 90,
    ["Deep"] = 72,
    ["Sam"] = 88
};

var passed = scores.Where(pair => pair.Value >= 80)
                   .Select(pair => $"{pair.Key}: {pair.Value}");

Console.WriteLine(string.Join("; ", passed)); // Mira: 90; Sam: 88
```

```csharp
var keys = scores.Select(pair => pair.Key);
var values = scores.Select(pair => pair.Value);
```

## Querying sets

```csharp
HashSet<int> values = [1, 2, 2, 3, 4];
var large = values.Where(value => value >= 3);

Console.WriteLine(string.Join(", ", large)); // 3, 4
```

The set is already unique. Use `Distinct()` when uniqueness must be applied to another sequence.

## Querying XML

LINQ to XML uses `System.Xml.Linq`.

```csharp
using System.Xml.Linq;

var document = XDocument.Parse("""
    <orders>
      <order id="101" total="25.50" />
      <order id="102" total="80.00" />
    </orders>
    """);

var largeOrders = document.Root!.Elements("order")
    .Where(order => decimal.Parse((string)order.Attribute("total")!) >= 50)
    .Select(order => (int)order.Attribute("id")!);

Console.WriteLine(string.Join(", ", largeOrders)); // 102
```

This query runs in memory over `XElement` objects.

## Provider-backed LINQ

`IQueryable<T>` lets a provider inspect an expression tree and translate supported operations.

```csharp
IQueryable<Product> query = db.Products
    .Where(product => product.Price >= 50)
    .OrderBy(product => product.Name);

List<Product> products = await query.ToListAsync();
```

`db` and `ToListAsync` come from a provider such as Entity Framework Core. The provider may translate the query to SQL.

## Database query through a provider

```csharp
var products = await db.Products
    .Where(product => product.IsActive)
    .Select(product => new { product.Id, product.Name })
    .ToListAsync();
```

- `Where` and `Select` can become SQL `WHERE` and `SELECT`.
- `ToListAsync` sends the query and materializes rows.
- Translation support depends on the provider.
- A method working with `IEnumerable<T>` may not translate to SQL.

Do not call `ToList()` early unless the remaining work should run in memory.

## `Enumerable` and `Queryable`

```csharp
IEnumerable<int> local = [1, 2, 3];
var localQuery = Enumerable.Where(local, number => number > 1);

IQueryable<Product> remote = db.Products;
var remoteQuery = Queryable.Where(remote, product => product.Price > 10);
```

- `Enumerable` normally receives delegates and runs over objects.
- `Queryable` normally receives expression trees for a provider.

## LINQ extension methods

```csharp
int[] values = [1, 2, 3];
var doubled = values.Select(value => value * 2);
```

This extension-method call is equivalent to:

```csharp
var doubled = Enumerable.Select(values, value => value * 2);
```

## Query syntax and method chains

```csharp
int[] values = [1, 2, 3, 4];

var query = from value in values
            where value % 2 == 0
            select value * 10;

var sameQuery = values.Where(value => value % 2 == 0)
                      .Select(value => value * 10);

Console.WriteLine(string.Join(", ", query)); // 20, 40
Console.WriteLine(string.Join(", ", sameQuery)); // 20, 40
```

Query syntax is converted to standard query-operator calls. Method syntax is often easier to compose conditionally.

## Query composition

```csharp
int[] values = [1, 2, 3, 4];
bool includeOnlyEven = true;
IEnumerable<int> query = values;

if (includeOnlyEven)
    query = query.Where(value => value % 2 == 0);

query = query.OrderBy(value => value);
Console.WriteLine(string.Join(", ", query)); // 2, 4
```

Build the query first and materialize it at the required boundary.

## Standard operators

```csharp
int[] values = [1, 2, 2, 3, 4];

Console.WriteLine(values.Count());                  // 5
Console.WriteLine(values.Any(value => value > 3)); // True
Console.WriteLine(values.First());                  // 1
Console.WriteLine(values.Distinct().Count());       // 4
```

`System.Linq` provides operators for filtering, projection, ordering, grouping, joining, aggregation, conversion, and element retrieval.

## Source → query → execution → result

```csharp
int[] source = [3, 1, 2];
IEnumerable<int> query = source.Where(value => value > 1);
int[] result = query.ToArray();

Console.WriteLine(string.Join(", ", result)); // 3, 2
```

- Source: original data.
- Query: pending operations.
- Execution: enumeration or terminal operation.
- Result: sequence or scalar value.

## Streaming and buffering

```csharp
IEnumerable<int> stream = values.Where(value => value > 1);
foreach (int value in stream)
    Console.WriteLine(value); // 2, 2, 3, 4
```

`Where` can stream. `OrderBy`, `GroupBy`, `ToList`, and `ToArray` generally buffer data.

## Empty results

```csharp
int[] empty = [];
Console.WriteLine(empty.Any());  // False
Console.WriteLine(empty.Count()); // 0
// empty.First() throws InvalidOperationException.
```

Use `FirstOrDefault` when an empty result is valid.

## When to use LINQ

- Use LINQ for readable filtering, mapping, ordering, grouping, and aggregation.
- Use a loop when mutation, complex control flow, or early exits are clearer.
- Keep database operations as `IQueryable<T>` until server-side work is complete.
- Materialize once when a stable snapshot is needed.
