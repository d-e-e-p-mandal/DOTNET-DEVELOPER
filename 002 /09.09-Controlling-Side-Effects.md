# 09.09 — CONTROLLING SIDE EFFECTS

In functional programming, controlling side effects means separating **computations that produce values** from **operations that interact with or modify the outside world**.

Examples of side effects include writing to files, accessing databases, sending network requests, changing shared variables, and printing to the console.

Functional programming does not mean that an application must avoid all side effects. Real applications need them. The goal is to **make side effects explicit, predictable, isolated, and testable**.

```text
APPLICATION
    │
    ├── PURE COMPUTATION
    │   ├── Calculations
    │   ├── Transformations
    │   ├── Validation
    │   └── Business Rules
    │
    └── SIDE EFFECTS
        ├── Database
        ├── Network
        ├── File System
        ├── Console
        ├── Logging
        └── External State
```

This section covers all **23 syllabus points in their original order**.

---

## 1. Side-Effect Concepts

A **side effect** occurs when evaluating a function interacts with or changes state beyond simply producing its return value.

### Example 1: Function without side effects

```csharp
static int Add(int a, int b)
{
    return a + b;
}

Console.WriteLine(Add(10, 20));
```

**Output:**

```text
30
```

The `Add()` function:

- Depends only on its parameters.
- Does not modify external state.
- Returns the same result for the same inputs.

The surrounding `Console.WriteLine()` is a side effect, but `Add()` itself is pure.

### Example 2: Function with side effects

```csharp
int counter = 0;

int Increment()
{
    counter++;
    return counter;
}

Console.WriteLine(Increment());
Console.WriteLine(Increment());
Console.WriteLine(Increment());
```

**Output:**

```text
1
2
3
```

The function modifies `counter`, which exists outside its local scope.

### Example 3: Hidden external dependency

```csharp
int multiplier = 10;

int Multiply(int number)
{
    return number * multiplier;
}

Console.WriteLine(Multiply(5));

multiplier = 20;

Console.WriteLine(Multiply(5));
```

**Output:**

```text
50
100
```

Although `Multiply(5)` receives the same explicit argument, its result changes because it reads external mutable state.

### Types of side effects

| Side Effect | Example |
|---|---|
| State mutation | Updating a shared variable |
| Console I/O | `Console.WriteLine()` |
| File I/O | `File.WriteAllText()` |
| Database I/O | Saving a database record |
| Network I/O | Sending an HTTP request |
| Logging | Writing a log entry |
| External state access | Reading environment variables |
| Nondeterministic dependency | Reading the current clock |

**Important distinction:** Reading time or randomness is not necessarily a mutation, but it introduces an external, nondeterministic dependency. Functional design often controls these dependencies using the same techniques used for side effects.

**Key point:** Side effects make a computation depend on or interact with the world outside its explicit inputs and outputs.

## 2. Pure Computation

A **pure computation** produces its result entirely from its explicit inputs and has no observable side effects.

A pure function has two important properties:

1. **Determinism:** The same inputs produce the same output.
2. **No observable side effects:** Evaluating the function does not modify externally observable state.

### Example 1: Pure addition

```csharp
static int Add(int a, int b)
{
    return a + b;
}

Console.WriteLine(Add(10, 20));
Console.WriteLine(Add(10, 20));
```

**Output:**

```text
30
30
```

### Example 2: Pure discount calculation

```csharp
static decimal CalculateDiscount(
    decimal price,
    decimal percentage)
{
    return price * percentage / 100m;
}

decimal discount = CalculateDiscount(
    1000m,
    10m
);

Console.WriteLine(discount);
```

**Output:**

```text
100
```

### Example 3: Pure transformation

```csharp
static int[] DoubleNumbers(
    IEnumerable<int> numbers)
{
    return numbers
        .Select(x => x * 2)
        .ToArray();
}

int[] result = DoubleNumbers(
    new[] { 1, 2, 3 }
);

Console.WriteLine(
    string.Join(", ", result)
);
```

**Output:**

```text
2, 4, 6
```

This function constructs a new array without modifying the input collection.

For purity, the input sequence itself should be stable and free from side effects during enumeration.

### Example 4: Impure calculation

```csharp
decimal taxRate = 0.18m;

decimal CalculateTax(decimal amount)
{
    return amount * taxRate;
}
```

The calculation depends on an external variable.

### Pure alternative

```csharp
static decimal CalculateTax(
    decimal amount,
    decimal taxRate)
{
    return amount * taxRate;
}
```

Now the dependencies are explicit.

### Comparison

| Pure Function | Impure Function |
|---|---|
| Depends on explicit inputs | May depend on external state |
| No observable side effects | May produce side effects |
| Easier to test | May require external setup |
| Predictable | May be nondeterministic |
| Easier to compose | Requires additional care |

**Key point:** Pure computation isolates business logic from external dependencies.

## 3. I/O as a Side Effect

**Input/Output (I/O)** involves communication with resources outside the current computation.

Examples include:

- Reading from a file.
- Writing to a database.
- Sending a network request.
- Reading console input.
- Printing output.

### Example 1: I/O inside a function

```csharp
static int CalculateTotal(int a, int b)
{
    int total = a + b;

    Console.WriteLine(total);

    return total;
}

CalculateTotal(10, 20);
```

**Output:**

```text
30
```

The function combines calculation and output.

### Example 2: Separate computation from I/O

```csharp
static int CalculateTotal(int a, int b)
{
    return a + b;
}

int total = CalculateTotal(10, 20);

Console.WriteLine(total);
```

**Output:**

```text
30
```

Here:

```text
CalculateTotal()
       │
       ▼
Pure Computation
       │
       ▼
Console.WriteLine()
       │
       ▼
I/O Side Effect
```

### Example 3: Processing external input

```csharp
static int Square(int number)
{
    return number * number;
}

string input = "5";

if (int.TryParse(input, out int number))
{
    int result = Square(number);

    Console.WriteLine(result);
}
```

**Output:**

```text
25
```

The calculation remains independent of how the input was obtained.

**Key point:** Keep I/O operations at clearly defined boundaries and pass their results into pure computations.

## 4. Database Access

Database operations interact with persistent external state.

Examples include:

- Retrieving records.
- Inserting records.
- Updating records.
- Deleting records.

### Example 1: Database access mixed with calculation

```csharp
// Conceptual example using an application DbContext.

decimal CalculateOrderTotal(
    int orderId,
    AppDbContext db)
{
    var order = db.Orders.Find(orderId);

    if (order is null)
        return 0;

    return order.Quantity * order.UnitPrice;
}
```

This function depends on a database.

Its result may change when the database changes.

`AppDbContext` and its entity types are application-defined and are not standalone .NET types.

### Example 2: Separate database access from calculation

```csharp
static decimal CalculateOrderTotal(
    int quantity,
    decimal unitPrice)
{
    return quantity * unitPrice;
}
```

The database-facing code retrieves the values:

```csharp
// Conceptual database boundary.

var order = db.Orders.Find(orderId);

if (order is not null)
{
    decimal total = CalculateOrderTotal(
        order.Quantity,
        order.UnitPrice
    );

    Console.WriteLine(total);
}
```

### Architecture

```text
DATABASE
    │
    ▼
REPOSITORY / DATA ACCESS
    │
    ▼
ORDER DATA
    │
    ▼
PURE CALCULATION
    │
    ▼
RESULT
```

### Example 3: Test calculation without a database

```csharp
static decimal CalculateOrderTotal(
    int quantity,
    decimal unitPrice)
{
    return quantity * unitPrice;
}

Console.WriteLine(
    CalculateOrderTotal(3, 500m)
);
```

**Output:**

```text
1500
```

No database is required to verify the calculation.

**Key point:** Database access belongs in an effectful layer, while business calculations should remain independent where practical.

## 5. Network Access

Network access is an external operation.

Its behavior may depend on:

- Network availability.
- Remote server state.
- Authentication.
- Timeouts.
- Remote responses.

### Example 1: Network request

```csharp
using HttpClient client = new();

string response = await client.GetStringAsync(
    "https://example.com"
);

Console.WriteLine(response.Length);
```

This operation is not pure because it depends on an external server and network conditions.

The output varies and the request can fail.

### Example 2: Separate response processing

```csharp
static string NormalizeResponse(string response)
{
    return response.Trim().ToUpperInvariant();
}

string response = "  success  ";

string result = NormalizeResponse(response);

Console.WriteLine(result);
```

**Output:**

```text
SUCCESS
```

The normalization function does not need network access.

### Example 3: Effectful network boundary

```csharp
static async Task<string> FetchTextAsync(
    HttpClient client,
    string url)
{
    return await client.GetStringAsync(url);
}
```

### Pure processing function

```csharp
static int CountCharacters(string text)
{
    return text.Length;
}
```

### Combined usage

```csharp
using HttpClient client = new();

string text = await FetchTextAsync(
    client,
    "https://example.com"
);

int count = CountCharacters(text);

Console.WriteLine(count);
```

The network request is effectful.

The character-counting function is pure.

**Key point:** Separate network communication from deterministic response processing.

## 6. File-System Access

File-system operations interact with external storage.

### Example 1: Writing a file

```csharp
File.WriteAllText(
    "output.txt",
    "Hello C#"
);
```

This changes external state.

### Example 2: Reading a file

```csharp
string content = File.ReadAllText(
    "output.txt"
);

Console.WriteLine(content);
```

**Output, assuming the preceding write succeeded:**

```text
Hello C#
```

Reading a file depends on its current contents and availability.

### Example 3: Pure file-content transformation

```csharp
static string NormalizeText(string text)
{
    return text.Trim().ToUpperInvariant();
}

string content = "  hello c#  ";

string result = NormalizeText(content);

Console.WriteLine(result);
```

**Output:**

```text
HELLO C#
```

### Example 4: Separate file access

```csharp
static string NormalizeText(string text)
{
    return text.Trim().ToUpperInvariant();
}

string input = File.ReadAllText("input.txt");

string output = NormalizeText(input);

File.WriteAllText("output.txt", output);
```

### Flow

```text
Read File
    │
    ▼
String Data
    │
    ▼
Pure Transformation
    │
    ▼
String Result
    │
    ▼
Write File
```

**Key point:** Keep file reading and writing separate from content transformations.

## 7. Console I/O

Console input and output are side effects because they interact with an external user interface.

### Example 1: Console output inside calculation

```csharp
static int Square(int number)
{
    int result = number * number;

    Console.WriteLine(result);

    return result;
}
```

The function calculates and prints.

### Example 2: Pure calculation

```csharp
static int Square(int number)
{
    return number * number;
}
```

### Console boundary

```csharp
int result = Square(5);

Console.WriteLine(result);
```

**Output:**

```text
25
```

### Example 3: Console input

```csharp
Console.Write("Enter number: ");

string? input = Console.ReadLine();

if (int.TryParse(input, out int number))
{
    Console.WriteLine(number * 2);
}
else
{
    Console.WriteLine("Invalid number");
}
```

### Better separation

```csharp
static int Double(int number)
{
    return number * 2;
}
```

The console layer handles reading and printing.

The function handles calculation.

**Key point:** Console operations should generally be kept outside reusable computation functions.

## 8. Logging

Logging records information about application behavior.

Logging is an observable side effect because it writes information to a console, file, service, or another destination.

### Example 1: Logging inside a calculation

```csharp
static int Add(int a, int b)
{
    Console.WriteLine("Calculating...");

    return a + b;
}

Console.WriteLine(Add(10, 20));
```

**Output:**

```text
Calculating...
30
```

The function is no longer pure.

### Example 2: Logging outside the calculation

```csharp
static int Add(int a, int b)
{
    return a + b;
}

Console.WriteLine("Starting calculation");

int result = Add(10, 20);

Console.WriteLine($"Result: {result}");
```

**Output:**

```text
Starting calculation
Result: 30
```

### Example 3: Structured logging boundary

In an ASP.NET Core application:

```csharp
public sealed class CalculationService
{
    private readonly ILogger<CalculationService> _logger;

    public CalculationService(
        ILogger<CalculationService> logger)
    {
        _logger = logger;
    }

    public int Add(int a, int b)
    {
        int result = a + b;

        _logger.LogInformation(
            "Calculated result: {Result}",
            result
        );

        return result;
    }
}
```

This service is not pure because it logs.

A cleaner separation is:

```csharp
public static class Calculator
{
    public static int Add(int a, int b)
    {
        return a + b;
    }
}
```

The caller performs logging.

**Key point:** Logging is useful, but keeping it at application boundaries preserves the purity of core calculations.

## 9. Time

The current time is an external dependency.

A function that reads the clock may return different results even when its explicit arguments are unchanged.

### Example 1: Hidden time dependency

```csharp
static bool IsExpired(DateTime expiry)
{
    return DateTime.UtcNow > expiry;
}
```

The result depends on when the function executes.

### Example 2: Explicit time parameter

```csharp
static bool IsExpired(
    DateTime expiry,
    DateTime currentTime)
{
    return currentTime > expiry;
}

DateTime expiry = new(
    2026, 10, 10,
    0, 0, 0,
    DateTimeKind.Utc
);

DateTime currentTime = new(
    2026, 10, 19,
    0, 0, 0,
    DateTimeKind.Utc
);

Console.WriteLine(
    IsExpired(expiry, currentTime)
);
```

**Output:**

```text
True
```

### Comparison

```text
IMPLICIT TIME

Function
    │
    ▼
DateTime.UtcNow
    │
    ▼
External Clock
```

```text
EXPLICIT TIME

Caller Reads Clock
    │
    ▼
Passes Time
    │
    ▼
Pure Function
```

**Key point:** Passing time explicitly makes time-dependent business rules deterministic and testable.

## 10. Randomness

Randomness introduces nondeterministic behavior when a function obtains random values from an external or mutable random-number generator.

### Example 1: Randomness inside a function

```csharp
static int GenerateNumber()
{
    return Random.Shared.Next(1, 101);
}
```

Repeated calls may produce different results.

### Example 2: Explicit random value

```csharp
static int CalculateReward(int randomNumber)
{
    return randomNumber * 10;
}

Console.WriteLine(
    CalculateReward(7)
);
```

**Output:**

```text
70
```

### Example 3: Generate randomness at the boundary

```csharp
static int CalculateReward(int randomNumber)
{
    return randomNumber * 10;
}

int randomNumber = Random.Shared.Next(1, 11);

int reward = CalculateReward(randomNumber);

Console.WriteLine(reward);
```

The output varies, but `CalculateReward()` remains pure.

### Example 4: Deterministic test

```csharp
static int CalculateReward(int randomNumber)
{
    return randomNumber * 10;
}

int result = CalculateReward(5);

Console.WriteLine(result == 50);
```

**Output:**

```text
True
```

**Key point:** Generate random values at controlled boundaries and pass them into pure computations.

## 11. Environment State

Environment state includes information supplied by the operating system or execution environment.

Examples include:

- Environment variables.
- Process settings.
- Machine information.
- Current working directory.
- Operating-system details.

### Example 1: Reading environment state

```csharp
string? environment =
    Environment.GetEnvironmentVariable(
        "ASPNETCORE_ENVIRONMENT"
    );

Console.WriteLine(
    environment ?? "Not Set"
);
```

The output depends on the process environment.

### Example 2: Hidden environment dependency

```csharp
static bool IsProduction()
{
    return Environment.GetEnvironmentVariable(
        "ASPNETCORE_ENVIRONMENT"
    ) == "Production";
}
```

### Example 3: Explicit environment input

```csharp
static bool IsProduction(string environment)
{
    return environment == "Production";
}

Console.WriteLine(
    IsProduction("Production")
);

Console.WriteLine(
    IsProduction("Development")
);
```

**Output:**

```text
True
False
```

### Example 4: Read environment at the boundary

```csharp
string environment =
    Environment.GetEnvironmentVariable(
        "ASPNETCORE_ENVIRONMENT"
    ) ?? "Development";

bool isProduction = IsProduction(environment);
```

**Key point:** Read environment state at application boundaries and pass relevant values explicitly to core functions.

## 12. Configuration

Configuration determines how an application behaves.

Examples include:

- Tax rates.
- Discount percentages.
- Maximum retry counts.
- Feature settings.
- Business limits.

### Example 1: Global configuration dependency

```csharp
static class Settings
{
    public static decimal TaxRate = 0.18m;
}

static decimal CalculateTax(decimal amount)
{
    return amount * Settings.TaxRate;
}
```

The calculation depends on global mutable configuration.

### Example 2: Explicit configuration parameter

```csharp
static decimal CalculateTax(
    decimal amount,
    decimal taxRate)
{
    return amount * taxRate;
}

Console.WriteLine(
    CalculateTax(1000m, 0.18m)
);
```

**Output:**

```text
180.00
```

### Example 3: Configuration object

```csharp
public sealed record TaxConfiguration(
    decimal Rate
);
```

Calculation:

```csharp
static decimal CalculateTax(
    decimal amount,
    TaxConfiguration configuration)
{
    return amount * configuration.Rate;
}
```

Usage:

```csharp
var configuration = new TaxConfiguration(0.18m);

decimal tax = CalculateTax(
    1000m,
    configuration
);

Console.WriteLine(tax);
```

**Output:**

```text
180.00
```

### Example 4: Multiple configuration values

```csharp
public sealed record PricingConfiguration(
    decimal TaxRate,
    decimal DiscountRate
);
```

```csharp
static decimal CalculateFinalPrice(
    decimal price,
    PricingConfiguration configuration)
{
    decimal discounted =
        price * (1 - configuration.DiscountRate);

    return discounted * (1 + configuration.TaxRate);
}
```

Usage:

```csharp
var config = new PricingConfiguration(
    TaxRate: 0.18m,
    DiscountRate: 0.10m
);

Console.WriteLine(
    CalculateFinalPrice(1000m, config)
);
```

**Output:**

```text
1062.0000
```

**Key point:** Explicit configuration makes dependencies visible and simplifies testing.

## 13. Global State

**Global state** is data accessible from multiple parts of an application.

Mutable global state can make functions unpredictable.

### Example 1: Mutable global counter

```csharp
static class GlobalState
{
    public static int Counter = 0;
}
```

Usage:

```csharp
GlobalState.Counter++;

Console.WriteLine(
    GlobalState.Counter
);
```

**Output:**

```text
1
```

### Example 2: Function reading global state

```csharp
static class GlobalSettings
{
    public static int Multiplier = 10;
}

static int Calculate(int number)
{
    return number * GlobalSettings.Multiplier;
}
```

The result depends on a mutable global field.

### Example 3: Explicit input

```csharp
static int Calculate(
    int number,
    int multiplier)
{
    return number * multiplier;
}

Console.WriteLine(
    Calculate(5, 10)
);
```

**Output:**

```text
50
```

### Problems with mutable global state

| Problem | Explanation |
|---|---|
| Hidden dependencies | Functions read state not shown in parameters |
| Test interference | One test may affect another |
| Concurrency issues | Multiple threads may modify the same data |
| Debugging difficulty | Changes can originate from many locations |
| Reduced predictability | Results depend on execution history |

**Key point:** Avoid unnecessary mutable global state in core computations.

## 14. Mutable Shared State

**Mutable shared state** is data that multiple functions, objects, or threads can access and modify.

### Example 1: Shared list mutation

```csharp
List<int> numbers = new()
{
    1, 2, 3
};

void AddNumber(int number)
{
    numbers.Add(number);
}

AddNumber(4);

Console.WriteLine(
    string.Join(", ", numbers)
);
```

**Output:**

```text
1, 2, 3, 4
```

The function changes a list outside its local scope.

### Example 2: Create a new collection

```csharp
static int[] AddNumber(
    IEnumerable<int> numbers,
    int number)
{
    return numbers
        .Append(number)
        .ToArray();
}

int[] original = { 1, 2, 3 };

int[] updated = AddNumber(original, 4);

Console.WriteLine(
    string.Join(", ", original)
);

Console.WriteLine(
    string.Join(", ", updated)
);
```

**Output:**

```text
1, 2, 3
1, 2, 3, 4
```

The original array remains unchanged.

### Example 3: Shared counter and concurrency

```csharp
int counter = 0;

Parallel.For(0, 1000, _ =>
{
    counter++;
});

Console.WriteLine(counter);
```

The final result is not guaranteed to be `1000`.

`counter++` is not an atomic operation.

### Example 4: Thread-safe mutation

```csharp
int counter = 0;

Parallel.For(0, 1000, _ =>
{
    Interlocked.Increment(ref counter);
});

Console.WriteLine(counter);
```

**Output:**

```text
1000
```

This controls the concurrent mutation, but the operation remains effectful.

### Example 5: Avoid shared mutation with independent results

```csharp
int[] numbers = Enumerable.Range(1, 5)
    .Select(x => x * x)
    .ToArray();

Console.WriteLine(
    string.Join(", ", numbers)
);
```

**Output:**

```text
1, 4, 9, 16, 25
```

**Key point:** Prefer local state and immutable results where practical. When shared mutation is necessary, coordinate access correctly.

## 15. Functional Core / Imperative Shell

The **Functional Core / Imperative Shell** pattern separates an application into two areas.

### Functional Core

Contains:

- Pure calculations.
- Business rules.
- Validation.
- Data transformations.
- Deterministic decisions.

### Imperative Shell

Handles:

- Console I/O.
- Database operations.
- Network requests.
- File operations.
- Logging.
- External state.

### Architecture

```text
┌─────────────────────────────────┐
│        IMPERATIVE SHELL         │
│                                 │
│  Input / Database / Network     │
│                                 │
│                │                │
│                ▼                │
│   ┌─────────────────────────┐   │
│   │     FUNCTIONAL CORE     │   │
│   │                         │   │
│   │  Pure Business Logic    │   │
│   │  Validation             │   │
│   │  Transformations        │   │
│   │  Calculations           │   │
│   └─────────────────────────┘   │
│                │                │
│                ▼                │
│  Output / Save / Logging        │
└─────────────────────────────────┘
```

### Example 1: Functional core

```csharp
public static class OrderCalculator
{
    public static decimal CalculateTotal(
        int quantity,
        decimal unitPrice)
    {
        return quantity * unitPrice;
    }
}
```

### Example 2: Imperative shell

```csharp
Console.Write("Quantity: ");

string? input = Console.ReadLine();

if (int.TryParse(input, out int quantity))
{
    decimal total =
        OrderCalculator.CalculateTotal(
            quantity,
            500m
        );

    Console.WriteLine($"Total: {total}");
}
```

### Example 3: Test the functional core

```csharp
decimal result =
    OrderCalculator.CalculateTotal(
        3,
        500m
    );

Console.WriteLine(result == 1500m);
```

**Output:**

```text
True
```

### Benefits

| Benefit | Explanation |
|---|---|
| Testability | Business logic can be tested without I/O |
| Predictability | Core logic depends on explicit inputs |
| Maintainability | Effects are concentrated at boundaries |
| Reusability | Pure functions work in different environments |
| Debugging | Easier to distinguish calculations from external failures |

**Key point:** Keep the functional core pure and let the imperative shell coordinate external interactions.

## 16. Dependency Injection of Effects

**Dependency injection of effects** means supplying external operations as dependencies rather than creating them inside business logic.

These dependencies can be represented using:

- Interfaces.
- Delegates.
- Services.
- Function parameters.

### Example 1: Hard-coded effect

```csharp
static void Process(int number)
{
    Console.WriteLine(number * 2);
}
```

The function directly controls console output.

### Example 2: Inject an Action

```csharp
static void Process(
    int number,
    Action<int> output)
{
    int result = number * 2;

    output(result);
}

Process(
    5,
    value => Console.WriteLine(value)
);
```

**Output:**

```text
10
```

The output behavior is supplied by the caller.

`Process()` is still effectful because it invokes an arbitrary callback, but the effect is now an explicit dependency.

### Example 3: Inject a data provider

```csharp
static int CalculateTotal(
    Func<int> getQuantity,
    int unitPrice)
{
    int quantity = getQuantity();

    return quantity * unitPrice;
}
```

Usage:

```csharp
int total = CalculateTotal(
    () => 3,
    500
);

Console.WriteLine(total);
```

**Output:**

```text
1500
```

### Example 4: Inject a logger

```csharp
static int Process(
    int number,
    Action<string> log)
{
    log("Processing started");

    int result = number * 2;

    log("Processing completed");

    return result;
}
```

Usage:

```csharp
int result = Process(
    5,
    message => Console.WriteLine(message)
);

Console.WriteLine(result);
```

**Output:**

```text
Processing started
Processing completed
10
```

### Example 5: Inject an interface

```csharp
public interface IMessageWriter
{
    void Write(string message);
}

public sealed class ConsoleMessageWriter
    : IMessageWriter
{
    public void Write(string message)
    {
        Console.WriteLine(message);
    }
}
```

Service:

```csharp
public sealed class NotificationService
{
    private readonly IMessageWriter _writer;

    public NotificationService(
        IMessageWriter writer)
    {
        _writer = writer;
    }

    public void Notify(string message)
    {
        _writer.Write(message);
    }
}
```

Usage:

```csharp
var service = new NotificationService(
    new ConsoleMessageWriter()
);

service.Notify("Hello");
```

**Output:**

```text
Hello
```

### Important distinction

Dependency injection does not automatically make a function pure.

It makes dependencies explicit and replaceable.

To achieve purity, pass the **result of an effect** into a pure function rather than invoking the effect inside it.

**Key point:** Dependency injection helps control and test effects by making external operations replaceable.

## 17. Explicit Time Input

An **explicit time input** replaces hidden clock access with a supplied time value.

### Example 1: Time-dependent function

```csharp
static bool IsExpired(DateTime expiry)
{
    return DateTime.UtcNow > expiry;
}
```

This function depends on the current clock.

### Example 2: Explicit time

```csharp
static bool IsExpired(
    DateTime expiry,
    DateTime now)
{
    return now > expiry;
}
```

Usage:

```csharp
DateTime expiry = new(
    2026, 10, 15,
    0, 0, 0,
    DateTimeKind.Utc
);

DateTime now = new(
    2026, 10, 19,
    0, 0, 0,
    DateTimeKind.Utc
);

Console.WriteLine(
    IsExpired(expiry, now)
);
```

**Output:**

```text
True
```

### Example 3: Calculate remaining time

```csharp
static TimeSpan RemainingTime(
    DateTime expiry,
    DateTime now)
{
    return expiry - now;
}

DateTime now = new(
    2026, 10, 19,
    10, 0, 0,
    DateTimeKind.Utc
);

DateTime expiry = now.AddHours(5);

TimeSpan remaining = RemainingTime(
    expiry,
    now
);

Console.WriteLine(remaining.TotalHours);
```

**Output:**

```text
5
```

### Example 4: Boundary reads the clock

```csharp
DateTime now = DateTime.UtcNow;

bool expired = IsExpired(
    expiry,
    now
);
```

The boundary performs the clock access.

The calculation receives an explicit value.

**Key point:** Explicit time inputs make time-dependent functions deterministic.

## 18. Explicit Randomness Input

An **explicit randomness input** separates random-number generation from the logic that uses the random value.

### Example 1: Hidden randomness

```csharp
static int CalculatePrize()
{
    int number = Random.Shared.Next(1, 11);

    return number * 100;
}
```

The result is unpredictable.

### Example 2: Explicit random number

```csharp
static int CalculatePrize(int number)
{
    return number * 100;
}

Console.WriteLine(
    CalculatePrize(7)
);
```

**Output:**

```text
700
```

### Example 3: Randomness at the boundary

```csharp
int randomNumber = Random.Shared.Next(1, 11);

int prize = CalculatePrize(randomNumber);

Console.WriteLine(prize);
```

### Example 4: Inject random generation

```csharp
static int GeneratePrize(
    Func<int> nextNumber)
{
    int number = nextNumber();

    return number * 100;
}
```

Usage:

```csharp
int result = GeneratePrize(
    () => 5
);

Console.WriteLine(result);
```

**Output:**

```text
500
```

This approach is deterministic when the injected function is deterministic.

However, `GeneratePrize()` is not inherently pure because the supplied delegate may use mutable or external state.

### Comparison

| Approach | Deterministic? |
|---|---|
| `Random.Shared.Next()` inside function | No |
| Explicit random value | Yes |
| Injected random delegate | Depends on delegate |
| Fixed test delegate | Yes |

**Key point:** Passing generated random values explicitly provides the strongest separation between randomness and pure computation.

## 19. Explicit Configuration Input

An **explicit configuration input** supplies configuration values directly to the function that needs them.

### Example 1: Hidden configuration

```csharp
static class Settings
{
    public static decimal Discount = 0.10m;
}

static decimal ApplyDiscount(decimal price)
{
    return price * (1 - Settings.Discount);
}
```

### Example 2: Explicit scalar configuration

```csharp
static decimal ApplyDiscount(
    decimal price,
    decimal discount)
{
    return price * (1 - discount);
}

Console.WriteLine(
    ApplyDiscount(1000m, 0.10m)
);
```

**Output:**

```text
900.00
```

### Example 3: Immutable configuration record

```csharp
public sealed record DiscountSettings(
    decimal Percentage,
    decimal MinimumPrice
);
```

Calculation:

```csharp
static decimal ApplyDiscount(
    decimal price,
    DiscountSettings settings)
{
    if (price < settings.MinimumPrice)
        return price;

    return price * (1 - settings.Percentage);
}
```

Usage:

```csharp
var settings = new DiscountSettings(
    Percentage: 0.10m,
    MinimumPrice: 500m
);

Console.WriteLine(
    ApplyDiscount(1000m, settings)
);

Console.WriteLine(
    ApplyDiscount(300m, settings)
);
```

**Output:**

```text
900.00
300
```

### Example 4: Test different configurations

```csharp
var normal = new DiscountSettings(
    0.10m,
    500m
);

var premium = new DiscountSettings(
    0.20m,
    500m
);

Console.WriteLine(
    ApplyDiscount(1000m, normal)
);

Console.WriteLine(
    ApplyDiscount(1000m, premium)
);
```

**Output:**

```text
900.00
800.00
```

**Key point:** Explicit configuration inputs allow the same function to be tested under different settings without modifying global state.

## 20. Logging at Boundaries

**Logging at boundaries** means performing logging where the application coordinates operations rather than embedding logging throughout pure calculations.

### Example 1: Logging inside business logic

```csharp
static decimal CalculateTotal(
    int quantity,
    decimal price)
{
    Console.WriteLine("Calculating total");

    return quantity * price;
}
```

The calculation is impure.

### Example 2: Logging at the boundary

```csharp
static decimal CalculateTotal(
    int quantity,
    decimal price)
{
    return quantity * price;
}

Console.WriteLine("Calculation started");

decimal total = CalculateTotal(
    3,
    500m
);

Console.WriteLine(
    $"Calculation completed: {total}"
);
```

**Output:**

```text
Calculation started
Calculation completed: 1500
```

### Example 3: Application service boundary

```csharp
public static class PriceCalculator
{
    public static decimal Calculate(
        int quantity,
        decimal unitPrice)
    {
        return quantity * unitPrice;
    }
}
```

An application service can log around the calculation:

```csharp
public sealed class OrderService
{
    private readonly ILogger<OrderService> _logger;

    public OrderService(
        ILogger<OrderService> logger)
    {
        _logger = logger;
    }

    public decimal CalculateOrder(
        int quantity,
        decimal price)
    {
        _logger.LogInformation(
            "Starting order calculation"
        );

        decimal total = PriceCalculator.Calculate(
            quantity,
            price
        );

        _logger.LogInformation(
            "Order total: {Total}",
            total
        );

        return total;
    }
}
```

### Architecture

```text
APPLICATION SERVICE
    │
    ├── Log Start
    │
    ▼
PURE CALCULATION
    │
    ▼
RESULT
    │
    └── Log Completion
```

**Key point:** Boundary logging preserves observability while keeping core computations independent of logging systems.

## 21. Avoiding Side Effects in LINQ Predicates

A LINQ **predicate** is a function that evaluates whether an element satisfies a condition.

Predicates are commonly used with:

```csharp
Where()
Any()
All()
Count(predicate)
FirstOrDefault(predicate)
```

Side effects inside predicates can cause unexpected behavior because LINQ queries may execute lazily or be enumerated multiple times.

### Example 1: Predicate with side effects

```csharp
int counter = 0;

int[] numbers = { 1, 2, 3, 4, 5 };

var query = numbers.Where(number =>
{
    counter++;

    return number % 2 == 0;
});

Console.WriteLine(counter);

Console.WriteLine(
    string.Join(", ", query)
);

Console.WriteLine(counter);
```

**Output:**

```text
0
2, 4
5
```

The predicate executes when the query is enumerated.

### Example 2: Multiple enumeration

```csharp
int counter = 0;

int[] numbers = { 1, 2, 3 };

var query = numbers.Where(number =>
{
    counter++;

    return number > 1;
});

query.ToList();
query.ToList();

Console.WriteLine(counter);
```

**Output:**

```text
6
```

The predicate executes again during the second enumeration.

### Example 3: Pure predicate

```csharp
static bool IsEven(int number)
{
    return number % 2 == 0;
}

int[] numbers = { 1, 2, 3, 4, 5 };

var result = numbers.Where(IsEven);

Console.WriteLine(
    string.Join(", ", result)
);
```

**Output:**

```text
2, 4
```

### Example 4: Avoid mutation in predicates

Avoid:

```csharp
List<int> selected = new();

var query = numbers.Where(number =>
{
    if (number > 2)
    {
        selected.Add(number);
        return true;
    }

    return false;
});
```

Prefer:

```csharp
int[] selected = numbers
    .Where(number => number > 2)
    .ToArray();
```

### Why pure predicates matter

| Problem | Explanation |
|---|---|
| Deferred execution | Predicate may execute later |
| Multiple enumeration | Side effects may repeat |
| Short-circuiting | Some predicates may never execute |
| Query reordering | Execution behavior may change with providers |
| Testing | Hidden mutations complicate verification |

**Key point:** LINQ predicates should normally express conditions without modifying external state.

## 22. Avoiding Side Effects in LINQ Selectors

A LINQ **selector** transforms an input element into an output value.

Selectors are commonly used with:

```csharp
Select()
SelectMany()
OrderBy()
GroupBy()
```

Side effects inside selectors can make transformations difficult to reason about.

### Example 1: Selector with a side effect

```csharp
int counter = 0;

int[] numbers = { 1, 2, 3 };

var query = numbers.Select(number =>
{
    counter++;

    return number * 10;
});

Console.WriteLine(counter);

Console.WriteLine(
    string.Join(", ", query)
);

Console.WriteLine(counter);
```

**Output:**

```text
0
10, 20, 30
3
```

### Example 2: Multiple enumeration

```csharp
int counter = 0;

int[] numbers = { 1, 2, 3 };

var query = numbers.Select(number =>
{
    counter++;

    return number * 10;
});

query.ToArray();
query.ToArray();

Console.WriteLine(counter);
```

**Output:**

```text
6
```

The selector runs twice for each element.

### Example 3: Pure selector

```csharp
static int Double(int number)
{
    return number * 2;
}

int[] numbers = { 1, 2, 3 };

var result = numbers.Select(Double);

Console.WriteLine(
    string.Join(", ", result)
);
```

**Output:**

```text
2, 4, 6
```

### Example 4: Avoid modifying source objects

Consider mutable objects:

```csharp
public sealed class Employee
{
    public string Name { get; set; } = "";
    public decimal Salary { get; set; }
}
```

Avoid:

```csharp
var result = employees.Select(employee =>
{
    employee.Salary *= 1.10m;

    return employee;
});
```

This changes the original objects when the query executes.

Prefer projection:

```csharp
var result = employees.Select(employee => new
{
    employee.Name,
    UpdatedSalary = employee.Salary * 1.10m
});
```

The source employees are not modified.

### Example 5: Immutable record transformation

```csharp
public sealed record Employee(
    string Name,
    decimal Salary
);
```

```csharp
Employee[] employees =
{
    new("Amit", 30000m),
    new("Rahul", 40000m)
};

var updated = employees.Select(
    employee => employee with
    {
        Salary = employee.Salary * 1.10m
    }
);

foreach (Employee employee in updated)
{
    Console.WriteLine(
        $"{employee.Name}: {employee.Salary}"
    );
}
```

**Output:**

```text
Amit: 33000.00
Rahul: 44000.00
```

The `with` expression creates new record instances.

**Key point:** LINQ selectors should generally transform values without modifying their source objects or external state.

## 23. Avoiding Side Effects in Deferred Queries

Many LINQ operations use **deferred execution**.

This means that constructing a query does not immediately execute it.

Execution begins when the query is enumerated.

### Example 1: Deferred execution

```csharp
int[] numbers = { 1, 2, 3 };

var query = numbers.Select(number =>
{
    Console.WriteLine(
        $"Processing {number}"
    );

    return number * 2;
});

Console.WriteLine("Query created");

foreach (int number in query)
{
    Console.WriteLine(number);
}
```

**Output:**

```text
Query created
Processing 1
2
Processing 2
4
Processing 3
6
```

The selector runs during enumeration, not query construction.

### Example 2: Repeated execution

```csharp
int[] numbers = { 1, 2 };

var query = numbers.Select(number =>
{
    Console.WriteLine(
        $"Processing {number}"
    );

    return number * 10;
});

query.ToList();
query.ToList();
```

**Output:**

```text
Processing 1
Processing 2
Processing 1
Processing 2
```

The side effects occur twice.

### Example 3: Source mutation before enumeration

```csharp
List<int> numbers = new()
{
    1, 2, 3
};

var query = numbers.Select(
    number => number * 2
);

numbers.Add(4);

Console.WriteLine(
    string.Join(", ", query)
);
```

**Output:**

```text
2, 4, 6, 8
```

The query observes the collection when it is enumerated.

### Example 4: Materialization

```csharp
int[] numbers = { 1, 2, 3 };

var result = numbers
    .Select(number => number * 2)
    .ToArray();

numbers[0] = 100;

Console.WriteLine(
    string.Join(", ", result)
);
```

**Output:**

```text
2, 4, 6
```

The array contains the results produced at materialization time.

### Example 5: Avoid side effects in deferred queries

Avoid:

```csharp
int counter = 0;

var query = numbers.Select(number =>
{
    counter++;
    return number * 2;
});
```

Prefer:

```csharp
int[] result = numbers
    .Select(number => number * 2)
    .ToArray();

int count = result.Length;
```

### Example 6: Perform effects explicitly after transformation

```csharp
int[] numbers = { 1, 2, 3 };

int[] results = numbers
    .Select(number => number * 2)
    .ToArray();

foreach (int result in results)
{
    Console.WriteLine(result);
}
```

**Output:**

```text
2
4
6
```

The transformation and output are separated.

### Important LINQ execution behaviors

| LINQ Operation | Execution Behavior |
|---|---|
| `Where()` | Deferred |
| `Select()` | Deferred |
| `SelectMany()` | Deferred |
| `OrderBy()` | Deferred; buffers and sorts during enumeration |
| `ToList()` | Immediate materialization |
| `ToArray()` | Immediate materialization |
| `Count()` | Immediate terminal operation |
| `First()` | Immediate terminal operation |
| `Aggregate()` | Immediate terminal operation |

Execution details can vary by query provider, and not every operation necessarily evaluates every source element.

### Rules for deferred queries

1. Prefer pure predicates.
2. Prefer pure selectors.
3. Avoid modifying external variables during enumeration.
4. Be aware that repeated enumeration can repeat computations.
5. Materialize when a stable snapshot of query results is required.
6. Perform logging and I/O outside transformation expressions where practical.

**Key point:** Deferred execution makes side effects inside LINQ queries especially unpredictable. Prefer pure transformations and perform effects at explicit boundaries.
