# 06.13 — `IEnumerable<T>`, `IQueryable<T>` & QUERY PROVIDERS

**Chapter:** 06 — LINQ Fundamentals  
**Namespaces:** `System.Collections.Generic`, `System.Linq`, `System.Linq.Expressions`

LINQ supports two important query models:

- **`IEnumerable<T>`:** Uses LINQ-to-Objects operators that execute .NET delegates.
- **`IQueryable<T>`:** Represents queries as expression trees that a query provider can interpret or translate.

The important distinction is not simply whether data is in memory or in a database. It is **how the query is represented and which component executes it**.

This section follows your master syllabus, including its nested topics. The internal construction of expression trees is reserved for Section 06.14.

---

# 1. `IEnumerable<T>`

`IEnumerable<T>` represents a sequence that can be enumerated using `foreach`.

It is the foundation of LINQ to Objects.

### Syntax

```csharp
IEnumerable<T> sequence;
```

### Example

```csharp
int[] numbers = { 10, 20, 30, 40 };

IEnumerable<int> sequence = numbers;

foreach (int number in sequence)
{
    Console.WriteLine(number);
}
```

**Output:**

```text
10
20
30
40
```

### Important properties

- Supports sequential enumeration.
- Uses `GetEnumerator()` to obtain an enumerator.
- Can represent arrays, lists, iterators, and other enumerable sources.
- Does not guarantee that data is already stored in memory.
- Does not guarantee deferred execution.
- Supports LINQ operators through `Enumerable`.

## 1.1 LINQ-to-Objects Foundation

LINQ to Objects executes queries over .NET enumerable sequences.

### Example

```csharp
List<int> numbers = new() { 10, 15, 20, 25, 30 };

IEnumerable<int> result = numbers
    .Where(n => n >= 20)
    .Select(n => n * 2);

foreach (int number in result)
{
    Console.WriteLine(number);
}
```

**Output:**

```text
40
50
60
```

### Execution flow

```text
List<int>
    │
    ▼
IEnumerable<int>
    │
    ▼
Enumerable.Where()
    │
    ▼
Enumerable.Select()
    │
    ▼
.NET Iterator
    │
    ▼
foreach
```

The LINQ operators process the elements through .NET code.

## 1.2 Delegate Execution

LINQ-to-Objects operators commonly accept delegates such as `Func<T, bool>`.

A delegate contains executable behavior.

### Example

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

Func<int, bool> condition = n => n > 2;

IEnumerable<int> result = numbers.Where(condition);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
3, 4, 5
```

### Explicit delegate

```csharp
Func<int, int> transform = n => n * 10;

var result = numbers.Select(transform);

// Output: 10, 20, 30, 40, 50
```

**Key point:** `Enumerable.Where()` receives a delegate that can be executed directly by .NET.

## 1.3 CLR Execution

CLR stands for **Common Language Runtime**.

For LINQ to Objects, the CLR executes the compiled .NET methods and delegates used by the query.

### Example

```csharp
int[] numbers = { 2, 4, 6, 8 };

bool IsGreaterThanFour(int n)
{
    return n > 4;
}

var result = numbers.Where(IsGreaterThanFour);

// Output: 6, 8
```

Here, `IsGreaterThanFour()` executes as an ordinary .NET method.

No database translation is involved.

## 1.4 In-Memory Evaluation

In-memory evaluation means the LINQ operators process elements locally in the application.

### Example

```csharp
record Student(string Name, int Marks);

List<Student> students = new()
{
    new("Amit", 90),
    new("Rahul", 75),
    new("Priya", 95)
};

var result = students
    .Where(s => s.Marks >= 90)
    .Select(s => s.Name);
```

**Output:**

```text
Amit
Priya
```

The application evaluates the predicate against the objects in the list.

**Note:** `IEnumerable<T>` can also represent streamed data from external sources. The interface itself does not mean the entire source is in memory.

## 1.5 Enumerable Operators

`Enumerable` is the static class containing LINQ-to-Objects extension methods.

### Example

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

var result = Enumerable.Where(
    numbers,
    n => n > 2
);
```

Equivalent extension-method syntax:

```csharp
var result = numbers.Where(n => n > 2);
```

### Method signature

```csharp
public static IEnumerable<TSource> Where<TSource>(
    this IEnumerable<TSource> source,
    Func<TSource, bool> predicate
);
```

### Common operators

| Category | Examples |
|---|---|
| Filtering | `Where`, `OfType` |
| Projection | `Select`, `SelectMany` |
| Sorting | `OrderBy`, `ThenBy` |
| Partitioning | `Skip`, `Take` |
| Aggregation | `Sum`, `Count`, `Average` |
| Materialization | `ToList`, `ToArray` |

These operators were covered in earlier sections; here, their importance is that they belong to the **`Enumerable` execution model**.

# 2. `IQueryable<T>`

`IQueryable<T>` represents a query that can be interpreted or executed by a query provider.

It inherits from `IEnumerable<T>` and `IQueryable`.

### Syntax

```csharp
IQueryable<T> query;
```

### Example

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

IQueryable<int> query = numbers.AsQueryable();

var result = query.Where(n => n > 2);
```

**Output when enumerated:**

```text
3
4
5
```

This example uses an in-memory query provider.

**Important:** `IQueryable<T>` does not automatically mean SQL or remote execution.

## 2.1 Queryable Sequences

A queryable sequence represents a query that a provider can process.

### Example

```csharp
IQueryable<int> query = new[]
{
    10, 20, 30, 40
}.AsQueryable();

IQueryable<int> filtered = query.Where(n => n > 20);
```

The resulting query can be further composed.

```csharp
var result = filtered.Select(n => n * 2);

// Output when enumerated: 60, 80
```

### Database example

With an Entity Framework Core `DbContext` containing `Students`:

```csharp
IQueryable<Student> query = db.Students;

var result = query.Where(s => s.Marks > 80);
```

The EF Core provider can translate supported query operations into SQL.

## 2.2 ElementType

`ElementType` identifies the type of elements returned by an `IQueryable`.

### Syntax

```csharp
query.ElementType;
```

### Example

```csharp
IQueryable<int> query = new[]
{
    1, 2, 3
}.AsQueryable();

Console.WriteLine(query.ElementType);
```

**Output:**

```text
System.Int32
```

### Object example

```csharp
record Student(int Id, string Name);

IQueryable<Student> query = new[]
{
    new Student(1, "Amit")
}.AsQueryable();

Console.WriteLine(query.ElementType.Name);
```

**Output:**

```text
Student
```

## 2.3 Expression

The `Expression` property exposes the expression tree representing the query.

### Syntax

```csharp
query.Expression;
```

### Example

```csharp
IQueryable<int> query = new[]
{
    1, 2, 3, 4, 5
}.AsQueryable();

query = query.Where(n => n > 2);

Console.WriteLine(query.Expression);
```

**Illustrative expression:**

```text
System.Int32[].Where(n => (n > 2))
```

The exact displayed text depends on the provider and runtime.

### Inspect expression type

```csharp
Console.WriteLine(query.Expression.NodeType);
```

For this query, the outer expression represents a method call.

**Key point:** `Expression` describes the query; it is not the materialized query result.

## 2.4 Provider

The `Provider` property identifies the component responsible for creating and executing queries.

### Syntax

```csharp
query.Provider;
```

### Example

```csharp
IQueryable<int> query = new[]
{
    1, 2, 3
}.AsQueryable();

IQueryProvider provider = query.Provider;

Console.WriteLine(provider.GetType().Name);
```

The concrete provider type depends on the query source.

### EF Core example

```csharp
IQueryable<Student> query = db.Students;

IQueryProvider provider = query.Provider;
```

Here, the provider is associated with EF Core.

**Key point:** The provider determines what the expression means and how it can be executed.

## 2.5 Expression Trees

An expression tree represents code as structured data.

### Delegate

```csharp
Func<int, bool> condition = n => n > 10;
```

### Expression tree

```csharp
using System.Linq.Expressions;

Expression<Func<int, bool>> condition =
    n => n > 10;
```

### Example

```csharp
Expression<Func<int, bool>> condition =
    n => n > 10;

Console.WriteLine(condition.Body);
```

**Output:**

```text
(n > 10)
```

The expression can be inspected by a query provider.

The detailed expression-tree structure is covered in **06.14**.

## 2.6 Provider Translation

Provider translation converts a query expression into another representation supported by the data source.

### Example

```csharp
var query = db.Students
    .Where(s => s.Marks >= 80)
    .OrderBy(s => s.Name)
    .Select(s => new
    {
        s.Name,
        s.Marks
    });
```

An EF Core relational provider might translate it into SQL resembling:

```sql
SELECT Name, Marks
FROM Students
WHERE Marks >= 80
ORDER BY Name;
```

The exact SQL depends on the provider, database, and mapping.

### Translation flow

```text
C# LINQ Query
      │
      ▼
Expression Tree
      │
      ▼
Query Provider
      │
      ▼
Translation
      │
      ▼
SQL / Provider-Specific Operation
```

Not every expression can be translated.

## 2.7 Remote Execution

Remote execution occurs when a query is evaluated by an external system such as a database.

### Example

```csharp
var query = db.Students
    .Where(s => s.Marks >= 90);

var students = await query.ToListAsync();
```

With EF Core and a relational database:

1. The LINQ query is composed.
2. EF Core translates the supported expression.
3. The database executes the query.
4. Results are returned to the application.
5. EF Core materializes the results.

`ToListAsync()` is an EF Core extension method, not a standard `Enumerable` method.

# 3. `IEnumerable<T>` vs `IQueryable<T>`

## 3.1 In-Memory vs Provider-Based

The main difference is the execution model.

### IEnumerable

```csharp
IEnumerable<Student> query = students
    .Where(s => s.Marks > 80);
```

`Enumerable.Where()` evaluates a delegate.

### IQueryable

```csharp
IQueryable<Student> query = db.Students
    .Where(s => s.Marks > 80);
```

`Queryable.Where()` builds a query expression for the provider.

### Comparison

| Feature | `IEnumerable<T>` | `IQueryable<T>` |
|---|---|---|
| Primary model | Enumeration | Provider-based querying |
| Typical LINQ class | `Enumerable` | `Queryable` |
| Predicate representation | Delegate | Expression tree |
| Execution | .NET enumerable processing | Provider-dependent |
| Database translation | Not provided by `Enumerable` | Possible |
| Remote execution | Not inherent | Possible |

## 3.2 Delegate vs Expression Tree

### Delegate

```csharp
Func<Student, bool> predicate =
    s => s.Marks >= 80;
```

### Expression tree

```csharp
Expression<Func<Student, bool>> predicate =
    s => s.Marks >= 80;
```

### Usage

```csharp
IEnumerable<Student> local = students.Where(
    (Func<Student, bool>)(s => s.Marks >= 80)
);
```

```csharp
IQueryable<Student> remote = db.Students.Where(
    (Expression<Func<Student, bool>>)(s => s.Marks >= 80)
);
```

A delegate provides executable behavior.

An expression tree provides a representation that can be analyzed.

## 3.3 Enumerable vs Queryable

`Enumerable` and `Queryable` are different static classes.

### Enumerable.Where

```csharp
IEnumerable<int> numbers = new[] { 1, 2, 3 };

var result = Enumerable.Where(
    numbers,
    n => n > 1
);
```

### Queryable.Where

```csharp
IQueryable<int> numbers = new[]
{
    1, 2, 3
}.AsQueryable();

var result = Queryable.Where(
    numbers,
    n => n > 1
);
```

### Simplified signatures

```csharp
Enumerable.Where(
    IEnumerable<T> source,
    Func<T, bool> predicate
);
```

```csharp
Queryable.Where(
    IQueryable<T> source,
    Expression<Func<T, bool>> predicate
);
```

These signatures explain why the same lambda syntax can result in different query behavior.

## 3.4 CLR vs Provider Execution

### CLR execution

```csharp
var result = students
    .Where(s => s.Marks > 80)
    .ToList();
```

If `students` is a `List<Student>`, .NET executes the filtering logic.

### Provider execution

```csharp
var result = db.Students
    .Where(s => s.Marks > 80)
    .ToList();
```

EF Core can translate the filter and execute it through the database provider.

**Important:** Provider execution may still use the CLR internally. The distinction is which component controls query interpretation and where filtering is performed.

## 3.5 Local vs Remote Evaluation

Local evaluation processes values within the application.

Remote evaluation processes supported operations in an external data source.

### Local

```csharp
var result = students
    .Where(s => s.Name.StartsWith("A"))
    .ToList();
```

### Remote

```csharp
var result = db.Students
    .Where(s => s.Name.StartsWith("A"))
    .ToList();
```

The second query may be translated to database-specific SQL.

Translation behavior depends on the provider.

## 3.6 Client-Side vs Server-Side Execution

Client-side execution processes data in application code.

Server-side execution processes data in a server, such as a database server.

### Server-side filtering

```csharp
var result = db.Students
    .Where(s => s.Marks >= 80)
    .ToList();
```

### Client-side filtering

```csharp
var result = db.Students
    .AsEnumerable()
    .Where(s => s.Marks >= 80)
    .ToList();
```

The second query crosses into LINQ-to-Objects before applying `Where()`.

### Important difference

```text
Server-side:

Database
   │
   ├── Filter
   │
   ▼
Matching Rows
   │
   ▼
Application
```

```text
Client-side:

Database
   │
   ▼
Rows Retrieved
   │
   ▼
Application
   │
   ├── Filter
   │
   ▼
Matching Objects
```

**Performance consideration:** Moving filtering to the client too early can increase network traffic and memory usage.

## 3.7 AsEnumerable Boundary

`AsEnumerable()` changes which LINQ extension methods are selected for subsequent operations.

### Example

```csharp
var query = db.Students
    .Where(s => s.Marks >= 80)
    .AsEnumerable()
    .Where(s => s.Name.Length > 4);
```

### Execution boundary

```text
Queryable.Where()
       │
       ▼
Provider Query
       │
       ▼
AsEnumerable()
       │
       ▼
Enumerable.Where()
       │
       ▼
Client-Side Filtering
```

The first filter can be translated by the provider.

The second filter executes through LINQ to Objects as the results are enumerated.

**Important:** `AsEnumerable()` itself does not immediately retrieve all rows.

## 3.8 AsQueryable Boundary

`AsQueryable()` exposes a source through `IQueryable<T>`.

### Example

```csharp
List<int> numbers = new() { 1, 2, 3, 4 };

IQueryable<int> query = numbers.AsQueryable();

var result = query.Where(n => n > 2);
```

The source is still a list.

### Example: After AsEnumerable

```csharp
IQueryable<Student> original = db.Students;

IEnumerable<Student> localView = original.AsEnumerable();

IQueryable<Student> query = localView.AsQueryable();
```

This does **not** restore the original EF Core provider. The queryable wrapper is based on the enumerable source.

**Key point:** `AsQueryable()` does not automatically convert local execution back into server-side execution.

# 4. `IQueryProvider`

`IQueryProvider` defines how a query provider creates queryable sequences and executes expression trees.

### Interface

```csharp
public interface IQueryProvider
{
    IQueryable CreateQuery(Expression expression);

    IQueryable<TElement> CreateQuery<TElement>(
        Expression expression
    );

    object? Execute(Expression expression);

    TResult Execute<TResult>(
        Expression expression
    );
}
```

The methods have two main responsibilities:

- **CreateQuery:** Construct a queryable sequence from an expression.
- **Execute:** Evaluate an expression and return a result.

## 4.1 CreateQuery

`CreateQuery(Expression)` creates a non-generic `IQueryable`.

### Example

```csharp
IQueryable<int> source = new[]
{
    1, 2, 3
}.AsQueryable();

var expression = source.Where(n => n > 1).Expression;

IQueryable query = source.Provider.CreateQuery(expression);
```

The resulting object represents the supplied expression.

### Inspect element type

```csharp
Console.WriteLine(query.ElementType.Name);

// Output: Int32
```

## 4.2 CreateQuery\<T>

`CreateQuery<T>()` creates a strongly typed queryable sequence.

### Example

```csharp
IQueryable<int> source = new[]
{
    1, 2, 3
}.AsQueryable();

var expression = source
    .Where(n => n > 1)
    .Expression;

IQueryable<int> result =
    source.Provider.CreateQuery<int>(expression);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
2, 3
```

### Difference

```csharp
IQueryable query;
```

versus:

```csharp
IQueryable<int> query;
```

The generic version preserves the compile-time element type.

## 4.3 Execute

`Execute(Expression)` evaluates an expression and returns its result as `object?`.

### Example

```csharp
IQueryable<int> source = new[]
{
    10, 20, 30
}.AsQueryable();

var countExpression = Expression.Call(
    typeof(Queryable),
    nameof(Queryable.Count),
    new[] { typeof(int) },
    source.Expression
);

object? result = source.Provider.Execute(countExpression);

Console.WriteLine(result);

// Output: 3
```

The provider interprets the supplied count expression.

## 4.4 Execute\<TResult>

`Execute<TResult>()` evaluates an expression and returns a strongly typed result.

### Example

```csharp
IQueryable<int> source = new[]
{
    10, 20, 30
}.AsQueryable();

var countExpression = Expression.Call(
    typeof(Queryable),
    nameof(Queryable.Count),
    new[] { typeof(int) },
    source.Expression
);

int result = source.Provider.Execute<int>(
    countExpression
);

Console.WriteLine(result);

// Output: 3
```

This avoids casting the result from `object`.

## 4.5 Expression Interpretation

Expression interpretation means analyzing the nodes of an expression to determine what operation it represents.

### Example

```csharp
IQueryable<int> query = new[]
{
    1, 2, 3
}.AsQueryable()
 .Where(n => n > 1);

Expression expression = query.Expression;

Console.WriteLine(expression.NodeType);
```

**Output:**

```text
Call
```

The provider can inspect the method call and its arguments to determine how to process it.

## 4.6 Query Translation

A provider may convert an expression into another query language.

### Example

```csharp
var query = db.Students
    .Where(s => s.Marks > 80);
```

**Conceptual translation:**

```text
Expression Tree
      │
      ▼
Where(Marks > 80)
      │
      ▼
Provider Translator
      │
      ▼
WHERE Marks > 80
```

Translation is provider-specific; `IQueryProvider` does not require SQL.

## 4.7 Query Execution

A provider executes or delegates execution of the query.

### Example

```csharp
var query = db.Students
    .Where(s => s.Marks > 80);

List<Student> result = query.ToList();
```

### Conceptual flow

```text
IQueryable<T>
     │
     ▼
Expression
     │
     ▼
IQueryProvider
     │
     ▼
Translation / Interpretation
     │
     ▼
Execution
     │
     ▼
Results
```

**Important:** Providers are free to implement internal execution differently. The interface does not prescribe a database, SQL, or a particular execution algorithm.

# 5. Provider Translation

Provider translation is the conversion of a LINQ expression into operations supported by a particular data source.

### Example: Filtering and Projection

```csharp
var query = db.Students
    .Where(s => s.Marks >= 80)
    .Select(s => new
    {
        s.Name,
        s.Marks
    });
```

**Possible SQL:**

```sql
SELECT Name, Marks
FROM Students
WHERE Marks >= 80;
```

### Example: Sorting

```csharp
var query = db.Students
    .OrderByDescending(s => s.Marks)
    .Take(5);
```

A relational provider may translate this into SQL using `ORDER BY` and database-specific row-limiting syntax.

### Translation stages

```text
LINQ Expression
      │
      ▼
Expression Analysis
      │
      ▼
Provider Translation
      │
      ▼
Source-Specific Query
      │
      ▼
Execution
```

**Key point:** Translation capabilities depend on the selected provider.

# 6. Provider Limitations

A query provider may support only a subset of .NET expressions and LINQ operations.

### Example: Custom Method

```csharp
bool IsExcellent(int marks)
{
    return marks >= 90;
}
```

Using it in a database predicate:

```csharp
var query = db.Students
    .Where(s => IsExcellent(s.Marks));
```

An EF Core relational provider generally cannot translate this arbitrary .NET method into SQL.

### Alternative: Translatable Expression

```csharp
var query = db.Students
    .Where(s => s.Marks >= 90);
```

### Common limitations

| Feature | Potential limitation |
|---|---|
| Custom .NET methods | No database translation |
| Reflection | Often unsupported |
| Complex object construction | Provider-dependent |
| Unsupported string operations | Provider-dependent |
| Custom comparers | Often unsupported in SQL |
| Culture-sensitive behavior | May differ from .NET |
| Date/time operations | Database-specific |
| Nested collections | Translation varies |

**Key point:** Code that works with LINQ to Objects may not work with every `IQueryable<T>` provider.

---

# 7. Unsupported Expressions

Unsupported expressions are parts of a query that a provider cannot interpret or translate.

### Example 1: Custom Predicate

```csharp
bool IsSpecial(string name)
{
    return name.StartsWith("A") && name.EndsWith("t");
}

var query = db.Students
    .Where(s => IsSpecial(s.Name));
```

A typical EF Core relational provider cannot translate this custom method call in a filter.

### Example 2: Rewrite Using Supported Operations

```csharp
var query = db.Students
    .Where(s =>
        s.Name.StartsWith("A") &&
        s.Name.EndsWith("t")
    );
```

Translation still depends on the provider, but common relational EF Core providers support these string operations.

### Example 3: Explicit Client Evaluation

```csharp
var result = db.Students
    .AsEnumerable()
    .Where(s => IsSpecial(s.Name))
    .ToList();
```

This processes the custom method locally.

**Warning:** The last approach may retrieve many more rows than necessary. Apply supported server-side filters first.

# 8. Translation Boundaries

A translation boundary separates operations handled by the query provider from operations handled locally.

### Example

```csharp
var result = db.Students
    .Where(s => s.Marks >= 80)
    .AsEnumerable()
    .Select(s => FormatStudent(s))
    .ToList();
```

Assume:

```csharp
string FormatStudent(Student student)
{
    return $"{student.Name}: {student.Marks}";
}
```

### Execution

```text
Database
   │
   ├── Marks >= 80
   │
   ▼
Matching Students
   │
   ▼
AsEnumerable()
   │
   ▼
FormatStudent()
   │
   ▼
List<string>
```

### Alternative: Materialization Boundary

```csharp
var students = db.Students
    .Where(s => s.Marks >= 80)
    .ToList();

var result = students
    .Select(FormatStudent)
    .ToList();
```

### Difference

| Boundary | Behavior |
|---|---|
| `AsEnumerable()` | Switches subsequent operations to LINQ to Objects without immediately materializing |
| `ToList()` | Executes and stores the provider query results |
| `ToArray()` | Executes and stores results in an array |

**Key point:** Choose the boundary deliberately to control how much work occurs in the data source versus the application.

# 9. Provider-Specific Semantics

Provider-specific semantics means a query can behave differently depending on the provider or underlying data source.

## 9.1 String Comparison

### LINQ to Objects

```csharp
string[] names = { "amit", "Amit", "AMIT" };

var result = names.Where(n => n == "Amit");

// Output: Amit
```

### Database query

```csharp
var result = db.Students
    .Where(s => s.Name == "Amit");
```

A database may use a case-insensitive collation, causing multiple casing variants to match.

## 9.2 Null Handling

### LINQ to Objects

```csharp
string?[] names = { null, "Amit" };

var result = names.Where(n => n == null);

// Output: null
```

### Database query

```csharp
var result = db.Students
    .Where(s => s.Name == null);
```

A relational provider must account for SQL's null semantics when translating this expression.

## 9.3 Ordering

### LINQ to Objects

```csharp
var result = students.OrderBy(s => s.Name);
```

### Database

```csharp
var result = db.Students.OrderBy(s => s.Name);
```

String ordering can differ because the database uses its configured collation.

## 9.4 Numeric and Date Operations

```csharp
var query = db.Students
    .Where(s => s.Marks / 2 > 40);
```

Arithmetic translation follows the provider's supported database semantics, which can differ from local .NET behavior in some cases.

### Summary

| Area | Potential difference |
|---|---|
| Strings | Case sensitivity and collation |
| Nulls | SQL null semantics |
| Ordering | Database collation and null placement |
| Arithmetic | Numeric types and division rules |
| Dates | Time zones and database functions |
| Precision | Floating-point and decimal behavior |

**Key point:** Equivalent LINQ syntax does not guarantee identical behavior across providers.

# 10. Custom Query Provider Concepts

A custom query provider is a component that implements query creation and execution for a particular data source or query language.

### Core components

```text
Custom IQueryable<T>
         │
         ▼
Expression Tree
         │
         ▼
Custom IQueryProvider
         │
         ├── Expression Analysis
         │
         ├── Query Translation
         │
         └── Query Execution
         │
         ▼
Results
```

## 10.1 Custom IQueryable

A custom queryable type typically exposes:

```csharp
public Type ElementType { get; }

public Expression Expression { get; }

public IQueryProvider Provider { get; }
```

It also implements enumeration.

## 10.2 Custom Provider

A custom provider implements:

```csharp
IQueryProvider
```

Its responsibilities include creating query objects and executing expressions.

### Minimal Interface Skeleton

```csharp
using System.Linq.Expressions;

public class CustomQueryProvider : IQueryProvider
{
    public IQueryable CreateQuery(Expression expression)
    {
        throw new NotImplementedException();
    }

    public IQueryable<TElement> CreateQuery<TElement>(
        Expression expression)
    {
        throw new NotImplementedException();
    }

    public object? Execute(Expression expression)
    {
        throw new NotImplementedException();
    }

    public TResult Execute<TResult>(
        Expression expression)
    {
        throw new NotImplementedException();
    }
}
```

**Note:** This is an interface-implementation skeleton, not a working provider. A real provider must implement expression handling, query construction, and execution.

## 10.3 Custom Translation Example

Suppose a provider supports a remote service with a filtering API.

A query:

```csharp
query.Where(p => p.Price > 100);
```

Might be translated into:

```text
GET /products?price_gt=100
```

This is a conceptual example of translation, not a built-in LINQ feature.

## 10.4 Custom Provider Use Cases

| Use Case | Possible Provider Behavior |
|---|---|
| SQL database | Translate LINQ to SQL |
| REST API | Translate expressions to HTTP query parameters |
| Search engine | Translate filters into search queries |
| Document database | Translate expressions into document queries |
| Custom storage engine | Interpret expressions against stored records |

**Key point:** `IQueryable<T>` provides a common query abstraction, but each provider defines what operations it supports.

# 11. Complete Practical Example

The following compares local execution with EF Core provider execution.

Assume the application has a configured EF Core `DbContext` with a `Students` entity set.

## 11.1 LINQ to Objects

```csharp
record Student(int Id, string Name, int Marks);

List<Student> students = new()
{
    new(1, "Amit", 90),
    new(2, "Rahul", 75),
    new(3, "Priya", 95),
    new(4, "Neha", 80)
};

IEnumerable<Student> query = students
    .Where(s => s.Marks >= 80)
    .OrderByDescending(s => s.Marks);

foreach (Student student in query)
{
    Console.WriteLine(student.Name);
}
```

**Output:**

```text
Priya
Amit
Neha
```

## 11.2 LINQ with EF Core

```csharp
IQueryable<Student> query = db.Students
    .Where(s => s.Marks >= 80)
    .OrderByDescending(s => s.Marks);

List<Student> result = query.ToList();
```

The EF Core provider attempts to translate the supported query operations for the configured database.

## 11.3 Explicit Client-Side Processing

```csharp
var result = db.Students
    .Where(s => s.Marks >= 80)
    .AsEnumerable()
    .Select(s => s.Name.ToUpperInvariant())
    .ToList();
```

Here:

- The `Where()` before `AsEnumerable()` is provider-based.
- The `Select()` after `AsEnumerable()` uses LINQ to Objects.
- `ToList()` materializes the final results.
