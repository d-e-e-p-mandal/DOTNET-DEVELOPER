**Chapter:** 08 — LINQ Joins & Set Operations

Data reconciliation is the process of comparing two or more data sources to identify differences, verify relationships, and ensure consistency.

In C#, LINQ provides several operators for reconciliation:

```csharp

GroupJoin()

ToLookup()
ToDictionary()
ToHashSet()
Except()
ExceptBy()
Intersect()
IntersectBy()
Union()
UnionBy()
Any()
All()
Count()
SequenceEqual()
```

## 1. Compare Two Data Sources

Comparing two data sources means checking whether their records are consistent.

The sources may represent existing data and newly imported data.

### Example 1: Compare two integer collections

```csharp
int[] sourceA = { 1, 2, 3, 4 };
int[] sourceB = { 3, 4, 5, 6 };

var onlyInA = sourceA.Except(sourceB);
var onlyInB = sourceB.Except(sourceA);
var common = sourceA.Intersect(sourceB);

Console.WriteLine(
    $"Only A: {string.Join(", ", onlyInA)}"
);

Console.WriteLine(
    $"Only B: {string.Join(", ", onlyInB)}"
);

Console.WriteLine(
    $"Common: {string.Join(", ", common)}"
);
```

**Output:**

```text
Only A: 1, 2
Only B: 5, 6
Common: 3, 4
```

### Example 2: Compare records by ID

```csharp
record Employee(int Id, string Name);

Employee[] sourceA =
{
    new(1, "Amit"),
    new(2, "Rahul"),
    new(3, "Priya")
};

Employee[] sourceB =
{
    new(2, "Rahul"),
    new(3, "Priya"),
    new(4, "Sneha")
};

var idsA = sourceA.Select(e => e.Id);
var idsB = sourceB.Select(e => e.Id);

var commonIds = idsA.Intersect(idsB);

Console.WriteLine(
    string.Join(", ", commonIds)
);
```

**Output:**

```text
2, 3
```

### Example 3: Compare source counts

```csharp
int[] sourceA = { 1, 2, 3 };
int[] sourceB = { 1, 2, 3, 4 };

Console.WriteLine(
    $"Source A: {sourceA.Length}"
);

Console.WriteLine(
    $"Source B: {sourceB.Length}"
);

Console.WriteLine(
    $"Equal Count: {sourceA.Length == sourceB.Length}"
);
```

**Output:**

```text
Source A: 3
Source B: 4
Equal Count: False
```

Equal counts do not necessarily mean equal data.

**Key point:** Comparing data sources identifies common records and differences between datasets.

## 2. Find Added Records

Added records are present in the new data source but absent from the old data source.

The comparison is usually performed using a unique key.

### Example 1: Find added IDs

```csharp
int[] oldIds = { 1, 2, 3 };
int[] newIds = { 1, 2, 3, 4, 5 };

var addedIds = newIds.Except(oldIds);

Console.WriteLine(
    string.Join(", ", addedIds)
);
```

**Output:**

```text
4, 5
```

### Example 2: Find added employees

```csharp
record Employee(int Id, string Name);

Employee[] oldEmployees =
{
    new(1, "Amit"),
    new(2, "Rahul")
};

Employee[] newEmployees =
{
    new(1, "Amit"),
    new(2, "Rahul"),
    new(3, "Priya"),
    new(4, "Sneha")
};

var oldIds = oldEmployees.Select(e => e.Id);

var added = newEmployees.ExceptBy(
    oldIds,
    e => e.Id
);

foreach (var employee in added)
{
    Console.WriteLine(
        $"{employee.Id}: {employee.Name}"
    );
}
```

**Output:**

```text
3: Priya
4: Sneha
```

### Example 3: Find added records using Join-related logic

```csharp
record Product(int Id, string Name);

Product[] oldProducts =
{
    new(1, "Mouse"),
    new(2, "Keyboard")
};

Product[] newProducts =
{
    new(1, "Mouse"),
    new(2, "Keyboard"),
    new(3, "Monitor")
};

var oldIds = oldProducts
    .Select(p => p.Id)
    .ToHashSet();

var added = newProducts.Where(
    p => !oldIds.Contains(p.Id)
);

foreach (var product in added)
{
    Console.WriteLine(product.Name);
}
```

**Output:**

```text
Monitor
```

**Key point:** Added records are found using `New - Old`.

## 4. Find Unchanged Records

Unchanged records exist in both data sources and have matching values.

Matching keys alone are insufficient to establish that a record is unchanged.

### Example 1: Unchanged integer values

```csharp
int[] oldValues = { 1, 2, 3, 4 };
int[] newValues = { 2, 3, 4, 5 };

var unchanged = oldValues.Intersect(newValues);

Console.WriteLine(
    string.Join(", ", unchanged)
);
```

**Output:**

```text
2, 3, 4
```

### Example 2: Unchanged employees

```csharp
record Employee(
    int Id,
    string Name,
    decimal Salary
);

Employee[] oldEmployees =
{
    new(1, "Amit", 30000),
    new(2, "Rahul", 40000),
    new(3, "Priya", 50000)
};

Employee[] newEmployees =
{
    new(1, "Amit", 30000),
    new(2, "Rahul", 45000),
    new(3, "Priya", 50000)
};

var unchanged = oldEmployees.Join(
    newEmployees,
    old => old.Id,
    current => current.Id,
    (old, current) => new
    {
        Old = old,
        Current = current
    }
)
.Where(x =>
    x.Old.Name == x.Current.Name &&
    x.Old.Salary == x.Current.Salary
)
.Select(x => x.Current);

foreach (var employee in unchanged)
{
    Console.WriteLine(employee.Name);
}
```

**Output:**

```text
Amit
Priya
```

### Example 3: Unchanged records using record equality

```csharp
record Product(
    int Id,
    string Name,
    decimal Price
);

Product[] oldProducts =
{
    new(1, "Mouse", 500),
    new(2, "Keyboard", 1000)
};

Product[] newProducts =
{
    new(1, "Mouse", 500),
    new(2, "Keyboard", 1200)
};

var unchanged = oldProducts.Intersect(newProducts);

foreach (var product in unchanged)
{
    Console.WriteLine(product.Name);
}
```

**Output:**

```text
Mouse
```

Records use value-based equality.

**Key point:** Unchanged records have matching business keys and matching relevant data values.

## 5. Find Modified Records

Modified records exist in both sources with the same key but different data values.

### Example 1: Detect salary changes

```csharp
record Employee(
    int Id,
    string Name,
    decimal Salary
);

Employee[] oldEmployees =
{
    new(1, "Amit", 30000),
    new(2, "Rahul", 40000)
};

Employee[] newEmployees =
{
    new(1, "Amit", 35000),
    new(2, "Rahul", 40000)
};

var modified = oldEmployees.Join(
    newEmployees,
    old => old.Id,
    current => current.Id,
    (old, current) => new
    {
        old.Id,
        old.Name,
        OldSalary = old.Salary,
        NewSalary = current.Salary
    }
)
.Where(x => x.OldSalary != x.NewSalary);

foreach (var employee in modified)
{
    Console.WriteLine(
        $"{employee.Name}: " +
        $"{employee.OldSalary} -> {employee.NewSalary}"
    );
}
```

**Output:**

```text
Amit: 30000 -> 35000
```

### Example 2: Detect product price changes

```csharp
record Product(
    int Id,
    string Name,
    decimal Price
);

Product[] oldProducts =
{
    new(1, "Mouse", 500),
    new(2, "Keyboard", 1000)
};

Product[] newProducts =
{
    new(1, "Mouse", 600),
    new(2, "Keyboard", 1000)
};

var modified = oldProducts.Join(
    newProducts,
    old => old.Id,
    current => current.Id,
    (old, current) => new
    {
        old.Name,
        OldPrice = old.Price,
        NewPrice = current.Price
    }
)
.Where(x => x.OldPrice != x.NewPrice);

foreach (var product in modified)
{
    Console.WriteLine(
        $"{product.Name}: " +
        $"{product.OldPrice} -> {product.NewPrice}"
    );
}
```

**Output:**

```text
Mouse: 500 -> 600
```

### Example 3: Detect multiple field changes

```csharp
record Employee(
    int Id,
    string Name,
    string Department,
    decimal Salary
);

Employee[] oldEmployees =
{
    new(1, "Amit", "IT", 30000)
};

Employee[] newEmployees =
{
    new(1, "Amit", "HR", 35000)
};

    newEmployees,

);

foreach (var item in modified)
{
    Console.WriteLine(
        $"{item.Old.Department} -> " +
        $"{item.Current.Department}"
    );

    Console.WriteLine(
        $"{item.Old.Salary} -> " +
        $"{item.Current.Salary}"
    );
}
```

**Output:**

```text
IT -> HR
30000 -> 35000
```

**Key point:** Modified records are identified by matching keys and comparing non-key fields.

## 6. Compare by Business Key

A business key uniquely identifies a record according to the application's business rules.

Examples include:

- Employee ID
- Product code
- Order number
- Customer number

Reconciliation should generally match records by their business keys rather than by their positions.

### Example 1: Compare employees by ID

```csharp
record Employee(int Id, string Name);

Employee[] oldEmployees =
{
    new(1, "Amit"),
    new(2, "Rahul")
};

Employee[] newEmployees =
{
    new(2, "Rahul Sharma"),
    new(1, "Amit")
};

var result = oldEmployees.Join(
    newEmployees,
    old => old.Id,
    current => current.Id,
    (old, current) => new
    {
        old.Id,
        OldName = old.Name,
        NewName = current.Name
    }
);

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.Id}: {item.OldName} -> {item.NewName}"
    );
}
```

**Output:**

```text
1: Amit -> Amit
2: Rahul -> Rahul Sharma
```

The records match even though their positions differ.

### Example 2: Compare by composite business key

```csharp
record OrderItem(
    int OrderId,
    int ProductId,
    int Quantity
);

OrderItem[] oldItems =
{
    new(101, 1, 2),
    new(101, 2, 3)
};

OrderItem[] newItems =
{
    new(101, 1, 5),
    new(101, 2, 3)
};

var result = oldItems.Join(
    newItems,
    old => (old.OrderId, old.ProductId),
    current => (current.OrderId, current.ProductId),
    (old, current) => new
    {
        old.OrderId,
        old.ProductId,
        OldQuantity = old.Quantity,
        NewQuantity = current.Quantity
    }
);

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.OrderId}-{item.ProductId}: " +
        $"{item.OldQuantity} -> {item.NewQuantity}"
    );
}
```

**Output:**

```text
101-1: 2 -> 5
101-2: 3 -> 3
```

**Key point:** Business keys identify corresponding records independently of their ordering or other changing attributes.

## 7. Detect Duplicate Records

Duplicate records contain repeated values or repeated business keys.

`GroupBy()` is commonly used to detect duplicates.

### Example 1: Detect duplicate integers

```csharp
int[] numbers =
{
    1, 2, 2, 3, 3, 3, 4
};

var duplicates = numbers
    .GroupBy(x => x)
    .Where(g => g.Count() > 1);

foreach (var group in duplicates)
{
    Console.WriteLine(
        $"{group.Key}: {group.Count()}"
    );
}
```

**Output:**

```text
2: 2
3: 3
```

### Example 2: Detect duplicate employee IDs

```csharp
record Employee(int Id, string Name);

Employee[] employees =
{
    new(1, "Amit"),
    new(2, "Rahul"),
    new(2, "Rahul Kumar"),
    new(3, "Priya")
};

var duplicates = employees
    .GroupBy(e => e.Id)
    .Where(g => g.Count() > 1);

foreach (var group in duplicates)
{
    Console.WriteLine(
        $"Duplicate ID: {group.Key}"
    );

    foreach (var employee in group)
    {
        Console.WriteLine(employee.Name);
    }
}
```

**Output:**

```text
Duplicate ID: 2
Rahul
Rahul Kumar
```

### Example 3: Detect duplicate composite keys

```csharp
record OrderItem(
    int OrderId,
    int ProductId
);

OrderItem[] items =
{
    new(101, 1),
    new(101, 2),
    new(101, 1),
    new(102, 1)
};

var duplicates = items
    .GroupBy(x => (x.OrderId, x.ProductId))
    .Where(g => g.Count() > 1);

foreach (var group in duplicates)
{
    Console.WriteLine(
        $"Order: {group.Key.OrderId}, " +
        $"Product: {group.Key.ProductId}"
    );
}
```

**Output:**

```text
Order: 101, Product: 1
```

**Key point:** Group records by their intended unique keys and identify groups containing more than one record.

## 8. Detect Missing Relationships

Missing relationships occur when a record references another record that does not exist.

For example, an employee may reference a nonexistent department.

### Example 1: Find employees with missing departments

```csharp
record Department(int Id, string Name);
record Employee(int Id, string Name, int DepartmentId);

Department[] departments =
{
    new(10, "IT"),
    new(20, "HR")
};

Employee[] employees =
{
    new(1, "Amit", 10),
    new(2, "Rahul", 30),
    new(3, "Priya", 20)
};

var departmentIds = departments
    .Select(d => d.Id)
    .ToHashSet();

var missing = employees.Where(
    e => !departmentIds.Contains(e.DepartmentId)
);

foreach (var employee in missing)
{
    Console.WriteLine(
        $"{employee.Name}: Missing Department {employee.DepartmentId}"
    );
}
```

**Output:**

```text
Rahul: Missing Department 30
```

### Example 2: Find missing relationships using GroupJoin

```csharp
var missing = employees
    .GroupJoin(
        departments,
        e => e.DepartmentId,
        d => d.Id,
        (employee, matches) => new
        {
            Employee = employee,
            Matches = matches
        }
    )
    .Where(x => !x.Matches.Any())
    .Select(x => x.Employee);

foreach (var employee in missing)
{
    Console.WriteLine(employee.Name);
}
```

**Output:**

```text
Rahul
```

**Key point:** Missing relationships can be detected using `GroupJoin()`, `Any()`, or `HashSet<T>.Contains()`.

var removed = existing.ExceptBy(

**Output:**

```text
Monitor
```

## 10. Parent/Child Reconciliation

Parent/child reconciliation verifies relationships between parent records and their associated child records.

Examples include:

```text
Department → Employees
Customer   → Orders
Order      → OrderItems
Category   → Products
```

### Example 1: Count children per parent

```csharp
record Department(int Id, string Name);
record Employee(int Id, string Name, int DepartmentId);

Department[] departments =
{
    new(10, "IT"),
    new(20, "HR"),
    new(30, "Finance")
};

Employee[] employees =
{
    new(1, "Amit", 10),
    new(2, "Rahul", 10),
    new(3, "Priya", 20)
};

var result = departments.GroupJoin(
    employees,
    d => d.Id,
    e => e.DepartmentId,
    (department, members) => new
    {
        department.Name,
        Count = members.Count()
    }
);

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.Name}: {item.Count}"
    );
}
```

**Output:**

```text
IT: 2
HR: 1
Finance: 0
```

### Example 2: Find parents without children

```csharp
var emptyDepartments = departments
    .GroupJoin(
        employees,
        d => d.Id,
        e => e.DepartmentId,
        (department, members) => new
        {
            Department = department,
            Members = members
        }
    )
    .Where(x => !x.Members.Any())
    .Select(x => x.Department);

foreach (var department in emptyDepartments)
{
    Console.WriteLine(department.Name);
}
```

**Output:**

```text
Finance
```

### Example 3: Find orphan children

```csharp
Employee[] employees =
{
    new(1, "Amit", 10),
    new(2, "Rahul", 99)
};

int[] departmentIds = { 10, 20 };

var orphans = employees.ExceptBy(
    departmentIds,
    e => e.DepartmentId
);

foreach (var employee in orphans)
{
    Console.WriteLine(employee.Name);
}
```

**Output:**

```text
Rahul
```

**Key point:** Parent/child reconciliation verifies child counts, empty parent groups, and missing parent references.

## 11. Choose Join vs Lookup

`Join()` and `ToLookup()` both support key-based relationships, but they serve different purposes.

### Join

`Join()` directly matches records from two sequences.

```csharp
var result = employees.Join(
    departments,
    e => e.DepartmentId,
    d => d.Id,
    (e, d) => new
    {
        Employee = e.Name,
        Department = d.Name
    }
);
```

Use `Join()` when the main goal is to produce matching record combinations.

### Lookup

`ToLookup()` creates a reusable mapping from keys to groups of elements.

```csharp
var employeeLookup = employees.ToLookup(
    e => e.DepartmentId
);
```

Access records using a key:

```csharp
foreach (var employee in employeeLookup[10])
{
    Console.WriteLine(employee.Name);
}
```

### Comparison

| Feature | Join | ToLookup |
|---|---|---|
| Main purpose | Match records | Group records by key |
| Result | Matching combinations | Key-to-elements lookup |
| Execution | Deferred | Immediate |
| Repeated key access | Requires another query or stored result | Efficient |
| Missing key | No matching result | Empty sequence |
| Multiple records per key | Supported | Supported |

**Key point:** Choose `Join()` for direct matching and `ToLookup()` for reusable grouped access.

## 12. Choose Dictionary vs Lookup

Both dictionaries and lookups support key-based access.

Their main difference is the number of values associated with each key.

### Dictionary

A dictionary maps each unique key to one value.

```csharp
record Employee(int Id, string Name);

Employee[] employees =
{
    new(1, "Amit"),
    new(2, "Rahul")
};

var dictionary = employees.ToDictionary(
    e => e.Id
);

Console.WriteLine(dictionary[1].Name);
```

**Output:**

```text
Amit
```

### Lookup

A lookup maps each key to a sequence of values.

```csharp
record Employee(
    int Id,
    string Name,
    int DepartmentId
);

Employee[] employees =
{
    new(1, "Amit", 10),
    new(2, "Rahul", 10),
    new(3, "Priya", 20)
};

var lookup = employees.ToLookup(
    e => e.DepartmentId
);

foreach (var employee in lookup[10])
{
    Console.WriteLine(employee.Name);
}
```

**Output:**

```text
Amit
Rahul
```

### Comparison

| Feature | Dictionary | Lookup |
|---|---|---|
| Values per key | One | Multiple |
| Duplicate keys during construction | Throws exception | Groups values |
| Missing key via indexer | Throws exception | Returns empty sequence |
| Mutable collection | Yes | No |
| Typical purpose | Unique record lookup | One-to-many relationship |

**Key point:** Choose `Dictionary<TKey,TValue>` for unique keys and `ILookup<TKey,TElement>` for keys associated with multiple elements.

## 13. Choose HashSet vs Set Operators

`HashSet<T>` and LINQ set operators both support equality-based operations.

### Example 1: Membership using HashSet

```csharp
int[] validIds = { 1, 2, 3 };

HashSet<int> validSet = validIds.ToHashSet();

Console.WriteLine(validSet.Contains(2));
Console.WriteLine(validSet.Contains(5));
```

**Output:**

```text
True
False
```

### Example 2: Difference using Except

```csharp
int[] oldIds = { 1, 2, 3 };
int[] newIds = { 2, 3, 4 };

var removed = oldIds.Except(newIds);

Console.WriteLine(
    string.Join(", ", removed)
);
```

**Output:**

```text
1
```

### Example 3: Set operations using HashSet

```csharp
HashSet<int> first = new() { 1, 2, 3 };
HashSet<int> second = new() { 3, 4, 5 };

first.IntersectWith(second);

Console.WriteLine(
    string.Join(", ", first.OrderBy(x => x))
);
```

**Output:**

```text
3
```

`IntersectWith()` modifies the first set.

### Comparison

| Feature | HashSet | LINQ Set Operators |
|---|---|---|
| Membership checks | `Contains()` | `Any()` or set-based queries |
| Union | `UnionWith()` | `Union()` |
| Intersection | `IntersectWith()` | `Intersect()` |
| Difference | `ExceptWith()` | `Except()` |
| Mutation | Set methods can mutate | Operators return new sequences |
| Deferred execution | No for set mutation | Yes |
| Repeated membership checks | Suitable | May require repeated evaluation |

**Key point:** Use `HashSet<T>` for reusable membership checks and mutable set operations; use LINQ set operators to produce query results.

## 14. Avoid Cartesian Products

A Cartesian product combines every element of one sequence with every element of another.

For sequences containing `m` and `n` elements, the result contains:

\[
m \times n
\]

elements.

### Example 1: Cartesian product

```csharp
int[] first = { 1, 2, 3 };
string[] second = { "A", "B" };

var result =
    from x in first
    from y in second
    select new { x, y };

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.x}-{item.y}"
    );
}
```

**Output:**

```text
1-A
1-B
2-A
2-B
3-A
3-B
```

Result count:

```text
3 × 2 = 6
```

### Example 2: Use Join for matching relationships

```csharp
record Employee(int Id, int DepartmentId);
record Department(int Id, string Name);

Employee[] employees =
{
    new(1, 10),
    new(2, 20)
};

Department[] departments =
{
    new(10, "IT"),
    new(20, "HR")
};

var result = employees.Join(
    departments,
    e => e.DepartmentId,
    d => d.Id,
    (e, d) => new
    {
        e.Id,
        Department = d.Name
    }
);

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.Id}: {item.Department}"
    );
}
```

**Output:**

```text
1: IT
2: HR
```

Only matching records are combined.

**Key point:** Avoid unintended Cartesian products by applying correct join conditions and validating relationship keys.

## 15. Handle Duplicate Keys

Duplicate keys can create ambiguous matches and unexpected result counts.

### Example 1: Duplicate keys in Join

```csharp
record Employee(int Id, string Name);

Employee[] first =
{
    new(1, "Amit")
};

Employee[] second =
{
    new(1, "Amit Kumar"),
    new(1, "Amit Sharma")
};

var result = first.Join(
    second,
    x => x.Id,
    y => y.Id,
    (x, y) => new
    {
        OldName = x.Name,
        NewName = y.Name
    }
);

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.OldName} -> {item.NewName}"
    );
}
```

**Output:**

```text
Amit -> Amit Kumar
Amit -> Amit Sharma
```

One record produces two matches.

### Example 2: Validate duplicate keys before reconciliation

```csharp
var duplicateKeys = second
    .GroupBy(e => e.Id)
    .Where(g => g.Count() > 1);

foreach (var group in duplicateKeys)
{
    Console.WriteLine(
        $"Duplicate ID: {group.Key}"
    );
}
```

**Output:**

```text
Duplicate ID: 1
```

### Example 3: Select one record per key

```csharp
var unique = second
    .GroupBy(e => e.Id)
    .Select(g => g.First());

foreach (var employee in unique)
{
    Console.WriteLine(employee.Name);
}
```

**Output:**

```text
Amit Kumar
```

Selecting the first record is appropriate only when that rule is explicitly acceptable. Otherwise, duplicate keys should be treated as validation errors or resolved using defined business rules.

**Key point:** Detect duplicate keys before performing reconciliation that assumes one record per key.

## 16. Handle Missing Keys

Missing keys occur when key values are absent, null, or invalid.

The reconciliation process must define how such records are handled.

### Example 1: Detect null keys

```csharp
record Employee(
    int? Id,
    string Name
);

Employee[] employees =
{
    new(1, "Amit"),
    new(null, "Rahul"),
    new(3, "Priya")
};

var missingKeys = employees.Where(
    e => e.Id is null
);

foreach (var employee in missingKeys)
{
    Console.WriteLine(employee.Name);
}
```

**Output:**

```text
Rahul
```

### Example 2: Detect invalid keys

```csharp
record Employee(int Id, string Name);

Employee[] employees =
{
    new(1, "Amit"),
    new(0, "Rahul"),
    new(-1, "Priya")
};

var invalid = employees.Where(
    e => e.Id <= 0
);

foreach (var employee in invalid)
{
    Console.WriteLine(employee.Name);
}
```

**Output:**

```text
Rahul
Priya
```

### Example 3: Validate keys before matching

```csharp
var validEmployees = employees.Where(
    e => e.Id > 0
);

foreach (var employee in validEmployees)
{
    Console.WriteLine(employee.Name);
}
```

**Output:**

```text
Amit
```

**Key point:** Validate missing and invalid business keys before using them to identify matching records.

## 17. Validate Result Cardinality

Cardinality describes the number of records associated with a relationship or returned by a query.

Common relationship types include:

```text
One-to-One
One-to-Many
Many-to-One
Many-to-Many
```

### Example 1: Validate one-to-one matching

```csharp
record Employee(int Id, string Name);

Employee[] oldEmployees =
{
    new(1, "Amit"),
    new(2, "Rahul")
};

Employee[] newEmployees =
{
    new(1, "Amit"),
    new(2, "Rahul")
};

var matches = oldEmployees.Join(
    newEmployees,
    old => old.Id,
    current => current.Id,
    (old, current) => new
    {
        old.Id
    }
);

Console.WriteLine(matches.Count());
```

**Output:**

```text
2
```

### Example 2: Duplicate keys increase cardinality

```csharp
int[] first = { 1, 1 };
int[] second = { 1, 1, 1 };

var matches = first.Join(
    second,
    x => x,
    y => y,
    (x, y) => x
);

Console.WriteLine(matches.Count());
```

**Output:**

```text
6
```

Each of the two first-sequence elements matches all three second-sequence elements.

\[
2 \times 3 = 6
\]

### Example 3: Validate unique business keys

```csharp
record Employee(int Id, string Name);

Employee[] employees =
{
    new(1, "Amit"),
    new(2, "Rahul"),
    new(2, "Rahul Kumar")
};

bool uniqueKeys = employees
    .GroupBy(e => e.Id)
    .All(g => g.Count() == 1);

Console.WriteLine(uniqueKeys);
```

**Output:**

```text
False
```

### Example 4: Validate expected reconciliation counts

```csharp
int[] oldIds = { 1, 2, 3 };
int[] newIds = { 2, 3, 4 };

int added = newIds.Except(oldIds).Count();
int removed = oldIds.Except(newIds).Count();
int common = oldIds.Intersect(newIds).Count();

Console.WriteLine($"Added: {added}");
Console.WriteLine($"Removed: {removed}");
Console.WriteLine($"Common: {common}");

Console.WriteLine(
    oldIds.Distinct().Count() == removed + common
);

Console.WriteLine(
    newIds.Distinct().Count() == added + common
);
```

**Output:**

```text
Added: 1
Removed: 1
Common: 2
True
True
```

These count relationships apply to distinct business keys.

**Key point:** Validate result counts against expected relationship cardinalities to detect duplicate matches and missing records.

## 18. Test Boundary & Adversarial Data

Reconciliation logic should be tested with unusual or problematic input data.

Important cases include empty sources, duplicates, missing keys, reordered records, and conflicting values.

### Example 1: Both sources empty

```csharp
int[] first = Array.Empty<int>();
int[] second = Array.Empty<int>();

Console.WriteLine(
    first.SequenceEqual(second)
);
```

**Output:**

```text
True
```

### Example 2: One source empty

```csharp
int[] oldIds = Array.Empty<int>();
int[] newIds = { 1, 2, 3 };

var added = newIds.Except(oldIds);

Console.WriteLine(
    string.Join(", ", added)
);
```

**Output:**

```text
1, 2, 3
```

### Example 3: Duplicate keys

```csharp
int[] ids = { 1, 2, 2, 3 };

bool hasDuplicates = ids
    .GroupBy(x => x)
    .Any(g => g.Count() > 1);

Console.WriteLine(hasDuplicates);
```

**Output:**

```text
True
```

### Example 4: Reordered records

```csharp
int[] first = { 1, 2, 3 };
int[] second = { 3, 1, 2 };

Console.WriteLine(
    first.SequenceEqual(second)
);

Console.WriteLine(
    first.ToHashSet().SetEquals(second)
);
```

**Output:**

```text
False
True
```

### Example 5: Null business keys

```csharp
record Employee(int? Id, string Name);

Employee[] employees =
{
    new(1, "Amit"),
    new(null, "Rahul")
};

bool hasMissingKeys = employees.Any(
    e => e.Id is null
);

Console.WriteLine(hasMissingKeys);
```

**Output:**

```text
True
```

### Example 6: Conflicting values

```csharp
record Product(
    int Id,
    decimal Price
);

Product[] oldProducts =
{
    new(1, 500)
};

Product[] newProducts =
{
    new(1, 700)
};

bool hasChanges = oldProducts.Join(
    newProducts,
    old => old.Id,
    current => current.Id,
    (old, current) => old.Price != current.Price
).Any(changed => changed);

Console.WriteLine(hasChanges);
```

**Output:**

```text
True
```

### Example 7: Duplicate frequency differences

```csharp
int[] first = { 1, 1, 2 };
int[] second = { 1, 2, 2 };

bool sameSet = first
    .ToHashSet()
    .SetEquals(second);

bool sameFrequency = first
    .OrderBy(x => x)
    .SequenceEqual(
        second.OrderBy(x => x)
    );

Console.WriteLine(sameSet);
Console.WriteLine(sameFrequency);
```

**Output:**

```text
True
False
```

### Boundary testing summary

| Test Case | Expected Validation |
|---|---|
| Both sources empty | No additions, removals, or modifications |
| Old source empty | All valid new records are additions |
| New source empty | All valid old records are removals |
| Duplicate keys | Detect or resolve duplicate identities |
| Missing keys | Identify invalid records |
| Reordered records | Match by business key |
| Modified values | Detect changes to non-key fields |
| Missing relationships | Identify orphan records |
| Unequal record counts | Classify additions and removals |
| Unexpected join count | Validate relationship cardinality |
| Duplicate frequency changes | Detect when occurrence counts matter |

**Key point:** Boundary and adversarial tests verify that reconciliation remains correct when input data is incomplete, duplicated, reordered, or inconsistent.
