# GROUP 08 — LINQ JOINS & RELATIONSHIPS

Having completed **07.09 — Grouped Reporting & Validation**, the next section begins LINQ joins.

Joins combine related data from two sequences using matching keys. They are commonly used to connect employees with departments, students with courses, and orders with customers.

### 1. Join Concepts

A join combines elements from two sequences based on matching keys.

**Basic syntax:**

```csharp
outer.Join(
    inner,
    outerKeySelector,
    innerKeySelector,
    resultSelector
);
```

**Example:**

```csharp
record Employee(int Id, string Name, int DepartmentId);
record Department(int Id, string Name);

Employee[] employees =
{
    new(1, "Amit", 10),
    new(2, "Rahul", 20),
    new(3, "Priya", 10)
};

Department[] departments =
{
    new(10, "IT"),
    new(20, "HR")
};

var result = employees.Join(
    departments,
    e => e.DepartmentId,
    d => d.Id,
    (e, d) => new
    {
        Employee = e.Name,
        Department = d.Name
    }
);

foreach (var item in result)
{
    Console.WriteLine($"{item.Employee}: {item.Department}");
}
```

**Output:**

```text
Amit: IT
Rahul: HR
Priya: IT
```

**Key point:** A join combines related records using matching keys.

---

### 2. Outer Source

The outer source is the first sequence supplied to a join.

**Syntax:**

```csharp
outerSource.Join(innerSource, ...);
```

**Example:**

```csharp
int[] outer = { 1, 2, 3 };
int[] inner = { 2, 3, 4 };

var result = outer.Join(
    inner,
    x => x,
    y => y,
    (x, y) => x
);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
2, 3
```

Here, `outer` is the outer source.

In LINQ to Objects, join results are produced in outer-source order.

---

### 3. Inner Source

The inner source is the second sequence supplied to a join.

**Example:**

```csharp
string[] outer = { "A", "B", "C" };
string[] inner = { "B", "C", "D" };

var result = outer.Join(
    inner,
    x => x,
    y => y,
    (x, y) => $"{x}-{y}"
);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
B-B, C-C
```

Here, `inner` is the inner source.

**Key point:** Both sequences participate in matching, but their roles determine how the join is expressed.

---

### 4. Join Key

A join key identifies the value used to match records.

For example:

```text
Employee.DepartmentId = Department.Id
```

**Example:**

```csharp
record Employee(string Name, int DepartmentId);
record Department(int Id, string Name);

Employee[] employees =
{
    new("Amit", 10),
    new("Rahul", 20)
};

Department[] departments =
{
    new(10, "IT"),
    new(20, "HR")
};

var result = employees.Join(
    departments,
    e => e.DepartmentId,
    d => d.Id,
    (e, d) => $"{e.Name}: {d.Name}"
);

foreach (string item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
Amit: IT
Rahul: HR
```

**Key point:** The two key selectors must produce compatible key types.

---

### 5. Outer Key Selector

The outer key selector extracts a key from each outer-source element.

Its general delegate type is:

```csharp
Func<TOuter, TKey>
```

**Example:**

```csharp
int[] outer = { 11, 22, 33 };
int[] inner = { 1, 2, 3 };

var result = outer.Join(
    inner,
    x => x % 10,
    y => y,
    (x, y) => $"{x} matches {y}"
);

foreach (var item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
11 matches 1
22 matches 2
33 matches 3
```

Here, `x => x % 10` is the outer key selector.

---

### 6. Inner Key Selector

The inner key selector extracts a key from each inner-source element.

Its general delegate type is:

```csharp
Func<TInner, TKey>
```

**Example:**

```csharp
int[] outer = { 1, 2, 3 };
int[] inner = { 10, 20, 30 };

var result = outer.Join(
    inner,
    x => x,
    y => y / 10,
    (x, y) => $"{x}: {y}"
);

foreach (var item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
1: 10
2: 20
3: 30
```

Here, `y => y / 10` is the inner key selector.

---

### 7. Result Selector

The result selector determines the output produced for each matching pair.

Its general delegate type is:

```csharp
Func<TOuter, TInner, TResult>
```

**Example 1: String result**

```csharp
int[] outer = { 1, 2 };
int[] inner = { 1, 2 };

var result = outer.Join(
    inner,
    x => x,
    y => y,
    (x, y) => $"Matched: {x}"
);

foreach (var item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
Matched: 1
Matched: 2
```

**Example 2: Anonymous object result**

```csharp
var result = outer.Join(
    inner,
    x => x,
    y => y,
    (x, y) => new
    {
        OuterValue = x,
        InnerValue = y
    }
);

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.OuterValue}, {item.InnerValue}"
    );
}
```

**Output:**

```text
1, 1
2, 2
```

**Key point:** The result selector controls the structure of joined output.

---

### 8. Equality Comparer

`Join()` compares keys using equality.

By default, it uses:

```csharp
EqualityComparer<TKey>.Default
```

A custom equality comparer can be supplied.

**Syntax:**

```csharp
outer.Join(
    inner,
    outerKeySelector,
    innerKeySelector,
    resultSelector,
    comparer
);
```

**Example: Case-insensitive join**

```csharp
string[] outer = { "IT", "HR" };
string[] inner = { "it", "hr" };

var result = outer.Join(
    inner,
    x => x,
    y => y,
    (x, y) => $"{x}: {y}",
    StringComparer.OrdinalIgnoreCase
);

foreach (var item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
IT: it
HR: hr
```

**Key point:** The comparer determines whether two join keys are considered equal.

---

### 9. Matching Keys

A matching key exists in both sequences.

For an inner join, only matching pairs appear in the result.

**Example:**

```csharp
int[] outer = { 1, 2, 3, 4 };
int[] inner = { 2, 4, 6 };

var result = outer.Join(
    inner,
    x => x,
    y => y,
    (x, y) => x
);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
2, 4
```

**Explanation:**

```text
Outer       Inner       Match
  1           —          No
  2           2          Yes
  3           —          No
  4           4          Yes
```

**Key point:** An inner join includes only elements with matching keys.

---

### 10. Missing Keys

A missing key has no corresponding match in the other sequence.

**Example:**

```csharp
int[] outer = { 1, 2, 3, 4 };
int[] inner = { 2, 3 };

var result = outer.Join(
    inner,
    x => x,
    y => y,
    (x, y) => x
);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
2, 3
```

Keys `1` and `4` have no matches.

**Example: All keys missing**

```csharp
int[] outer = { 1, 2 };
int[] inner = { 3, 4 };

var result = outer.Join(
    inner,
    x => x,
    y => y,
    (x, y) => x
);

Console.WriteLine(result.Count());
```

**Output:**

```text
0
```

**Key point:** Missing keys do not produce result pairs in an inner join.

---

### 11. Duplicate Keys

A join supports duplicate keys.

When a key occurs multiple times in either sequence, each matching combination appears.

**Example:**

```csharp
int[] outer = { 1, 1, 2 };
int[] inner = { 1, 1, 2 };

var result = outer.Join(
    inner,
    x => x,
    y => y,
    (x, y) => $"{x}-{y}"
);

foreach (var item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
1-1
1-1
1-1
1-1
2-2
```

The key `1` occurs twice in each sequence.

Therefore:

\[
2 \times 2 = 4
\]

Four matching pairs are produced for key `1`.

**Key point:** Duplicate keys can multiply join results.

### 12. One-to-One Relationships

A one-to-one relationship means one record corresponds to at most one record in the other sequence.

**Example:**

```csharp
record Employee(int Id, string Name);
record Badge(int EmployeeId, string Code);

Employee[] employees =
{
    new(1, "Amit"),
    new(2, "Rahul")
};

Badge[] badges =
{
    new(1, "B101"),
    new(2, "B102")
};

var result = employees.Join(
    badges,
    e => e.Id,
    b => b.EmployeeId,
    (e, b) => $"{e.Name}: {b.Code}"
);

foreach (var item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
Amit: B101
Rahul: B102
```

**Relationship:**

```text
Employee 1 ─── Badge B101
Employee 2 ─── Badge B102
```

**Key point:** One-to-one relationships associate each record with at most one corresponding record.

---

### 13. One-to-Many Relationships

A one-to-many relationship means one record can correspond to several records in another sequence.

**Example:**

```csharp
record Department(int Id, string Name);
record Employee(string Name, int DepartmentId);

Department[] departments =
{
    new(1, "IT"),
    new(2, "HR")
};

Employee[] employees =
{
    new("Amit", 1),
    new("Priya", 1),
    new("Rahul", 2)
};

var result = departments.Join(
    employees,
    d => d.Id,
    e => e.DepartmentId,
    (d, e) => $"{d.Name}: {e.Name}"
);

foreach (var item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
IT: Amit
IT: Priya
HR: Rahul
```

**Relationship:**

```text
IT ──┬── Amit
     └── Priya

HR ───── Rahul
```

**Key point:** One key can match multiple records.

---

### 14. Many-to-Many Relationships

A many-to-many relationship means multiple records on one side can be associated with multiple records on the other side.

It is commonly represented using a linking sequence.

**Example: Students and courses**

```csharp
record Student(int Id, string Name);
record Course(int Id, string Name);
record Enrollment(int StudentId, int CourseId);

Student[] students =
{
    new(1, "Amit"),
    new(2, "Rahul")
};

Course[] courses =
{
    new(10, "C#"),
    new(20, "Java")
};

Enrollment[] enrollments =
{
    new(1, 10),
    new(1, 20),
    new(2, 10)
};

var result = enrollments
    .Join(
        students,
        e => e.StudentId,
        s => s.Id,
        (e, s) => new
        {
            e.CourseId,
            StudentName = s.Name
        }
    )
    .Join(
        courses,
        x => x.CourseId,
        c => c.Id,
        (x, c) => new
        {
            Student = x.StudentName,
            Course = c.Name
        }
    );

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.Student}: {item.Course}"
    );
}
```

**Output:**

```text
Amit: C#
Amit: Java
Rahul: C#
```

**Relationship:**

```text
Amit  ─── C#
   └────── Java

Rahul ─── C#
```

**Key point:** Many-to-many relationships can be represented through a linking collection.

### 15. Join Cardinality

Join cardinality describes how many records on one side can match records on the other side.

Common relationship cardinalities are:

| Cardinality | Description |
|---|---|
| One-to-one | One record matches at most one record |
| One-to-many | One record can match multiple records |
| Many-to-one | Multiple records can match one record |
| Many-to-many | Multiple records can match multiple records |

**Example:**

```csharp
int[] outer = { 1, 1, 2 };
int[] inner = { 1, 2, 2 };

var result = outer.Join(
    inner,
    x => x,
    y => y,
    (x, y) => x
);

Console.WriteLine(result.Count());
```

**Output:**

```text
4
```

**Explanation:**

```text
Key 1:
Outer occurrences = 2
Inner occurrences = 1
Matches = 2

Key 2:
Outer occurrences = 1
Inner occurrences = 2
Matches = 2
```

Total:

\[
2 + 2 = 4
\]

**Key point:** Cardinality determines how many matching pairs a join can produce.

---

### 16. Result Cardinality

Result cardinality is the total number of elements produced by a join.

For an inner join:

\[
\text{Result Count}
=
\sum_{k}
\left(
\text{OuterCount}(k)
\times
\text{InnerCount}(k)
\right)
\]

The sum includes keys present in both sequences.

**Example 1: Unique keys**

```csharp
int[] outer = { 1, 2, 3 };
int[] inner = { 2, 3, 4 };

var result = outer.Join(
    inner,
    x => x,
    y => y,
    (x, y) => x
);

Console.WriteLine(result.Count());
```

**Output:**

```text
2
```

**Example 2: Duplicate keys**

```csharp
int[] outer = { 1, 1, 1 };
int[] inner = { 1, 1 };

var result = outer.Join(
    inner,
    x => x,
    y => y,
    (x, y) => x
);

Console.WriteLine(result.Count());
```

**Output:**

```text
6
```

Because:

\[
3 \times 2 = 6
\]

**Example 3: No matching keys**

```csharp
int[] outer = { 1, 2 };
int[] inner = { 3, 4 };

Console.WriteLine(
    outer.Join(
        inner,
        x => x,
        y => y,
        (x, y) => x
    ).Count()
);
```

**Output:**

```text
0
```

**Key point:** The number of joined results depends on matching-key frequencies, not simply the sizes of the two sequences.

### 17. In-Memory Joins

In-memory joins operate on collections such as arrays, lists, and other `IEnumerable<T>` sequences.

LINQ to Objects executes these joins within the .NET application.

**Example:**

```csharp
List<int> outer = new()
{
    1, 2, 3
};

List<int> inner = new()
{
    2, 3, 4
};

var result = outer.Join(
    inner,
    x => x,
    y => y,
    (x, y) => x
);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
2, 3
```

For LINQ to Objects, `Join()` typically uses a hash-based lookup of the inner sequence.

**Typical complexity:**

\[
O(n+m+r)
\]

Where:

- \(n\) = outer-source elements
- \(m\) = inner-source elements
- \(r\) = result pairs produced

This is an average-case estimate assuming efficient hashing and equality comparisons.

**Key point:** In-memory joins execute within the application and operate on local sequences.

---

### 18. Provider-Translated Joins

Provider-translated joins operate on query providers such as Entity Framework Core.

Instead of performing the entire join in memory, the provider can translate a LINQ join into a database query.

**Example: Entity Framework Core**

Assume `db.Employees` and `db.Departments` are database-backed `DbSet` properties.

```csharp
var query = db.Employees.Join(
    db.Departments,
    e => e.DepartmentId,
    d => d.Id,
    (e, d) => new
    {
        EmployeeName = e.Name,
        DepartmentName = d.Name
    }
);

var result = await query.ToListAsync();
```

A relational provider can translate this into SQL similar to:

```sql
SELECT
    e.Name AS EmployeeName,
    d.Name AS DepartmentName
FROM Employees AS e
INNER JOIN Departments AS d
    ON e.DepartmentId = d.Id;
```

### IQueryable execution

```csharp
IQueryable<Employee> employees = db.Employees;
IQueryable<Department> departments = db.Departments;
```

The query provider processes the expression and determines how it will execute.

### In-memory vs provider-translated joins

| Feature | In-Memory Join | Provider-Translated Join |
|---|---|---|
| Typical source | `IEnumerable<T>` | `IQueryable<T>` |
| Execution location | .NET application | Often database server |
| Query representation | Delegates | Expression trees |
| Join processing | LINQ to Objects | Query provider |
| SQL translation | No | Possible |
| Performance depends on | Collection size and hashing | Database indexes, query plan, provider |

Not every LINQ expression can be translated by every query provider.

**Key point:** Provider-translated joins allow supported LINQ operations to execute through an external query system such as a relational database.
