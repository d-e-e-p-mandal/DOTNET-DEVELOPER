Equality determines whether two values are considered the same.

LINQ uses equality comparisons in operations such as:

```csharp
Distinct()

Intersect()
```

## 1. Equality Fundamentals

Equality determines whether two objects or values should be treated as equivalent.

In C#, two important forms of equality are:

- **Reference equality:** Two references point to the same object.
- **Value equality:** Two values are considered equal according to their contents or equality rules.

### Example 1: Integer equality

```csharp
int a = 10;
int b = 10;

Console.WriteLine(a == b);
Console.WriteLine(a.Equals(b));
```

**Output:**

```text
True
True
```

Both integers contain the same value.

### Example 2: Object equality

```csharp
class Student
{
    public int Id { get; set; }
}

Student s1 = new Student { Id = 1 };
Student s2 = new Student { Id = 1 };

Console.WriteLine(s1 == s2);
Console.WriteLine(s1.Equals(s2));
```

**Output:**

```text
False
False
```

Although both objects contain the same `Id`, they are separate instances.

The class does not override the default equality behavior.

### Example 3: Equality in LINQ

```csharp
int[] numbers = { 10, 20, 10, 30, 20 };

var result = numbers.Distinct();

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
10, 20, 30
```

`Distinct()` uses equality to identify repeated values.

**Key point:** LINQ equality behavior depends on the equality rules of the element or key type.

## 3. IEquatable<T>

`IEquatable<T>` allows a type to define strongly typed equality.

### Interface

```csharp
public interface IEquatable<T>
{
    bool Equals(T? other);
}
```

### Example: Student equality by ID

```csharp
class Student : IEquatable<Student>
{
    public int Id { get; set; }
    public string Name { get; set; } = "";

    public bool Equals(Student? other)
    {
        return other is not null &&
               Id == other.Id;
    }

    public override bool Equals(object? obj)
    {
        return obj is Student other &&
               Equals(other);
    }

    public override int GetHashCode()
    {
        return Id.GetHashCode();
    }
}
```

### Using LINQ

```csharp
Student[] students =
{
    new Student { Id = 1, Name = "Amit" },
    new Student { Id = 2, Name = "Rahul" },
    new Student { Id = 1, Name = "Amit Kumar" }
};

var result = students.Distinct();

foreach (var student in result)
{
    Console.WriteLine(
        $"{student.Id}: {student.Name}"
    );
}
```

**Output:**

```text
1: Amit
2: Rahul
```

The third student is considered equal to the first because their IDs match.

### Important rules

When implementing `IEquatable<T>`:

1. Implement `Equals(T?)`.
2. Override `Equals(object?)`.
3. Override `GetHashCode()`.
4. Ensure equality and hash codes remain consistent.

**Key point:** `IEquatable<T>` defines equality as part of a type's behavior.

## 4. IEqualityComparer<T>

`IEqualityComparer<T>` defines equality externally without changing the compared type.

### Interface

```csharp
public interface IEqualityComparer<T>
{
    bool Equals(T? x, T? y);

    int GetHashCode(T obj);
}
```

### Example: Student comparer

```csharp
record Student(int Id, string Name);

class StudentIdComparer : IEqualityComparer<Student>
{
    public bool Equals(Student? x, Student? y)
    {
        if (ReferenceEquals(x, y))
            return true;

        if (x is null || y is null)
            return false;

        return x.Id == y.Id;
    }

    public int GetHashCode(Student obj)
    {
        return obj.Id.GetHashCode();
    }
}
```

### Using Distinct

```csharp
Student[] students =
{
    new(1, "Amit"),
    new(2, "Rahul"),
    new(1, "Amit Kumar")
};

var result = students.Distinct(
    new StudentIdComparer()
);

foreach (var student in result)
{
    Console.WriteLine(
        $"{student.Id}: {student.Name}"
    );
}
```

**Output:**

```text
1: Amit
2: Rahul
```

### IEquatable<T> vs IEqualityComparer<T>

| Feature | IEquatable<T> | IEqualityComparer<T> |
|---|---|---|
| Equality location | Inside the type | Separate comparer |
| Main method | `Equals(T)` | `Equals(T, T)` |
| Hash code | Override `GetHashCode()` | Implement `GetHashCode(T)` |
| Multiple equality rules | Requires additional design | Easy to create multiple comparers |
| LINQ usage | Default equality | Explicit comparer argument |

**Key point:** `IEqualityComparer<T>` is useful when an operation needs custom equality rules.

## 6. GetHashCode

`GetHashCode()` produces an integer hash code for an object or value.

Hash-based collections use hash codes to organize values efficiently.

### Syntax

```csharp
value.GetHashCode();
```

### Example 1: Hash codes

```csharp
int a = 10;
int b = 10;

Console.WriteLine(
    a.GetHashCode() == b.GetHashCode()
);
```

**Output:**

```text
True
```

### Example 2: Custom hash code

```csharp
class Student
{

    public override bool Equals(object? obj)
    {
        return obj is Student other &&
               Id == other.Id;
    }

    public override int GetHashCode()
    {
        return Id.GetHashCode();
    }
}
```

### Example 3: HashCode.Combine


```text

```

**Key point:** Equal values must produce equal hash codes, but different values may produce the same hash code.

## 7. Equals/GetHashCode Contract

`Equals()` and `GetHashCode()` must follow consistent rules.

### Rule 1: Equal objects must have equal hash codes

If:

```csharp
a.Equals(b) == true
```

Then:

```csharp
a.GetHashCode() == b.GetHashCode()
```

must also be true.

### Rule 2: Equal hash codes do not guarantee equality

```csharp
a.GetHashCode() == b.GetHashCode()
```

does not necessarily mean:

```csharp
a.Equals(b) == true
```

Hash collisions are possible.

### Rule 3: Equality should be reflexive

```csharp
a.Equals(a)
```

must be `true` for non-null values following the usual equality contract.

### Rule 4: Equality should be symmetric

If:

```csharp
a.Equals(b)
```

is `true`, then:

```csharp
b.Equals(a)
```

must also be `true`.

### Rule 5: Equality should be transitive

If:

```text
A equals B
B equals C
```

then:

```text
A equals C
```

### Example: Correct implementation

```csharp
class Product : IEquatable<Product>
{
    public int Id { get; set; }

    public bool Equals(Product? other)
    {
        return other is not null &&
               Id == other.Id;
    }

    public override bool Equals(object? obj)
    {
        return obj is Product other &&
               Equals(other);
    }

    public override int GetHashCode()
    {
        return Id.GetHashCode();
    }
}
```

```csharp
Product p1 = new() { Id = 10 };
Product p2 = new() { Id = 10 };

Console.WriteLine(p1.Equals(p2));

Console.WriteLine(
    p1.GetHashCode() == p2.GetHashCode()
);
```

**Output:**

```text
True
True
```

**Key point:** Equality and hashing must agree for hash-based LINQ operations to work correctly.

## 8. Reference Identity

Reference identity determines whether two references point to the exact same object.

### Syntax

```csharp
ReferenceEquals(a, b)
```

### Example 1: Same reference

```csharp
class Student
{
    public int Id { get; set; }
}

Student s1 = new() { Id = 1 };
Student s2 = s1;

Console.WriteLine(
    ReferenceEquals(s1, s2)
);
```

**Output:**

```text
True
```

### Example 2: Different references

```csharp
Student s1 = new() { Id = 1 };
Student s2 = new() { Id = 1 };

Console.WriteLine(
    ReferenceEquals(s1, s2)
);
```

**Output:**

```text
False
```

### Example 3: Reference equality in Distinct

```csharp
Student s1 = new() { Id = 1 };
Student s2 = new() { Id = 1 };

Student[] students =
{
    s1,
    s2,
    s1
};

var result = students.Distinct();

Console.WriteLine(result.Count());
```

**Output:**

```text
2
```

Because the class does not override equality, `Distinct()` uses reference-based equality.

**Key point:** Reference identity compares object instances rather than their contents.

## 10. Records and Value Equality

C# records provide built-in value-based equality.

### Example 1: Record equality

```csharp
record Employee(int Id, string Name);

Employee e1 = new(1, "Amit");
Employee e2 = new(1, "Amit");

Console.WriteLine(e1 == e2);
Console.WriteLine(e1.Equals(e2));
```

**Output:**

```text
True
True
```

### Example 2: Records with Distinct

```csharp
record Student(int Id, string Name);

Student[] students =
{
    new(1, "Amit"),
    new(1, "Amit"),
    new(2, "Rahul")
};

var result = students.Distinct();

foreach (var student in result)
{
    Console.WriteLine(student.Name);
}
```

**Output:**

```text
Amit
Rahul
```

### Example 3: Records as join keys

```csharp
record Key(int DepartmentId, int Year);

record Employee(
    string Name,
    Key DepartmentKey
);

record Department(
    Key DepartmentKey,
    string Name
);

Employee[] employees =
{
    new("Amit", new Key(1, 2026)),
    new("Rahul", new Key(2, 2026))
};

Department[] departments =
{
    new(new Key(1, 2026), "IT"),
    new(new Key(2, 2026), "HR")
};

var result = employees.Join(
    departments,
    e => e.DepartmentKey,
    d => d.DepartmentKey,
    (e, d) => $"{e.Name}: {d.Name}"
);

foreach (var item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
Amit: IT
Rahul: HR
```

**Important:** Record equality is based on the equality of their components. A record containing an array does not automatically compare array contents element by element.

**Key point:** Records are convenient for defining immutable, value-based LINQ keys.

## 16. Culture-Aware Comparisons

Culture-aware comparisons use linguistic rules associated with a particular culture.

Common comparers include:

```csharp
StringComparer.CurrentCulture
StringComparer.CurrentCultureIgnoreCase

StringComparer.InvariantCulture
StringComparer.InvariantCultureIgnoreCase
```

### Example 1: Culture-aware equality

```csharp

var culture = CultureInfo.GetCultureInfo("en-US");

var comparer = StringComparer.Create(
    culture,
    ignoreCase: true
);

Console.WriteLine(
    comparer.Equals("hello", "HELLO")
);
```

**Output:**

```text
True
```

### Example 2: Culture-aware Distinct

```csharp
using System.Globalization;

string[] words =
{
    "Apple",
    "apple",
    "Banana"
};

var comparer = StringComparer.Create(
    CultureInfo.GetCultureInfo("en-US"),
    ignoreCase: true
);

var result = words.Distinct(comparer);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
Apple, Banana
```

### Example 3: Culture-aware GroupBy

```csharp
using System.Globalization;

string[] names =
{
    "Amit",
    "amit",
    "Rahul"
};

var comparer = StringComparer.Create(
    CultureInfo.GetCultureInfo("en-US"),
    ignoreCase: true
);

var result = names.GroupBy(
    x => x,
    comparer
);

foreach (var group in result)
{
    Console.WriteLine(
        $"{group.Key}: {group.Count()}"
    );
}
```

**Output:**

```text
Amit: 2
Rahul: 1
```

### Comparison

| Comparer | Culture-Aware | Case-Sensitive |
|---|---|---|
| `Ordinal` | No | Yes |
| `OrdinalIgnoreCase` | No | No |
| `CurrentCulture` | Yes | Yes |
| `CurrentCultureIgnoreCase` | Yes | No |
| `InvariantCulture` | Yes, invariant rules | Yes |
| `InvariantCultureIgnoreCase` | Yes, invariant rules | No |

**Key point:** Culture-aware equality is appropriate when linguistic comparison rules are required.

## 18. Custom Comparers

Custom comparers allow different equality rules for the same data.

### Example 1: Product equality by category

```csharp
record Product(
    int Id,
    string Name,
    string Category
);

class CategoryComparer : IEqualityComparer<Product>
{
    public bool Equals(Product? x, Product? y)
    {
        if (ReferenceEquals(x, y))
            return true;

        if (x is null || y is null)
            return false;

        return StringComparer.OrdinalIgnoreCase.Equals(
            x.Category,
            y.Category
        );
    }

    public int GetHashCode(Product obj)
    {
        return StringComparer.OrdinalIgnoreCase.GetHashCode(
            obj.Category
        );
    }
}
```

### Using Distinct

```csharp
Product[] products =
{
    new(1, "Mouse", "Electronics"),
    new(2, "Keyboard", "Electronics"),
    new(3, "Chair", "Furniture")
};

var result = products.Distinct(
    new CategoryComparer()
);

foreach (var product in result)
{
    Console.WriteLine(product.Name);
}
```

**Output:**

```text
Mouse
Chair
```

### Example 2: Custom comparer with GroupBy

```csharp
var result = products.GroupBy(
    p => p,
    new CategoryComparer()
);

foreach (var group in result)
{
    Console.WriteLine(
        $"{group.Key.Category}: {group.Count()}"
    );
}
```

**Output:**

```text
Electronics: 2
Furniture: 1
```

**Key point:** Custom comparers allow LINQ operations to use domain-specific equality rules.

## 19. Hash-Based Operations

Many LINQ operations use hash-based data structures internally.

Examples include:

```csharp
Distinct()
Union()
Intersect()
Except()
GroupBy()
Join()
GroupJoin()
ToLookup()
```

### Example 1: Distinct

```csharp
int[] numbers =
{
    1, 2, 2, 3, 3, 3
};

var result = numbers.Distinct();

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
1, 2, 3
```

### Example 2: GroupBy

```csharp
string[] words =
{
    "Apple",
    "Ant",
    "Banana",
    "Ball"
};

var result = words.GroupBy(
    word => word[0]
);

foreach (var group in result)
{
    Console.WriteLine(
        $"{group.Key}: {group.Count()}"
    );
}
```

**Output:**

```text
A: 2
B: 2
```

### Example 3: Join

```csharp
int[] first = { 1, 2, 3 };
int[] second = { 2, 3, 4 };

var result = first.Join(
    second,
    x => x,
    y => y,
    (x, y) => x
);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
2, 3
```

### Hash-based operation complexity

For efficient hash functions and equality comparers, typical average-case behavior is:

| Operation | Typical Complexity |
|---|---|
| `Distinct()` | \(O(n)\) |
| `GroupBy()` | \(O(n)\) |
| `ToLookup()` | \(O(n)\) |
| `Join()` | \(O(n+m+r)\) |
| `Union()` | \(O(n+m)\) |
| `Intersect()` | \(O(n+m)\) |
| `Except()` | \(O(n+m)\) |

Where:

- \(n\) = first sequence size
- \(m\) = second sequence size
- \(r\) = number of join result pairs

These are typical average-case estimates, not worst-case guarantees.

**Key point:** Correct equality and hashing are essential for efficient hash-based LINQ operations.

## 20. Mutable-Key Risks

A mutable key is a key whose value can change after it has been used in an equality-based collection.

Changing a key after insertion into a hash-based collection can cause incorrect lookup behavior.

### Example 1: Mutable object key

```csharp
class Student
{
    public int Id { get; set; }
}
```

```csharp
Student student = new()
{
    Id = 1
};

student.Id = 2;

Console.WriteLine(student.Id);
```

**Output:**

```text
2
```

Changing a property is allowed, but it becomes dangerous when that property participates in hashing.

### Example 2: HashSet with mutable equality

```csharp
class Student : IEquatable<Student>
{
    public int Id { get; set; }

    public bool Equals(Student? other)
    {
        return other is not null &&
               Id == other.Id;
    }

    public override bool Equals(object? obj)
    {
        return obj is Student other &&
               Equals(other);
    }

    public override int GetHashCode()
    {
        return Id.GetHashCode();
    }
}
```

```csharp
Student student = new()
{
    Id = 1
};

HashSet<Student> students = new();

students.Add(student);

Console.WriteLine(students.Contains(student));

student.Id = 2;

Console.WriteLine(students.Contains(student));
```

**Typical output:**

```text
True
False
```

The lookup may fail because the object's hash code changed after insertion.

### Example 3: Immutable record key

```csharp
record StudentKey(int Id);

StudentKey key = new(1);

HashSet<StudentKey> keys = new()
{
    key
};

Console.WriteLine(keys.Contains(new StudentKey(1)));
```

**Output:**

```text
True
```

### Example 4: Record with init-only properties

```csharp
record EmployeeKey
{
    public int EmployeeId { get; init; }
    public int Year { get; init; }
}
```

```csharp
EmployeeKey key = new()
{
    EmployeeId = 1,
    Year = 2026
};

Console.WriteLine(key.EmployeeId);
```

**Output:**

```text
1
```

The properties cannot be reassigned after initialization through ordinary property assignment.

### Recommended practices

1. Prefer immutable equality keys.
2. Do not modify equality-relevant properties while an object is stored in a hash-based collection.
3. Keep `Equals()` and `GetHashCode()` consistent.
4. Use immutable records, tuples, or appropriately designed structs for composite keys.
5. If a key must change, remove the item from the hash-based collection before modifying it, then reinsert it.

**Key point:** Equality keys should remain stable while participating in hash-based operations.
