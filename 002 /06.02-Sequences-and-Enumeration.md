# 06.02 Sequences and Enumeration

## IEnumerable and IEnumerable<T>

- `IEnumerable<T>` exposes a typed sequence.
- The older non-generic `IEnumerable` exposes elements as objects and may require casts or boxing.

```csharp
IEnumerable<int> values = new[] { 10, 20 };
foreach (int value in values) Console.WriteLine(value); // 10, 20
```

An enumerable contract does not promise indexing, a cheap count, materialized storage, or safe repeated use.

## IEnumerator and IEnumerator<T>

An enumerator stores traversal state. Advance with `MoveNext` before reading `Current`.

```csharp
IEnumerable<string> names = new[] { "Deep", "Mira" };
using IEnumerator<string> iterator = names.GetEnumerator();
while (iterator.MoveNext())
    Console.WriteLine(iterator.Current); // Deep, Mira
```

- Do not depend on `Reset`; many enumerators do not support it.
- Requesting another enumerator is the usual way to begin a new traversal when the source supports repetition.

### The enumerator state transition

```csharp
IEnumerable<int> values = new[] { 10, 20 };
using var iterator = values.GetEnumerator();
Console.WriteLine(iterator.MoveNext()); // True
Console.WriteLine(iterator.Current);    // 10
Console.WriteLine(iterator.MoveNext()); // True
Console.WriteLine(iterator.Current);    // 20
Console.WriteLine(iterator.MoveNext()); // False
```

- `Current` does not advance the position.
- Two reads of Current after one successful MoveNext observe the same current element.
- After MoveNext returns false, the traversal is finished; do not use Current as though another element exists.

## foreach and custom sources

```csharp
foreach (int value in Squares(3)) Console.WriteLine(value); // 1, 4, 9

IEnumerable<int> Squares(int count)
{
    for (int i = 1; i <= count; i++) yield return i * i;
}
```

- Arrays and lists are stored sources; an iterator can generate elements during traversal.
- `foreach` manages the enumerator and appropriate disposal.

## Finite, empty, and infinite sequences

```csharp
Console.WriteLine(Enumerable.Empty<int>().Any()); // False
Console.WriteLine(string.Join(", ", RepeatForever(7).Take(3))); // 7, 7, 7

IEnumerable<int> RepeatForever(int value)
{
    while (true) yield return value;
}
```

- An empty sequence is a valid sequence with no elements.
- Materializing an unbounded sequence with `ToList` or counting it to completion will not finish normally.

## Reusable versus single-pass sources

- Arrays and lists can normally be re-enumerated.
- A stream, cursor, or custom source may expose data only once or perform new work on each traversal.
- Do not call `Count()` and then enumerate merely to learn whether a sequence has items.

### Re-enumeration repeats work

```csharp
var query = GetValues();
Console.WriteLine(query.Sum()); // Start, then 3.
Console.WriteLine(query.Sum()); // Start again, then 3.

IEnumerable<int> GetValues()
{
    Console.WriteLine("Start");
    yield return 1;
    yield return 2;
}
```

- This source is repeatable, but each traversal performs the body again.
- Other sources may read changing files or remote data, making both cost and results different.

## State, disposal, and mutation

- Each enumerator generally has its own position, but the underlying source may still be shared.
- Structural mutation of a list during enumeration normally invalidates its enumerator.
- Changing a referenced element's property is a different operation and may still affect query results.

- Use a snapshot when you need stable membership, and arrange proper resource disposal for manually driven enumerators.
- A snapshot of object references is still not a deep copy of their state.

### Early exit still disposes an iterator

```csharp
foreach (int value in Read().Take(1))
    Console.WriteLine(value);

IEnumerable<int> Read()
{
    Console.WriteLine("Opened");
    try
    {
        yield return 10;
        yield return 20;
    }
    finally
    {
        Console.WriteLine("Closed");
    }
}
```

Output:

```text
Opened
10
Closed
```

- Take stops after one element, and disposal unwinds the active iterator.
- A manually obtained enumerator that is never disposed does not receive this same timely cleanup guarantee.

### Materializing before changing membership

```csharp
var values = new List<int> { 1, 2, 3 };
foreach (int value in values.ToArray())
    if (value % 2 == 1) values.Remove(value);
Console.WriteLine(string.Join(", ", values)); // 2
```

- Enumeration uses the array snapshot while the list changes.
- This is different from enumerating the original list and removing from it inside that enumeration.

## LINQ architecture

```text
Data source
  → source sequence
  → query operators
  → query pipeline
  → enumeration or terminal operation
  → result sequence or scalar result
```

```csharp
int[] source = [5, 2, 8, 1];

IEnumerable<int> query = source                 // Source sequence
    .Where(value => value > 2)                  // Intermediate filter
    .OrderBy(value => value);                   // Intermediate ordering

int[] result = query.ToArray();                 // Terminal materialization
Console.WriteLine(string.Join(", ", result)); // 5, 8
```

## Data source and source sequence

```csharp
List<string> dataSource = ["red", "blue", "green"];
IEnumerable<string> sourceSequence = dataSource;
```

- The data source is the actual object or provider.
- The source sequence is the sequence view consumed by LINQ.
- A source can be an array, list, set, dictionary, iterator, XML tree, or provider query.

## Query and query operators

```csharp
IEnumerable<string> query = sourceSequence
    .Where(color => color.Length > 3)
    .Select(color => color.ToUpperInvariant());
```

- Query: the composed operations.
- Query operator: `Where`, `Select`, `OrderBy`, `GroupBy`, `Join`, and similar methods.
- Intermediate operators usually return another sequence.
- Terminal operators return a value or materialize a collection.

## Query pipeline

```csharp
var pipeline = new[] { 1, 2, 3, 4, 5 }
    .Where(value => value % 2 != 0)
    .Select(value => value * 10)
    .Take(2);

Console.WriteLine(string.Join(", ", pipeline)); // 10, 30
```

Read the pipeline from left to right: filter odd values, multiply, then keep two.

## Intermediate and terminal operations

```csharp
int[] values = [1, 2, 3, 4];

IEnumerable<int> intermediate = values
    .Where(value => value > 1)
    .Select(value => value * 2);

List<int> terminal = intermediate.ToList();
Console.WriteLine(string.Join(", ", terminal)); // 4, 6, 8
```

Common terminal operations include `ToList`, `ToArray`, `Count`, `Any`, `First`, `Single`, `Sum`, and `foreach` enumeration.

## Result sequence versus scalar result

```csharp
var sequence = values.Where(value => value > 2); // IEnumerable<int>
int scalar = sequence.Count();                   // int
Console.WriteLine(string.Join(", ", sequence)); // 3, 4
Console.WriteLine(scalar);                       // 2
```

Do not use a scalar result as if it were another sequence.

## LINQ terminology: element and range variable

```csharp
var query = values.Where(number => number > 2);
```

- Element: one value from the sequence, such as `3`.
- Range variable: `number`, the name used for the current element in query/lambda syntax.

## Query expression

```csharp
var query = from number in values
            where number > 2
            select number * 10;
```

`from`, `where`, and `select` form a query expression. The compiler translates supported clauses to standard query operators.

## Predicate

A predicate returns `bool` and decides whether an element remains.

```csharp
var positive = values.Where(number => number > 0);
```

Type shape:

```csharp
Func<int, bool> predicate = number => number > 0;
```

## Selector

A selector maps one element to another value.

```csharp
var labels = values.Select(number => $"N{number}");
```

Type shape:

```csharp
Func<int, string> selector = number => $"N{number}";
```

## Key selector

A key selector chooses the value used for ordering, grouping, or joining.

```csharp
var ordered = people.OrderBy(person => person.Age);
var grouped = people.GroupBy(person => person.Age);
```

`person => person.Age` is the key selector in both examples.

## Element selector

An element selector chooses what each group stores.

```csharp
var namesByAge = people.GroupBy(
    person => person.Age,
    person => person.Name);
```

Each grouping key is an age, and each grouping element is a name.

## Collection selector

A collection selector maps one element to another sequence.

```csharp
var groups = new[]
{
    new[] { 1, 2 },
    new[] { 3, 4 }
};

var flattened = groups.SelectMany(group => group);
Console.WriteLine(string.Join(", ", flattened)); // 1, 2, 3, 4
```

`group => group` is the collection selector.

## Result selector

A result selector combines values from two inputs or a group key and its elements.

```csharp
var report = people.GroupBy(person => person.Age)
    .Select(group => new { Age = group.Key, Count = group.Count() });

foreach (var row in report)
    Console.WriteLine($"{row.Age}: {row.Count}");
```

Join result selectors can combine the outer and inner elements into one result object.

## Accumulator

An accumulator carries a running result through an aggregation.

```csharp
int total = values.Aggregate(0, (current, value) => current + value);
Console.WriteLine(total); // 10
```

`current` is the accumulator; `value` is the current element.

## Comparer and equality comparer

```csharp
var names = new[] { "mira", "Deep", "SAM" };
var ordered = names.OrderBy(name => name, StringComparer.OrdinalIgnoreCase);
var unique = names.Distinct(StringComparer.OrdinalIgnoreCase);

Console.WriteLine(string.Join(", ", ordered)); // Deep, mira, SAM (ordinal order)
Console.WriteLine(string.Join(", ", unique));  // mira, Deep, SAM
```

- A comparer orders values.
- An equality comparer decides whether values are equal.
- Pass a comparer when default equality or culture behavior is not suitable.

## Query provider

```csharp
IQueryable<Product> query = db.Products.Where(product => product.Price > 100);
```

A query provider receives expression trees and decides how to execute them. A database provider can translate supported expressions into SQL.

```csharp
IQueryable<int> ids = db.Products
    .Where(product => product.IsActive)
    .Select(product => product.Id);

int[] result = await ids.ToArrayAsync(); // Provider execution
```

## Enumeration

Enumeration asks a sequence for its elements one at a time.

```csharp
foreach (int value in values)
    Console.WriteLine(value);
```

`foreach`, `ToList`, `Count`, `Any`, and most result-consuming operations enumerate the source.

## Materialization

Materialization executes a query and stores the result in a collection.

```csharp
List<int> snapshot = values.Where(value => value > 1).ToList();
int[] arraySnapshot = values.Where(value => value > 1).ToArray();
```

The stored result does not rerun the original query when read.

## Deferred and immediate execution

```csharp
var source = new List<int> { 1, 2 };
var deferred = source.Where(value => value > 1);
var immediate = source.Where(value => value > 1).ToList();

source.Add(3);
Console.WriteLine(string.Join(", ", deferred));  // 2, 3
Console.WriteLine(string.Join(", ", immediate)); // 2
```

- Deferred: operations run during enumeration.
- Immediate: a terminal operation runs now and stores or returns the result.

## Streaming

Streaming produces an element before all source elements are stored.

```csharp
foreach (int value in Enumerable.Range(1, 5).Where(value => value % 2 == 1))
    Console.WriteLine(value); // 1, 3, 5
```

`Where`, `Select`, and `Take` commonly stream. They can stop early when the consumer stops.

## Buffering

Buffering reads source data before returning some results.

```csharp
var ordered = values.OrderBy(value => value); // Sort needs source values
Console.WriteLine(string.Join(", ", ordered)); // 1, 2, 3, 4
```

`OrderBy`, `GroupBy`, `ToLookup`, `ToList`, and `ToArray` normally buffer.

## Filtering, projection, and flattening

```csharp
var filtered = values.Where(value => value > 2);
var projected = values.Select(value => value * 10);
var flattened = new[] { new[] { 1, 2 }, new[] { 3 } }
    .SelectMany(group => group);
```

- Filtering changes which elements remain.
- Projection changes each element's shape or type.
- Flattening combines nested sequences into one sequence.

## Ordering, partitioning, grouping, and joining

```csharp
var ordered = values.OrderBy(value => value);
var firstTwo = values.Take(2);
var groups = values.GroupBy(value => value % 2);
var joined = people.Join(people,
    left => left.Age,
    right => right.Age,
    (left, right) => new { left.Name, SameAge = right.Name });
```

- Ordering arranges elements.
- Partitioning selects a portion.
- Grouping creates key-based groupings.
- Joining matches elements by keys.

## Aggregation and quantification

```csharp
int sum = values.Sum();
bool allPositive = values.All(value => value > 0);
bool anyLarge = values.Any(value => value > 3);
```

- Aggregation reduces a sequence to a value: `Sum`, `Count`, `Average`, `Min`, `Max`, `Aggregate`.
- Quantification asks a yes/no question: `Any`, `All`, `Contains`.

## `IEnumerable` and `IEnumerable<T>`

```csharp
IEnumerable<int> typed = new[] { 10, 20 };
IEnumerable untyped = typed;

foreach (object value in untyped)
    Console.WriteLine(value); // 10, 20
```

- `IEnumerable<T>` provides typed enumeration.
- Non-generic `IEnumerable` exposes `object` values.
- Neither interface promises indexing, a cheap count, materialization, or repeatability.

## `IEnumerator` and `IEnumerator<T>`

```csharp
IEnumerable<string> names = ["Deep", "Mira"];
using IEnumerator<string> enumerator = names.GetEnumerator();

while (enumerator.MoveNext())
    Console.WriteLine(enumerator.Current);
```

- `GetEnumerator()` creates traversal state.
- `MoveNext()` advances and returns `true` when an element exists.
- `Current` returns the current element and does not advance.
- `IEnumerator<T>` is the typed form of `IEnumerator`.

## Enumerator state

```csharp
using var enumerator = new[] { 10, 20 }.AsEnumerable().GetEnumerator();
Console.WriteLine(enumerator.MoveNext()); // True
Console.WriteLine(enumerator.Current);    // 10
Console.WriteLine(enumerator.MoveNext()); // True
Console.WriteLine(enumerator.Current);    // 20
Console.WriteLine(enumerator.MoveNext()); // False
```

Do not read `Current` before the first successful `MoveNext` or after it returns `false`.

## `IDisposable` and enumerator lifetime

```csharp
using IEnumerator<int> enumerator = values.AsEnumerable().GetEnumerator();
while (enumerator.MoveNext())
    Console.WriteLine(enumerator.Current);
```

`using` disposes the enumerator. `foreach` emits equivalent disposal logic when the enumerator supports it.

## Arrays and collections as sources

```csharp
int[] array = [1, 2, 3];
List<int> list = [4, 5, 6];
HashSet<int> set = [7, 8, 9];
Dictionary<string, int> dictionary = new() { ["A"] = 1 };

Console.WriteLine(array.Count());
Console.WriteLine(list.Count());
Console.WriteLine(set.Count());
Console.WriteLine(dictionary.Count());
```

Dictionary enumeration produces `KeyValuePair<TKey,TValue>` elements.

## Custom enumerable source with `yield return`

```csharp
foreach (int square in Squares(3))
    Console.WriteLine(square); // 1, 4, 9

static IEnumerable<int> Squares(int count)
{
    for (int number = 1; number <= count; number++)
        yield return number * number;
}
```

The iterator body runs as the caller requests elements, not when the method is called.

## Finite, empty, and potentially infinite sequences

```csharp
Console.WriteLine(Enumerable.Empty<int>().Any()); // False
Console.WriteLine(string.Join(", ", Repeat(7).Take(3))); // 7, 7, 7

static IEnumerable<int> Repeat(int value)
{
    while (true)
        yield return value;
}
```

Never call `ToList`, `ToArray`, `Count`, or an unbounded `foreach` on an infinite sequence without a stopping condition.

## Reusable versus single-pass sources

```csharp
var query = GetValues();
Console.WriteLine(query.Sum()); // Start, then 3
Console.WriteLine(query.Sum()); // Start again, then 3

static IEnumerable<int> GetValues()
{
    Console.WriteLine("Start");
    yield return 1;
    yield return 2;
}
```

An iterator can be enumerated again, but its body runs again. A stream, cursor, or custom source may be single-pass or may produce different data each time.

## Re-enumeration cost

```csharp
var query = Enumerable.Range(1, 1_000_000).Where(value => value % 2 == 0);
int firstCount = query.Count();
int secondCount = query.Count(); // Work runs again
```

Materialize once when repeated use should read a stable result:

```csharp
int[] cached = query.ToArray();
int first = cached.Length;
int second = cached.Length;
```

## Source mutation during enumeration

```csharp
var list = new List<int> { 1, 2, 3 };

try
{
    foreach (int value in list)
        if (value == 2) list.Remove(value);
}
catch (InvalidOperationException)
{
    Console.WriteLine("Collection changed during enumeration");
}
```

Use a snapshot when membership must change during traversal:

```csharp
foreach (int value in list.ToArray())
    if (value == 2) list.Remove(value);
```

Changing a referenced object's property is different from changing the collection structure, but deferred queries can still observe that changed property.

## Early exit and disposal

```csharp
foreach (int value in Read().Take(1))
    Console.WriteLine(value); // 10

static IEnumerable<int> Read()
{
    Console.WriteLine("Opened");
    try
    {
        yield return 10;
        yield return 20;
    }
    finally
    {
        Console.WriteLine("Closed");
    }
}
```

Output:

```text
Opened
10
Closed
```

`Take(1)` stops enumeration and disposal runs the iterator's `finally` block.
