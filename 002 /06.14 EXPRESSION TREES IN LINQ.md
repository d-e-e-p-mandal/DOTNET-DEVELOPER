# 06.14 — EXPRESSION TREES IN LINQ

**Chapter:** 06 — LINQ Fundamentals  
**Namespaces:** `System.Linq.Expressions`, `System.Linq`

Expression trees represent code as a structured collection of objects. Instead of simply executing a lambda expression, an application can **inspect, construct, modify, combine, or compile** its expression tree.

Expression trees are particularly important in LINQ providers such as Entity Framework Core, where a provider analyzes query expressions and translates supported operations into SQL.

This section covers all **17 topics** in your syllabus, with detailed explanations and practical C# examples.

### Common setup

The following examples use these namespaces:

```csharp
using System;
using System.Collections.Generic;
using System.Linq;
using System.Linq.Expressions;
```

Where a `Student` type is needed:

```csharp
public class Student
{
    public string Name { get; set; } = "";
    public int Marks { get; set; }
}
```

---

## 1. `Expression<TDelegate>`

`Expression<TDelegate>` represents a strongly typed lambda expression as an expression tree.

### Syntax

```csharp
Expression<Func<T, TResult>> expression = x => ...;
```

### Example 1: Simple expression

```csharp
Expression<Func<int, int>> expression = x => x * 2;

Console.WriteLine(expression);
```

**Output:**

```text
x => (x * 2)
```

The expression is stored as a tree rather than immediately executed.

### Example 2: Boolean expression

```csharp
Expression<Func<int, bool>> expression = n => n > 10;

Console.WriteLine(expression.Body);
```

**Output:**

```text
(n > 10)
```

### Example 3: Two parameters

```csharp
Expression<Func<int, int, int>> expression =
    (a, b) => a + b;

Console.WriteLine(expression);
```

**Output:**

```text
(a, b) => (a + b)
```

### Example 4: Object property

```csharp
Expression<Func<Student, bool>> expression =
    student => student.Marks >= 80;
```

**Key points:**

- `Expression<TDelegate>` contains a representation of code.
- The generic argument specifies the lambda's delegate signature.
- The expression can be inspected before execution.
- Expression trees can be compiled into delegates.
- Expression-tree lambdas have restrictions; for example, a statement-bodied lambda cannot be directly converted to an expression tree.

---

## 2. Expression Trees vs Delegates

Delegates and expression trees may use identical lambda syntax, but they represent different things.

### Delegate

```csharp
Func<int, int> operation = x => x * 2;
```

This represents executable behavior.

### Expression tree

```csharp
Expression<Func<int, int>> operation = x => x * 2;
```

This represents the structure of the calculation.

### Example: Execute delegate

```csharp
Func<int, int> operation = x => x * 2;

Console.WriteLine(operation(5));
```

**Output:**

```text
10
```

### Example: Inspect expression

```csharp
Expression<Func<int, int>> operation = x => x * 2;

Console.WriteLine(operation.Body.NodeType);
```

**Output:**

```text
Multiply
```

### Comparison

| Feature | Delegate | Expression Tree |
|---|---|---|
| Common type | `Func<T, TResult>` | `Expression<Func<T, TResult>>` |
| Represents | Executable behavior | Code structure |
| Direct invocation | Yes | No |
| Inspection | Limited | Yes |
| Modification through tree construction | No | Yes |
| Compilation required before direct invocation | No | Yes |
| LINQ use | `Enumerable` | `Queryable` |

**Important:** Compiling an expression tree produces a delegate; it does not translate the expression into SQL.

## 3. `LambdaExpression`

`LambdaExpression` is the non-generic base class for lambda expression trees.

It exposes information about a lambda without requiring the exact delegate type at compile time.

### Example 1: Assign expression

```csharp
Expression<Func<int, bool>> expression = n => n > 10;

LambdaExpression lambda = expression;

Console.WriteLine(lambda);
```

**Output:**

```text
n => (n > 10)
```

### Example 2: Inspect return type

```csharp
LambdaExpression lambda =
    (Expression<Func<int, bool>>)(n => n > 10);

Console.WriteLine(lambda.ReturnType);
```

**Output:**

```text
System.Boolean
```

### Example 3: Inspect parameter count

```csharp
LambdaExpression lambda =
    (Expression<Func<int, int, int>>)((a, b) => a + b);

Console.WriteLine(lambda.Parameters.Count);
```

**Output:**

```text
2
```

### Common properties

| Property | Purpose |
|---|---|
| `Body` | Expression representing the lambda body |
| `Parameters` | Lambda parameter collection |
| `ReturnType` | Lambda return type |
| `Type` | Delegate type represented by the lambda |
| `NodeType` | `Lambda` |
| `Name` | Optional lambda name |

## 4. Expression Nodes

An expression tree consists of nodes representing operations, values, parameters, and other program constructs.

### Example

```csharp
Expression<Func<int, int>> expression = x => x + 5;
```

### Tree structure

```text
              Lambda
                │
                ▼
               Add
              /   \
             /     \
        Parameter  Constant
            x          5
```

### Example: Inspect root and body

```csharp
Expression<Func<int, int>> expression = x => x + 5;

Console.WriteLine(expression.NodeType);
Console.WriteLine(expression.Body.NodeType);
```

**Output:**

```text
Lambda
Add
```

### Common node types

| Node Type | Expression Example |
|---|---|
| `Parameter` | `x` |
| `Constant` | `10` |
| `MemberAccess` | `student.Marks` |
| `Call` | `name.StartsWith("A")` |
| `Add` | `a + b` |
| `Multiply` | `a * b` |
| `GreaterThan` | `a > b` |
| `Equal` | `a == b` |
| `Not` | `!condition` |
| `Conditional` | `condition ? a : b` |
| `Lambda` | `x => x + 1` |

Each node can contain references to other nodes, forming a tree.

## 5. `ParameterExpression`

`ParameterExpression` represents a named parameter or variable in an expression tree.

### Syntax

```csharp
ParameterExpression parameter =
    Expression.Parameter(typeof(int), "x");
```

### Example 1: Create a parameter

```csharp
ParameterExpression parameter =
    Expression.Parameter(typeof(int), "number");

Console.WriteLine(parameter.Name);
Console.WriteLine(parameter.Type);
```

**Output:**

```text
number
System.Int32
```

### Example 2: Use parameter in an expression

```csharp
ParameterExpression x =
    Expression.Parameter(typeof(int), "x");

BinaryExpression body = Expression.Add(
    x,
    Expression.Constant(10)
);

Expression<Func<int, int>> lambda =
    Expression.Lambda<Func<int, int>>(body, x);

Console.WriteLine(lambda);
```

**Output:**

```text
x => (x + 10)
```

### Important rule

When constructing a lambda manually, reuse the **same `ParameterExpression` instance** throughout the body and parameter list.

Creating two separate parameter objects with the same name does not make them the same parameter.

`MethodCallExpression` represents a method invocation.

### Example 3: Build a method call

```csharp

    Expression.Parameter(typeof(string), "name");

var method = typeof(string).GetMethod(
```

```csharp
Console.WriteLine(predicate("Rahul"));
```

**Output:**

```text
True
False
```

## 14. Building Expression Trees

Expression trees can be constructed manually using the static methods of the `Expression` class.

This is useful when the structure of a query must be determined at runtime.

### Example 1: Build `x => x + 10`

**Step 1 — Create parameter**

```csharp
ParameterExpression x =
    Expression.Parameter(typeof(int), "x");
```

**Step 2 — Create constant**

```csharp
ConstantExpression ten =
    Expression.Constant(10);
```

**Step 3 — Create operation**

```csharp
BinaryExpression addition =
    Expression.Add(x, ten);
```

**Step 4 — Create lambda**

```csharp
Expression<Func<int, int>> expression =
    Expression.Lambda<Func<int, int>>(
        addition,
        x
    );
```

**Step 5 — Inspect result**

```csharp
Console.WriteLine(expression);
```

**Output:**

```text
x => (x + 10)
```

### Example 2: Build `n => n > 18`

```csharp
ParameterExpression n =
    Expression.Parameter(typeof(int), "n");

BinaryExpression body = Expression.GreaterThan(
    n,
    Expression.Constant(18)
);

Expression<Func<int, bool>> expression =
    Expression.Lambda<Func<int, bool>>(
        body,
        n
    );

Console.WriteLine(expression);
```

**Output:**

```text
n => (n > 18)
```

### Example 3: Dynamic property filter

Suppose the property name and minimum value are supplied at runtime.

```csharp
string propertyName = nameof(Student.Marks);
int minimum = 80;

ParameterExpression student =
    Expression.Parameter(typeof(Student), "student");

MemberExpression property =
    Expression.Property(student, propertyName);

ConstantExpression value =
    Expression.Constant(minimum);

BinaryExpression comparison =
    Expression.GreaterThanOrEqual(property, value);

Expression<Func<Student, bool>> predicate =
    Expression.Lambda<Func<Student, bool>>(
        comparison,
        student
    );
```

This constructs:

```csharp
student => student.Marks >= 80
```

### Apply to LINQ

```csharp
IQueryable<Student> query = students
    .AsQueryable()
    .Where(predicate);
```

Here, `students` is an existing collection of `Student` objects.

### Building process

```text
Parameter
    │
    ▼
Property Access
    │
    ▼
Comparison
    │
    ▼
Lambda Expression
    │
    ▼
LINQ Query
```

**Key point:** Manual expression construction enables runtime-generated queries without building C# source-code strings.

## 15. Inspecting Expression Trees

Expression-tree inspection examines nodes to understand the structure of an expression.

For simple expressions, properties such as `Body`, `Left`, and `Right` are sufficient.

For complex expressions, use `ExpressionVisitor`.

### Example 1: Inspect a comparison

```csharp
Expression<Func<int, bool>> expression =
    n => n > 100;

BinaryExpression body =
    (BinaryExpression)expression.Body;

Console.WriteLine($"Operation: {body.NodeType}");
Console.WriteLine($"Left: {body.Left}");
Console.WriteLine($"Right: {body.Right}");
```

**Output:**

```text
Operation: GreaterThan
Left: n
Right: 100
```

### Example 2: Inspect a method call

```csharp
Expression<Func<string, bool>> expression =
    text => text.Contains("LINQ");

MethodCallExpression call =
    (MethodCallExpression)expression.Body;

Console.WriteLine(call.Method.Name);
Console.WriteLine(call.Arguments[0]);
```

**Output:**

```text
Contains
"LINQ"
```

### Example 3: Custom ExpressionVisitor

`ExpressionVisitor` recursively visits expression nodes.

```csharp
public class NodePrinter : ExpressionVisitor
{
    public override Expression? Visit(Expression? node)
    {
        if (node != null)
        {
            Console.WriteLine(node.NodeType);
        }

        return base.Visit(node);
    }
}
```

### Use the visitor

```csharp
Expression<Func<int, bool>> expression =
    n => n > 10;

NodePrinter visitor = new();

visitor.Visit(expression);
```

**Output:**

```text
Lambda
GreaterThan
Parameter
Constant
Parameter
```

The final `Parameter` comes from visiting the lambda's parameter declaration.

### Example 4: Count expression nodes

```csharp
public class NodeCounter : ExpressionVisitor
{
    public int Count { get; private set; }

    public override Expression? Visit(Expression? node)
    {
        if (node != null)
        {
            Count++;
        }

        return base.Visit(node);
    }
}
```

### Usage

```csharp
Expression<Func<int, int>> expression =
    x => x + 5;

NodeCounter counter = new();

counter.Visit(expression);

Console.WriteLine(counter.Count);
```

**Output:**

```text
5
```

The visitor counts each node visit, including the parameter's appearance in the body and in the lambda's parameter list.

**Key point:** `ExpressionVisitor` is the standard mechanism for recursively inspecting and rewriting expression trees.

## 16. Combining Expressions

Expression combination creates a new expression from existing expressions.

This is useful for dynamic filtering, search conditions, and reusable predicates.

### Example 1: Combine conditions manually

```csharp
Expression<Func<int, bool>> first =
    n => n > 10;

Expression<Func<int, bool>> second =
    n => n < 100;
```

The desired result is:

```csharp
n => n > 10 && n < 100
```

However, the two expressions have different `ParameterExpression` instances.

Their parameters must be unified.

### Example 2: Parameter replacement visitor

```csharp
public sealed class ParameterReplacer : ExpressionVisitor
{
    private readonly ParameterExpression _oldParameter;
    private readonly ParameterExpression _newParameter;

    public ParameterReplacer(
        ParameterExpression oldParameter,
        ParameterExpression newParameter)
    {
        _oldParameter = oldParameter;
        _newParameter = newParameter;
    }

    protected override Expression VisitParameter(
        ParameterExpression node)
    {
        return node == _oldParameter
            ? _newParameter
            : base.VisitParameter(node);
    }
}
```

### Example 3: Combine with AND

```csharp
Expression<Func<int, bool>> first =
    n => n > 10;

Expression<Func<int, bool>> second =
    x => x < 100;

ParameterExpression parameter = first.Parameters[0];

Expression secondBody = new ParameterReplacer(
    second.Parameters[0],
    parameter
).Visit(second.Body)!;

BinaryExpression combinedBody = Expression.AndAlso(
    first.Body,
    secondBody
);

Expression<Func<int, bool>> combined =
    Expression.Lambda<Func<int, bool>>(
        combinedBody,
        parameter
    );
```

### Test the combined expression

```csharp
Func<int, bool> predicate = combined.Compile();

Console.WriteLine(predicate(5));
Console.WriteLine(predicate(50));
Console.WriteLine(predicate(150));
```

**Output:**

```text
False
True
False
```

### Example 4: Combine with OR

Using the same `first`, `secondBody`, and `parameter`:

```csharp
BinaryExpression orBody = Expression.OrElse(
    first.Body,
    secondBody
);

Expression<Func<int, bool>> combinedOr =
    Expression.Lambda<Func<int, bool>>(
        orBody,
        parameter
    );
```

This represents:

```csharp
n => n > 10 || n < 100
```

That particular condition is true for every integer. It demonstrates the combination mechanism rather than a useful filter.

### Example 5: Reusable AND extension

```csharp
public static class ExpressionExtensions
{
    public static Expression<Func<T, bool>> And<T>(
        this Expression<Func<T, bool>> first,
        Expression<Func<T, bool>> second)
    {
        ParameterExpression parameter = first.Parameters[0];

        Expression secondBody = new ParameterReplacer(
            second.Parameters[0],
            parameter
        ).Visit(second.Body)!;

        Expression body = Expression.AndAlso(
            first.Body,
            secondBody
        );

        return Expression.Lambda<Func<T, bool>>(
            body,
            parameter
        );
    }
}
```

### Usage

```csharp
Expression<Func<Student, bool>> minimumMarks =
    s => s.Marks >= 80;

Expression<Func<Student, bool>> nameFilter =
    s => s.Name.StartsWith("A");

var combined = minimumMarks.And(nameFilter);

var result = students.AsQueryable().Where(combined);
```

**Important:** Combining expression bodies directly without unifying their parameters can create invalid expressions.

## 17. Compiling Expressions

`Compile()` converts an expression tree into an executable delegate.

### Syntax

```csharp
Func<T, TResult> function = expression.Compile();
```

### Example 1: Compile a mathematical expression

```csharp
Expression<Func<int, int>> expression =
    n => n * n;

Func<int, int> function = expression.Compile();

Console.WriteLine(function(5));
```

**Output:**

```text
25
```

### Example 2: Compile a predicate

```csharp
Expression<Func<int, bool>> expression =
    n => n % 2 == 0;

Func<int, bool> predicate = expression.Compile();

Console.WriteLine(predicate(10));
Console.WriteLine(predicate(7));
```

**Output:**

```text
True
False
```

### Example 3: Use compiled expression with IEnumerable

```csharp
Expression<Func<Student, bool>> expression =
    s => s.Marks >= 80;

Func<Student, bool> predicate = expression.Compile();

IEnumerable<Student> result = students.Where(predicate);
```

The compiled delegate is executed by LINQ to Objects.

### Example 4: Compile once, reuse many times

```csharp
Expression<Func<int, int>> expression =
    n => n * 10;

Func<int, int> transform = expression.Compile();

Console.WriteLine(transform(2));
Console.WriteLine(transform(5));
Console.WriteLine(transform(8));
```

**Output:**

```text
20
50
80
```

### Expression vs Compiled Delegate

```csharp
Expression<Func<int, bool>> expression =
    n => n > 10;
```

Can be supplied to a query provider:

```csharp
IQueryable<int> query = numbers
    .AsQueryable()
    .Where(expression);
```

After compilation:

```csharp
Func<int, bool> predicate = expression.Compile();
```

It can be executed locally:

```csharp
IEnumerable<int> result = numbers.Where(predicate);
```

**Important:** Do not compile an expression merely to pass it to an EF Core query. Compilation changes it into a delegate, preventing normal provider translation of that predicate.

## 18. Query Provider Translation

Expression trees allow query providers to examine the operations in a LINQ query and translate supported expressions into another language or execution plan.

The provider translation architecture was introduced in **06.13**. This section focuses on the expression-tree structure involved.

### Example 1: LINQ expression

```csharp
Expression<Func<Student, bool>> predicate =
    s => s.Marks >= 80;
```

### Expression structure

```text
Lambda
  │
  └── GreaterThanOrEqual
         │
         ├── MemberAccess
         │      │
         │      ├── Parameter: s
         │      └── Property: Marks
         │
         └── Constant: 80
```

### Example 2: Supply expression to IQueryable

```csharp
IQueryable<Student> query = db.Students.Where(predicate);
```

Here, `db.Students` represents an EF Core entity set.

The query provider can inspect the expression and translate the supported comparison.

### Conceptual SQL

```sql
SELECT *
FROM Students
WHERE Marks >= 80;
```

Actual SQL depends on entity mapping and the database provider.

### Example 3: Inspect the query expression

```csharp
Console.WriteLine(query.Expression.NodeType);
```

**Output:**

```text
Call
```

The outer expression represents the LINQ `Where()` method call.

### Example 4: Inspect the method call

```csharp
MethodCallExpression call =
    (MethodCallExpression)query.Expression;

Console.WriteLine(call.Method.Name);
```

**Output:**

```text
Where
```

### Example 5: Inspect the predicate argument

```csharp
UnaryExpression quotedPredicate =
    (UnaryExpression)call.Arguments[1];

LambdaExpression lambda =
    (LambdaExpression)quotedPredicate.Operand;

Console.WriteLine(lambda.Body);
```

**Output:**

```text
(s.Marks >= 80)
```

The `Quote` node wraps the lambda expression when it is supplied as an expression-tree argument to `Queryable.Where()`.

### Translation flow

```text
C# Lambda
    │
    ▼
Expression<Func<Student, bool>>
    │
    ▼
Queryable.Where()
    │
    ▼
MethodCallExpression
    │
    ▼
Query Provider
    │
    ▼
Expression Analysis
    │
    ▼
Supported Translation
    │
    ▼
Database Query
    │
    ▼
Results
```

### Important limitations

A query provider does not automatically understand every expression-tree node.

For example:

```csharp
Expression<Func<Student, bool>> predicate =
    s => CustomCheck(s.Marks);
```

A relational provider may be unable to translate `CustomCheck()`.

Expression trees describe operations, but the provider must implement support for translating those operations.

# 19. Complete Practical Example — Dynamic LINQ Filter

This example builds a predicate at runtime and applies it to a collection.

### Requirement

Select students whose marks are greater than or equal to a runtime-supplied minimum.

### Step 1: Sample data

```csharp
List<Student> students = new()
{
    new Student { Name = "Amit", Marks = 90 },
    new Student { Name = "Rahul", Marks = 75 },
    new Student { Name = "Priya", Marks = 95 },
    new Student { Name = "Neha", Marks = 80 }
};
```

### Step 2: Runtime condition

```csharp
int minimumMarks = 85;
```

### Step 3: Create parameter

```csharp
ParameterExpression parameter =
    Expression.Parameter(typeof(Student), "s");
```

### Step 4: Access Marks property

```csharp
MemberExpression property =
    Expression.Property(parameter, nameof(Student.Marks));
```

### Step 5: Create constant

```csharp
ConstantExpression value =
    Expression.Constant(minimumMarks);
```

### Step 6: Build comparison

```csharp
BinaryExpression comparison =
    Expression.GreaterThanOrEqual(property, value);
```

### Step 7: Build lambda

```csharp
Expression<Func<Student, bool>> predicate =
    Expression.Lambda<Func<Student, bool>>(
        comparison,
        parameter
    );
```

### Step 8: Apply to LINQ

```csharp
IQueryable<Student> query = students
    .AsQueryable()
    .Where(predicate);
```

### Step 9: Execute

```csharp
foreach (Student student in query)
{
    Console.WriteLine($"{student.Name}: {student.Marks}");
}
```

**Output:**

```text
Amit: 90
Priya: 95
```

### Generated expression

```csharp
Console.WriteLine(predicate);
```

**Output:**

```text
s => (s.Marks >= 85)
```

### Complete execution flow

```text
Runtime Value: 85
       │
       ▼
ParameterExpression
       │
       ▼
MemberExpression
       │
       ▼
ConstantExpression
       │
       ▼
BinaryExpression
       │
       ▼
Expression<Func<Student, bool>>
```

## 21. Important Rules

1. **Expression trees are immutable.** To change an expression, construct a new tree or use an `ExpressionVisitor` to produce a rewritten tree.
2. **Parameter identity matters.** Expressions combined into one lambda must use correctly bound parameter objects.
3. **Not every C# construct is supported.** Expression-tree lambdas have language restrictions.
4. **Compilation and translation are different.** `Compile()` produces a .NET delegate; a query provider may translate an expression into SQL or another representation.
5. **Provider support varies.** A valid expression tree is not necessarily translatable by every LINQ provider.
6. **Use expression trees when runtime inspection or translation is needed.** For ordinary local calculations, delegates are usually simpler.
