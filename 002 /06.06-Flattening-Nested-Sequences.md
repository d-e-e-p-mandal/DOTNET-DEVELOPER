**Language:** C#  
**Level:** Beginner → Advanced

## Introduction

**Projection** means transforming each element of a sequence into another value or object.

In LINQ, the primary projection operator is:

```csharp
Select()
```

A projection can produce a value of the same type or a completely different type.

### Basic concept

```text
SOURCE COLLECTION
        │
        ▼
      Select()
        │
        ▼
RESULT COLLECTION
```

For example:

```text
Input:  1, 2, 3, 4, 5

Select(x => x * 2)

Output: 2, 4, 6, 8, 10
```

### General syntax

```csharp
IEnumerable<TResult> result =
    source.Select(x => expression);
```

The main LINQ-to-Objects overloads are:

```csharp
Select<TSource, TResult>(
    IEnumerable<TSource> source,
    Func<TSource, TResult> selector
)
```

```csharp
Select<TSource, TResult>(
    IEnumerable<TSource> source,
    Func<TSource, int, TResult> selector
)
```

The second overload also supplies the element's zero-based index.

### Example

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

var result = numbers.Select(x => x * 2);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
2, 4, 6, 8, 10
```

`Select()` normally uses deferred execution. The transformation runs when the resulting sequence is enumerated.

# 1. Select

`Select()` transforms every source element using a selector function.

It is one of the most frequently used LINQ operators.

### Method syntax

```csharp
var result = numbers.Select(x => x * 2);
```

### Query syntax

```csharp
var result =
    from x in numbers
    select x * 2;
```

Both expressions produce equivalent results for this example.

### Transformation flow

```text
Source element     Selector       Result

      1             x * 2            2
      2             x * 2            4
      3             x * 2            6
      4             x * 2            8
      5             x * 2           10
```

The `Select` topic includes the following 11 syllabus subtopics.

## 1.1 Basic Projection

**Basic projection** transforms simple values into other values.

### Example 1: Multiply each number

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

var result = numbers.Select(x => x * 10);

foreach (int number in result)
{
    Console.WriteLine(number);
}
```

**Output:**

```text
10
20
30
40
50
```

### Example 2: Square each number

```csharp
int[] numbers = { 2, 3, 4, 5 };

var squares = numbers.Select(x => x * x);

Console.WriteLine(string.Join(", ", squares));
```

**Output:**

```text
4, 9, 16, 25
```

### Example 3: Convert integers to strings

```csharp
int[] numbers = { 10, 20, 30 };

IEnumerable<string> result =
    numbers.Select(x => $"Number: {x}");

foreach (string value in result)
{
    Console.WriteLine(value);
}
```

**Output:**

```text
Number: 10
Number: 20
Number: 30
```

Here:

```text
Input Type:  int
Output Type: string
```

### Example 4: String transformation

```csharp
string[] names =
{
    "amit",
    "rahul",
    "priya"
};

var result = names.Select(
    name => name.ToUpperInvariant()
);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
AMIT, RAHUL, PRIYA
```

### Key concepts

| Concept | Explanation |
|---|---|
| Source | Original sequence |
| Selector | Function applied to each element |
| Result | Transformed sequence |
| Input type | Original element type |
| Output type | Projected element type |
| Deferred execution | Transformation normally occurs during enumeration |

**Key point:** Basic projection transforms individual values without needing to change the original collection.

## 1.2 Property Projection

**Property projection** extracts selected properties from objects.

### Example model

```csharp
public class Student
{
    public int Id { get; set; }

    public string Name { get; set; } = "";

    public int Age { get; set; }

    public int Marks { get; set; }
}
```

### Source collection

```csharp
List<Student> students = new()
{
    new Student
    {
        Id = 1,
        Name = "Amit",
        Age = 20,
        Marks = 85
    },

    new Student
    {
        Id = 2,
        Name = "Rahul",
        Age = 21,
        Marks = 90
    },

    new Student
    {
        Id = 3,
        Name = "Priya",
        Age = 19,
        Marks = 95
    }
};
```

### Example 1: Select one property

```csharp
var names = students.Select(s => s.Name);

foreach (string name in names)
{
    Console.WriteLine(name);
}
```

**Output:**

```text
Amit
Rahul
Priya
```

### Example 2: Select another property

```csharp
var marks = students.Select(s => s.Marks);

Console.WriteLine(string.Join(", ", marks));
```

**Output:**

```text
85, 90, 95
```

### Example 3: Select multiple properties

```csharp
var result = students.Select(s => new
{
    s.Name,
    s.Marks
});

foreach (var student in result)
{
    Console.WriteLine(
        $"{student.Name}: {student.Marks}"
    );
}
```

**Output:**

```text
Amit: 85
Rahul: 90
Priya: 95
```

### Property projection flow

```text
Student Object
    │
    ├── Id
    ├── Name ───────┐
    ├── Age         │
    └── Marks ──────┤
                    ▼
               New Object
               ├── Name
               └── Marks
```

**Key point:** Property projection selects only the object properties required by the result.

## 1.3 Computed Projection

**Computed projection** calculates new values using source properties or elements.

### Example 1: Calculate total price

```csharp
public record Product(
    string Name,
    decimal Price,
    int Quantity
);
```

```csharp
Product[] products =
{
    new("Laptop", 50000m, 2),
    new("Mouse", 500m, 5),
    new("Keyboard", 1500m, 3)
};

var result = products.Select(p => new
{
    p.Name,
    TotalPrice = p.Price * p.Quantity
});

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.Name}: {item.TotalPrice}"
    );
}
```

**Output:**

```text
Laptop: 100000
Mouse: 2500
Keyboard: 4500
```

### Example 2: Calculate percentage

```csharp
int[] marks = { 80, 90, 70 };

var percentages = marks.Select(
    mark => mark / 100.0 * 100
);

Console.WriteLine(
    string.Join(", ", percentages)
);
```

**Output:**

```text
80, 90, 70
```

### Example 3: Compute pass/fail status

```csharp
int[] marks = { 85, 30, 60, 25 };

var results = marks.Select(mark => new
{
    Mark = mark,
    Passed = mark >= 40
});

foreach (var item in results)
{
    Console.WriteLine(
        $"{item.Mark}: {item.Passed}"
    );
}
```

**Output:**

```text
85: True
30: False
60: True
25: False
```

### Computed projection structure

```text
Source Values
     │
     ▼
Calculation
     │
     ▼
Computed Result
```

**Key point:** Computed projection derives new information from existing data.

## 1.4 Indexed Select

**Indexed Select** provides both the element and its position.

### Syntax

```csharp
source.Select((element, index) => expression);
```

The index begins at `0`.

### Example 1: Display positions

```csharp
string[] names =
{
    "Amit",
    "Rahul",
    "Priya"
};

var result = names.Select(
    (name, index) => $"{index}: {name}"
);

foreach (string item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
0: Amit
1: Rahul
2: Priya
```

### Example 2: One-based numbering

```csharp
var result = names.Select(
    (name, index) => $"{index + 1}. {name}"
);

foreach (string item in result)
{
    Console.WriteLine(item);
}
```

**Output:**

```text
1. Amit
2. Rahul
3. Priya
```

### Example 3: Multiply by position

```csharp
int[] numbers = { 10, 20, 30 };

var result = numbers.Select(
    (number, index) => number * (index + 1)
);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
10, 40, 90
```

### Indexed projection

| Index | Element | Calculation | Result |
|---|---|---|---|
| 0 | 10 | 10 × 1 | 10 |
| 1 | 20 | 20 × 2 | 40 |
| 2 | 30 | 30 × 3 | 90 |

**Key point:** Indexed `Select()` is useful when the transformation depends on the element's position.

## 1.5 Anonymous-Type Projection

An **anonymous type** is a compiler-generated type created using `new { ... }`.

It is useful when a query needs a temporary result structure.

### Example

```csharp
var students = new[]
{
    new { Id = 1, Name = "Amit", Marks = 85 },
    new { Id = 2, Name = "Rahul", Marks = 90 },
    new { Id = 3, Name = "Priya", Marks = 95 }
};

var result = students.Select(s => new
{
    s.Name,
    s.Marks
});

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.Name}: {item.Marks}"
    );
}
```

**Output:**

```text
Amit: 85
Rahul: 90
Priya: 95
```

### Example: Renamed properties

```csharp
var result = students.Select(s => new
{
    StudentName = s.Name,
    Score = s.Marks
});
```

The resulting properties are:

```text
StudentName
Score
```

### Example: Computed anonymous property

```csharp
var result = students.Select(s => new
{
    s.Name,
    Passed = s.Marks >= 40
});
```

### Characteristics

| Feature | Anonymous Type |
|---|---|
| Syntax | `new { ... }` |
| Explicit class declaration | Not required |
| Property types | Inferred |
| Properties | Read-only after construction |
| Common usage | Local query projections |

Anonymous types are primarily intended for use within a local scope.

**Key point:** Anonymous-type projection creates temporary structured results without defining a named class.

## 1.6 Tuple Projection

**Tuple projection** produces tuples containing multiple values.

C# supports named tuple elements.

### Example 1: Basic tuple projection

```csharp
string[] names =
{
    "Amit",
    "Rahul",
    "Priya"
};

var result = names.Select(
    (name, index) => (Index: index, Name: name)
);

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.Index}: {item.Name}"
    );
}
```

**Output:**

```text
0: Amit
1: Rahul
2: Priya
```

### Example 2: Tuple with calculations

```csharp
int[] numbers = { 2, 3, 4 };

var result = numbers.Select(
    x => (Number: x, Square: x * x)
);

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.Number}: {item.Square}"
    );
}
```

**Output:**

```text
2: 4
3: 9
4: 16
```

### Explicit tuple type

```csharp
IEnumerable<(int Number, int Square)> result =
    numbers.Select(x => (x, x * x));
```

### Tuple vs anonymous type

| Tuple | Anonymous Type |
|---|---|
| `(Name: x, Age: y)` | `new { Name = x, Age = y }` |
| Value tuple | Anonymous reference type |
| Can be used in method signatures | Primarily local |
| Supports deconstruction | Supports named property access |
| Elements are mutable by default | Properties are read-only |

**Key point:** Tuple projection is useful for lightweight results containing a small number of related values.

## 1.7 Record Projection

**Record projection** transforms elements into record objects.

Records provide concise syntax for data-focused types.

### Define a record

```csharp
public record StudentDto(
    int Id,
    string Name,
    int Marks
);
```

### Source model

```csharp
public class Student
{
    public int Id { get; set; }

    public string Name { get; set; } = "";

    public int Marks { get; set; }
}
```

### Projection

```csharp
Student[] students =
{
    new Student { Id = 1, Name = "Amit", Marks = 85 },
    new Student { Id = 2, Name = "Rahul", Marks = 90 }
};

StudentDto[] result = students
    .Select(s => new StudentDto(
        s.Id,
        s.Name,
        s.Marks
    ))
    .ToArray();

foreach (StudentDto student in result)
{
    Console.WriteLine(
        $"{student.Id}: {student.Name}"
    );
}
```

**Output:**

```text
1: Amit
2: Rahul
```

### Record projection flow

```text
Student
   │
   ▼
Select()
   │
   ▼
StudentDto Record
```

### Advantages

- Concise type declarations.
- Value-based equality by default.
- Useful for data transfer and immutable-style models.
- Named types can be reused across methods.

A positional record's generated properties are `init`-only, but a record is not automatically deeply immutable.

**Key point:** Record projection produces strongly typed data-focused results.

## 1.8 DTO Projection

**DTO** means **Data Transfer Object**.

DTO projection converts application entities into objects containing only the information required by another layer.

### Entity model

```csharp
public class Employee
{
    public int Id { get; set; }

    public string Name { get; set; } = "";

    public string Email { get; set; } = "";

    public decimal Salary { get; set; }
}
```

### DTO model

```csharp
public class EmployeeDto
{
    public int Id { get; set; }

    public string Name { get; set; } = "";
}
```

### Example

```csharp
Employee[] employees =
{
    new Employee
    {
        Id = 1,
        Name = "Amit",
        Email = "amit@example.com",
        Salary = 50000m
    },

    new Employee
    {
        Id = 2,
        Name = "Rahul",
        Email = "rahul@example.com",
        Salary = 60000m
    }
};

EmployeeDto[] result = employees
    .Select(e => new EmployeeDto
    {
        Id = e.Id,
        Name = e.Name
    })
    .ToArray();

foreach (EmployeeDto employee in result)
{
    Console.WriteLine(
        $"{employee.Id}: {employee.Name}"
    );
}
```

**Output:**

```text
1: Amit
2: Rahul
```

### Transformation

```text
EMPLOYEE ENTITY
    │
    ├── Id ─────────┐
    ├── Name ───────┤
    ├── Email       │
    └── Salary      │
                    ▼
                EMPLOYEE DTO
                    │
                    ├── Id
                    └── Name
```

### Why use DTO projection?

| Benefit | Explanation |
|---|---|
| Data minimization | Transfer only required fields |
| Encapsulation | Avoid exposing internal entity structure |
| Maintainability | Separate application models from output models |
| API design | Return a defined response structure |
| Strong typing | Use explicit result types |

**Key point:** DTO projection transforms entities into application-specific transfer models.

## 1.9 Conditional Projection

**Conditional projection** selects output values based on conditions.

The conditional operator is:

```csharp
condition ? valueIfTrue : valueIfFalse
```

### Example 1: Pass/fail

```csharp
int[] marks = { 85, 30, 60, 25 };

var result = marks.Select(
    mark => mark >= 40 ? "Pass" : "Fail"
);

Console.WriteLine(
    string.Join(", ", result)
);
```

**Output:**

```text
Pass, Fail, Pass, Fail
```

### Example 2: Grade classification

```csharp
int[] marks = { 95, 75, 55, 30 };

var result = marks.Select(mark => new
{
    Mark = mark,

    Grade = mark >= 90 ? "A" :
            mark >= 75 ? "B" :
            mark >= 50 ? "C" : "F"
});

foreach (var item in result)
{
    Console.WriteLine(
        $"{item.Mark}: {item.Grade}"
    );
}
```

**Output:**

```text
95: A
75: B
55: C
30: F
```

### Example 3: Discount category

```csharp
decimal[] prices =
{
    500m,
    1500m,
    5000m
};

var result = prices.Select(price => new
{
    Price = price,
    Category = price >= 3000m
        ? "Premium"
        : "Regular"
});
```

### Conditional projection flow

```text
SOURCE VALUE
     │
     ▼
CHECK CONDITION
     │
     ├── TRUE  → OUTPUT A
     │
     └── FALSE → OUTPUT B
```

**Key point:** Conditional projection produces different result values based on business rules.

## 1.10 Null-Safe Projection

**Null-safe projection** handles missing references while transforming data.

Common C# operators include:

```csharp
?.
??
```

`?.` is the null-conditional operator.

`??` is the null-coalescing operator.

### Example 1: Nullable strings

```csharp
string?[] names =
{
    "Amit",
    null,
    "Priya"
};

var result = names.Select(
    name => name?.ToUpperInvariant() ?? "UNKNOWN"
);

foreach (string name in result)
{
    Console.WriteLine(name);
}
```

**Output:**

```text
AMIT
UNKNOWN
PRIYA
```

### Example 2: Nullable property

```csharp
public class Employee
{
    public string Name { get; set; } = "";

    public string? Department { get; set; }
}
```

```csharp
Employee[] employees =
{
    new Employee
    {
        Name = "Amit",
        Department = "IT"
    },

    new Employee
    {
        Name = "Rahul",
        Department = null
    }
};

var result = employees.Select(e => new
{
    e.Name,
    Department = e.Department ?? "Not Assigned"
});

foreach (var employee in result)
{
    Console.WriteLine(
        $"{employee.Name}: {employee.Department}"
    );
}
```

**Output:**

```text
Amit: IT
Rahul: Not Assigned
```

### Example 3: Nested nullable property

```csharp
public class Address
{
    public string City { get; set; } = "";
}

public class Person
{
    public string Name { get; set; } = "";

    public Address? Address { get; set; }
}
```

```csharp
Person[] people =

    new Person
    {
        Name = "Amit",
        Address = new Address { City = "Kolkata" }

    new Person
    {
        Name = "Rahul",
        Address = null
    }

    p.Name,

    Console.WriteLine(
```

```text

```

**Key point:** Null-safe projection prevents unexpected null dereferences and provides defined fallback values.

## 1.11 Nested Projection

**Nested projection** creates a result containing another object or collection.

It preserves hierarchical structure.

### Example models

```csharp
public record Student(
    string Name,
    int[] Marks
);
```

### Source data

```csharp
Student[] students =
{
    new("Amit", new[] { 80, 90, 85 }),
    new("Rahul", new[] { 70, 75, 80 })
};
```

### Example 1: Nested object projection

```csharp
var result = students.Select(s => new
{
    s.Name,

    Statistics = new
    {
        Total = s.Marks.Sum(),
        Average = s.Marks.Average()
    }
});

foreach (var student in result)
{
    Console.WriteLine(student.Name);
    Console.WriteLine(
        $"Total: {student.Statistics.Total}"
    );
    Console.WriteLine(
        $"Average: {student.Statistics.Average}"
    );
}
```

**Output:**

```text
Amit
Total: 255
Average: 85
Rahul
Total: 225
Average: 75
```

### Example 2: Nested collection projection

```csharp
var result = students.Select(s => new
{
    s.Name,

    DoubledMarks = s.Marks
        .Select(mark => mark * 2)
        .ToArray()
});

foreach (var student in result)
{
    Console.WriteLine(
        $"{student.Name}: " +
        string.Join(", ", student.DoubledMarks)
    );
}
```

**Output:**

```text
Amit: 160, 180, 170
Rahul: 140, 150, 160
```

### Nested projection structure

```text
Student
   │
   ▼
Projected Student
   │
   ├── Name
   │
   └── Statistics
          ├── Total
          └── Average
```

### Nested projection vs flattening

| Nested Projection | Flattening |
|---|---|
| Preserves hierarchy | Removes a nesting level |
| Often uses `Select()` | Often uses `SelectMany()` |
| Parent contains nested result | Parent-child values become flat results |

**Key point:** Nested projection transforms hierarchical data while preserving its nested structure.

# 2. Projection vs Mutation

Projection and mutation are fundamentally different operations.

**Projection creates a transformed result.**

**Mutation changes an existing object or collection.**

Understanding the difference is important when writing predictable LINQ queries.

## 2.1 Projection

Projection returns new values or objects without intentionally changing the source.

### Example

```csharp
int[] numbers = { 10, 20, 30 };

int[] result = numbers
    .Select(x => x * 2)
    .ToArray();

Console.WriteLine(
    "Original: " + string.Join(", ", numbers)
);

Console.WriteLine(
    "Projected: " + string.Join(", ", result)
);
```

**Output:**

```text
Original: 10, 20, 30
Projected: 20, 40, 60
```

The original array remains unchanged.

### Execution flow

```text
ORIGINAL COLLECTION
     │
     ├── 10
     ├── 20
     └── 30
          │
          ▼
        Select()
          │
          ▼
NEW RESULT COLLECTION
     │
     ├── 20
     ├── 40
     └── 60
```

## 2.2 Mutation

Mutation modifies existing data.

### Example

```csharp
int[] numbers = { 10, 20, 30 };

for (int i = 0; i < numbers.Length; i++)
{
    numbers[i] *= 2;
}

Console.WriteLine(
    string.Join(", ", numbers)
);
```

**Output:**

```text
20, 40, 60
```

The original array has changed.

## 2.3 Projection with reference types

A projection does not automatically protect source objects from mutation.

Consider:

```csharp
public class Product
{
    public string Name { get; set; } = "";

    public decimal Price { get; set; }
}
```

### Example: Returning existing references

```csharp
Product[] products =
{
    new Product
    {
        Name = "Laptop",
        Price = 50000m
    }
};

var result = products
    .Select(p => p)
    .ToArray();

result[0].Price = 60000m;

Console.WriteLine(products[0].Price);
```

**Output:**

```text
60000
```

Why?

Because:

```csharp
.Select(p => p)
```

returns the same object references.

It does not create copies.

### Example: Creating new objects

```csharp
Product[] products =
{
    new Product
    {
        Name = "Laptop",
        Price = 50000m
    }
};

Product[] result = products
    .Select(p => new Product
    {
        Name = p.Name,
        Price = p.Price
    })
    .ToArray();

result[0].Price = 60000m;

Console.WriteLine(products[0].Price);
Console.WriteLine(result[0].Price);
```

**Output:**

```text
50000
60000
```

The projection creates separate `Product` instances.

This is a shallow copy of the selected properties. If those properties themselves referenced mutable objects, further copying might be necessary.

## 2.4 Side effects inside Select

Avoid using `Select()` primarily to mutate objects.

### Problematic approach

```csharp
var result = products.Select(p =>
{
    p.Price += 1000m;

    return p;
});
```

This selector modifies existing objects.

Because `Select()` is deferred, the mutation occurs during enumeration. Enumerating the query again may apply the mutation again.

### Better approach

```csharp
var result = products.Select(p => new Product
{
    Name = p.Name,
    Price = p.Price + 1000m
});
```

The selector now creates transformed objects without modifying the originals.

### Comparison

| Feature | Projection | Mutation |
|---|---|---|
| Purpose | Transform data | Change existing data |
| Original values | Can remain unchanged | Modified |
| Typical LINQ operator | `Select()` | Not a LINQ operator |
| Predictability | Easier with pure selectors | Depends on changing state |
| Repeated execution | Recalculates results | May repeat side effects |
| Functional programming | Commonly preferred | Usually minimized |

**Key point:** Use projection to produce transformed values and explicit mutation when changing existing state is genuinely required.

# 3. Projection before Filtering

**Projection before filtering** means applying `Select()` before `Where()`.

### General syntax

```csharp
source
    .Select(x => transformation)
    .Where(x => condition);
```

The filter operates on the **projected values**, not directly on the original elements.

## 3.1 Basic example

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

var result = numbers
    .Select(x => x * 2)
    .Where(x => x > 5);

Console.WriteLine(
    string.Join(", ", result)
);
```

**Output:**

```text
6, 8, 10
```

### Execution

```text
ORIGINAL
1, 2, 3, 4, 5
       │
       ▼
Select(x => x * 2)
       │
       ▼
2, 4, 6, 8, 10
       │
       ▼
Where(x => x > 5)
       │
       ▼
6, 8, 10
```

The `Where()` predicate receives the doubled values.

## 3.2 Filtering computed properties

Projection before filtering is useful when a condition depends on a newly calculated property.

### Example model

```csharp
public record Product(
    string Name,
    decimal Price,
    int Quantity
);
```

### Example

```csharp
Product[] products =
{
    new("Laptop", 50000m, 2),
    new("Mouse", 500m, 5),
    new("Keyboard", 1500m, 3)
};

var result = products
    .Select(p => new
    {
        p.Name,
        Total = p.Price * p.Quantity
    })
    .Where(p => p.Total > 4000m);

foreach (var product in result)
{
    Console.WriteLine(
        $"{product.Name}: {product.Total}"
    );
}
```

**Output:**

```text
Laptop: 100000
Keyboard: 4500
```

### Execution flow

```text
PRODUCTS
   │
   ▼
CALCULATE TOTAL PRICE
   │
   ▼
FILTER TOTAL > 4000
   │
   ▼
RESULT
```

## 3.3 Advantages

Projection before filtering is appropriate when:

- Filtering depends on computed values.
- Filtering depends on a newly created property.
- The transformed representation is easier to validate.
- The projected value would otherwise need to be calculated repeatedly.

## 3.4 Performance consideration

Consider:

```csharp
var result = products
    .Select(p => new
    {
        p.Name,
        Total = p.Price * p.Quantity
    })
    .Where(p => p.Total > 4000m);
```

Every source element must first pass through the projection to determine whether it satisfies the filter.

If a cheap condition can eliminate many source elements before an expensive transformation, filtering first may be preferable.

**Key point:** Project before filtering when the filtering condition requires the projected result.

# 4. Projection after Filtering

**Projection after filtering** means applying `Where()` before `Select()`.

### General syntax

```csharp
source
    .Where(x => condition)
    .Select(x => transformation);
```

The filter operates on the original source elements.

Only matching elements are projected.

## 4.1 Basic example

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };

var result = numbers
    .Where(x => x > 2)
    .Select(x => x * 2);

Console.WriteLine(
    string.Join(", ", result)
);
```

**Output:**

```text
6, 8, 10
```

### Execution

```text
ORIGINAL
1, 2, 3, 4, 5
       │
       ▼
Where(x => x > 2)
       │
       ▼
3, 4, 5
       │
       ▼
Select(x => x * 2)
       │
       ▼
6, 8, 10
```

## 4.2 Filtering objects before projection

Using the `Product` record from Point 3:

```csharp
Product[] products =
{
    new("Laptop", 50000m, 2),
    new("Mouse", 500m, 5),
    new("Keyboard", 1500m, 3)
};

var result = products
    .Where(p => p.Price > 1000m)
    .Select(p => new
    {
        p.Name,
        Total = p.Price * p.Quantity
    });

foreach (var product in result)
{
    Console.WriteLine(
        $"{product.Name}: {product.Total}"
    );
}
```

**Output:**

```text
Laptop: 100000
Keyboard: 4500
```

Only products priced above `1000` are projected.

## 4.3 Why filtering first can be efficient

Suppose there are 1,000 products.

Only 100 products satisfy the filtering condition.

### Projection before filtering

```text
1,000 PRODUCTS
      │
      ▼
1,000 PROJECTIONS
      │
      ▼
100 MATCHES
```

### Filtering before projection

```text
1,000 PRODUCTS
      │
      ▼
100 MATCHES
      │
      ▼
100 PROJECTIONS
```

Filtering first can reduce transformation work.

This benefit is particularly relevant when projections are expensive.

## 4.4 Important semantic difference

These two expressions are not automatically equivalent:

```csharp
numbers
    .Select(x => x * 2)
    .Where(x => x > 5);
```

```csharp
numbers
    .Where(x => x > 5)
    .Select(x => x * 2);
```

For:

```csharp
int[] numbers = { 1, 2, 3, 4, 5 };
```

The first produces:

```text
6, 8, 10
```

The second produces an empty sequence.

Why?

In the first query, the condition checks doubled values.

In the second query, the condition checks original values.

### Equivalent transformations

To preserve the first query's meaning while filtering first:

```csharp
var result = numbers
    .Where(x => x * 2 > 5)
    .Select(x => x * 2);
```

**Output:**

```text
6, 8, 10
```

### Comparison

| Feature | Projection Before Filtering | Projection After Filtering |
|---|---|---|
| First operator | `Select()` | `Where()` |
| Second operator | `Where()` | `Select()` |
| Predicate receives | Projected elements | Original elements |
| Transformation count | Potentially more | Potentially fewer |
| Best suited for | Filtering computed results | Filtering original data |
| Semantics | Depends on transformed values | Depends on source values |

**Key point:** Filter before projection when possible, but never change the order without checking that the query's meaning remains correct.

# 5. Narrow Projection

**Narrow projection** means selecting only the fields required by the result.

Instead of returning an entire object, project a smaller representation.

## 5.1 Full object vs narrow projection

### Example model

```csharp
public class Employee
{
    public int Id { get; set; }

    public string Name { get; set; } = "";

    public string Email { get; set; } = "";

    public string Department { get; set; } = "";

    public decimal Salary { get; set; }

    public string Address { get; set; } = "";
}
```

### Source

```csharp
Employee[] employees =
{
    new Employee
    {
        Id = 1,
        Name = "Amit",
        Email = "amit@example.com",
        Department = "IT",
        Salary = 50000m,
        Address = "Kolkata"
    },

    new Employee
    {
        Id = 2,
        Name = "Rahul",
        Email = "rahul@example.com",
        Department = "HR",
        Salary = 40000m,
        Address = "Howrah"
    }
};
```

### Full object selection

```csharp
var result = employees.Select(e => e);
```

The result contains references to the original `Employee` objects, which expose all their properties.

### Narrow projection

```csharp
var result = employees.Select(e => new
{
    e.Id,
    e.Name
});

foreach (var employee in result)
{
    Console.WriteLine(
        $"{employee.Id}: {employee.Name}"
    );
}
```

**Output:**

```text
1: Amit
2: Rahul
```

Only the required properties are included in the result.

## 5.2 Narrow projection with DTOs

### DTO

```csharp
public record EmployeeSummary(
    int Id,
    string Name
);
```

### Projection

```csharp
EmployeeSummary[] result = employees
    .Select(e => new EmployeeSummary(
        e.Id,
        e.Name
    ))
    .ToArray();
```

### Structure

```text
EMPLOYEE
   │
   ├── Id ─────────────┐
   ├── Name ───────────┤
   ├── Email           │
   ├── Department      │
   ├── Salary          │
   └── Address         │
                       ▼
                EMPLOYEE SUMMARY
                       │
                       ├── Id
                       └── Name
```

## 5.3 Narrow projection in database queries

Narrow projection can be especially useful when querying databases.

Consider an Entity Framework Core query:

```csharp
var result = await dbContext.Employees
    .Select(e => new EmployeeSummary(
        e.Id,
        e.Name
    ))
    .ToListAsync();
```

This example assumes the application has a configured EF Core context, an `Employees` entity set, and the required EF Core namespace.

With a supported relational provider, the projection can allow SQL to select only the necessary columns.

Conceptually:

```sql
SELECT Id, Name
FROM Employees;
```

Instead of:

```sql
SELECT *
FROM Employees;
```

The exact SQL depends on the database provider and query translation.

## 5.4 Benefits of narrow projection

| Benefit | Explanation |
|---|---|
| Reduced data transfer | Fewer fields may need to be retrieved |
| Smaller result objects | Avoid unnecessary properties |
| Improved encapsulation | Expose only required data |
| Readability | Makes result requirements explicit |
| Maintainability | Separates output models from source models |
| API design | Helps control response structure |

## 5.5 Important performance distinction

For in-memory LINQ:

```csharp
employees.Select(e => new
{
    e.Id,
    e.Name
});
```

The original `Employee` objects already exist in memory.

The projection does not reduce the memory occupied by those original objects.

It creates smaller result objects containing fewer fields.

For provider-backed queries such as Entity Framework Core, narrow projection can also reduce the amount of data fetched from the database.

**Key point:** Narrow projection selects only the fields required by the consumer, improving clarity and potentially reducing data transfer and memory use.

```text
             │              │              │

                            ▼
                    OPTIONAL FILTERING
                            │
                            ▼
                       MATERIALIZE
                            │
                            ▼
                       FINAL RESULT
```

### Important rules

1. `Select()` transforms each element using a selector.
2. The input and output types can be different.
3. Indexed `Select()` provides a zero-based position.
4. Anonymous types, tuples, records, and DTOs provide different result representations.
5. Conditional projection applies business rules during transformation.
6. Null-safe projection handles missing values explicitly.
7. Nested projection preserves hierarchical structures.
8. Projection should generally avoid mutating source objects.
9. Projection before filtering evaluates conditions on transformed values.
10. Projection after filtering evaluates conditions on original values.
11. Narrow projection selects only the data required by the result.
12. `Select()` is normally deferred; `ToArray()` and `ToList()` materialize its results.
