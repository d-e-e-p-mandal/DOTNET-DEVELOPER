## 1. Recursion

**Recursion** occurs when a method calls itself directly or indirectly.

A recursive method generally requires two components:

1. **Base case:** A condition that stops recursion.
2. **Recursive case:** A call that works toward the base case.

### Example 1: Basic recursion

```csharp
static void PrintNumbers(int number)
{
    if (number == 0)
        return;

    Console.WriteLine(number);

    PrintNumbers(number - 1);
}

PrintNumbers(5);
```

**Output:**

```text
5
4
3
2
1
```

### Execution flow

```text
PrintNumbers(5)
    │
    ▼
Print 5
    │
    ▼
PrintNumbers(4)
    │
    ▼
Print 4
    │
    ▼
PrintNumbers(3)
    │
    ▼
Print 3
    │
    ▼
PrintNumbers(2)
    │
    ▼
Print 2
    │
    ▼
PrintNumbers(1)
    │
    ▼
Print 1
    │
    ▼
PrintNumbers(0)
    │
    ▼
Return
```

### Example 2: Recursive sum

```csharp
static int Sum(int number)
{
    if (number == 0)
        return 0;

    return number + Sum(number - 1);
}

Console.WriteLine(Sum(5));
```

**Output:**

```text
15
```

Mathematically:

```text
Sum(5)
= 5 + Sum(4)
= 5 + 4 + Sum(3)
= 5 + 4 + 3 + Sum(2)
= 5 + 4 + 3 + 2 + Sum(1)
= 5 + 4 + 3 + 2 + 1 + Sum(0)
= 15
```

**Important:** This implementation assumes a nonnegative input. A negative input would not reach the base case.

**Key point:** Recursion solves a problem by repeatedly reducing it to smaller instances of the same problem.

## 2. Recursive Decomposition

**Recursive decomposition** means breaking a large problem into smaller problems of the same form.

A recursive solution should identify:

- What the smaller problem is.
- How to solve that smaller problem.
- How to combine its result with the current step.
- When to stop.

### Example 1: Factorial decomposition

Factorial is defined as:

```text
5! = 5 × 4 × 3 × 2 × 1

n! = n × (n - 1)!

0! = 1
```

C# implementation:

```csharp
static long Factorial(int number)
{
    if (number < 0)
        throw new ArgumentOutOfRangeException(
            nameof(number)
        );

    if (number <= 1)
        return 1;

    return number * Factorial(number - 1);
}

Console.WriteLine(Factorial(5));
```

**Output:**

```text
120
```

### Decomposition

```text
Factorial(5)
    │
    ├── Current part: 5
    │
    └── Smaller problem: Factorial(4)
                              │
                              ├── Current part: 4
                              │
                              └── Factorial(3)
```

### Example 2: Recursive array sum

```csharp
static int SumArray(int[] numbers, int index)
{
    if (index == numbers.Length)
        return 0;

    return numbers[index]
         + SumArray(numbers, index + 1);
}

int[] numbers = { 10, 20, 30, 40 };

Console.WriteLine(SumArray(numbers, 0));
```

**Output:**

```text
100
```

Each recursive call processes one element and delegates the remaining elements to another call.

**Key point:** Recursive decomposition converts a complex problem into a smaller instance plus a simple combination step.

## 3. Base Case

The **base case** is the condition that terminates recursion.

Without a reachable base case, recursion can continue until the program exhausts its call stack.

### Example 1: Correct base case

```csharp
static int Countdown(int number)
{
    if (number <= 0)
        return 0;

    return Countdown(number - 1);
}

Console.WriteLine(Countdown(5));
```

**Output:**

```text
0
```

The base case is:

```csharp
if (number <= 0)
    return 0;
```

### Example 2: Fibonacci base cases

```csharp
static int Fibonacci(int number)
{
    if (number < 0)
        throw new ArgumentOutOfRangeException(
            nameof(number)
        );

    if (number <= 1)
        return number;

    return Fibonacci(number - 1)
         + Fibonacci(number - 2);
}

Console.WriteLine(Fibonacci(6));
```

**Output:**

```text
8
```

Here:

```text
Fibonacci(0) = 0
Fibonacci(1) = 1
```

Both are base cases.

### Characteristics of a good base case

| Characteristic | Explanation |
|---|---|
| Reachable | Recursive calls eventually satisfy it |
| Correct | It returns the expected result for the simplest input |
| Terminates | It does not make another recursive call |
| Complete | It covers all relevant stopping conditions |

**Key point:** Every recursive path must eventually reach a terminating condition.

## 4. Recursive Case

The **recursive case** defines how a method calls itself with a smaller or simpler problem.

### Example: Recursive multiplication

For a nonnegative multiplier:

```text
Multiply(4, 3)
= 4 + Multiply(4, 2)
= 4 + 4 + Multiply(4, 1)
= 4 + 4 + 4 + Multiply(4, 0)
= 12
```

C# implementation:

```csharp
static int Multiply(int number, int times)
{
    if (times < 0)
        throw new ArgumentOutOfRangeException(
            nameof(times)
        );

    if (times == 0)
        return 0;

    return number + Multiply(number, times - 1);
}

Console.WriteLine(Multiply(4, 3));
```

**Output:**

```text
12
```

The recursive case is:

```csharp
return number + Multiply(number, times - 1);
```

### Recursive-case requirements

1. The recursive call must make progress toward termination.
2. The smaller problem must have the same general structure.
3. The returned result must be combined correctly.
4. The input domain must be handled appropriately.

### Base case vs recursive case

| Base Case | Recursive Case |
|---|---|
| Stops recursion | Continues recursion |
| Handles simplest problem | Reduces problem |
| Does not call itself | Calls itself |
| Produces direct result | Uses result of smaller problem |

**Key point:** The recursive case describes how to reduce and solve the remaining problem.

## 5. Recursive Traversal

**Recursive traversal** means visiting the elements of a data structure by repeatedly processing smaller portions of that structure.

It is especially useful when data contains nested elements.

### Example 1: Traversing an array recursively

```csharp
static void Traverse(int[] numbers, int index)
{
    if (index >= numbers.Length)
        return;

    Console.WriteLine(numbers[index]);

    Traverse(numbers, index + 1);
}

int[] numbers = { 10, 20, 30, 40 };

Traverse(numbers, 0);
```

**Output:**

```text
10
20
30
40
```

### Execution flow

```text
Traverse(numbers, 0)
    │
    ├── Print 10
    │
    ▼
Traverse(numbers, 1)
    │
    ├── Print 20
    │
    ▼
Traverse(numbers, 2)
    │
    ├── Print 30
    │
    ▼
Traverse(numbers, 3)
    │
    ├── Print 40
    │
    ▼
Traverse(numbers, 4)
    │
    └── Stop
```

### Example 2: Traversal without console side effects

```csharp
static IEnumerable<int> Traverse(
    int[] numbers,
    int index)
{
    if (index >= numbers.Length)
        yield break;

    yield return numbers[index];

    foreach (int value in Traverse(numbers, index + 1))
        yield return value;
}

int[] numbers = { 10, 20, 30 };

var result = Traverse(numbers, 0);

Console.WriteLine(string.Join(", ", result));
```

**Output:**

```text
10, 20, 30
```

This version produces a sequence rather than printing during traversal.

**Key point:** Recursive traversal processes elements by recursively visiting the remaining structure.

## 6. Trees

A **tree** is a hierarchical data structure containing nodes connected through parent-child relationships.

Trees are naturally recursive because each child may itself be the root of another tree.

### Tree structure

```text
          10
         /  \
        5    20
       / \     \
      2   7     30
```

### Example 1: Define a tree node

```csharp
public sealed class TreeNode
{
    public int Value { get; }

    public TreeNode? Left { get; }

    public TreeNode? Right { get; }

    public TreeNode(
        int value,
        TreeNode? left = null,
        TreeNode? right = null)
    {
        Value = value;
        Left = left;
        Right = right;
    }
}
```

The properties are read-only after construction.

### Example 2: Construct a tree

```csharp
TreeNode root = new(
    10,
    new TreeNode(
        5,
        new TreeNode(2),
        new TreeNode(7)
    ),
    new TreeNode(
        20,
        right: new TreeNode(30)
    )
);
```

### Example 3: Recursive tree traversal

```csharp
static void PrintTree(TreeNode? node)
{
    if (node is null)
        return;

    Console.WriteLine(node.Value);

    PrintTree(node.Left);
    PrintTree(node.Right);
}

PrintTree(root);
```

**Output:**

```text
10
5
2
7
20
30
```

This is a **preorder traversal**: process the current node before its children.

### Example 4: Sum tree values

```csharp
static int SumTree(TreeNode? node)
{
    if (node is null)
        return 0;

    return node.Value
         + SumTree(node.Left)
         + SumTree(node.Right);
}

Console.WriteLine(SumTree(root));
```

**Output:**

```text
74
```

Calculation:

```text
10 + 5 + 2 + 7 + 20 + 30 = 74
```

### Example 5: Count tree nodes

```csharp
static int CountNodes(TreeNode? node)
{
    if (node is null)
        return 0;

    return 1
         + CountNodes(node.Left)
         + CountNodes(node.Right);
}

Console.WriteLine(CountNodes(root));
```

**Output:**

```text
6
```

**Key point:** Recursive functions naturally match the hierarchical structure of trees.

## 7. Nested Structures

A **nested structure** contains elements that can themselves contain more elements of the same general kind.

Examples include nested folders, categories, comments, and organizational hierarchies.

### Example 1: Nested category model

```csharp
public sealed record Category(
    string Name,
    IReadOnlyList<Category> Children
);
```

### Example 2: Create nested categories

```csharp
Category root = new(
    "Programming",
    new Category[]
    {
        new(
            "C#",
            new Category[]
            {
                new("LINQ", Array.Empty<Category>()),
                new("ASP.NET Core", Array.Empty<Category>())
            }
        ),
        new(
            "Java",
            Array.Empty<Category>()
        )
    }
);
```

Structure:

```text
Programming
    │
    ├── C#
    │   ├── LINQ
    │   └── ASP.NET Core
    │
    └── Java
```

### Example 3: Recursive flattening

```csharp
static IEnumerable<string> GetNames(Category category)
{
    yield return category.Name;

    foreach (Category child in category.Children)
    {
        foreach (string name in GetNames(child))
        {
            yield return name;
        }
    }
}

foreach (string name in GetNames(root))
{
    Console.WriteLine(name);
}
```

**Output:**

```text
Programming
C#
LINQ
ASP.NET Core
Java
```

### Example 4: Count nested categories

```csharp
static int CountCategories(Category category)
{
    return 1 + category.Children.Sum(CountCategories);
}

Console.WriteLine(CountCategories(root));
```

**Output:**

```text
5
```

**Key point:** Recursion allows the same processing logic to work at every nesting level.

## 8. Accumulator Parameters

An **accumulator parameter** carries an intermediate result through recursive calls.

Instead of waiting for recursive calls to return before combining values, each call passes updated state into the next call.

### Example 1: Factorial without accumulator

```csharp
static long Factorial(int number)
{
    if (number < 0)
        throw new ArgumentOutOfRangeException(nameof(number));

    if (number <= 1)
        return 1;

    return number * Factorial(number - 1);
}
```

### Example 2: Factorial with accumulator

```csharp
static long Factorial(int number, long accumulator)
{
    if (number < 0)
        throw new ArgumentOutOfRangeException(nameof(number));

    if (number <= 1)
        return accumulator;

    return Factorial(
        number - 1,
        checked(accumulator * number)
    );
}

Console.WriteLine(Factorial(5, 1));
```

**Output:**

```text
120
```

### Execution

```text
Factorial(5, 1)
    │
    ▼
Factorial(4, 5)
    │
    ▼
Factorial(3, 20)
    │
    ▼
Factorial(2, 60)
    │
    ▼
Factorial(1, 120)
    │
    ▼
120
```

### Example 3: Recursive sum using an accumulator

```csharp
static int Sum(
    int[] numbers,
    int index,
    int accumulator)
{
    if (index == numbers.Length)
        return accumulator;

    return Sum(
        numbers,
        index + 1,
        accumulator + numbers[index]
    );
}

int[] numbers = { 10, 20, 30 };

Console.WriteLine(Sum(numbers, 0, 0));
```

**Output:**

```text
60
```

### Comparison

| Without Accumulator | With Accumulator |
|---|---|
| Combines results after recursive calls return | Updates result before recursive call |
| Often has pending calculations | Can have no pending calculation |
| May be non-tail-recursive | Can be tail-recursive |
| State may be implicit in call stack | State is explicitly passed |

**Important:** An accumulator does not guarantee constant stack usage in C#.

**Key point:** Accumulator parameters make intermediate state explicit during recursion.

## 9. State Transformation

**State transformation** means converting an existing state into a new state.

In functional programming, a function often receives state as input and returns updated state as output.

### General pattern

```text
Old State
    │
    ▼
Transformation Function
    │
    ▼
New State
```

### Example 1: Simple numeric state

```csharp
static int Increment(int state)
{
    return state + 1;
}

int state1 = 10;
int state2 = Increment(state1);

Console.WriteLine(state1);
Console.WriteLine(state2);
```

**Output:**

```text
10
11
```

The original value remains unchanged.

### Example 2: State represented by a record

```csharp
public sealed record CounterState(
    int Count
);
```

Transformation:

```csharp
static CounterState Increment(CounterState state)
{
    return state with
    {
        Count = state.Count + 1
    };
}
```

Usage:

```csharp
CounterState initial = new(0);

CounterState first = Increment(initial);
CounterState second = Increment(first);

Console.WriteLine(initial.Count);
Console.WriteLine(first.Count);
Console.WriteLine(second.Count);
```

**Output:**

```text
0
1
2
```

### Example 3: Multiple state properties

```csharp
public sealed record AccountState(
    decimal Balance,
    int TransactionCount
);
```

```csharp
static AccountState Deposit(
    AccountState state,
    decimal amount)
{
    return state with
    {
        Balance = state.Balance + amount,
        TransactionCount = state.TransactionCount + 1
    };
}
```

Usage:

```csharp
AccountState initial = new(1000m, 0);

AccountState updated = Deposit(initial, 500m);

Console.WriteLine(initial.Balance);
Console.WriteLine(updated.Balance);
Console.WriteLine(updated.TransactionCount);
```

**Output:**

```text
1000
1500
1
```

**Key point:** Functional state transformation returns new state instead of changing the existing state in place.

## 10. Immutable State Transitions

An **immutable state transition** produces a new state object while preserving the previous one.

### Example 1: Immutable application state

```csharp
public sealed record AppState(
    int Counter,
    string Status
);
```

### Example 2: State transition function

```csharp
static AppState Increment(AppState state)
{
    return state with
    {
        Counter = state.Counter + 1
    };
}
```

### Example 3: Another transition

```csharp
static AppState ChangeStatus(
    AppState state,
    string status)
{
    return state with
    {
        Status = status
    };
}
```

### Example 4: Apply multiple transitions

```csharp
AppState initial = new(0, "Ready");

AppState first = Increment(initial);

AppState second = ChangeStatus(
    first,
    "Completed"
);

Console.WriteLine(
    $"{initial.Counter}, {initial.Status}"
);

Console.WriteLine(
    $"{first.Counter}, {first.Status}"
);

Console.WriteLine(
    $"{second.Counter}, {second.Status}"
);
```

**Output:**

```text
0, Ready
1, Ready
1, Completed
```

### State history

```text
Initial State
    │
    ▼
(0, Ready)
    │
    ▼
Increment
    │
    ▼
(1, Ready)
    │
    ▼
ChangeStatus
    │
    ▼
(1, Completed)
```

All previous states remain available.

### Important consideration

Records and `with` expressions provide shallow copying by default.

If a state record contains mutable collections or mutable reference-type objects, those nested objects can still change.

For reliable immutable state transitions, the entire relevant state graph should be immutable.

**Key point:** Immutable state transitions represent changes as new values rather than in-place mutations.

## 11. Stack Depth

**Stack depth** describes how many active method calls are present on the call stack.

Each recursive call generally adds another stack frame.

### Example 1: Recursive call depth

```csharp
static void PrintDepth(int depth)
{
    if (depth == 0)
        return;

    Console.WriteLine(depth);

    PrintDepth(depth - 1);
}

PrintDepth(4);
```

**Output:**

```text
4
3
2
1
```

### Call stack

```text
PrintDepth(4)
    │
    └── PrintDepth(3)
            │
            └── PrintDepth(2)
                    │
                    └── PrintDepth(1)
                            │
                            └── PrintDepth(0)
```

At the deepest point, multiple calls are active.

### Example 2: Measuring logical depth

```csharp
static int Depth(int number)
{
    if (number == 0)
        return 1;

    return 1 + Depth(number - 1);
}

Console.WriteLine(Depth(5));
```

**Output:**

```text
6
```

This calculates the number of calls along the recursive path, including the base-case call. It does not measure actual runtime stack memory.

### Complexity

For a simple recursive countdown:

```text
Time Complexity:  O(n)
Stack Space:      O(n)
```

For balanced recursive tree traversal:

```text
Stack Space: O(h)
```

Where `h` is the height of the tree.

A balanced tree may have logarithmic height, while a highly unbalanced tree can have linear height.

**Key point:** Recursive depth affects stack memory usage and program reliability.

## 12. Stack Overflow Risk

A **stack overflow** occurs when recursive calls exhaust the available call stack.

### Example 1: Infinite recursion

```csharp
static void Recurse()
{
    Recurse();
}
```

Calling `Recurse()` without a terminating condition can eventually cause a `StackOverflowException`.

**Do not execute this example.**

### Example 2: Deep recursion

```csharp
static int Sum(int number)
{
    if (number == 0)
        return 0;

    return number + Sum(number - 1);
}
```

For a sufficiently large positive input, this may exhaust the stack.

The maximum safe depth depends on the runtime, platform, stack size, and generated code.

### Example 3: Bounded recursion

```csharp
static int Sum(int number)
{
    if (number < 0 || number > 1000)
    {
        throw new ArgumentOutOfRangeException(
            nameof(number)
        );
    }

    if (number == 0)
        return 0;

    return number + Sum(number - 1);
}
```

This example limits the supported input range. It is not a universal guarantee against stack exhaustion.

### Common causes

| Cause | Explanation |
|---|---|
| Missing base case | Recursion never terminates |
| Incorrect base case | Stopping condition cannot be reached |
| No progress | Recursive arguments do not approach termination |
| Very deep input | Too many active calls |
| Cyclic structure | Traversal repeatedly revisits nodes |

### Important C# behavior

A `StackOverflowException` generally cannot be reliably recovered from with ordinary application-level exception handling.

Prevention is preferable to attempting recovery.

**Key point:** Use recursion only when termination and expected recursion depth are understood.

## 13. Tail Recursion Concepts

**Tail recursion** occurs when the recursive call is the final operation performed by a function.

### Example 1: Non-tail recursion

```csharp
static int Sum(int number)
{
    if (number == 0)
        return 0;

    return number + Sum(number - 1);
}
```

This is not tail-recursive because addition must occur after the recursive call returns.

```text
Sum(n - 1)
    │
    ▼
Add number
    │
    ▼
Return
```

### Example 2: Tail-recursive form

```csharp
static int Sum(int number, int accumulator)
{
    if (number == 0)
        return accumulator;

    return Sum(
        number - 1,
        accumulator + number
    );
}

Console.WriteLine(Sum(5, 0));
```

**Output:**

```text
15
```

The recursive call is the final operation.

### Execution

```text
Sum(5, 0)
    │
    ▼
Sum(4, 5)
    │
    ▼
Sum(3, 9)
    │
    ▼
Sum(2, 12)
    │
    ▼
Sum(1, 14)
    │
    ▼
Sum(0, 15)
    │
    ▼
15
```

### Comparison

| Non-Tail Recursion | Tail Recursion |
|---|---|
| Work remains after recursive call | Recursive call is the final operation |
| Often combines returned values | Often uses accumulators |
| Requires pending calculations | No pending calculation in the source logic |
| Can consume stack space | May be optimized in some environments |

**Key point:** Tail recursion restructures recursion so no additional calculation remains after the recursive call.

## 14. Tail-Call Assumptions

A **tail call** is a function call performed as the final action of another function.

Some languages and runtimes optimize tail calls so that they do not require an additional stack frame.

However, **C# does not guarantee tail-call optimization**.

### Example

```csharp
static long Factorial(
    int number,
    long accumulator)
{
    if (number <= 1)
        return accumulator;

    return Factorial(
        number - 1,
        accumulator * number
    );
}
```

The method is written in tail-recursive form.

That does not guarantee that the runtime will execute it using constant stack space.

### Important distinctions

| Concept | Meaning |
|---|---|
| Tail position | Function call is the final operation |
| Tail recursion | A function calls itself in tail position |
| Tail-call optimization | Runtime reuses or eliminates stack frames |
| C# guarantee | No general guarantee of tail-call optimization |

### Practical consequence

Do not assume this is safe for arbitrarily large inputs:

```csharp
return RecursiveMethod(nextState);
```

Even though the recursive call appears in tail position, stack usage may still increase.

### Safer alternative

For potentially very large recursion depths, use an iterative implementation.

**Key point:** Tail-recursive C# code must not depend on tail-call optimization for correctness.

## 15. Iterative Alternatives

An **iterative alternative** uses loops instead of recursive calls.

Iteration is often preferable for large, linear problems because it avoids deep call stacks.

### Example 1: Recursive sum

```csharp
static long SumRecursive(int number)
{
    if (number == 0)
        return 0;

    return number + SumRecursive(number - 1);
}
```

### Example 2: Iterative sum

```csharp
static long SumIterative(int number)
{
    if (number < 0)
        throw new ArgumentOutOfRangeException(nameof(number));

    long total = 0;

    for (int i = 1; i <= number; i++)
    {
        total += i;
    }

    return total;
}

Console.WriteLine(SumIterative(5));
```

**Output:**

```text
15
```

### Example 3: Iterative factorial

```csharp
static long Factorial(int number)
{
    if (number < 0 || number > 20)
        throw new ArgumentOutOfRangeException(nameof(number));

    long result = 1;

    for (int i = 2; i <= number; i++)
    {
        result = checked(result * i);
    }

    return result;
}

Console.WriteLine(Factorial(5));
```

**Output:**

```text
120
```

The upper bound prevents overflow of `long` for factorial inputs.

### Example 4: Iterative tree traversal

Using the `TreeNode` class from Point 6:

```csharp
static IEnumerable<int> Traverse(TreeNode? root)
{
    if (root is null)
        yield break;

    Stack<TreeNode> stack = new();

    stack.Push(root);

    while (stack.Count > 0)
    {
        TreeNode current = stack.Pop();

        yield return current.Value;

        if (current.Right is not null)
            stack.Push(current.Right);

        if (current.Left is not null)
            stack.Push(current.Left);
    }
}
```

This uses an explicit stack rather than recursive method calls.

### Comparison

| Recursion | Iteration |
|---|---|
| Uses recursive method calls | Uses loops |
| Often natural for trees | Often natural for linear sequences |
| Consumes call-stack space | Can use constant call-stack space |
| May be concise | Often easier to control for large inputs |
| Deep recursion can overflow | Avoids recursion-related stack overflow |

**Key point:** Iteration is a practical alternative when recursion depth may become excessive.

## 16. Memoization

**Memoization** is an optimization technique that stores previously computed results so repeated calculations can reuse them.

It is especially useful for recursive functions with overlapping subproblems.

### Example 1: Fibonacci without memoization

```csharp
static long Fibonacci(int number)
{
    if (number <= 1)
        return number;

    return Fibonacci(number - 1)
         + Fibonacci(number - 2);
}
```

For `Fibonacci(5)`:

```text
Fibonacci(5)
    │
    ├── Fibonacci(4)
    │       ├── Fibonacci(3)
    │       └── Fibonacci(2)
    │
    └── Fibonacci(3)
            ├── Fibonacci(2)
            └── Fibonacci(1)
```

The same values are calculated repeatedly.

### Example 2: Fibonacci with memoization

```csharp
static long Fibonacci(
    int number,
    Dictionary<int, long> cache)
{
    if (number <= 1)
        return number;

    if (cache.TryGetValue(number, out long result))
        return result;

    result = checked(
        Fibonacci(number - 1, cache)
        + Fibonacci(number - 2, cache)
    );

    cache[number] = result;

    return result;
}

Dictionary<int, long> cache = new();

Console.WriteLine(Fibonacci(10, cache));
```

**Output:**

```text
55
```

For this implementation, use nonnegative inputs no greater than 92 to keep Fibonacci values within `long`.

### How memoization works

```text
Fibonacci(5)
    │
    ▼
Check Cache
    │
    ├── Found ──────► Return Cached Result
    │
    └── Not Found
            │
            ▼
       Calculate Result
            │
            ▼
        Store in Cache
            │
            ▼
         Return Result
```

### Complexity comparison

| Approach | Time Complexity | Extra Storage |
|---|---|---|
| Naive Fibonacci recursion | Exponential | O(n) call stack |
| Memoized Fibonacci recursion | O(n) | O(n) cache plus call stack |

### Important consideration

The calculation being memoized should be deterministic for its cache key.

Memoizing a function that depends on changing external state can return stale or incorrect results.

**Key point:** Memoization improves performance by reusing results of previously solved subproblems.

## 17. Cache Keys

A **cache key** identifies a previously computed result.

For memoization to be correct, the key must distinguish inputs that can produce different outputs.

### Example 1: Single-parameter key

```csharp
Dictionary<int, long> cache = new();
```

For Fibonacci:

```text
Key:   10
Value: 55
```

The function depends on one integer input, so that integer can serve as the key.

### Example 2: Multiple-parameter function

```csharp
static int Calculate(int a, int b)
{
    return a * a + b;
}
```

Both parameters affect the result.

An appropriate cache is:

```csharp
Dictionary<(int A, int B), int> cache = new();
```

### Example 3: Memoize multiple parameters

```csharp
static int Calculate(
    int a,
    int b,
    Dictionary<(int, int), int> cache)
{
    var key = (a, b);

    if (cache.TryGetValue(key, out int result))
        return result;

    result = a * a + b;

    cache[key] = result;

    return result;
}

var cache = new Dictionary<(int, int), int>();

Console.WriteLine(Calculate(3, 4, cache));
Console.WriteLine(Calculate(3, 4, cache));
Console.WriteLine(Calculate(3, 5, cache));
```

**Output:**

```text
13
13
14
```

### Cache-key requirements

| Requirement | Explanation |
|---|---|
| Complete | Includes all inputs affecting the result |
| Stable | Does not change while stored |
| Correct equality | Equal keys represent equivalent computations |
| Correct hashing | Equal keys produce equal hash codes |
| Efficient | Can be compared and hashed reasonably quickly |

### Incorrect key example

Suppose a function depends on both `price` and `taxRate`.

Using only `price` as the cache key is incorrect because different tax rates can produce different results.

**Key point:** Correct memoization requires cache keys that represent every input affecting the computation.

## 18. Cache Lifetime

**Cache lifetime** describes how long memoized results remain stored and reusable.

Different cache lifetimes affect memory usage, performance, and correctness.

### Common cache lifetimes

| Lifetime | Description |
|---|---|
| Single invocation | Cache exists during one calculation |
| Object lifetime | Cache exists while an object is alive |
| Application lifetime | Cache may remain for the application process |
| Time-limited | Entries expire after a configured duration |

### Example 1: Cache local to one operation

```csharp
static long Fibonacci(int number)
{
    Dictionary<int, long> cache = new();

    return Calculate(number);

    long Calculate(int n)
    {
        if (n <= 1)
            return n;

        if (cache.TryGetValue(n, out long value))
            return value;

        value = checked(
            Calculate(n - 1) + Calculate(n - 2)
        );

        cache[n] = value;

        return value;
    }
}

Console.WriteLine(Fibonacci(10));
```

**Output:**

```text
55
```

The cache is created for each call to `Fibonacci()`.

When the call finishes and nothing references the cache, it becomes eligible for garbage collection.

### Example 2: Cache stored in an object

```csharp
public sealed class FibonacciCalculator
{
    private readonly Dictionary<int, long> _cache = new();

    public long Calculate(int number)
    {
        if (number < 0 || number > 92)
            throw new ArgumentOutOfRangeException(
                nameof(number)
            );

        if (number <= 1)
            return number;

        if (_cache.TryGetValue(number, out long value))
            return value;

        value = checked(
            Calculate(number - 1)
            + Calculate(number - 2)
        );

        _cache[number] = value;

        return value;
    }
}
```

Usage:

```csharp
var calculator = new FibonacciCalculator();

Console.WriteLine(calculator.Calculate(10));
Console.WriteLine(calculator.Calculate(20));
```

**Output:**

```text
55
6765
```

The cache is reused across calls to the same calculator instance.

This implementation is not safe for unsynchronized concurrent access to its dictionary.

### Cache-lifetime tradeoffs

**Short lifetime:**

- Uses memory for a shorter period.
- Provides less reuse across operations.
- Simplifies cache management.

**Long lifetime:**

- May provide more cache hits.
- Can consume more memory.
- May retain outdated results if dependencies change.
- May require synchronization when shared.

**Key point:** Cache lifetime should balance result reuse, memory consumption, and correctness.

## 19. Bounded Memoization

**Bounded memoization** limits the number of cached results or the resources consumed by a cache.

An unbounded cache can grow indefinitely as new input values are encountered.

### Example 1: Unbounded cache

```csharp
Dictionary<int, int> cache = new();

for (int i = 0; i < 100000; i++)
{
    cache[i] = i * 2;
}
```

This stores 100,000 entries.

If new keys continue arriving, memory usage continues growing.

### Example 2: Simple bounded cache

```csharp
public sealed class BoundedSquareCache
{
    private readonly Dictionary<int, long> _cache = new();

    private readonly Queue<int> _insertionOrder = new();

    private readonly int _capacity;

    public BoundedSquareCache(int capacity)
    {
        if (capacity <= 0)
        {
            throw new ArgumentOutOfRangeException(
                nameof(capacity)
            );
        }

        _capacity = capacity;
    }

    public long Calculate(int number)
    {
        if (_cache.TryGetValue(number, out long result))
            return result;

        result = (long)number * number;

        if (_cache.Count >= _capacity)
        {
            int oldestKey = _insertionOrder.Dequeue();

            _cache.Remove(oldestKey);
        }

        _cache[number] = result;

        _insertionOrder.Enqueue(number);

        return result;
    }

    public int CachedCount => _cache.Count;
}
```

### Example 3: Usage

```csharp
var calculator = new BoundedSquareCache(3);

Console.WriteLine(calculator.Calculate(2));
Console.WriteLine(calculator.Calculate(3));
Console.WriteLine(calculator.Calculate(4));

Console.WriteLine(calculator.CachedCount);

Console.WriteLine(calculator.Calculate(5));

Console.WriteLine(calculator.CachedCount);
```

**Output:**

```text
4
9
16
3
25
3
```

The cache never stores more than three entries during this sequential execution.

### Eviction behavior

```text
Capacity = 3

Insert 2:
[2]

Insert 3:
[2, 3]

Insert 4:
[2, 3, 4]

Insert 5:
[3, 4, 5]
```

The oldest inserted entry is removed.

This is a simple **FIFO eviction strategy**, not a least-recently-used strategy.

### Important limitations

The example is intended for sequential use. It is not thread-safe.

A production cache may also need to consider entry sizes, expiration, concurrent access, and eviction policy.

### Bounded vs unbounded memoization

| Feature | Unbounded Cache | Bounded Cache |
|---|---|---|
| Maximum entry count | No explicit limit | Configured limit |
| Memory growth | Can continue increasing | Controlled by capacity |
| Result reuse | Potentially higher | Depends on eviction |
| Eviction | Not required | Required when full |
| Implementation | Simpler | More complex |

**Key point:** Bounded memoization controls memory growth by limiting retained cached results.
