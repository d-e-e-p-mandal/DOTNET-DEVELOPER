# 09.04 — CLOSURES

**Chapter:** 09 — Functional C#  
**Total Syllabus Points:** 16  
**Language:** C#  
**Namespace:** `System`

A **closure** is a function that captures variables from its surrounding scope and can continue accessing those variables even after the original scope has finished executing.

Closures are commonly created using lambda expressions, anonymous methods, and local functions.

They are important in functional programming, delegates, LINQ, callbacks, and asynchronous programming.

This section covers all **16 syllabus points in their original order**.

---

## 1. Closure Concept

A closure combines a function with access to variables from its surrounding scope.

### Basic example

```csharp
int number = 10;

Func<int> getNumber = () => number;

Console.WriteLine(getNumber());
```

**Output:**

```text
10
```

Here:

```csharp
() => number
```

captures the local variable `number`.

The lambda can access that variable even though `number` is not a parameter of the lambda.

### Example 2: Closure with calculation

```csharp
int multiplier = 5;

Func<int, int> multiply =
    number => number * multiplier;

Console.WriteLine(multiply(10));
Console.WriteLine(multiply(20));
```

**Output:**

```text
50
100
```

The lambda receives `number` as a parameter and captures `multiplier` from its surrounding scope.

### Example 3: Closure returned from a method

```csharp
static Func<int> CreateCounter()
{
    int count = 0;

    return () =>
    {
        count++;
        return count;
    };
}

Func<int> counter = CreateCounter();

Console.WriteLine(counter());
Console.WriteLine(counter());
Console.WriteLine(counter());
```

**Output:**

```text
1
2
3
```

Although `CreateCounter()` has returned, the captured variable `count` remains accessible through the returned function.

### Closure structure

```text
Surrounding Scope
       │
       ├── Local Variable
       │       count = 0
       │
       └── Lambda Expression
               │
               └── Captures count
                       │
                       ▼
                    Closure
```

**Key point:** A closure allows a function to retain access to variables from its surrounding scope.

## 2. Captured Variables

A **captured variable** is a variable declared outside a function but accessed inside that function.

### Example 1: Capture an integer

```csharp
int value = 100;

Func<int> function = () => value;

Console.WriteLine(function());
```

**Output:**

```text
100
```

### Example 2: Capture multiple variables

```csharp
int a = 10;
int b = 20;

Func<int> calculate = () => a + b;

Console.WriteLine(calculate());
```

**Output:**

```text
30
```

Both `a` and `b` are captured.

### Example 3: Capture a string

```csharp
string prefix = "Hello";

Func<string, string> greet =
    name => $"{prefix} {name}";

Console.WriteLine(greet("Amit"));
Console.WriteLine(greet("Rahul"));
```

**Output:**

```text
Hello Amit
Hello Rahul
```

### Example 4: Capture a variable used in LINQ

```csharp
int minimum = 3;

int[] numbers = { 1, 2, 3, 4, 5 };

var result = numbers.Where(
    number => number > minimum
);

Console.WriteLine(
    string.Join(", ", result)
);
```

**Output:**

```text
4, 5
```

The LINQ predicate captures `minimum`.

**Key point:** A captured variable belongs to the surrounding scope but is accessible inside the closure.

## 3. Captured State

Captured state refers to data retained and accessed by a closure.

Closures can preserve state between function calls.

### Example 1: Stateful counter

```csharp
static Func<int> CreateCounter()
{
    int count = 0;

    return () => ++count;
}

var counter = CreateCounter();

Console.WriteLine(counter());
Console.WriteLine(counter());
Console.WriteLine(counter());
```

**Output:**

```text
1
2
3
```

### Example 2: Independent captured states

```csharp
static Func<int> CreateCounter()
{
    int count = 0;

    return () => ++count;
}

var first = CreateCounter();
var second = CreateCounter();

Console.WriteLine(first());
Console.WriteLine(first());

Console.WriteLine(second());
Console.WriteLine(second());
```

**Output:**

```text
1
2
1
2
```

Each call to `CreateCounter()` creates a separate captured `count` variable.

### Example 3: Accumulating values

```csharp
static Func<int, int> CreateAccumulator()
{
    int total = 0;

    return value =>
    {
        total += value;
        return total;
    };
}

var accumulate = CreateAccumulator();

Console.WriteLine(accumulate(10));
Console.WriteLine(accumulate(20));
Console.WriteLine(accumulate(30));
```

**Output:**

```text
10
30
60
```

### Example 4: Shared captured state

```csharp
int count = 0;

Func<int> increment = () => ++count;
Func<int> decrement = () => --count;

Console.WriteLine(increment());
Console.WriteLine(increment());
Console.WriteLine(decrement());
```

**Output:**

```text
1
2
1
```

Both delegates access the same captured variable.

**Key point:** Captured state can persist across invocations and may be shared between multiple closures.

## 5. Capturing Parameters

Lambda expressions can capture parameters from their enclosing methods.

This is common when creating configurable functions.

### Example 1: Capture a multiplier parameter

```csharp
static Func<int, int> CreateMultiplier(int factor)
{
    return number => number * factor;
}

var multiplyByThree = CreateMultiplier(3);

Console.WriteLine(multiplyByThree(10));
```

**Output:**

```text
30
```

`factor` is captured by the returned lambda.

### Example 2: Capture an addition parameter

```csharp
static Func<int, int> CreateAdder(int amount)
{
    return number => number + amount;
}

var addTen = CreateAdder(10);
var addTwenty = CreateAdder(20);

Console.WriteLine(addTen(5));
Console.WriteLine(addTwenty(5));
```

**Output:**

```text
15
25
```

### Example 3: Capture multiple parameters

```csharp
static Func<int, bool> CreateRangeValidator(
    int minimum,
    int maximum
)
{
    return value =>
        value >= minimum &&
        value <= maximum;
}

var validator = CreateRangeValidator(10, 20);

Console.WriteLine(validator(15));
Console.WriteLine(validator(25));
```

**Output:**

```text
True
False
```

### Example 4: Capture a string parameter

```csharp
static Func<string, string> CreatePrefixer(
    string prefix
)
{
    return value => prefix + value;
}

var addTitle = CreatePrefixer("Mr. ");

Console.WriteLine(addTitle("Rahul"));
```

**Output:**

```text
Mr. Rahul
```

**Key point:** Capturing parameters allows functions to retain configuration values supplied to their enclosing methods.

## 6. Capturing this

An instance lambda can capture `this`, giving it access to the current object.

### Example 1: Access an instance field

```csharp
class Calculator
{
    private int multiplier = 5;

    public Func<int, int> GetMultiplier()
    {
        return number => number * multiplier;
    }
}
```

Usage:

```csharp
Calculator calculator = new();

var multiply = calculator.GetMultiplier();

Console.WriteLine(multiply(10));
```

**Output:**

```text
50
```

The lambda accesses the instance field through the current object.

### Example 2: Explicitly capture `this`

```csharp
class Employee
{
    public string Name { get; set; } = "Amit";

    public Func<string> GetNameFunction()
    {
        return () => this.Name;
    }
}
```

Usage:

```csharp
Employee employee = new();

Func<string> getName = employee.GetNameFunction();

Console.WriteLine(getName());

employee.Name = "Rahul";

Console.WriteLine(getName());
```

**Output:**

```text
Amit
Rahul
```

The closure reads the current property value from the captured object.

### Example 3: Capture an instance property

```csharp
class PriceCalculator
{
    public decimal TaxRate { get; set; } = 0.10m;

    public Func<decimal, decimal> CreateCalculator()
    {
        return price => price * (1 + TaxRate);
    }
}
```

Usage:

```csharp
PriceCalculator calculator = new();

var calculate = calculator.CreateCalculator();

Console.WriteLine(calculate(1000));

calculator.TaxRate = 0.20m;

Console.WriteLine(calculate(1000));
```

**Output:**

```text
1100.00
1200.00
```

### Important behavior

Capturing `this` can keep the containing object alive while the closure remains reachable.

**Key point:** Instance lambdas can capture the current object and access its fields, properties, and methods.

## 7. Capturing Variable vs Value

A closure generally captures a **variable**, not a fixed snapshot of its value.

This distinction is essential for understanding closures.

### Example 1: Captured variable

```csharp
int number = 10;

Func<int> getNumber = () => number;

Console.WriteLine(getNumber());

number = 20;

Console.WriteLine(getNumber());
```

**Output:**

```text
10
20
```

The closure observes the updated value.

### Example 2: Capture a snapshot through a separate variable

```csharp
int number = 10;

int snapshot = number;

Func<int> getNumber = () => snapshot;

number = 20;

Console.WriteLine(getNumber());
```

**Output:**

```text
10
```

The lambda captures `snapshot`, which was initialized with the original value.

### Example 3: Two closures sharing a variable

```csharp
int value = 10;

Func<int> first = () => value;
Func<int> second = () => value * 2;

value = 20;

Console.WriteLine(first());
Console.WriteLine(second());
```

**Output:**

```text
20
40
```

### Example 4: Separate captured variables

```csharp
int a = 10;
int b = 20;

Func<int> first = () => a;
Func<int> second = () => b;

a = 100;

Console.WriteLine(first());
Console.WriteLine(second());
```

**Output:**

```text
100
20
```

### Comparison

| Capturing Variable | Capturing a Snapshot Variable |
|---|---|
| Reads the captured variable | Reads a separate snapshot variable |
| Changes to the captured variable are visible | Changes to the original variable are not reflected |
| Can share mutable state | Can preserve an earlier value |
| Useful for stateful closures | Useful for stable configuration |

**Key point:** Closures capture variable storage, so later changes to that variable can affect the function's result.

## 8. Closure Lifetime

A captured variable can remain alive after the method that declared it returns.

Its lifetime depends on whether the closure retaining it remains reachable.

### Example 1: Closure outliving its method

```csharp
static Func<int> CreateFunction()
{
    int value = 100;

    return () => value;
}

Func<int> function = CreateFunction();

Console.WriteLine(function());
```

**Output:**

```text
100
```

### Example 2: Captured state persists

```csharp
static Func<int> CreateCounter()
{
    int count = 0;

    return () => ++count;
}

Func<int> counter = CreateCounter();

Console.WriteLine(counter());
Console.WriteLine(counter());
```

**Output:**

```text
1
2
```

### Example 3: Independent closure lifetimes

```csharp
static Func<int> CreateCounter()
{
    int count = 0;

    return () => ++count;
}

var first = CreateCounter();
var second = CreateCounter();

Console.WriteLine(first());
Console.WriteLine(second());
Console.WriteLine(first());
```

**Output:**

```text
1
1
2
```

### Example 4: Release a delegate reference

```csharp
static Func<int> CreateFunction()
{
    int value = 50;

    return () => value;
}

Func<int>? function = CreateFunction();

Console.WriteLine(function());

function = null;
```

**Output:**

```text
50
```

Assigning `null` removes that reference to the delegate.

If no other references keep the closure reachable, its associated objects may become eligible for garbage collection.

Garbage collection does not necessarily occur immediately.

**Key point:** Captured variables can outlive their declaring method when reachable closures still need them.

## 9. Mutable Captures

A mutable capture occurs when a closure accesses a variable whose value can change.

Mutable captures introduce state into functions.

### Example 1: Increment captured state

```csharp
int count = 0;

Func<int> increment = () => ++count;

Console.WriteLine(increment());
Console.WriteLine(increment());
Console.WriteLine(increment());
```

**Output:**

```text
1
2
3
```

### Example 2: Modify a captured string variable

```csharp
string message = "Hello";

Func<string> getMessage = () => message;

Console.WriteLine(getMessage());

message = "Welcome";

Console.WriteLine(getMessage());
```

**Output:**

```text
Hello
Welcome
```

### Example 3: Mutable captured collection

```csharp
List<int> numbers = new()
{
    1, 2, 3
};

Func<int> getCount = () => numbers.Count;

Console.WriteLine(getCount());

numbers.Add(4);

Console.WriteLine(getCount());
```

**Output:**

```text
3
4
```

### Example 4: Shared mutable capture

```csharp
int balance = 100;

Action<int> deposit = amount =>
{
    balance += amount;
};

Action<int> withdraw = amount =>
{
    balance -= amount;
};

deposit(50);
withdraw(20);

Console.WriteLine(balance);
```

**Output:**

```text
130
```

### Example 5: Avoid mutable capture using explicit input

Instead of:

```csharp
int multiplier = 2;

Func<int, int> multiply =
    number => number * multiplier;
```

Use:

```csharp
static int Multiply(int number, int multiplier)
{
    return number * multiplier;
}

Console.WriteLine(Multiply(10, 2));
```

**Output:**

```text
20
```

The second version makes all calculation inputs explicit.

**Key point:** Mutable captures are useful for maintaining state but can make functions harder to reason about.

## 10. Loop-Variable Capture

Loop-variable capture is a common source of unexpected behavior.

The result depends on how the loop variable is declared.

### Example 1: Capturing a `for` loop variable

```csharp
List<Func<int>> functions = new();

for (int i = 0; i < 3; i++)
{
    functions.Add(() => i);
}

foreach (var function in functions)
{
    Console.WriteLine(function());
}
```

**Output:**

```text
3
3
3
```

**Explanation:**

The lambdas capture the same variable `i`.

After the loop finishes, `i` equals `3`.

When the functions execute, they all read that value.

### Example 2: Correct `for` loop capture

```csharp
List<Func<int>> functions = new();

for (int i = 0; i < 3; i++)
{
    int copy = i;

    functions.Add(() => copy);
}

foreach (var function in functions)
{
    Console.WriteLine(function());
}
```

**Output:**

```text
0
1
2
```

Each iteration creates a separate `copy` variable.

### Example 3: Capturing a `foreach` iteration variable

```csharp
List<Func<int>> functions = new();

foreach (int number in new[] { 10, 20, 30 })
{
    functions.Add(() => number);
}

foreach (var function in functions)
{
    Console.WriteLine(function());
}
```

**Output:**

```text
10
20
30
```

In modern C#, each `foreach` iteration has its own iteration variable.

### Example 4: Capture a loop value in a function factory

```csharp
static Func<int> CreateFunction(int value)
{
    return () => value;
}

List<Func<int>> functions = new();

for (int i = 0; i < 3; i++)
{
    functions.Add(CreateFunction(i));
}

foreach (var function in functions)
{
    Console.WriteLine(function());
}
```

**Output:**

```text
0
1
2
```

Each factory invocation captures its own parameter.

### Comparison

| Loop | Capture Behavior |
|---|---|
| `for` | Closures can share the same loop variable |
| `for` with local copy | Each iteration captures a separate variable |
| Modern C# `foreach` | Each iteration has a distinct iteration variable |
| Function factory | Each invocation has its own parameter |

**Key point:** When capturing a `for` loop variable, create an iteration-local copy if each closure needs its own value.

## 11. Deferred Execution + Closures

LINQ queries often use deferred execution.

This means the query's operations execute when the sequence is enumerated rather than when the query is constructed.

When a LINQ lambda captures a variable, its value may change before enumeration.

### Example 1: Captured variable changes before execution

```csharp
int minimum = 2;

int[] numbers = { 1, 2, 3, 4, 5 };

var query = numbers.Where(
    x => x > minimum
);

minimum = 4;

Console.WriteLine(
    string.Join(", ", query)
);
```

**Output:**

```text
5
```

The query uses the value `4` because enumeration happens after `minimum` changes.

### Example 2: Enumerating the same query twice

```csharp
int minimum = 2;

int[] numbers = { 1, 2, 3, 4, 5 };

var query = numbers.Where(
    x => x > minimum
);

Console.WriteLine(
    string.Join(", ", query)
);

minimum = 3;

Console.WriteLine(
    string.Join(", ", query)
);
```

**Output:**

```text
3, 4, 5
4, 5
```

### Example 3: Materialization fixes the result at execution time

```csharp
int minimum = 2;

int[] numbers = { 1, 2, 3, 4, 5 };

var result = numbers
    .Where(x => x > minimum)
    .ToList();

minimum = 4;

Console.WriteLine(
    string.Join(", ", result)
);
```

**Output:**

```text
3, 4, 5
```

The query was executed by `ToList()` before `minimum` changed.

### Example 4: Deferred execution with mutable state

```csharp
int multiplier = 2;

int[] numbers = { 1, 2, 3 };

var query = numbers.Select(
    x => x * multiplier
);

multiplier = 10;

Console.WriteLine(
    string.Join(", ", query)
);
```

**Output:**

```text
10, 20, 30
```

### Example 5: Preserve a value for a deferred query

```csharp
int multiplier = 2;

int capturedMultiplier = multiplier;

int[] numbers = { 1, 2, 3 };

var query = numbers.Select(
    x => x * capturedMultiplier
);

multiplier = 10;

Console.WriteLine(
    string.Join(", ", query)
);
```

**Output:**

```text
2, 4, 6
```

**Key point:** Deferred LINQ queries read captured variables when their lambdas execute, which may be later than query construction.

## 12. Closure Allocation

Closures may require additional runtime objects to store captured variables.

The compiler can generate an object that holds captured state and arrange for a delegate to reference code that accesses that state.

The exact allocation behavior depends on the compiler, runtime, and surrounding code.

### Example 1: Capturing lambda

```csharp
int multiplier = 10;

Func<int, int> multiply =
    number => number * multiplier;

Console.WriteLine(multiply(5));
```

**Output:**

```text
50
```

The lambda needs access to `multiplier` outside its own parameter list.

### Example 2: Noncapturing lambda

```csharp
Func<int, int> square =
    number => number * number;

Console.WriteLine(square(5));
```

**Output:**

```text
25
```

This lambda does not capture external variables.

The compiler may cache its delegate.

### Example 3: Repeated creation of capturing delegates

```csharp
static Func<int, int> CreateMultiplier(int factor)
{
    return x => x * factor;
}

var first = CreateMultiplier(2);
var second = CreateMultiplier(3);

Console.WriteLine(first(10));
Console.WriteLine(second(10));
```

**Output:**

```text
20
30
```

Each invocation requires independently retained configuration state.

### Example 4: Avoid capture when unnecessary

**Capturing:**

```csharp
int factor = 2;

Func<int, int> multiply =
    x => x * factor;
```

**Noncapturing:**

```csharp
Func<int, int, int> multiply =
    (x, factor) => x * factor;

Console.WriteLine(multiply(10, 2));
```

**Output:**

```text
20
```

The second function receives all required values as parameters.

### Allocation considerations

| Lambda Type | Captures External State | Allocation Consideration |
|---|---|---|
| Capturing lambda | Yes | May require closure storage |
| Noncapturing lambda | No | Delegate may be cached |
| Static lambda | No | Capture is prohibited |
| Lambda with explicit parameters | Not necessarily | Can avoid captured-state storage |

**Key point:** Capturing lambdas may introduce allocation overhead. Avoid unnecessary captures in performance-sensitive code, but measure before optimizing.

## 13. Retained Objects

A closure can keep objects reachable longer than expected.

If a closure captures an object, the object may remain alive as long as the closure or its associated captured state is reachable.

### Example 1: Capture a collection

```csharp
static Func<int> CreateCounter()
{
    List<int> numbers = new()
    {
        10, 20, 30
    };

    return () => numbers.Count;
}

Func<int> counter = CreateCounter();

Console.WriteLine(counter());
```

**Output:**

```text
3
```

The closure retains access to the list after `CreateCounter()` returns.

### Example 2: Capture a large array

```csharp
static Func<int> CreateFunction()
{
    int[] numbers = new int[1_000_000];

    return () => numbers.Length;
}

Func<int> function = CreateFunction();

Console.WriteLine(function());
```

**Output:**

```text
1000000
```

The captured reference can keep the array reachable.

### Example 3: Avoid retaining a collection unnecessarily

Instead of capturing the entire array:

```csharp
static Func<int> CreateFunction()
{
    int[] numbers = new int[1_000_000];

    return () => numbers.Length;
}
```

Capture only the required value:

```csharp
static Func<int> CreateFunction()
{
    int[] numbers = new int[1_000_000];

    int length = numbers.Length;

    return () => length;
}

var function = CreateFunction();

Console.WriteLine(function());
```

**Output:**

```text
1000000
```

The returned lambda references `length`, not the array.

### Example 4: Capturing an object instance

```csharp
class Employee
{
    public string Name { get; set; } = "Amit";

    public Func<string> GetNameReader()
    {
        return () => Name;
    }
}
```

Usage:

```csharp
Employee employee = new();

Func<string> reader = employee.GetNameReader();

Console.WriteLine(reader());
```

**Output:**

```text
Amit
```

The returned delegate can keep the `Employee` instance reachable.

**Key point:** Capture only the state needed by a closure, especially when dealing with large or long-lived objects.

## 14. Thread-Safety Problems

Closures that access shared mutable variables can create thread-safety problems.

When multiple threads modify the same captured state without synchronization, race conditions may occur.

### Example 1: Shared captured counter

```csharp
int count = 0;

Action increment = () =>
{
    count++;
};

Parallel.For(0, 1000, _ =>
{
    increment();
});

Console.WriteLine(count);
```

**Output:**

```text
Value may be less than 1000.
```

The increment operation is not atomic.

Multiple threads may read and update `count` concurrently.

### Example 2: Thread-safe increment

```csharp
int count = 0;

Action increment = () =>
{
    Interlocked.Increment(ref count);
};

Parallel.For(0, 1000, _ =>
{
    increment();
});

Console.WriteLine(count);
```

**Output:**

```text
1000
```

`Interlocked.Increment()` performs an atomic increment.

### Example 3: Avoid shared mutable capture

```csharp
int[] numbers = Enumerable.Range(1, 5).ToArray();

int[] result = numbers
    .AsParallel()
    .Select(x => x * x)
    .ToArray();

Console.WriteLine(
    string.Join(", ", result.OrderBy(x => x))
);
```

**Output:**

```text
1, 4, 9, 16, 25
```

The selector uses only its input and does not mutate shared state.

### Example 4: Thread-safe accumulation

```csharp
int total = 0;

Action<int> add = value =>
{
    Interlocked.Add(ref total, value);
};

Parallel.For(1, 6, number =>
{
    add(number);
});

Console.WriteLine(total);
```

**Output:**

```text
15
```

### Thread-safety comparison

| Approach | Thread-Safety Consideration |
|---|---|
| Mutable captured variable | Can introduce races |
| Read-only captured immutable value | Generally safe to read concurrently |
| `Interlocked` | Supports specific atomic operations |
| `lock` | Protects critical sections |
| Pure functions | Avoid shared-state mutation |

**Key point:** Closures do not automatically make shared state thread-safe. Synchronize mutable captured state or avoid sharing it.

## 15. Static Lambdas

A `static` lambda expression cannot capture local variables, parameters, or `this` from its enclosing scope.

Static lambdas were introduced in C# 9.

### Syntax

```csharp
static parameters => expression
```

### Example 1: Basic static lambda

```csharp
Func<int, int> square =
    static x => x * x;

Console.WriteLine(square(5));
```

**Output:**

```text
25
```

### Example 2: Static lambda with multiple parameters

```csharp
Func<int, int, int> add =
    static (a, b) => a + b;

Console.WriteLine(add(10, 20));
```

**Output:**

```text
30
```

### Example 3: Static lambda in LINQ

```csharp
int[] numbers = { 1, 2, 3, 4, 5, 6 };

var result = numbers.Where(
    static x => x % 2 == 0
);

Console.WriteLine(
    string.Join(", ", result)
);
```

**Output:**

```text
2, 4, 6
```

### Example 4: Capturing is prohibited

The following code produces a compilation error:

```csharp
int multiplier = 10;

Func<int, int> multiply =
    static x => x * multiplier;
```

**Error:**

```text
A static anonymous function cannot contain
a reference to 'multiplier'.
```

The lambda attempts to capture a local variable.

### Example 5: Correct static lambda using explicit inputs

```csharp
Func<int, int, int> multiply =
    static (number, multiplier) =>
        number * multiplier;

Console.WriteLine(multiply(5, 10));
```

**Output:**

```text
50
```

### Example 6: Static lambda with a constant

```csharp
const int multiplier = 10;

Func<int, int> multiply =
    static number => number * multiplier;

Console.WriteLine(multiply(5));
```

**Output:**

```text
50
```

Compile-time constants can be referenced without capturing runtime state.

### Static vs ordinary lambdas

| Feature | Ordinary Lambda | Static Lambda |
|---|---|---|
| Capture local variables | Yes | No |
| Capture parameters | Yes | No |
| Capture `this` | Yes | No |
| Access static members | Yes | Yes |
| Use lambda parameters | Yes | Yes |
| Reference constants | Yes | Yes |
| Prevent accidental capture | No | Yes |

**Key point:** Use static lambdas when no captured state is required and you want the compiler to enforce that restriction.

## 16. Explicit State instead of Capture

Instead of capturing values from the surrounding scope, a function can receive its required state through explicit parameters.

This makes dependencies visible and often simplifies reasoning, testing, and concurrency.

### Example 1: Captured multiplier

```csharp
int multiplier = 5;

Func<int, int> multiply =
    number => number * multiplier;

Console.WriteLine(multiply(10));
```

**Output:**

```text
50
```

The multiplier is an implicit dependency.

### Example 2: Explicit multiplier parameter

```csharp
Func<int, int, int> multiply =
    static (number, multiplier) =>
        number * multiplier;

Console.WriteLine(multiply(10, 5));
```

**Output:**

```text
50
```

Both values are explicit inputs.

### Example 3: Captured validation state

```csharp
int minimumAge = 18;

Func<int, bool> isAdult =
    age => age >= minimumAge;

Console.WriteLine(isAdult(20));
```

**Output:**

```text
True
```

### Example 4: Explicit validation state

```csharp
static bool IsAdult(
    int age,
    int minimumAge
)
{
    return age >= minimumAge;
}

Console.WriteLine(IsAdult(20, 18));
Console.WriteLine(IsAdult(16, 18));
```

**Output:**

```text
True
False
```

### Example 5: Explicit state in LINQ

A LINQ predicate normally accepts the element, not arbitrary additional state.

One option is to use a named helper method and pass the state through an enclosing function.

```csharp
static IEnumerable<int> FilterGreaterThan(
    IEnumerable<int> numbers,
    int minimum
)
{
    return numbers.Where(
        number => number > minimum
    );
}

int[] numbers = { 1, 2, 3, 4, 5 };

var result = FilterGreaterThan(numbers, 3);

Console.WriteLine(
    string.Join(", ", result)
);
```

**Output:**

```text
4, 5
```

Here, the public method receives `minimum` explicitly, although its internal LINQ lambda still captures that parameter.

### Example 6: Avoid capture using a static lambda with explicit state

```csharp
static IEnumerable<int> FilterGreaterThan(
    IEnumerable<int> numbers,
    int minimum
)
{
    return numbers.Where(
        number => IsGreaterThan(number, minimum)
    );
}

static bool IsGreaterThan(
    int number,
    int minimum
)
{
    return number > minimum;
}
```

The helper method has explicit inputs, but the lambda passed to `Where()` still captures `minimum`.

To avoid that capture entirely, use a direct loop:

```csharp
static IEnumerable<int> FilterGreaterThan(
    IEnumerable<int> numbers,
    int minimum
)
{
    foreach (int number in numbers)
    {
        if (IsGreaterThan(number, minimum))
        {
            yield return number;
        }
    }
}

static bool IsGreaterThan(
    int number,
    int minimum
)
{
    return number > minimum;
}

int[] numbers = { 1, 2, 3, 4, 5 };

Console.WriteLine(
    string.Join(
        ", ",
        FilterGreaterThan(numbers, 3)
    )
);
```

**Output:**

```text
4, 5
```

### Explicit state vs captured state

| Captured State | Explicit State |
|---|---|
| Dependencies can be hidden inside a closure | Dependencies appear in parameters |
| Convenient for short callbacks | Clearer for reusable calculations |
| May retain captured objects | Avoids unnecessary closure retention |
| Mutable captures can cause surprises | Inputs are easier to control |
| Useful for function factories | Useful for pure functions |
| May require closure allocations | Can avoid captured-state allocations |

**Key point:** Prefer explicit state when it makes dependencies clearer or avoids unnecessary mutable captures. Closures remain useful when capturing configuration is intentional.
